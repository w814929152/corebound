# 《守核》(Corebound) — 游戏概念文档

> **暂定名**：《守核》/ Corebound（**待用户拍板**，备选：《不动如山》IMMOVABLE、《雪球要塞》SNOWFORT）  
> **类型**：Roguelite 等距塔防 × 卡牌构筑（Auto-battler Tower Defense + Deckbuilder）  
> **引擎 / 平台**：Godot 4 / PC (Steam) / 2.5D 等距视角  
> **文档状态**：Phase 1 概念孵化 · **v0.4** · 含待定项，需用户审批后进入 Phase 2 系统设计  
> **v0.2 变更**：① 商店由「打开即暂停」改为**不暂停 · 实时**（用户拍板，推翻 v0.1 方案 A）；② 新增**塔 Build 分支**机制（主塔 / 挂件塔 / 多塔流）。  
> **v0.3 变更（由程基岩 W1–W20 纸面数值模拟驱动）**：③ **叠层复利拉入 MVP** 作为雪崩引擎（原「同 Tag +25% 加法」数学上无法起飞，作废）；④ 新增**共鸣网络 `Resonance`** 作为多塔的专属指数出口；⑤ §8 数值全面回写为校准值。见文末变更记录。  
> **作者**：文策渊（设计主理人）

## 0. 一句话设计

> **站着不动，把商店刷穿。**  
> 你从不移动任何一个单位。你唯一做的事，是在无限刷新的商店里，把有限的卡位组装成一台能吞掉整个屏幕的杀戮机器。

---

## 1. 设计支柱（Design Pillars）

支柱是**不可妥协**的判据：任何系统、任何数值、任何美术决策，若与以下四条冲突，砍掉它而不是改支柱。

### P1 · 不动如山 — 站位即策略（Static by Design）

玩家**永不操作单位移动**。所有战术深度来自「空间配置」而非「微操」：塔放在哪个位、射程覆盖哪段路径、火力集中在主路还是支路。  
**推论**：本作没有技能释放、没有集火指令、没有撤退。玩家的注意力预算 100% 归属于 build 构筑。  
**反向检验**：如果某个设计需要玩家在战斗中频繁点击战场 → 违反 P1。

> **v0.2 澄清（重要，修正了我此前的过强解读）**：P1 禁止的是**战场层**的微操（调兵、集火、撤退、技能释放），**不是 UI 层**的操作。玩家在商店面板上点击卡牌，不构成"操作单位"，因此**商店实时化本身不与 P1 冲突**——只要实时化不反过来逼玩家去关注/干预战场。  
> 实时化的真实约束是**注意力预算**：玩家看商店时，战场必须能靠**余光**维持（见 §2.1 C3 与视觉锚点 6）。只要做到这一点，注意力依然 100% 归属 build 构筑。

### P2 · 雪崩无上限 — 数值失控是设计目标（Snowball Without Ceiling）

后期数值爆炸**不是平衡事故，是核心卖点**。商店刷新次数无限，收入指数增长，一旦 build 成型，玩家的 DPS 必须能在几波内从三位数跳到六位数，屏幕必须被自己的弹幕填满。  
**但失控必须被 earned**：起飞（Takeoff）需要时间成本、卡位成本与决策风险。免费送的爽不算爽。  
**反向检验**：如果玩家的 DPS 曲线始终是线性 → 违反 P2。

### P3 · 每局一个新解 — 卡组即战术（Every Run, A New Answer）

卡池随机，玩家无法预设最优解，必须「读牌」临场创造。协同（Tag）走**乘法**而非加法：A×B 永远大于堆 10 张 A。  
**刹车机制**：**卡位有限（MVP 为 5 槽）**。无限刷的意义不是无限堆卡，而是「找到对的那一张 / 升级已有的那一张」——这让每一次刷新都是一个真实的赌注。  
**反向检验**：如果连续 20 局玩家都在走同一套 build → 违反 P3。

### P4 · 零操作，高密度 — 决策而非动作（Decisions, Not Actions）

APM = 0，但**决策密度**必须高。玩家的每一次输入都是不可逆的取舍：买攻击还是买经济？锁这张还是再刷一次？这张弱卡现在换掉还是等升级？  
**本作的"操作层"就是刷商店本身** —— 翻牌、购买、锁定的触感必须做得像动作游戏一样有反馈。  
**反向检验**：如果玩家在商店阶段无事可做只能无脑点 → 违反 P4。

> **v0.2 澄清**：P4 的敌人从来不是"操作次数"，而&#x662F;**"操作取代了决策"**。因此判断实时化的标准不是 APM 是否上升，而是：  
> **决策有没有被时间挤压成直觉反应？** 只要「要不要再刷一次」在实时下依然是一个可思考的取舍，P4 就成立。  
> 换言之：**APM 可以上升，决策质量不可以下降**。这是实时化唯一的设计红线，也是 §2.1 C1（战术减速）存在的全部理由。

> **可选支柱 P5（暂不纳入，Tier 1 再评估）**：失败即进度 — 每局结束带回 meta 资源，失败也是产出。  
> **理由**：MVP 阶段加入 meta 会污染「核心循环是否好玩」的验证信号，故 MVP 明确不做。

#### 🟢 关键机制决策 Q2（**v0.2 已由用户拍板**）：商店 = 不暂停 · 实时

> **用户决策**：商店打开时**游戏不暂停**，玩家可以边打怪边升级。v0.1 的方案 A（打开即暂停）**作废**。

**① 我对 v0.1 判断的修正（诚实标注）**  
v0.1 我把"不暂停"判为「违反 P1/P4」，这个结论**下得过重**，现修正：

| 支柱            | v0.1 我的判断 | v0.2 重新论证                                                                                                        |
| ------------- | --------- | ---------------------------------------------------------------------------------------------------------------- |
| **P1 不动如山**   | ❌ 违反      | ✅ **不冲突**。P1 禁的是**战场层**微操，商店操作在 **UI 层**，玩家依然不碰任何一个单位。「注意力 100% 给 build」在实时下依然成立——只是 build 决策从"静态时刻做"变成"在战斗流里做"。 |
| **P4 零操作高密度** | ❌ 违反      | ⚠️ **有条件兼容**。P4 的敌人是"操作取代决策"，不是"操作次数"。只要实时压力没把「要不要再刷一次」压成「快点刷」，P4 就还在。                                           |

→ **结论：不暂停与四条支柱兼容，但必须附加三条硬约束 C1–C3。没有这三条，它确实会退化成手忙脚乱。**

**② 压力来源的迁移（本次变更最被低估的价值）**

| 维度      | v0.1 暂停方案             | **v0.2 实时方案**                    |
| ------- | --------------------- | -------------------------------- |
| 压力来源    | 积分不够（**纯经济**）         | **注意力带宽 + 时机机会成本**               |
| "何时开商店" | **假选择**（反正暂停，何时开完全等价） | ✅ **真选择**（现在开 = 消耗减速预算 + 承担战场风险） |
| "开多久"   | 无成本（仅刷新成本）            | ✅ **有成本**（每一秒战场都在推进）             |
| 决策维度    | 1 维（经济）               | **2 维（经济 × 时序）**                 |

> **关键洞察**：v0.1 里"何时开商店"其实是一个**假决策**——因为暂停，任何时候开都完全等价。实时化把它变成了真决策。  
> 所以实时化**没有降低决策密度，而是增加了决策维度**。这是我 v0.1 论证中的盲点，也是我现在支持这个方向的核心理由。  
> 压力也从「我手慢了」（手速，违反 P4）迁移到了「**我现在敢不敢分心**」（时机判断，符合 P4）。

**③ C1 · 战术减速 Time Dilation —— 用慢动作替代暂停**

打开商店 → 全局时间缩放至 **`0.35×`**（**不是暂停，是慢动作**），战斗继续推进、怪物继续走。

- **为什么不是暂停**：暂停 = 零风险；慢动作 = **风险仍在，但思考时间 ×2.9**。保住紧张感与机会成本，同时把 APM 压力降到可思考区间。
- **减速不是免费的**：每波有 **减速预算 `DilationBudget = 20s`（实时秒）**，耗尽后自动恢复 `1.0×`，下一波重置。  
  → **时间本身成为一种货币**。这是本次变更我最想保住的一点：它把"开多久商店"从无成本动作变成**可分配资源**，直接喂给 P4 的决策密度，也避免玩家全程龟速。
- **新手保护**：W1–W5 打开商店自动进入 **`0.25×` 且不消耗预算**。苟活期的主要任务是学会 build，不该被实时压力锁死（见 R8）。
- **后期自然消解**：雪崩期（W13+）玩家 DPS 远超怪物，"战场威胁"趋近于 0，减速需求自然下降 → 后期玩家会本能地不再减速，**观赏感（Submission 美学）得以保留**。

**④ C2 · 智能高亮 Smart Highlight —— 降比较成本，不降取舍成本**

减速期间商店面板自动标注三类**事实**：

1. **买得起 / 买不起**（卡片亮 / 暗）
2. **与当前 build 存在 Tag 协同**（Tag 图标脉冲）
3. **差 1 张即可触发协同阈值**（"+1 协同"角标）

> 🔴 **红线**：高亮**只标事实，绝不标"推荐这张卡"**。  
> 一旦系统替玩家算出最优解，**Discovery 美学与自主性（SDT）当场死亡**，P3 也随之一块死。  
> 高亮要拿掉的是**比较成本**（"这张和那张哪个是火焰来着"），要留下的正是**取舍成本**（"买攻击还是买经济"）——后者才是本作的乐趣所在。

**⑤ C3 · 双焦点界面 Dual Focus —— 战斗与商店的视觉焦点分配**

| 项           | 方案                                                                                 |
| ----------- | ---------------------------------------------------------------------------------- |
| **形态**      | 商店 = **右侧抽屉式半透明覆盖层**（约 32% 宽度），战场保留左侧约 68% 可见                                      |
| **焦点切换**    | 打开即触发**背景压暗 + 去饱和**（vignette），视觉焦点自动跟随商店；关闭时反向恢复                                   |
| **穿透式 HUD** | **核心 HP 条**与"突破警告"绘制在商店层**之上**，永不被遮挡 —— 核心 HP 是唯一必须始终可见的战场信息                       |
| **余光告警**    | 怪物逼近核心时，战场侧屏幕边缘发**红光脉冲**。⚠️ **必须用动效而非文字**：人眼余光只对**运动与亮度**敏感，对形状与文字几乎不敏感（生理约束，不可违背） |
| **键盘直选**    | 刷新 `R` / 购买 `1``2``3` / 锁定 `Space` / 开关 `Tab`。缩短操作路径，把 APM 压力从"操作长度"里拿掉            |

- ❌ **否决「常驻侧栏」（v0.1 方案 C 的原型）**：常驻会永久占用 25–30% 屏幕，与 P2「屏幕被弹幕填满」直接冲突；且让玩家永远分心，**剥夺"纯粹观赏自己造物"的时刻**（Submission 美学）。覆盖层能开能关 = 玩家自己决定何时分心，这是自主性。
- ⏸ **保留波次间安全窗**：波次结算时**完全暂停**（Balatro 式），用于承载"**弃哪张**"这类不可逆的重决策。  
  → **职责切分：实时内做轻决策（买 / 刷 / 锁），波次间做重决策（弃卡 / 重构 / 转分支）**。

**⑥ 最终方案：方案 D**

| 方案                            | 描述                                                  | 状态            |
| ----------------------------- | --------------------------------------------------- | ------------- |
| A 随时可开 + 打开即暂停                | v0.1 推荐                                             | ❌ **用户已否决**   |
| B 纯波次间商店                      | 节奏规整但打断心流                                           | 备选            |
| C 常驻侧栏不暂停                     | 永久分心，占用屏幕                                           | ❌ 否决（见 C3）    |
| **D · 实时覆盖层 + 战术减速 + 波次间安全窗** | 战斗不停 · 打开降速到 0.35× · 减速预算 20s/波 · 智能高亮 · 波间完全暂停做重决策 | ✅ **v0.2 采用** |

> **方案 D 的一句话**：**用"时间缩放"替代"时间停止"，用"减速预算"把时间变成资源。**  
> 它同时满足了用户的体验诉求（边打边升，紧张感真实）与支柱底线（决策不被手速取代）。

### 2.2 Dynamics（动态 — 玩家实际体验到的行为）

#### 心流三阶段曲线

```
 强度
  ↑
  │                                                    ╱ 雪崩期 C
  │                                              ╱╱╱╱╱
  │                                        ╱╱╱╱╱        ← DPS 曲线（指数）
  │                              ┌───╱╱╱╱╱
  │                     ╱╱╱╱╱╱╱╱╱                        ← 起飞点 Takeoff
  │          ╱╱╱╱╱╱╱╱╱
  │    ╱╱╱╱╱  ································            ← 怪物强度曲线（指数）
  │ ╱╱╱ ·····
  │╱·····
  └──────────────────────────────────────────────────→ 波次
    苟活期 A        成型期 B            雪崩期 C
   (W1-5)          (W6-12)             (W13+)
```

| 阶段        | 波次    | 玩家状态                                | 资源特征                          | 主导情感         |
| --------- | ----- | ----------------------------------- | ----------------------------- | ------------ |
| **A 苟活期** | W1–5  | 塔太少，输出勉强跟上，核心 HP 缓慢下降               | 积分稀缺，每次刷新都肉疼，只能买最便宜的卡         | 紧张 · 脆弱 · 期待 |
| **B 成型期** | W6–12 | 第一个 Tag 协同达成（如 3 张火焰 → 点燃乘区），输出首次反超 | 开始有余裕；面临核心抉择：**继续投经济 还是 转攻击** | 顿悟 · 掌控 · 焦灼 |
| **C 雪崩期** | W13+  | DPS 远超怪物成长，屏幕被弹幕填满，数值跳到 6 位数        | 刷新成本相对收入趋近于 0 → **无限刷成为现实**   | 狂喜 · 主宰 · 观赏 |

**核心动态：正反馈环（刻意设计，不做抑制）**

```
击杀↑ → 积分速率↑ → 更多刷新 → 更强卡牌 → 输出↑ → 击杀↑  (闭环增益 > 1)
```

**设计目标（硬性）**：玩家 DPS 的复合增速必须**持续超过**怪物 HP 的增速。这是 P2 的数学表达。

> **🔴 v0.3 · 模拟推翻了 v0.2 的一个隐含假设（重要）**  
> 模拟证明：若强化卡是**加法**（v0.1/§8 原值 `同Tag +25%`），DPS 填满 5 槽后**触顶 ~111**，怪物指数增长 → **永远无法起飞**。  
> → **P2「雪崩无上限」在加法 buff 下数学不成立。** 必须引入**叠层复利**作为雪崩引擎（见 §8）。  
> **起飞是相变（悬崖），不是斜坡**：复利越过临界质量后，DPS 一两波内从不足 → 碾压。这正是 P2 要的手感。  
> ⚠️ **设计含义**：起飞点对系数**高度敏感**，因此"把悬崖推到 W10–15"必须靠**商店库存摩擦**（每波可获取的火焰卡上限），  
> 而不是靠调怪物成长率。→ 这让起飞时机重新回到**玩家可控**（凑不凑 Tag、什么时候开始深叠），见 §2.4.7。  
> **刹车机制（v0.2：由 1 个增至 3 个）**：收益递减不靠削弱正反馈，而靠**物理上限**——这比削数值优雅得多，且天然生成高价值决策。

1. **卡位 5 槽**（原）：天然生成「弃哪张」的决策。
2. **🆕 塔位有限 + 强化卡归属**：总层数固定时，**投给谁**决定你能吃 `AllIn` 还是 `Crossfire` / `Resonance`（见 §2.4）。
3. **🆕 减速预算 `20s/波`**：实时化后，连"思考时间"本身都变成了有限资源（见 §2.1 C1）。
4. **🆕 叠层软上限 `StackCap`**（v0.3）：复利不能无限叠，否则数值溢出。  
   ⚠️ **必须是软 cap（分段衰减），不能是硬墙** —— 模拟显示多塔的 `FrostUp` 在 W10 撞硬 cap=100 后**增速骤降**，  
   是"雪崩期 DPS/HP 见顶回落"的直接原因之一。硬墙 = 反 P2（雪崩期反而失速）。**建议改为分段衰减 + 协同可提高分段点**（见 §8、R12）。

> ⚠️ **自查**：四个刹车同时存在，需警惕**认知过载**（R10）。MVP 试玩中若出现"算不过来"，优先砍第 3 个的 UI 暴露（保留机制）。

#### 张力来源（**v0.2 更新为五个**，缺一即无聊）

1. **刷新成本递增 vs 收益递减**：再刷一次，还是拿走手上这张？
2. **攻击 vs 经济的时机抉择**：投经济是复利，但投晚了怪物就压死你。这是本作**第一个核心技巧维度**。
3. **卡位挤兑**：5 槽装不下所有好卡，弃卡 = 永久损失（MVP 不可回收）。
4. **🆕 什么时候敢开商店**（实时化新增）：现在开 = 消耗减速预算 + 承担战场推进风险。这是本作**第二个核心技巧维度**，也是实时化把"假选择"升级成的"真选择"。
5. **🆕 集中 vs 分散**（塔 Build 分支新增）：强化卡投给主塔冲 `AllIn ×1.6`，还是分散投去吃 `Crossfire`？—— 且**转型有代价**，必须预判。

### 2.4 塔 Build 分支：单核 / 挂件 / 多塔（Tower Build Archetypes）

> **v0.2 新增机制（用户需求）**：玩家可以只升级一座核心主塔、其他塔当挂件；也可以分散升级多座塔。  
> 这**不是**一个开局菜单选项，而是一套由机制自然涌现的策略分支。

#### 2.4.1 为什么它是本作的策略深度来源

| 支柱            | 如何兑现                                               |
| ------------- | -------------------------------------------------- |
| **P1 站位即策略**  | 分支由**塔位覆盖值 + 发牌 + 怪物构成**共同逼出，本质是空间配置决策，不是数值菜单      |
| **P3 每局一个新解** | 三条分支各有**独立的乘区来源**，没有一条在所有局面下都最优 → 玩家必须**读牌 + 读局面** |
| **P4 决策密度**   | 稀缺维度从 1 个（卡位 5 槽）增加到 3 个（卡位 × 塔位 × 强化卡归属）          |

#### 2.4.2 唯一新规则：强化卡装配到「具体某座塔」

> **本机制的全部地基，就是这一条规则**：  
> **强化卡不是全局生效，必须装配到某一座具体的塔。**

由此，**主塔是涌现的，不是声明的**：

- **主塔 `CoreTower` = 累计强化层数最高的那座塔**（自动判定），塔顶显示徽章 + 底座发光。
- **零额外 UI、零额外操作负担** → 符合 P1/P4。玩家的"主塔选择"就是他自己投资行为的自然结果，不需要他去点一个"设为主塔"按钮。
- 装配默认投给当前主塔；点击其他塔即可切换装配目标。
- **卸卡有代价**：装配到塔上的强化卡可卸下，但**卸下时该卡降 1 层**（MVP 规则）。  
  → "什么时候从单核转型到多塔"是**有代价的真决策**，而不是随时无痛重来（否则分支选择就失去意义）。

#### 2.4.3 结构修正（v0.3）：**两条主干 + 一个修饰层**

> ⚠️ **我对 v0.2 的自我修正**：v0.2 把「单核 / 挂件 / 多塔」并列为**三条分支**，这个表述**不准确**，现修正。

- **挂件塔不产 DPS**，它只提供乘区 → 它**永远无法独立成立**，必须寄生在一个能输出的塔上。
- 因此正确结构是：**两条主干路径（单核 / 多塔） + 一个可叠加在任一主干上的修饰层（挂件）**。
- 玩家的真实选择是 **2 × 2**：`单核裸奔 / 单核+挂件 / 多塔裸奔 / 多塔+挂件`。

#### 2.4.4 三条路径各自的「专属指数出口」（v0.3 核心新增）

> **问题源头（程基岩模拟，§0.6）**：多塔在 W12 见顶 `DPS/HP = 9.3×` 后**回落到 W20 的 2.5×**，  
> 而单核一路涨到 10.09× → 雪崩期策略多样性**向单核坍缩**，P3 崩塌。
>
> **我的根因诊断（比"缺一个出口"更深一层）**：  
> **单核的投资标的（强化卡叠层）是「指数」的；多塔的投资标的（塔卡）是「一次性 + 次线性 ∝level^0.6」的。**  
> 指数 vs 次线性 —— 在这个结构下多塔**必然**在后期被反超，给它贴任何 buff 都只是"推迟见顶"（扫参已证实）。  
> **并且还有一个更硬的结构问题：原 MVP 塔位只有 4 个，"广度"的基数上限太小（4 塔全互连也仅 `k=3`），根本撑不起一个分支。**  
> → 故我提出 **Q10：塔位 4 → 6**（关卡多摆 2 个基座，美术完全复用，成本极低）。**这是模拟驱动的范围修正，不是范围膨胀。**
>
> → **正确解法不是给多塔贴 buff，而是让「广度」本身成为一个独立的复利维度。**

**① 单核 → 深度复利 `DeepCompound`** ✅ 模拟已验证

- **引擎**：强化卡叠层，**每层 `×1.10`**，软上限 100 层（可由 Tag 协同提高）。
- **数学**：`DPS ∝ Base × 1.10^L` → 单塔指数增长。
- **模拟结果**：起飞 **W11**，W20 `DPS/HP = 10.09` 且**持续甩开** ✓
- **天花板（刻意保留）**：**目标并发数 = 1** → 撞**数量墙**，怕海、怕 Swarm。
- **雪崩的视觉形态**：**数字爆炸** —— 一座塔打出天文数字，弹幕从它身上喷涌。

**② 多塔 → 广度复利「共鸣网络 `Resonance`」** 🆕 v0.3 新增（我的方案，替代 A/B）

> **一句话**：**让"一次投入"通过链接网络被放大 k 次。**

| 规则          | 内容                                                                |
| ----------- | ----------------------------------------------------------------- |
| **链接 Link** | 两座塔的射程发生重叠 → 自动建立一条链接（视觉：两塔之间一道光弧）。**不需要玩家操作**，是站位的自然结果           |
| **谐波层 `h`** | 塔 j 的**塔卡层数**即其谐波层数 `h_j`（复用现有叠层，不新增卡种）                           |
| **共鸣乘区**    | 塔 i 的伤害 `× (1 + κ_r)^(E_i)`，其中 **`E_i = Σ_{j 与 i 链接} (1 + h_j)`** |
| **`κ_r`**   | ✅ **定稿 `0.050`**（v0.7 复扫确认；MVP flat 全场统一施加，无 Tag / 中性塔同值；档位 `0.040/0.045/0.050` 保留为 T1 扩展位）。低于单核的 0.10，因为多塔每层被放大 k 次，需打折 |

**为什么这能产生雪崩**：

- 给塔 j 投 1 层塔卡 → 塔 j 自身 `∝level^0.6`（**次线性，会衰减**），但**与 j 链接的 k 座塔各 `×1.05`（指数，永不衰减）**。
- → 有效复利/层 ≈ `k × ln(1.05)`。k=3 时 ≈ `0.146/层`，而单核是 `ln(1.10) = 0.095/层`。
- → **多塔用"放大倍数 k"换"更低的单层利率"**，两条路径总增速同量级，但**形态完全不同**。

**为什么它同时兑现 P1 与 P3**（这是我最看重的一点）：

- **`k` 完全由站位拓扑决定** → **你的布局直接决定你的复利率**。这是 P1「站位即策略」迄今最硬核的机制化。
- 不同地图的塔位拓扑不同 → 能形成的链接数不同 → **多塔流的上限每局不同**。  
  有的局塔位密集（多塔强，走多塔），有的局塔位分散（链接少，多塔弱，走单核）→ **P1 与 P3 直接咬合**。

**成本与天花板**：

- 前置投入大（要先把 k 座塔建起来并互连），塔卡有价。
- 塔挤在一起才有链接 → **覆盖盲区**：路径其他段没塔 → **怕分流 / 多路径地图**。
- 吃不到 `AllIn ×1.6` → 依然**怕硬**（Tank / Elite / Boss 单体）。

**为什么选它而不是 A / B**（对程基岩两个出口方向的取舍）：

| 方案                          | 判断                                                                          | 理由                                                                                                                               |
| --------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **A 塔进化 / 合成**              | ❌ 不推荐                                                                       | 需新美术资产（高阶塔模型）+ 新 UI（合成界面）+ 新卡种 → **MVP 范围大幅膨胀**；且合成会**销毁已有塔位**，与 P1 直接冲突（合成后塔位空出，要重新布局）；更关键：合成是**一次性跃迁**而非持续复利，无法支撑 W13–W20 的长雪崩 |
| **B 全局复利光环**（每有一座满级塔 ×1.05） | ❌ 不推荐                                                                       | MVP 塔位 4 个 → 天花板仅 `1.05^4 ≈ 1.22×`，**弱指数撑不起雪崩**；且与**站位无关**，是纯数值 buff，缺乏策略纹理，浪费了 P1 这个支柱                                          |
| **C 共鸣网络** ✅ **推荐**         | **零新增塔原型、零新增卡种、零新增合成 UI** —— 只需**链接可视化 + 塔上显示共鸣层数**。且**直接把 P1 变成复利引擎的驱动变量** |                                                                                                                                  |

**③ 挂件 → 寄生跃迁「赋能 `Empowerment`」** 🆕 v0.3 新增（**T1**，MVP 保留固定减速 30%）

- **规则**：挂件塔的减益强度随**主塔层数**增长 —— `slow = min(0.30 + 0.002 × CoreTower层数, 0.75)`。
- **为什么这是它自己的雪崩**：等效倍率 `1/(1-slow)` 是**超线性**的 ——  
  `30% → 1.43×`，`50% → 2.0×`，`75% → 4.0×`。**减速率逼近 1 时效用爆炸**，这是一个天然的跃迁点。
- **雪崩的视觉形态**：**时间凝固** —— 怪物越走越慢，最后几乎**静止在弹幕里爬行**。
- ⚠️ **硬 cap 0.75**（等效 4.0×）：**禁止减速 → 1**，否则"守核"变成零风险，Challenge 美学当场死亡。
- **挂件必须寄生**：它不产 DPS，永远只能修饰单核或多塔 → 再次印证 §2.4.3 的结构修正。

> 🎨 **给美术（林绘澄）的额外收获**：三条路径的雪崩**视觉形态彼此可区分** ——  
> **单核 = 数字爆炸**（一个塔打出天文数字）· **多塔 = 覆盖爆炸**（塔间连成共鸣光网，整片区域沦为杀戮场）· **挂件 = 时间凝固**（怪物龟速爬行）。  
> 这直接支撑 Fantasy 美学与玩家身份认同（"我这局造的是什么"），也让结算界面的 build 展示有画面可讲。

#### 2.4.6 "每局一个新解"如何生成（v0.3 更新）

分支由五个随机变量共同逼出，**玩家开局并不知道这局会走哪条**：

1. **发牌顺序 + 库存摩擦** —— 早期刷到什么、每波能拿到几张火焰卡，决定你能深叠哪张。
2. **塔位覆盖值 `CoverageScore`** —— 高覆盖位 = 天然主塔位，低覆盖位 = 天然挂件位。
3. **🆕 塔位链接拓扑 `LinkTopology`**（v0.3）—— **能形成几条链接直接决定多塔流的复利率**。这是"每局一个新解"**最强的新来源**。
4. **怪物构成漂移** —— Swarm 占比高的局逼你转多塔；Boss 单体逼你保 `AllIn`。
5. **卸卡代价** —— 转型有成本，必须**预判** → 产生"我这局是不是该早点分散"的复盘价值。

#### 2.4.7 复利引擎对 P3 与 Tag 协同的影响评估（v0.3 必答题）

> **承峰的问题**：叠层复利会不会让"凑 Tag 协同"变得不重要（因为叠层就够了）？会不会削弱 P3「每局一个新解」？

**Q：Tag 协同会被复利稀释吗？**  
**A：会 —— 如果保持 v0.2 的定义。所以我把 Tag 的定义改了。**

- **问题所在**：v0.2 中 Tag 协同提供**一次性乘区 ×1.5**。但在复利引擎下，叠 100 层 = `1.10^100 ≈ 13,780×`。  
  **一个一次性 ×1.5 相对 13,780× 完全不可见 → Tag 确实会沦为摆设。这个风险是真实的。**
- **✅ 解法（v0.3 重定义 M8）**：**Tag 协同不再提供一次性乘区，改为提供「复利率加成 + 软上限解锁」。**

| 该 Tag 的投入层数    | 复利率             | 软上限 `StackCap` |
| -------------- | --------------- | -------------- |
| 0–2 层（未协同）     | `×1.06` / 层     | 50             |
| **≥3 层（协同成立）** | **`×1.10` / 层** | **100**        |
| ≥6 层（深度协同）     | `×1.12` / 层     | 150            |

- **杠杆对比**：复利率从 1.06 → 1.10，在 100 层时的差距是 `1.10^100 / 1.06^100 = 13780 / 339 ≈ **40.6×**`。  
  → **原来 Tag 协同值 ×1.5，现在值 ×40.6。Tag 的杠杆被放大了 27 倍。**
- **结论（反直觉但重要）**：**复利引擎不但没有削弱 Tag，反而把 Tag 变成了复利引擎的「转速开关」。**  
  Tag 从"小额一次性奖金"升级为"决定你这局能滚多快的档位"，**P3 被强化而非削弱**。

**Q：复利会不会让每局都一样（"找到一张能叠的卡然后叠满"）？**  
**A：风险成立，我诚实标注。但它被三重防御化解，且"解"的形态发生了迁移。**

| 防御                       | 机制                                                    |
| ------------------------ | ----------------------------------------------------- |
| ① **发牌 + 库存摩擦**          | 你不一定能拿到想叠的那张 → **"叠什么"由发牌决定**。每局的核心 Tag 不同 → build 不同 |
| ② **协同按「投入层数」判定**（程基岩修正） | 深叠本身即达成协同 → 深叠与凑 Tag 不再互相排斥，而是同一件事的两面                 |
| ③ **🆕 共鸣网络依赖塔位拓扑**      | 多塔流的形态每局随地图链接拓扑变化                                     |

- **P3 的形态迁移**：从「**组合多样性**」（这局组什么 combo）→ 「**约束下的应变多样性**」（这局发给我的牌里哪张值得叠 / 什么时候从铺场转深叠 / 要不要为了凑 Tag 买一张低价值卡）。  
  → **依然是"每局一个新解"，只是"解"从「组合」变成了「投资路径」。**
- 🔴 **新的卡池红线（比 v0.1 更关键）**：**每张强化卡都必须"可叠且叠了有用"**。  
  一旦出现"叠了也没用"的卡，P3 立刻退化为假选择。这是 Phase 2 卡池设计的第一约束。

**Q：起飞是悬崖，会不会让玩家觉得"突然就赢了"（胜任感受损）？**  
**A：不会，前提是悬崖要绑在玩家可控的开关上。**

- 程基岩发现：起飞是**相变**，对系数高度敏感。若靠调数值把悬崖推到 W10–15，玩家会觉得"突然就赢了" → 归因滑向运气。
- ✅ **解法**：既然复利率由 **Tag 协同档位**决定（1.06 / 1.10 / 1.12），那&#x4E48;**"什么时候起飞"就变成一个玩家可主动争取的决策**（凑不凑够 3 层火焰）。
- → **把数值悬崖转化为玩家可控的开关**：失败时玩家能明确说"我这局没凑够火焰，复利率一直在低档" → **归因于决策而非运气**，胜任感的"清晰归因"得以保全（见 §4.1）。

#### 2.4.8 与认知过载的平衡（红线自查）

新增 2 个稀缺维度会显著抬高决策密度（P4 受益），但**认知过载是我的设计红线之一**，故设三条缓解：

1. **装配默认投主塔**，切换只需点击目标塔（1 次输入）。
2. **塔顶层数徽章 + 主塔专属发光** → 分支状态一眼可读，不需要玩家心算。
3. **商店智能高亮（§2.1 C2）同步显示**"这张卡投给主塔 / 投给挂件"的**预估收益数字**。  
   ⚠️ **只显示数字，不显示推荐** —— 与 C2 同一条红线。
4. **🆕 共鸣层数不要求玩家心算**（v0.3）：链接光弧的**亮度/粗细**直接编码 `E_i`（共鸣强度），  
   塔上只显示一个**总共鸣倍率数字**（如 `×7.4`）。玩家不需要知道公式，只需要看到"这条链接很粗 = 很值"。  
   ⚠️ **这是 `Resonance` 能否落地的关键 UI 约束**：若玩家看不懂链接，整个机制等于不存在。
5. **🆕 若试玩显示过载 → 优先砍 `E_i` 的公式暴露，保留视觉编码**（与 R10 同一处置原则）。

## 3. 核心循环（Core Loop）

### 3.1 单局内循环（微循环，秒级闭合）

```
  ┌────────────────────────────────────────────────────────────────┐
  │                                                                │
  ▼                                                                │
[战斗·持续] 怪物沿路径推进 ──→ [塔自动攻击] ──→ 击杀 ──→ 掉落积分 Scrap
      │                                                            │
      │  ⚠️ 战斗永不停止                                            │
      │                                                            ▼
      │                                            [积分入账 + 到账速率可视化]
      │                                                            │
      │   ┌────────────────────────────────────────────────────────┘
      │   │
      ▼   ▼
[商店·随时呼出，不暂停]  Tab 打开 → 时间缩放 0.35×（减速预算 20s/波）
                          ├─ 浏览 3 个商品位（智能高亮：买得起 / 协同 / +1 协同）
                          ├─ 轻决策：买 / 锁 / 再刷一次（成本 5+3n，单波内递增）
                          └─ 购买 → 装配到 5 卡位 → 再装配到「具体某座塔」
      │
      ▼
[反馈] 输出↑ 或 经济↑ ──→ 回到战斗（战斗从未中断）──────────────┘
```

> **v0.2 关键变化**：战斗与商店从「串行」变为「**并行**」。  
> 反馈链因此缩短到 **< 1 秒**（买完立刻看到弹幕变化，无需等待波次结算）——这是实时化对「即时反馈」（胜任感来源之一）的**额外增益**。

### 3.2 波次循环（中循环）

```
Wave N 战斗（40–70s，全程可与商店并行）
   → 波次结算【完全暂停 · 安全窗】← 承载重决策：弃卡 / 重构 / 分支转型
   → Wave N+1（怪物 HP `×1.42` · 数量 `8+1.6w`，v0.4 定稿值）
```

- **战斗内** = 轻决策区（买 / 刷 / 锁），**波次间** = 重决策区（弃 / 转 / 重构）。职责切分见 §2.1 C3。
- 减速预算 `DilationBudget` **每波重置**，与刷新成本 `5+3n` 的重置节奏对齐（两个"每波重置"的资源，构成波次内的资源规划）。
- 每 5 波插入一个 **Elite 波**作为节奏标点（Tier 1 起加入 Boss）。

### 3.3 局循环（宏循环）

```
开局（1 张起始塔卡） → 苟活 → 成型 → 雪崩 → 结局
                                              ├─ 核心 HP 归零 → 失败 → 重开
                                              └─ 达成目标波次（MVP: W15）→ 通关 / 无限波继续冲榜
```

### 3.4 跨局 Meta 循环（Tier 1 起，MVP 不做）

```
局结束 → 按「最高波次 + 总积分」结算 蓝图碎片 Blueprint Shards
       → 解锁：新塔原型 / 新卡池 / 新起始卡 / 地图 modifier
       → 下一局起点更高、卡池更大
```

**⚠️ 硬性约束**：meta 提供的强度收益上限 **≤ 30%**。超过这个阈值，roguelite 的随机乐趣会被数值碾压稀释（风险 R4 相关）。  
**⚠️ MVP 明确不做 meta**：避免污染核心循环的验证信号。

## 4. 玩家心理学

### 4.1 自我决定论（SDT）

#### 自主性 Autonomy — ★★★ 强

玩家拥有**真实且非虚假的选择**：

- **何时开商店、刷多少次**（刷新是可以永远继续的，停手是玩家自己的决定）
  - **v0.2 强化**：实时化后，"何时开"从**假选择升级为真选择**（要消耗减速预算 + 承担战场推进风险），自主性维度增加
- 钱花在攻击、经济还是刷新折扣上
- 5 个卡位装什么、弃什么
- 走哪个 Tag 协同（取决于发牌，不由玩家预设，但**如何应对**由玩家决定）

**关键设计约束**：必须保证「每张卡都 viable，只是取决于当前 build」。一旦出现废卡，自主感立刻退化为假选择。这是卡池设计的红线。

#### 胜任感 Competence — ★★★ 强（本作的主引擎）

| 来源         | 实现                                                                                |
| ---------- | --------------------------------------------------------------------------------- |
| **即时反馈**   | 击杀 → 积分 → 数字跳动 → 输出提升，反馈链 **< 2 秒**                                               |
| **可理解的成长** | 伤害数字从 12 → 120 → 12,000，成长是**看得见的数字**，不是隐藏属性                                      |
| **可迁移的技巧** | **v0.2 更新为核心技巧两个**：① **「经济转攻击的时机」**；② **「何时敢分心开商店」**（注意力分配）。两者都在每局可练习、可复盘、可通过失败提升 |
| **清晰的归因**  | 失败局玩家能明确说出"我这局刷太早了/经济投晚了" → 归因于**决策**而非运气                                         |

**⚠️ 风险**：若起飞率过低（<60%），归因会滑向"运气不好"，胜任感崩塌。故设**起飞率目标 ≥ 80%**（见 R4）。

#### 关联感 Relatedness — ★ 弱（诚实标注）

本作本质是**孤独的爽游**，关联感只能靠异步手段：

- MVP：结算成绩卡（一键截图 / 种子分享）
- Tier 2：Steam 排行榜、每日挑战（全服同一种子）  
  **不做**：多人、社交系统、公会。这是范围红线。

### 4.2 Bartle 玩家类型

| 类型                 | 目标度     | 满足方式                | 交付内容                             |
| ------------------ | ------- | ------------------- | -------------------------------- |
| **Achiever 成就者**   | ★★★ 主目标 | 冲波次记录、解锁全卡池、100% 图鉴 | 波次里程碑、局内统计面板、Steam 成就（T2）        |
| **Explorer 探索者**   | ★★★ 主目标 | 发现协同组合、找隐藏 combo    | 大卡池 + 强乘法协同 + 图鉴"已发现 combo X/50" |
| **Socialiser 社交者** | ★ 弱     | 分享 build 与成绩        | 一键生成成绩卡（种子 + 最高波次 + 最终 build 截图） |
| **Killer 杀手**      | ★ 弱（异步） | 排行榜竞速               | Steam Leaderboard + 每日种子（T2）     |

> **核心洞察**：Achiever 与 Explorer 是本作的双引擎，两者共享同一个驱动——**「这一局的 build 有多离谱」**。因此结算界面必须把「最终 build 的离谱程度」作为展示核心（最高单卡叠层、总倍率、触发的 combo 数），而不是只显示波次。

### 4.3 为什么这个玩法成立（一句话总结）

> 它把**操作的负担**全部换成**决策的密度**，把**线性的成长**全部换成**指数的回报**——因此玩家在零操作的前提下，依然能获得满额的胜任感与自主感。
>
> **v0.2 补记**：商店实时化**没有推翻这句话，而是给它加了一个维度** —— 决策不仅有「选什么」，还有「**什么时候选**」。操作负担依然是 0（玩家从不操作单位），决策密度反而从 1 维升到 2 维（经济 × 时序）。前提是 §2.1 的 C1–C3 三条约束必须落地，否则密度会退化成压力。

## 6. 视觉锚点（给美术主理人 林绘澄）

> **v0.2 更新为 6 条锚点**（新增锚点 6 · 双焦点界面，由"商店实时化"直接导出）。按优先级排序。锚点 2 与锚点 4 是**本作视觉能否成立的关键**，请优先确认；**锚点 6 为新增，请林绘澄优先过一遍**。

### 锚点 1 · 等距要塞 Isometric Bastion

2.5D 等距（约 30° / 2:1 菱形网格），**相机固定不旋转**，核心居中俯视。  
**硬要求**：地形必须有**明确的主路径视觉引导**（地面材质/颜色区分路径与非路径），玩家一眼能看出怪物从哪来到哪去。  
参考：《王国保卫战》的地形可读性 + 《Dorfromantik》的低多边形柔和感 + 《Into the Breach》的等距棋盘清晰度。

### 锚点 2 · 克制底色，高饱和特效 Muted Base, Loud Effects ⭐关键

场景用**低饱和冷灰 / 沙褐色**，让后期满屏的火焰、闪电、爆炸成为画面里**唯一的高饱和**。  
**为什么这是关键**：数值爆炸的爽感必须靠对比才能成立——**底色越静，爆发越响**。如果场景本身就五颜六色，后期弹幕只会变成一坨糊。  
**硬要求**：场景饱和度上限设定为 特效饱和度的 1/3 以下。

### 锚点 3 · 机械 vs 有机 Clockwork vs Flesh

- **塔 = 精密机械 / 炼金装置**：金属、齿轮、发光管路、铆钉
- **怪物 = 有机黏腻**：血肉、甲壳、黏液、不对称轮廓

视觉对立直接强化「守 vs 攻」的叙事张力，也让玩家在满屏混乱中仍能瞬间区分敌我（配合锚点 4）。

### 锚点 4 · 信息即美术 Readable Chaos ⭐关键

后期满屏弹幕，**塔的可读性 必须 > 特效的华丽度**。  
**硬性规则**：

1. 任何特效**不得遮挡塔的轮廓与核心 HP 条**（可用 additive blending + 深度裁切实现）
2. 伤害数字使用**固定网格排布**，禁止随机乱飞重叠（参考《吸血鬼幸存者》的处理）
3. 每个塔必须有**唯一剪影**——关掉特效后玩家仍能一眼分辨 3 种塔
4. **🆕 余光可读性 Peripheral Readability**（v0.2 因商店实时化新增的硬约束）：  
   玩家看商店时，战场只能靠**余光**维持。人眼周边视觉只对**运动与亮度**敏感，**对形状、文字、细节几乎不敏感**（生理约束，不可违背）。  
   → 因此**战场的关键告警必须编码为「运动 + 亮度」**：核心告急 = 屏幕边缘**红光脉冲**；怪物突破 = 路径上**高频闪烁**。  
   → **禁止**把"核心 HP 数字"作为唯一的告警手段（玩家在看商店时读不到数字）。

### 锚点 5 · 卡牌 = 机械蓝图 Cards as Blueprints

卡牌视觉**不走奇幻塔罗**，走**工程蓝图 / 仪表盘**风格：细线描边、等宽字体、Tag 用彩色电路符号表示。  
**目的**：强化「我是工程师在改装要塞」的身份认同（对应 Fantasy 美学），同时与《小丑牌》的扑克牌视觉**明确拉开距离**，避免"换皮"观感。

### 锚点 6 · 双焦点界面 Dual Focus 🆕（v0.2 新增 · 由实时商店导出）

> **给林绘澄**：商店实时化意味着**同一屏幕上必须同时存在两个视觉焦点**（战场 + 商店），且焦点要能在两者之间**明确切换**。这是本作 UI 的最大难点，请优先给方案。

**硬要求**：

1. **层级分明**：商店覆盖层（右 ~32%）为**前景高亮**， battlefield（左 ~68%）在商店打开瞬间**压暗 + 降饱和**（vignette），焦点自动切换；关闭时反向恢复。**禁止两个区域同等亮度**——那会让玩家哪个都看不清。
2. **穿透式 HUD**：**核心 HP 条**绘制在商店层**之上**，永不被遮挡（这是唯一豁免遮挡规则的 UI 元素）。
3. **半透明但可读**：商店覆盖层允许透出战场动效（保持"边打边升"的临场感），但**卡片文字区域的对比度必须 ≥ WCAG AA**（可访问性红线，见 accessibility-requirements）。
4. **减速的视觉语言**：进入 `0.35×` 时必须有明确的视觉信号（轻微色偏 / 边缘模糊 / 慢动作粒子），否则玩家不知道自己在减速、也不知道预算快用完了。**减速预算剩余量必须常驻可见**（商店面板上的一条环形/条形指示）。
5. **常驻侧栏方案已被否决**（见 §2.1 C3）——覆盖层是唯一可行的形态，请勿按常驻侧栏设计布局。

### 参考方向关键词

`Kingdom Rush`（布局可读性） · `Vampire Survivors`（视觉过载美学） · `Balatro`（卡面信息密度） · `Dorfromantik`（等距柔和） · `Into the Breach`（等距棋盘清晰度）

### 8.2 叠层复利引擎（🔴 v0.3 核心变更）

> **原「同 Tag +25% 加法」已作废。** 模拟证明加法 buff 下 DPS 触顶 ~111，**永远无法起飞**（P2 数学不成立）。

| 项                | 原值                  | **v0.3 校准值**                 | 备注                              |
| ---------------- | ------------------- | ---------------------------- | ------------------------------- |
| 强化卡叠层            | 同 Tag `+25%` **加法** | **每层 `×1.10` 复利**（单核）        | 5 卡位上限下**唯一**能产生 P2 雪崩的引擎       |
| 多塔叠层复利           | —                   | **每层 `×1.06`**（多塔，因 buff 摊薄） | 路径差异的来源                         |
| 叠层软上限 `StackCap` | 无                   | **100**（⚠️ 必须是**分段衰减**，见下）   | 🔴 硬 cap 会导致雪崩期失速（R12），**硬墙禁止** |
| 塔叠层              | 线性                  | **`∝ level^0.6`（次线性）**       | 边际递减，使"深叠强化卡"成为更优再投资方向          |
| 协同判定             | 按**张数**             | 按**投入层数**                    | 修正：深叠同一火焰塔也应达成协同                |
| 经济卡              | 占卡位                 | **全局升级，不占卡位**                | 否则理性玩家永远买不起协同位                  |

**🔴 Tag 协同 = 复利率档位开关（v0.3 重定义，见 §2.4.7）**

| 该 Tag 投入层数     | 复利率             | `StackCap` |
| -------------- | --------------- | ---------- |
| 0–2 层（**未协同**） | `×1.06` / 层     | 50         |
| **≥3 层（协同成立）** | **`×1.10` / 层** | **100**    |
| ≥6 层（深度协同，T1）  | `×1.12` / 层     | 150        |

> **杠杆验算**：\`1.10^100 / 1.06^100 = 13780 / 339 ≈ **40.6×**  
> → 协同从"一次性 ×1.5"变成"复利档位差 ×40.6"，**Tag 的重要性被放大 27 倍**，P3 被强化而非稀释。

**软 cap 分段衰减（PLACEHOLDER，交工程扫参）**

```
层 ≤ 100  : ×1.10 / 层
层 > 100  : ×1.03 / 层（衰减但不归零）
```

> 目的：避免"撞硬墙 → 增速骤降"。最终衰减曲线由程基岩扫参确定，**设计层只给一条红线：软 cap 后复利不得归零**（归零 = 反 P2）。
