## 0. 结论前置（给赶时间的人）

1. **商店不是"菜单"，是一条与战斗并行的第二条时间线。** 方案 D 的本质是：**用「时间缩放」替代「时间停止」，用「减速预算」把时间变成货币。** 本 GDD 把它落成一张五态状态机（§2.1），五个态的**时钟口径各不相同** —— 这是实现时最容易写错的地方。
2. **减速预算是本系统的灵魂，它让"何时开商店"从假选择变成真选择。** `20s/波` 实时秒 @ `0.35×` → 战场只推进 `7s`，玩家拿到 `20s` 思考 ≈ **2.86× 思考时间增益**。它**只在商店打开期间消耗**，耗尽不赶人（回 `1.0×`），每波重置。
3. **无限刷新的张力来自 `5+3n`，不来自任何额外惩罚。** 概念 §8.4 已实证「分心惩罚不需要」——单波递增本身就是天然时间税。本 GDD **不新增任何分心惩罚**。
4. 🔴 **pity 保底修的是归因，不是数值。** 摘除 `×1.5` 后单核 A 起飞率 `64.0% → 47.0%`，而失败局 **100% 是"整局没抽到几张 FireUp"** → 成败归因滑向运气，违反概念 §4.1。保底保证「**每波至少买得到 1 张**」，**不保证刷到什么** → **刷商店的赌徒张力（张力来源 1）完整保留**，G2 供应链仍然值得买。
5. **智能高亮只降「比较成本」，不降「取舍成本」。** 它拿掉的是「这张和那张哪个是火焰来着」，留下的是「买攻击还是买经济」——**后者才是本作的乐趣所在**。§2.3 的规则表是本 GDD 最该被反复引用的一页。
6. **售卖 ≡ 拆塔，且它只在安全窗。** 战斗内**完全禁止**任何塔相关操作（红线 **T-C1**）。这是 P4 的底线：**重决策必须发生在无时间压力的时刻**。

## 1. 系统目标（System Goal）

### 1.1 一句话

> 商店是玩家**唯一的输入面**。它必须在**战斗永不停止**的前提下，让「要不要再刷一次」依然是一个**可思考的取舍**，而不是一个手速反射。

### 1.2 与支柱的兑现关系

| 支柱 | 本系统如何兑现 | 若不满足则 |
|---|---|---|
| **P1 不动如山** | 商店操作发生在 **UI 层**，不触碰任何一个单位。玩家从不点战场上的单位 | 若实时化反过来逼玩家去干预战场 → 违反 P1 |
| **P2 雪崩无上限** | 刷新次数**无限**、成本仅单波递增 → 雪崩期"刷穿商店"成为现实（概念 §2.2 C 阶段） | 若刷新有全局上限 → 雪崩被人为封顶 |
| **P3 每局一个新解** | 发牌随机 + `pity` 只保"买得到"不保"刷到什么" → 每局的卡序与库存摩擦不同 | 若商店按玩家 build 定向发牌 → Discovery 死亡 |
| **P4 决策而非动作** | `0.35×` 减速 + `20s` 预算 → **APM 可升，决策质量不可降**；`Tab/R/1-3/Space` 键盘直选把操作路径压到最短 | 若"要不要再刷"被压成"快点刷" → **P4 破裂（R5′）** |

### 1.3 本系统的五条设计红线（自检用）

| # | 红线 | 出处 |
|---|---|---|
| 🔴 **SR-R1** | **战斗永不停止**。商店打开 = 慢动作，**永远不是暂停**；唯一例外是波次间安全窗 | 方案 D · 概念 §2.1 ⑥ |
| 🔴 **SR-R2** | **智能高亮只标事实，绝不标推荐**（不排序、不评分、不指向、不隐藏"差"卡） | C-3 · 概念 §2.1 ④ · `card-system` C-3 |
| 🔴 **SR-R3** | **战斗内完全禁止任何塔相关操作**（不能修 / 不能卖 / 不能加固 / 不能撤退） | T-C1 · `mechanics-tower-life-death` v1.0 §2.2 |
| 🔴 **SR-R4** | **pity 不覆盖玩家锁定的商品位**（锁定是玩家已付代价的显性决策） | `card-system` §4.5.1 / E15 |
| 🔴 **SR-R5** | **`Engine.time_scale` 不得为 `0`**（安全窗用 `get_tree().paused`，预算计时用 unscaled） | 本 GDD §8.8 交接点 2 |

### 1.4 本系统承载的三条上游红线（登记，不重定义）

| # | 红线 | 本系统的落地方式 |
|---|---|---|
| 🔴 **T-R1** | 塔移除返还系数 ≤ 100%，且不得存在「买入折扣」与「移除返还」同时生效的组合 | 本系统**无任何买卡折扣机制**（🆕 明确声明：MVP 商店**不做**打折/优惠券），从源头杜绝套利环 |

## 2. 核心机制（Core Mechanics）

### 2.1 方案 D 落地：五态状态机（本 GDD 的骨架）

> **为什么需要显式状态机**：方案 D 的难点不是"不暂停"，而是**五个态的时钟口径各不相同**。若用一个布尔 `is_shop_open` 去驱动，必然出现"减速期间预算不消耗""安全窗里商店还在扣预算"这类 bug。

```

                    │  重置 n=0（刷新次数）· 重置 DilationBudget=20s · 发初始商店+pity │
```

**五态时钟口径总表（🔴 实现必读）**

| 态 | `Engine.time_scale` | 战斗推进 | 减速预算 | 可做的操作 | 商店形态 |
|---|---|---|---|---|---|
| ① `Combat` | `1.0` | ✅ | **冻结** | — | 关闭 |
| ② `ShopDilated` | `0.35`（W1–5 `0.25`） | ✅ | ✅ **消耗**（W1–5 不消耗） | 买 / 刷 / 锁 / 放置 | 抽屉展开 · **轻决策模式** |
| ③ `ShopRealTime` | `1.0` | ✅ | ❌ 已耗尽 | 同上（但无减速） | 抽屉展开 · 预算条标红"已耗尽" |
| ④ `SafeWindow` | `1.0`（世界暂停靠 `paused`） | ⏸ **完全停止** | **冻结** | ✅ **全部**（含重决策） | 抽屉展开 · **重决策模式** |
| ⑤ `PlacementMode` | `0.25` | ✅ | ✅ 消耗（W1–5 不消耗） | 点塔位落子 / Esc | 抽屉**收起**，战场全屏 |

> 🔴 **四条最容易写错的口径**：
> 1. **预算只在 ②⑤ 消耗**，①③④ **冻结** —— 预算计的是"思考时间"，不是"惩罚计时"。
> 2. **②④ 的差别是"暂停"不是"倍率"**：④ 用 `get_tree().paused = true`，`time_scale` **保持 1.0**；若用 `time_scale = 0` 会让 unscaled 计时出现除零。
> 3. **⑤ 从 ② 进入时商店抽屉收起**（战场要全屏看高亮）；从 ④ 进入时同样收起。
> 4. **⑤ 的预算耗尽处置（Q-S3-A，v1.2）**：放置模式中预算耗尽 → **立即退出放置**，卡退回待放置队列（不销毁不退款）；**回落目标按进入来源分两种**：
>    - **从 ②/③ 进 ⑤ 耗尽 → 落 ③ 全速**（回不了 ②，因其减速额度已尽）；
>    - **从 ④ 进 ⑤ 耗尽 → 回 ④**（世界本暂停、预算在 ④ 冻结，原路返回；🔴 不会造成"免费慢动作"——④ 里 `paused=true` 时间完全停止）。
>    另：**预算为 0 时进入 ⑤ 不得再减速（等效 `1.0×`）**。🔴 预算永远是减速的前提——放任 ⑤ 在 0 预算下继续 `0.25×` = 免费无限慢动作，"时间即货币"当场作废。

### 2.2 C1 · 战术减速与减速预算（把时间变成货币）

| 项 | 规则 | 出处 |
|---|---|---|
| 减速倍率 | `0.35×`（**慢动作，不是暂停**） | 概念 §2.1 ③ · §8.4 |
| 新手保护 | **W1–W5**：打开商店自动 `0.25×`，🔴 **不消耗预算** | 概念 §2.1 ③（缓解 R8） |
| 减速预算 | `DilationBudget = 20s`（**实时秒**）/ 波，**每波重置** | 概念 §2.1 ③ · M16 |
| 计时口径 | 🔴 **unscaled**（`delta / Engine.time_scale` 或 `Time.get_ticks_msec()` 差值） | `damage-pipeline` §4.3 实时时钟 |
| 耗尽行为 | 自动回 `1.0×`（态 ③），🔴 **商店不强制关闭**，预算条标红；**⑤ 中耗尽 → 退出放置**，回落目标按来源分：②/③进→落③、④进→回④（Q-S3-A，v1.2） | 本 GDD §9 **Q-SR2** · §2.1 口径 4 |
| 消耗时机 | 🔴 **仅商店打开期间（态 ②⑤）**；关闭即停；**单帧计入上限 `MAX_FRAME_REAL_DT=0.25s`**（Q-S3-B，v1.2，防失焦整段吃预算） | 本 GDD §9 **Q-SR1** · §3.1 |
| 后期自然消解 | 雪崩期（W13+）DPS 远超怪物 → 减速需求自然下降 → 玩家本能地不再减速 → **Submission 美学保留** | 概念 §2.1 ③ |

### 2.5 无限刷新经济（M5 · M6）

| 项 | 规则 |
|---|---|
| 刷新次数 | 🔴 **无限** |
| 刷新成本 | `Cost(n) = max(1, floor((5 + 3n) × (1 − discount_global)))`，`n` = **本波已刷新次数**（第 1 次刷新时 `n=0` → 5 分） |
| 重置 | `n` **每波重置为 0** |
| 折扣 | `discount_global` = G2 供应链的饱和输出，∈ `[0, 0.50]`（`τ=8`，`card-system` §7.3） |
| 取整 | 🔴 **向下取整，下限 1 分** —— 刷新**永不免费**（否则"刷穿商店"退化成无成本动作，张力来源 1 死亡）。见 §9 **Q-SR9** |
| 🆕 **折扣作用口径（D-3，v1.3）** | 🔴 **乘法**：`discount_global` 作用于**整个 `(5+3n)`**，即 §5.1 的 `max(1, floor((5+3n)×(1−discount_global)))`。金标本 AI 路径的**减法**口径 `5+3n−disc` 是**旧实现遗留**（`shop_ai.gd` S6），**非定稿口径**；MVP 无折扣来源（`reroll_disc` 恒 0）时两式逐位相同，**不影响 MC**。🔴 未来若引入折扣卡，**一律按乘法落地**，不得沿用减法 |
| 积分来源 | 🔴 **M5：仅从击杀获得**。商店**不产出**积分，**不回收**积分（退款除外，见 E1） |
| 每波收入 | `≈ N(w) × (2 + 0.5w)`（W5≈101 / W10≈336 / W15≈608 / W20≈960，模拟实测） |

### 2.8 🔴 pity 起飞保底（发牌算法）

#### 2.8.1 规则定稿（`card-system` §4.5，本 GDD 原样落地）

| 项 | 规则 |
|---|---|
| **触发范围** | 🔴 **仅「每波开始时生成的初始商店」**（3 商品位）**必含 ≥1 张**与主塔同 Tag 的**单塔效果卡** |
| **手动 reroll** | 🔴 **不保证**（纯随机）。→ 保底只保证"每波**至少买得到 1 张**"，**不剥夺刷商店的张力**，G2 供应链仍然值得买 |
| 🆕 **两条发牌路线的分工（D-1，v1.3）** | 🔴 **玩家路线**（真实游戏）：只有「每波初始商店」走 pity 保底（`deal_initial_shop`），**手动 reroll 走纯随机**（`deal_reroll`，`force=null`）。**金标本 AI 路线**（`shop_phase`）为简化搜刮，**每次刷新都带 pity**——这是 **AI 特化，不回溯到玩家路线**，也**不改金标本**（改则 MC 判据链需重跑）。两条路线的口径差异是**刻意的**：玩家路线严守"reroll 不保底"以保留张力，AI 路线的保底只是让它更快搜到解。见 §9.2 拍板留档 |
| **占位方式** | 保底**改写 1 个未锁定的商品位**，🔴 **不额外增加第 4 个位**；若自然刷出已含 ≥1 张目标 Tag 卡 → **不干预** |
| **与锁定** | 🔴 **不得覆盖玩家锁定的商品位**（SR-R4 / E15） |
| **与 E9** | **E9 优先**：场上无塔时 pity 不生效（无宿主的强化卡无意义） |
| **生效时机** | 玩家做出**第一笔 Tag 投资**后的**下一波**起生效 |
| **卡池** | 目标 Tag 的 **3 张**单塔效果卡中等概率随机（🔥 = T1/T2/T3；❄ = T4/T5/T6） |

#### 2.8.2 兜底链 P1–P4（判定自上而下，**命中即停**）

| 序 | 条件 | pity 行为 |
|---|---|---|
| **P1** | **主塔存在**（`CoreTower = argmax(单塔效果卡层数)`）**且该塔原型有 Tag** | 出**该 Tag** 的单塔效果卡（该 Tag 的 3 张中等概率随机） |
| **P2** | 主塔存在但**原型无 Tag**（`Arrow` / `Beacon`）**且全场已有 Tag 投入**（`max_Tag(L_tag) ≥ 1`） | 出 **`argmax_Tag(L_tag)`** 的单塔效果卡。默认投主塔；玩家可先点选副塔再购买来改投（2 次输入） |
| **P3** | 主塔存在但无 Tag，**且全场 Tag 投入为 0** | ❌ **pity 不生效**（商店全随机） |
| **P4** | **场上无塔** | ❌ **pity 不生效**（E9 优先） |

> **为什么 P3 定「不生效」**：此时玩家**还没做出"这局走火焰还是冰霜"的决策**。保底若替他选，就是**系统替玩家定路线** → 违反 P4 与 P3。玩家只要买下**第一张**带 Tag 的效果卡、或建起第一座有 Tag 的塔，主塔即定、pity 从下一波起生效 —— **这是玩家自己的第一笔投资在回报他，不是系统在施舍。**

#### 2.8.3 发牌算法（伪代码 · GDScript 风格）

```gdscript
# ============================================================
#  ShopRNG · 每波初始商店发牌（含 pity 起飞保底 + 兜底链 P1–P4）
#  🔴 本函数只在「波次开始时」被调用一次。手动 reroll 走 deal_reroll()
# ============================================================

func deal_initial_shop(wave: int) -> Array[CardOffer]:
    var shop := _draw_random_offers(SHOP_SLOTS)      # 3 个位，纯随机（受 pool_legal 过滤）
    if run.pity_armed:                                # 需先有第一笔 Tag 投资
        var pity_card := _try_pity_pick()
        if pity_card != null:
            _apply_pity(shop, pity_card)
    return shop


# ---------- 手动 reroll：🔴 纯随机，不走 pity ----------
func deal_reroll(shop: Array[CardOffer]) -> Array[CardOffer]:
    var kept := shop.filter(func(o): return o.locked)     # 锁定最多 1 张，保留
    var fresh := _draw_random_offers(SHOP_SLOTS - kept.size())
    return kept + fresh


# ============================================================
#  兜底链 P1–P4：决定「保底发哪一张」
# ============================================================
func _try_pity_pick() -> CardDef:
    var core: Tower = run.core_tower            # argmax(单塔效果卡层数)，E4 稳定排序
                                                # 全平局（全为 0 层）→ 取「最早建成」的塔
    if core == null:
        return null                             # ★ P4：场上无塔 → 不生效（E9 优先）

    var tag: StringName = core.prototype.tag

    # ---- P1：主塔原型有 Tag ----
    if tag != null and tag != &"":
        return _pick_from_tag(tag)

    # ---- P2：主塔无 Tag（Arrow / Beacon），看全场 Tag 投入 ----
    var L: Dictionary = run.tag_invest_layers()          # { &"fire": n, &"frost": m }
    var best = _argmax_tag_stable(L)                     # 平局取「先达到该层数」的 Tag（E4 同口径）
    if best == null or int(L[best]) == 0:
        return null                                      # ★ P3：全场 Tag 投入为 0 → 不生效
    return _pick_from_tag(best)                          # ★ P2


# ---- 从某 Tag 的 3 张单塔效果卡中挑一张（含 4.5.3 两个细节）----
func _pick_from_tag(tag: StringName) -> CardDef:
    var pool := CARDS.filter(func(c):
        return c.kind == CardKind.TowerEffect \
           and c.tag  == tag \
           and not _is_at_cap(c))                        # ① 排除已满卡（E7 同口径）
    if pool.is_empty():
        pool = CARDS.filter(func(c):
            return c.kind == CardKind.TowerEffect and c.tag == tag)
        # 🔴 E13 退化：3 张全满 → 仍发一张，卡面标「已达上限 (+0%)」
        #    保底是「买得到」，不是「有收益」→ 不得因此停发
    return pool.pick_random()


# ---- 把保底卡写进商店（不额外占位 · 不覆盖锁定）----
func _apply_pity(shop: Array[CardOffer], card: CardDef) -> void:
    for o in shop:
        if o.card.id == card.id:
            return                                       # 已含 ≥1 张目标 Tag 卡 → 不干预
    var unlocked := shop.filter(func(o): return not o.locked)
    if unlocked.is_empty():
        return                                           # 🔴 E15：不得覆盖玩家锁定
    unlocked.pick_random().set_card(card)                # 改写 1 个未锁定位


# ---- 合法卡池过滤（E1 / E9：无合法目标则不进池）----
func _draw_random_offers(count: int) -> Array[CardOffer]:
    var pool := CARDS.filter(_is_legal_now)              # E1 建筑卡 / E9 单塔效果卡
    var out: Array[CardOffer] = []
    for i in count:
        out.append(CardOffer.new(pool.pick_random(), locked = false))
    return out


# ---- 武装条件：第一笔 Tag 投资 → 下一波起生效 ----
func _on_any_tag_invested() -> void:
    run.pity_armed = true                                # 建起有 Tag 的塔 或 买下带 Tag 的卡
```

|---|---|

| A2 | 手动 `reroll` 后的商店 **不含任何保底逻辑**（命中率 = 纯随机基线） |

### 2.9 售卖入口 = 塔移除结算器（售卖 ≡ 拆塔）

> 🆕 **术语统一（`card-system` v1.1.4 · Q-T1 = A′）**：「售卖」与「拆塔」是**同一个动作、同一套规则、同一个确认弹窗**，只是玩家侧的叫法不同 → 🔴 **UI 统一为「拆除并回收 `Salvage`」**。

| 项 | 定稿规则（**Q-C3 原文，一字不改**） |
|---|---|
| **返还** | 该塔**累计投入的 50%**（该塔花费的建筑卡分 + 其上装配的单塔效果卡分之和，**向下取整**） |
| **装配卡** | 该塔装配的**全部单塔效果卡及其层数全部销毁** 🔴（不可回收，与"弃卡"同口径） |
| **塔位** | 释放，可再建新塔 |
| **确认** | 🔴 **必须二次确认**（不可逆），弹窗列出「返还 **X** 分 / 销毁 **N** 张卡（共 **M** 层）」 |
| **时机** | 🔴 **仅波次间安全窗**（红线 T-C1：战斗内完全禁止任何塔相关操作） |
| **重算链** | 🆕 **兜底①：`N_tower_histmax` 只增不减** → **拆塔不改变 κ**（κ 仍按历史最大塔数计）；链接重算、`Aux` 重算、`CoreTower` 重算 |

> 🔴 **反通胀红线（T-R1 / T-R2）**：本系统**不做任何买卡折扣**，返还**只来自被拆塔自身的累计投入**，**不产生任何额外铸币**。

## 5. 数值（Numbers）

> 口径：**凡本表与 `card-system` §5.8 锚点冲突，以 §5.8 为准**；凡与 `calibration-report-v04.md` 冲突，以 v0.4 为准（数值关已关闭）。**本 GDD 不新增任何定稿数值。**

### 5.1 刷新成本

```
Cost(n) = max(1, floor((5 + 3n) × (1 − discount_global)))

  n               = 本波已刷新次数（第 1 次刷新时 n = 0）        单位：次
  discount_global = G2 供应链的饱和输出                        单位：—，∈ [0, 0.50]
  Cost            = 本次刷新需支付的积分                       单位：积分
  每波重置：n ← 0
```

累计：`Σ_{i=0}^{m-1} (5 + 3i) = 5m + 1.5m(m − 1)`（无折扣基准）。

> 🆕 **折扣口径锁定（D-3，v1.3）**：上式 `discount_global` 以**乘法**作用于整个 `(5+3n)`。金标本 AI 路径的**减法**口径 `5+3n−disc`（`shop_ai.gd` S6）是**旧实现遗留，非定稿口径**；MVP 无折扣来源（`reroll_disc` 恒 0）时两式逐位相同，MC 不受影响。🔴 未来引入折扣卡时**一律按乘法落地**。

### 5.2 减速预算

```
budget_left(w) = 20.0                                    单位：实时秒；每波重置

budget_left −= dt_unscaled        当且仅当 state ∈ {ShopDilated, PlacementMode} 且 w ≥ 6
  dt_unscaled = delta / Engine.time_scale                 单位：实时秒
  🔴 或直接用 Time.get_ticks_msec() 差值（更稳，不受 time_scale 影响）

budget_left ≤ 0  →  state = ShopRealTime（time_scale = 1.0）
新手保护：w ∈ [1, 5]  →  state = ShopDilated(0.25×)，budget_left 不减
```

**思考时间增益验算**：`20s` 预算 @ `0.35×` → 战场仅推进 `20 × 0.35 = 7s`，玩家获得 `20s` 思考 ≈ **2.86× 思考时间增益**（概念 §2.1 ③ 的 "×2.9"）。

### 5.3 商店经济（收入侧）

```
每波收入 ≈ N(w) × (2 + 0.5w)      N(w) = 8 + 1.6w（只）
  W5 ≈ 101 · W10 ≈ 336 · W15 ≈ 608 · W20 ≈ 960（模拟实测）
```

> 🟢 **设计含义**：收入随波次**超线性**（数量 × 单价双涨）→ 雪崩期刷新成本相对收入趋近 0 → **"无限刷"从口号变成现实**（P2 兑现路径）。这是**刻意的**，不做抑制（概念 §2.2 正反馈环）。

### 5.4 κ 折价预告公式（H6 · 🔴 `card-system` E11 强制披露项）

```
κ_now   = max(0.02, κ_tag(L_tag) − 0.01 × clamp(N_hist     − 2, 0, 4))
κ_after = max(0.02, κ_tag(L_tag) − 0.01 × clamp(N_hist + Δ − 2, 0, 4))

  κ_tag   = Tag 档位基准利率（0–2 层 0.06 / ≥3 层 0.10）      单位：—
  L_tag   = 该 Tag 的投入层数（建筑卡层数 + 单塔效果卡层数）     单位：层
  N_hist  = N_tower_histmax，本局历史最大塔数（🆕 只增不减）      单位：座
  Δ       = 本次建造将增加的塔数（新建 = 1，仅升级 = 0）         单位：座
  下限     = 0.02（🔴 R12：折价后复利不得归零）

UI 文案（🔴 必须同时披露不可逆性）：
  「建造新塔：κ 0.10 → 0.09（拆除塔不会让 κ 回升）」
  Δ = 0 时（只升级不新建）→ 🔴 不显示该预告
```

> 🔴 **为什么必须披露不可逆性**：`v1.1.5` 兜底①把 `N_tower` 改成**历史最大值** → 广度折价**永久生效**，拆塔退不回来。只说"会降"而不说"退不回来"是**不完整的事实披露**，会把隐形陷阱留给玩家（违反概念 §4.1 胜任感）。

### 5.5 暴露度事实标注（H10 · 🔒 T1）

```
Exposure_i = 塔位 i 到怪物路径的最短距离 d_path
  🔴 只给图标，不给数字（R-T5：暴露度是第 4 个稀缺维度，禁止再增加认知负荷）
  ⚔ 会挨打（d_path < AGGRO_R，实算：S0 6.00 / S1 8.00 / S2 5.00 / S3 8.00）
  🛡 安全   （S4 10.82 / S5 13.00）
  全部参数见 mechanics-tower-life-death §0.4 / §2；🔒 随 Q-T10 = ② 进 T1
```

## 6. 边界与失败（Edge Cases & Failure Modes）

> 输出规范要求不少于 3 类，本节给 **16 类**（其中 8 类为 `card-system` 已定稿、本系统需**承接**的，标注 ↩）。

| # | 边缘情况 | 处理规则 |
|---|---|---|
| **E1** ↩ | **塔位已满 且 场上无同原型塔** → 建筑卡无合法目标 | 商店**停止刷出**该建筑卡（置灰不出现）。已购买入队列 → 卡滞留；UI 显示「无可放置目标」并允许**以 50% 价格退回**（防死锁）。🔴 这是 M5 之外**唯一**的积分回流，且是退币非铸币（T-R1 合规） |
| **E2** ↩ | **待放置队列积压** | 队列无上限；HUD 角标持续提醒；**安全窗强制提示一次** |
| **E3** | **减速预算在商店打开瞬间已 < 1s** | 仍按剩余量减速 → 耗尽即转 `ShopRealTime`。🔴 **不得**因预算不足而拒绝打开商店 |
| **E4** | **玩家在 `ShopRealTime`（1.0×）下继续刷** | 允许。战斗全速推进，风险自负 → **这正是"何时收手"的取舍** |
| **E5** | **刷新成本 > 当前积分** | 刷新按钮置灰 + 价格标红。🔴 **不得**允许赊账 / 负积分 |
| **E6** | **G2 供应链满级（−50%）时** | `Cost = max(1, floor((5+3n) × 0.5))` → 第 1 次 `floor(2.5) = 2` 分。🔴 下限 1 分保证刷新**永不免费** |
| **E7** | **玩家锁定 1 张后刷到只剩锁定卡可买** | 允许。锁定位保留，另 2 位重 roll。`Space` 可随时解锁 |
| **E8** | **pity 与 E9 冲突**（场上无塔 / 主塔无 Tag 且全场 Tag 投入 0） | **E9 胜出、pity 不生效**（P3 / P4）。玩家买入第一张带 Tag 的卡或建起第一座有 Tag 的塔后，**下一波**起生效 |
| **E9** ↩ | **开局无塔时刷到单塔效果卡** | 商店**不刷出**单塔效果卡（无宿主则无意义），或置灰标注「需先建造一座塔」 |
| **E10** ↩ | **pity 目标 Tag 的卡全部达 cap** | 保底退化为该 Tag 任意一张，卡面标「已达上限 (+0%)」；🔴 **不得**因此停发保底 |
| **E11** ↩ | **玩家已锁定 1 位，且该位不是目标 Tag 卡** | 保底改写**未锁定的 2 个位中的 1 个**；🔴 **不得覆盖锁定**（SR-R4） |
| **E12** | **`CoreTower` 全平局**（全部塔 0 层） | 取「**最早建成**」的塔（E4 稳定排序同口径）→ pity 的 P1/P2 判定有确定输入，避免每波抖动 |
| **E13** | **`argmax_Tag(L_tag)` 平局** | 取**先达到该层数**的 Tag（稳定排序，避免每波抖动） |
| **E14** | **安全窗内玩家不点「开始下一波」** | 无超时强制推进（概念未定义，本 GDD 定：**无超时**）。理由：安全窗是重决策区，强制超时 = 用时间压决策 → 违反 P4 |
| **E15** | **拆除确认弹窗期间波次状态** | 弹窗 `CanvasLayer 140`，世界仍 `paused`。🔴 弹窗打开时**不得**解除暂停 |
| **E16** | **战斗中玩家试图点塔 / 试图拆除** | 🔴 **入口置灰 + 拒绝响应**（T-C1 + Q-C3「仅安全窗」）。**不弹提示**（避免战斗中制造新决策压力） |
| 🆕 **E17** | **火焰库存摩擦（D-7，v1.3）** | 🔴 **玩家路线不实现**。金标本 AI 的 `fire_stock`（A=6/B=3 每波火焰卡上限）是 **AI 搜刮约束**，不是玩家规则。玩家路线**火焰卡无每波上限**——玩家花自己的积分买火焰卡，摩擦已由 `5+3n` 刷新成本与积分稀缺性自然约束，无需额外限流（否则凭空给玩家加摩擦，违反 P4） |

**失败模式（系统级）**

| 失败模式 | 判据 | 兜底 |
|---|---|---|
| **实时化导致手忙脚乱 / 决策降级**（R5′，本系统的头号风险） | 试玩中玩家反馈"来不及看牌只能乱点" | ① `0.35×` 减速；② `20s` 预算（时间变资源）；③ 智能高亮（只降比较成本）；④ **波次间完全暂停兜底**。验证 = §10.2 验收 1 |
| **"永远不敢开商店"锁死**（R8） | 新手全程不开商店 → 学不会 build | ① W1–5 自动 `0.25×` 且不耗预算；② 苟活期怪物强度本就低；③ **首次开商店的引导必须在安全窗内完成** |
| **全程龟速（玩家一直开着商店）** | 减速预算全程耗尽且玩家从不关闭 | 预算本身就是刹车（20s/波）。若试玩显示玩家"攒着不敢用" → 优先调 UI 提示（预算条更醒目），🔴 **不调数值** |
| **玩家全程只买全局卡**（"油门当引擎"） | 全局卡饱和 cap 使边际收益 → 0 | 数值自限（C-2：全局卡禁止复利），无需额外设计 |
| **商店常开导致失去观赏感** | 雪崩期玩家仍全程开商店 | 概念 §2.1 ③ 的"后期自然消解"应生效；若未生效 → 试玩中观察，兜底为 UI 提示（非数值） |
