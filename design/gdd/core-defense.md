## 0. 结论前置（给赶时间的人）

1. **四要素一句话**：核心是被守的 HP 目标（HP=1000，漏怪扣 50/只）；6 个固定塔位是唯一的建造点（Q10 定稿）；每个塔位有一个**覆盖率** `CoverageScore_i`（射程覆盖路径长度占比）；塔与塔之间按**射程实质重叠**建立**链接**，构成 `LinkGraph`。
2. **本系统最关键的一条定义 —— 链接判定**：两塔建立链接当且仅当 `d ≤ 0.65 × (R_i + R_j)`（`d` = 两塔位中心水平距离，`R_i` = 塔 i 当前射程半径）。**系数 0.65 是工程 card-verify §2.1 / calibration-v03 §2.1 的定稿值**，不是拍脑袋——若用 `R_i + R_j`（即系数 1.0），6 塔位链接图会**饱和成完全图**，链接数 `k` 失去作为变量的意义（`Resonance` 退化成纯数值 buff）。✅ **v0.5：P-CD2 已关闭 —— 引擎已对齐**（v0.7 `link_rule="substantial"`，`f=0.65` 真生效：定稿 B 终局画像 `k̄` **4.333 → 3.333**，主理人画像 **4.33 → 3.67** —— `mapA-kappaR-sweep` §1）。✅ **且复扫证明：0.65 生效 ≠ `E` 变化** —— 定稿 B 的 `E` 向量在 any 与 0.65 两口径下**逐位相同 `[9,0,134,0,0,0]`**（机理见 §2.5.1「几何链接图 ≠ 共鸣有效图」）。
3. **共鸣指数**（✅ v0.2 校订为**双向门槛**）：`E_i = Σ_{j 与 i 链接, h_i ≥ 3 ∧ h_j ≥ 3} (1 + h_j)`（`h_i`、`h_j` 双双 ≥3 才计入；`h_j` = 塔 j 建筑卡层数）。**塔自己不吃自己的 `h_i`**（`j ≠ i`，calibration-v03 §5.3 陷阱 1）——单塔无链接时 `Resonance ≡ ×1.00`。
4. **重算时机是本系统的工程命脉**（三条，缺一即出 bug）：① 建塔/拆塔/塔位变化 → **重建邻接表**；② 塔**射程**变化 → **链接增减（重建邻接表）**（⚠️ MVP 射程固定不随等级变，见 §2.5.3 CD-4）；③ 塔卡层数 `h` 变化 → **不重建拓扑，只让邻居 `E_i` 失效重算（`E_dirty` 脏标记）**。全部**事件驱动**，与 `Engine.time_scale` 无关（减速时不漏帧）。
5. **覆盖率存在一处未闭合的标定冲突（P-CD1 → ✅ 已于 v0.3 降级为设计选择 D-1，不再需拍板；见 §10.1）**：`CoverageScore_i` 的**几何定义是权威的**（逐塔、射程覆盖路径占比），但 calibration-v03 §6.2 实测：**直接以逐塔几何覆盖喂伤害管线会让两条路径都起不来**（单塔覆盖率仅 0.2–0.5，而定稿基线的 0.78/0.95 是"塔网合计"而非"单塔"）。→ MVP **默认沿用聚合常量**（A 0.78 / B 0.95），逐塔几何覆盖**需整体重标定后才能切换**。本 GDD 给出几何定义 + 标定接口，但**不擅自切换**。
6. **MVP 塔位布局 ✅ 已定稿（真实 sim 坐标，§5.3 —— v0.5 拍板为「方案 A」，P-CD3 关闭）**：用工程 sim 真身 `SLOTS6` + 真实射程**实算**，6 塔位 + 0.65 → `k` 均值 **3.67**、节点度 [3,5,5,3,3,3]（未饱和），`k ≥ 3` 可达；**S1/S2 是枢纽**（深 carry 落此链接全体，`E≈134` 可复现 —— 复扫在 0.65 下逐位复现 `E=[9,0,134,0,0,0]`）；union 覆盖 6塔=1.00 / 2塔=0.77（复现定稿）。**CD-5 三条全过，多塔流几何成立。**
7. **与实时化/可访问性的两条硬约束**：放置建筑卡时全局减速 **0.25×**（复用 `DilationBudget` 池，不新增资源）；**塔的可读性 > 特效华丽度**（美术锚点 4）—— 任何 VFX 禁止遮挡塔轮廓与核心 HP 条。
8. 🆕 **塔位坐标已给到可直接落地的粒度**（§5.4）：含 2:1 菱形屏幕偏移 `Δsx=(X−Z)×64 / Δsy=(X+Z)×32`、到核心距离、逐塔覆盖值、0.65 节点度。**并暴露一个此前没人发现的事实**：定稿采用的 sim 布局里，**6 个塔位全部位于核心左侧**（`Δsx` 全负）—— 塔并没有"围绕"核心，与视觉锚点 1 不一致。→ ✅ **v0.5：该视觉不一致已被主理人核实并显式接受** —— 为保 P1「位置即策略」（0.65 下站位是真策略变量），**取舍视觉锚点 1 的"核心被环抱"感**；叙事上读作"**守一条走廊的尽头**"。此条不再作为冲突项（§5.4.1）。
9. 🆕 ✅ **P-CD2 已关闭（v0.5）**：`k_deep` 当量对照实测 **A+1.0=4.78（校准基线）/ A+0.65=3.56（−25.5%）/ B+0.65=4.67（−2.3%）**（§5.5 留档）。**v0.7 复扫推翻了本条的两个预判**：①「`k_deep` 掉 25.5% ⇒ `E` 缩水 ⇒ `κ_r` 必须重扫到 0.055–0.06」→ ❌ **方向错误**——0.65 砍掉的边**根本不进 `E`**（双向门槛挡住，§2.5.1），`E` 逐位不变；且 `κ_r ≥ 0.060` 时 `B/A = 1.63`，**直接违反概念 §2.4.5「单核必须是后期 carry」** → 可行区间实为 `[0.045, 0.055]`。②「改方案 B 可免重扫 `κ_r`」→ ❌ **方案 B 已否决**（`k_deep=4.67` 让 0.65 名存实亡），且其"免重扫"收益随复扫归零。**✅ 最终定稿：方案 A + 0.65 + `κ_r` flat 0.050**（余量 +11pp、`B/A` 0.458，6 条判据全过）。

## 1. 系统目标（System Goal）

### 1.1 一句话

> 防御阵地是玩家**唯一的舞台**。它必须把「我把塔摆在哪」这一个空间动作，翻译成下游能直接消费的三个空间量：**覆盖了哪段路（CoverageScore）、和谁连成片（LinkGraph）、守没守住（Core HP）**。

### 1.2 与支柱的兑现关系

| 支柱 | 本系统如何兑现 | 若不满足则 |
|---|---|---|
| **P1 站位即策略** | 塔位覆盖值 + 链接拓扑**由布局决定**：高覆盖位 = 天然主塔位，密集位 = 多塔流，分散位 = 单核流。分支是空间配置的**涌现结果**，不是数值菜单 | 若布局不影响 `CoverageScore`/`LinkGraph` → 站位退化为装饰，P1 崩塌 |
| **P2 雪崩无上限** | `LinkGraph` 是广度复利 `Resonance = (1+κ_r)^{E_i}` 的**几何引擎**；`CoverageScore` 喂 `Coverage_i` / `Crossfire`。空间配置越好，指数出口越大 | 若链接/覆盖不接进伤害 → 多塔流没有指数出口（R9 复发） |
| **P3 每局一个新解** | 不同地图的塔位拓扑不同 → 能形成的链接数 `k` 不同 → **多塔流的上限每局不同**（概念 §2.4.4）。有的局塔位密集（多塔强），有的局分散（链接少，走单核） | 若所有地图 `k` 相同 → 多塔流天花板恒定，P3 少一个最强来源 |
| **P4 决策而非动作** | 塔位**不可逆**（建塔只能升级或拆塔返还 50%）、塔只能放塔位上 → 每一次落子都是不可回退的空间取舍 | 若塔位可无痛重来 → 空间决策退化为假选择 |

### 1.3 本系统的三条设计红线（自检用）

| # | 红线 | 出处 |
|---|---|---|
| 🔴 C-1 | **链接判定必须用实质重叠 `d ≤ 0.65(R_i+R_j)`，禁止用 `R_i+R_j`** | calibration-v03 §2.1 · card-verify §2.1 |
| 🔴 C-2 | **`CoverageScore` / `LinkGraph` 只在事件后重算，禁止每帧算**（每帧 O(n²) 会炸，且与减速时钟耦合） | calibration-v03 §5.3 / §7.1 |
| 🔴 C-3 | **塔的可读性 > 特效华丽度**：VFX 禁遮挡塔轮廓与核心 HP 条 | 美术锚点 4 · art-bible §1 视觉第一原则 |

## 2. 核心机制（Core Mechanics）

### 2.1 四要素总览与依赖方向

```
核心 Core  ←── 被防守目标；漏怪扣血；HP 归零 = 局终
  │
  ├─ 塔位 Slot（6 个，固定基座）── 塔只能放塔位上
  │     │
  │     ├─→ CoverageScore_i  ──→ damage-pipeline: Coverage_i / Crossfire（空间事实）
  │     │
  │     └─→ LinkGraph ── 由塔位间距 + 各塔射程决定
  │           │
  │           └─→ E_i（共鸣指数）──→ damage-pipeline: Resonance_i = (1+κ_r)^{E_i}
  │
  └─ 路径 Path ── 怪物沿固定路径冲向核心（wave-spawner 负责）
        └─ 覆盖率 = 塔网射程覆盖的路径长度 / 路径总长（苟活期核心缓降的来源）
```

> **依赖方向铁律**：`Core` 与 `Slot` 是**静态舞台**（地图加载即定）；`CoverageScore` 与 `LinkGraph` 是**动态空间量**（随建塔/拆塔/升级/拆装配而变化）。下游只读这两个动态量，**不反向写回**（`damage-pipeline` 不改塔位几何）。

- 怪物逼近核心时，战场侧屏幕边缘发**红光脉冲**——🔴 **必须用动效而非文字**（人眼余光只对运动与亮度敏感，concept §2.3.2 生理约束）。

2. **链接拓扑 `LinkGraph`**（§2.5）：塔位 i 与 j 的间距决定能否形成链接 → 密集布局 = 多塔流。

### 2.4 覆盖率 CoverageScore（M3 · 空间事实，喂 damage-pipeline）

#### 2.4.1 权威几何定义（逐塔）

> **`CoverageScore_i` = 塔位 i 的射程圆所覆盖的路径长度 / 路径总长度**，取值 `[0, 1]`。

```
CoverageScore_i = ( 路径上落入塔 i 射程圆 R_i 内的弧长 ) / ( 路径总长度 )
```

- 射程圆是**水平面（XZ）圆**，半径 `R_i` = 塔 i 当前射程（随塔等级/原型变化）。
- 路径是怪物行进的**折线**（waypoint 序列）。覆盖判定沿路径折线逐段积分，非面积。
- 这是**逐塔**量：多塔射程重叠时，各塔 `CoverageScore_i` 之和**可 > 1.0**（重叠段被重复计入各塔）。

#### 2.4.2 🔴 未闭合的标定冲突（P-CD1 · ✅ v0.3 已降级为 §10.1 设计选择 D-1，**不再占用拍板位**；MVP 处置不变：沿用聚合常量）

> **这是本 GDD 最重要的一处"定义权威但数值未闭合"，务必交接给程基岩与主理人。**

### 2.5 链接几何 LinkGraph（M17 共鸣的几何基础 · 本系统最关键定义）

#### 2.5.1 链接判定（🔴 C-1 红线）

> **两塔 i、j 建立一条链接，当且仅当：**
> ```
> d(i, j) ≤ LINK_FRAC × (R_i + R_j)
>
>   d(i, j)  = 两塔位中心的水平距离（XZ 平面，world 坐标 distance_to）
>   R_i, R_j = 塔 i、j 的当前射程半径（水平面）
>   LINK_FRAC = 0.65  ✅ 定稿（card-verify §2.1 · calibration-v03 §2.1）
>                     ✅ v0.5 引擎已对齐：`corebound_sim_v07_mapA.py` `link_rule="substantial"`（f=0.65）真生效
> ```

**为什么系数必须是 0.65 而不是 1.0（四条理由，务必写进 GDD）**：

| 系数 | 6 塔位典型布局的链接数 `k` | 后果 |
|---|---|---|
| **1.0**（`d ≤ R_i + R_j`，任意重叠） | `k` 顶到 **5**（全互连完全图） | 🔴 `k` 不再是变量 → `Resonance` 退化成纯数值 buff → **P1 站位失去意义** |
| **0.65**（实质重叠）✅ | `k` 落 **2–4** | ✅ `k ≥ 3` 可达（§8.3 要求），且不同布局产生真实差异 |

> calibration-v03 §2.1 纸面估计：6 塔位 + 系数 0.65 → `k` 均值 3.33、区间 2–4。**✅ 2025 校订：用真实 SLOTS6 坐标实算（§5.3）得 `k` 均值 3.67、节点度 [3,5,5,3,3,3]**（对比系数 1.0 时是 [5,5,5,5,5,5] 完全图——饱和），与纸面估计同量级、`k≥3` 可达。→ **0.65 是"让 `k` 保持为变量"的唯一可用阈值**；**不同布局 `k` 不同 → P3「每局一个新解」的最强来源**（概念 §2.4.4）。

> ✅ **v0.5 · P-CD2 关闭：引擎已对齐，0.65 真生效**（依据 `mapA-kappaR-sweep.md` §1）：引擎 v0.7 的 `link_rule` 由 `"any"`（`f=1.0`）切为 **`"substantial"`（`f=0.65`）**，同一构筑的链接图平均度 `k̄` 实测下降 —— **定稿 B 终局画像 4.333 → 3.333**、主理人画像 **4.33 → 3.67**（全 Cannon 4.000→2.333、全 Arrow 5.000→3.667）→ **文档与引擎口径已一致，链接判定 `d ≤ 0.65(Rᵢ+Rⱼ)` 定稿。**
>
> ✅ **v0.5 核心发现（务必读懂，否则会系统性误判 0.65 的代价）：0.65 生效 ≠ `E` 变化 ——「几何链接图」≠「共鸣有效图」。**
> 复扫 §2.1 逐对审计：定稿多塔 B 的终局形态是「**1 座深塔 + 5 座杂兵**」（`Arrow@S0 h=133`、`Cannon@S2 h=8`、其余 4 座 `h=1`）。真正喂进 `E_i` 还要再过**双向门槛 `h_i≥3 ∧ h_k≥3`**（§2.5.2）→
> ① **「深塔 ↔ 杂兵」这类边在 any 口径下本来就进不了 `E`**（杂兵 `h<3`，贡献恒为 0），而 **0.65 砍掉的恰恰就是这一类边**；
> ② 唯一真正喂 `E` 的「深塔 ↔ 深塔」边 `Arrow@S0 ↔ Cannon@S2`，`d = 24.00 < 0.65 × 40 = 26.00` → **存活**（贡献 `1+h`：9 与 134）。
> → 因此定稿 B 在 any 与 0.65 两口径下 **`E` 向量逐位相同 `[9, 0, 134, 0, 0, 0]`**，B 起飞 **W13→W13**、W20 **5.258→5.258**、终局 DPS **2,633,250 逐位不变**。
> ⚠️ **这不代表 0.65 无害**：它削的是**广度流派的拓扑上限**（深塔铺开时的多邻居加成）。定稿 B 是「一座深塔 + 挂件」的极端形态，本来就吃不到多邻居 → **本次躲过**。见 §10.2 遗留风险。

**判定细节（工程正确性）**：
- **距离用水平面（XZ）**：射程是水平半径，链接是"射程在平面上实质交叠"，**不判 Y（高度）**。等距下塔模型有高度，但射程圆始终在地面 XZ。
- **空塔位不参与**：只有**已建塔**（有原型、有射程）的塔位才进邻接表。空塔位无射程 → 无链接。
- **`i ≠ j`**：邻接表**不含塔自己**（calibration-v03 §5.3 陷阱 1）。

#### 2.5.2 共鸣指数 E_i（几何 → 权重的转换）

> **`E_i = Σ_{j ∈ N(i), h_i ≥ 3 ∧ h_j ≥ 3} (1 + h_j)`**
> - `N(i)` = 塔 i 在 `LinkGraph` 中的邻居集合（与 i 有链接的塔，**不含 i 自己**）。
> - `h_j` = 塔 j 的**建筑卡层数**（= 谐波层，card-system §3.2）。
> - **门槛是双向的 `h_i ≥ 3 ∧ h_j ≥ 3`**（🔴 2025 校订，见下）：只有**塔 i 自身层数 ≥3 且**邻居 j 层数 ≥3 时，才把 `(1+h_j)` 计入 `E_i`。这是引擎 `corebound_sim_v03.py:317` 的**实际口径**（`if h[i]>=lmin and h[k]>=lmin`）——低层塔即使链接高塔也吃不到共鸣。**v0.4 定稿多塔 B 的 4 座 `h=1` 填充塔 `E=0` 正是这道双向闸的效果**。（card-system §5.3 文字公式只写了 `h_j≥3`，需回写为双向；damage-pipeline §9 D-6 已按双向定稿，本系统对齐之。）
> - **塔自己不吃自己**：`j ≠ i`。塔 i 的自身层数 `h_i` **不进入求和项**（`(1+h_j)` 只取邻居的），但 `h_i` 通过双向门槛 `h_i≥3` **决定 i 能否吃到共鸣**（这是"自己"参与的唯一方式——是闸门，不是权重）。
> - **单塔无链接 → `E_i = 0` → `Resonance_i = (1+κ_r)^0 = ×1.00`**（必须显式写这条边界）。

> `E_i` 是**几何（LinkGraph）与权重（h_j）的合成交集**：拓扑由本系统（§2.5.1）产出，`h_j` 由 `card-system`（建筑卡层数）产出。本系统负责"谁和谁链接"，`card-system`/`damage-pipeline` 负责"链接上权重多少"。
>
> 🟢 **v0.5：这道双向门槛不是可省的实现细节，它是本次免重扫 `κ_r` 的机理本身。** 正因为低层塔（杂兵）与深塔之间的边**无论连不连都不进 `E`**，0.65 收边才砍不到共鸣质量（§2.5.1 核心发现）。→ 🔴 **工程实现时双向门槛 `h_i≥3 ∧ h_j≥3` 必须逐字照做**；若退化成单向 `h_j≥3`，0.65 会立刻咬到 `E`，`κ_r=0.050` 随即失效、须重扫。

#### 2.5.3 重算时机（🔴 C-2 红线 · 三条失效路径，缺一即出 bug）

> 全部**事件驱动 + 脏标记**，**与 `Engine.time_scale` 无关**（calibration-v03 §7.4：减速时不能跟着变慢或漏帧）。

| # | 触发事件 | 拓扑变？ | 权重变？ | 动作 |
|---|---|---|---|---|
| **T1** | 建塔 / 拆塔 / 塔位变化 | ✅ 是 | — | **重建邻接表**（`_dirty`）+ 邻居 `E_i` 重算 |
| **T2** | 塔**射程**变化（`R_i` 变） | ✅ 是 | — | **重建邻接表**（链接增减）+ 邻居 `E_i` 重算。⚠️ **MVP 射程固定不随等级变**（见下），故 T2 在 MVP **仅由"换塔原型"触发**，升级塔不改射程 → 走 T3 |

> 🔴 **射程是否随塔等级变化（CD-4 答案，2025 校订定稿）：MVP 固定，不随等级变。**
> 依据：① 工程 sim `TOWERS` 射程是**固定字典**（Arrow22/Cannon18/Frost20/Beacon20，`corebound_sim_v03.py:42-44`），不随 level 变；② v0.4/v0.6 定稿数值就是在"固定射程"下扫的；③ 固定射程让链接**纯由落位决定**——升级塔只改 `h_j`（走 T3 权重路径），不改拓扑，P1 更干净、引擎更省。
> ⚠️ **这与 `card-system §4.4 / E6`「射程随等级变化 → 链接重算」的假设冲突** → 请主理人回写 card-system（MVP 按固定射程；T1 若引入"升级改射程"的塔原型再启用 T2 全量重算）。
| **T3** | 塔卡层数 `h_j` 变化（买/升/拆建筑卡） | ❌ 否 | ✅ 是 | **不重建拓扑**，只让**邻居的 `E_i` 失效重算**（`E_dirty` 脏标记） |

> ⚠️ **T3 是最易漏的一处**（calibration-v03 §5.3 陷阱 2 / §7.1）：买一张建筑卡会同时触发 `h_j +1` **和**所有邻居的 `E_i` 重算。拓扑没变（塔没挪、射程没变），只是权重变了 → **用 `E_dirty` 脏标记，不重建邻接表**。若误在此处重建邻接表，是纯浪费（O(n²) 无意义重算）。

**脏标记双通道（工程交接要点，见 §8 交接点 1）**：
```
_topology_dirty : bool   # T1/T2 触发 → 下一物理帧重建邻接表
_E_dirty[i]      : bool  # T3 触发 → 只对标记的塔重算 E_i
# 重算走 _physics_process 且用真实 dt，不依赖 time_scale
```

### 2.8 射程曲线 `R(L)` 与 T2 触发口径（🆕 v0.3 · 补 `card-system` 交接点 1）

> **问题**：`card-system` §4.4 / E6 假设「建筑卡升级 → 射程变化 → 链接重算」，而本系统 v0.2 的 CD-4 定稿「MVP 射程固定」→ 交接点 1 在 MVP **没有触发源**，工程会白实现一个分支。
> **本节的处置**：MVP 维持固定射程（不动 v0.2 定稿、不动任何数值），但**把 `R(L)` 的函数形状与触发口径先定义死**，使 T2 通道在 T1 启用"射程随等级成长"时**开箱可用、不需要重构**。

#### 2.8.1 MVP 口径（沿用 v0.2 CD-4）

```
R_i = R₀(prototype)           # MVP：常量，不随 level 变化
  R₀: Arrow 22.0 / Cannon 18.0 / Frost 20.0 / Beacon 20.0
```

→ **T2（射程变 → 重建邻接表）在 MVP 仅由「换塔原型」触发**（拆塔后在同一塔位新建异原型塔，射程字典值变化）。升级塔只走 T3（改 `h_j`，不重建拓扑）。

#### 2.8.2 T1 推荐曲线（🆕 · 本 GDD 给形状与推荐值，不属 MVP 必做）

```
R(L) = R₀ × ( 1 + ρ × min(L − 1, 10) )     ρ = 0.01  →  Lv1 = R₀，Lv11 起封顶 1.10 × R₀
```

| 参数 | 推荐值 | 理由 |
|---|---|---|
| `ρ`（每级射程增长率） | **0.01**（+1%/级） | ① 让"升级 → 射程变长 → 多连一条"成为**可感知的 Discovery 时刻**（R13）；② 幅度小 → 对拓扑扰动可控 |
| 封顶 | `min(L−1, 10)` → **+10%** | 防止后期射程膨胀把链接图重新推成完全图（🔴 C-1 红线） |

> 🟢 **为什么 +10% 是安全的（本 GDD 已实测）**：阈值 `0.65(Rᵢ+Rⱼ)` 最大上移 10% → 最长边阈值 `28.6 → 31.5`（Arrow+Arrow）。在 §5.3 布局下，被翻转的边**只有"同原型炮塔的对角线边"（24.04 vs 23.40→25.74）**，且该边两端若都是 `h=1` 的占位塔，按 §2.5.2 双向门槛 **对 `E_i` 贡献为 0** → **射程成长对共鸣总质量（ΣE）的扰动 ≈ 0**。
> ⚠️ 若 T1 采用更大 `ρ`（>0.02），**必须重扫 `κ_r`**（v0.3 §2.3 红线：拓扑一变，κ_r 就得重扫）。

### 2.9 主塔涌现 `CoreTower` 判定（🆕 v0.3 · 对齐 card-system A18 / E4）

> **归属切分（本 GDD 的建议，交主理人确认）**：
> - **语义定义权**归 `card-system`（`CoreTower = argmax(该塔的单塔效果卡层数)`，**涌现、非声明**，A18 / §2.3）—— 本系统**不改语义**。
> - **实体与计算**归 `core-defense`：`L_i` 挂在 `Tower` 上，而 `Tower` 是本系统的实体；由本系统在装配层数变化时**派生并缓存**，以**只读接口 + 信号**对外暴露。
> - 🔴 **本系统不提供任何 `set_core_tower()` 写入口** —— 玩家永远不能点按钮"设为主塔"，否则主塔从涌现退化成声明，直接违反 A18。

#### 2.9.1 判定算法（含平局稳定排序）

```
L_i        = Σ(装配到塔 i 的单塔效果卡 stack_n)      # card-system §3.3
reached_at = 该塔最近一次 L_i 增加时的全局动作序号     # 稳定排序键（E4）

CoreTower  = argmax_i ( L_i , −reached_at_i )       # 先取层数最大；并列取"先达到该层数"者
           = null  若 场上无塔 或 ΣL == 0            # card-system §4.5.2 P3/P4：pity 不生效
```

- **平局口径 = `card-system` E4「取先达到该层数者」**，本系统用单调递增的 `reached_at` 序号实现 → **避免每帧徽章闪烁**（E4 原话：稳定排序）。
- **触发重算的事件**：装配 / 卸下（降 1 层）/ 弃卡 / 拆塔（装配卡全销毁）→ 均走 `card-system` §4.4 重算链；本系统只负责在 `L_i` 变化后重跑一次 `argmax`。
- **下游消费**：`tower-build` 的 `AllIn`（主塔且占比 ≥60% → ×1.6，card-system §5.6）、`damage-pipeline` 的阶段 A5、`shop-reroll` 的 pity 兜底链（§4.5.2 P1–P4）。

#### 2.9.2 对外接口（只读）

| 接口 | 返回 | 消费方 |
|---|---|---|
| `get_core_tower() -> Tower?` | 当前主塔（可能为 null） | `tower-build` / `damage-pipeline` / `shop-reroll` |
| `get_core_tower_share() -> float` | `L_core / ΣL`（`AllIn` 的 60% 判据输入） | `tower-build` |
| `signal core_tower_changed(new, old)` | 徽章/底座发光切换时发一次 | UI / 美术 |

#### 3.4.1 完整伪代码（GDScript · 可直接照抄）

```gdscript
# autoload: res://scripts/core_defense/link_graph.gd   （事件驱动 + 双脏标记）
extends Node

const LINK_FRAC     := 0.65   # ✅ 定稿（card-verify §2.1 / calibration-v03 §2.1）
const HARMONIC_GATE := 3      # ✅ 共鸣门槛 Lv3（A11，双向：h_i≥3 ∧ h_j≥3）

var _towers: Array = []        # 索引 = 塔位序号 0..5；空位为 null
var _adj:    Array = []        # _adj[i] = 邻居塔位序号数组（★ 不含 i）
var _E:      Array = []        # E_i
var _topology_dirty := true    # T1/T2 → 重建邻接表
var _e_dirty: Array = []       # T3    → 只重算被标记的 E_i

# 🔴 走 _physics_process 且用真实 dt，不受 Engine.time_scale 影响（C-2 / v03 §7.4）
func _physics_process(_dt: float) -> void:
    if _topology_dirty:
        _rebuild_topology()
    if _e_dirty.has(true):
        _recompute_E_marked()

func _rebuild_topology() -> void:
    var n := _towers.size()
    _adj = []; _adj.resize(n); _E.resize(n); _e_dirty.resize(n)
    for i in n:
        _adj[i] = []
        if _towers[i] == null:            # 🔴 空塔位不参与链接（无射程）
            continue
        for j in n:
            if i == j or _towers[j] == null:
                continue                  # ★ 不含 i 自己
            var d := _dist_xz(_towers[i], _towers[j])          # 水平面 XZ，不判 Y
            if d <= LINK_FRAC * (_towers[i].range_R + _towers[j].range_R):
                _adj[i].append(j)
    _topology_dirty = false
    _e_dirty.fill(true)                   # 拓扑变了 → 全员 E 失效
    emit_signal("links_changed")

func _recompute_E_marked() -> void:
    for i in _towers.size():
        if not _e_dirty[i]:
            continue
        var s := 0
        if _towers[i] != null and _towers[i].level >= HARMONIC_GATE:   # 闸门①：自己 ≥3
            for j in _adj[i]:
                if _towers[j] != null and _towers[j].level >= HARMONIC_GATE:  # 闸门②：邻居 ≥3
                    s += 1 + _towers[j].level
        _E[i] = s                          # 单塔无链接 / 未过闸 → E=0 → Resonance ≡ ×1.00
        _e_dirty[i] = false
    emit_signal("e_changed", _changed_list)

func _dist_xz(a, b) -> float:              # 等距投影不参与计算，只取 XZ
    return Vector2(a.pos.x - b.pos.x, a.pos.z - b.pos.z).length()

# ---------- 事件订阅（四个，缺一即出 bug） ----------
func _on_tower_placed(_slot: int) -> void:      _topology_dirty = true          # T1
func _on_tower_removed(_slot: int) -> void:     _topology_dirty = true          # T1
func _on_tower_range_changed(_i: int) -> void:  _topology_dirty = true          # T2（MVP 仅换原型触发）
func _on_tower_level_changed(i: int) -> void:                                    # T3
    _e_dirty[i] = true
    for j in _adj[i]:
        _e_dirty[j] = true                 # 🔴 只让邻居失效，不重建邻接表（最易漏）
```

> ⚠️ **T2 与 T3 的区别一定要写进代码注释**：`射程变 → 拓扑变 → 重建邻接表`；`层数变 → 拓扑不变、只有权重变 → 只刷 `E``。把 T3 误写成重建邻接表是纯浪费（O(n²) 无意义重算）；把 T2 漏掉则升级/换塔后链接不刷新（card-system 交接点 1 的 bug 现场）。

## 4. 交互流程（Interaction Flow）

### 4.1 空间动作 → 重算链（本系统的核心流程）

```
[建塔] 建筑卡放置到空塔位 slot_i
   ├─→ Slot.is_occupied = true, Tower.range 生效
   ├─→ 🔴 _topology_dirty = true   （T1：重建邻接表 → 链接增减）
   └─→ 邻居 E_i 重算

[升级] 建筑卡升级某塔（level +1）
   ├─→ Tower.level (h_j) +1
   ├─→ 若射程 R 随等级变化 → 🔴 _topology_dirty = true（T2：链接增减）
   └─→ 邻居 E_i 重算（h_j 变，T3：E_dirty，不重建拓扑）

[拆塔]（card-system §7.2.2，仅波次间安全窗，返还 50%，二次确认）
   ├─→ Slot.is_occupied = false, Tower.range 失效
   ├─→ 🔴 _topology_dirty = true   （T1：重建邻接表 → 链接减少）
   ├─→ 邻居 E_i 重算
   └─→ N_tower 变化 → 全场 κ 重算（card-system §5.2，非本系统职责，仅标注依赖）
```

> ⚠️ **职责边界**：`N_tower` 变化触发的**全场 κ 重算**归 `card-system`/`damage-pipeline`（A5/A6），本系统只负责发出"塔数变了"这一事件（`_topology_dirty`），**不算 κ**。

### 4.2 放置模式（建筑卡买/放解耦，card-system §4.2 的空间侧落地）

```
[购买] 建筑卡 → 入 HUD「待放置队列」（右下角蓝图图标，显示张数）
             ↑ 此时不占塔位、不进战场
[放置] 玩家点队列图标 → 进入放置模式
        → 全局减速 0.25×（复用 DilationBudget 池）
        → 战场高亮所有合法目标：
            · 空塔位   → 绿光脉冲（= 新建）
            · 同原型塔 → 金光脉冲（= 升级，显示 Lv_n → Lv_n+1）
        → 单次点击落子 / Esc 取消（取消不退款，卡留队列）
        → 落子瞬间触发 §4.1 [建塔] 重算链
```

- **符合 P1**：放置塔是**建造**（build 层），不是"操作单位移动/释放技能"。玩家从不碰任何单位。
- **符合 C-2**：放置模式减速到 0.25×，但 `LinkGraph` 重算走事件驱动、不受 `time_scale` 影响。

### 4.3 重决策区（仅波次间安全窗）

| 操作 | 空间侧后果 | 依据 |
|---|---|---|
| **拆塔** | 塔位释放 → `_topology_dirty`（链接减少）+ 邻居 `E_i` 重算 + `N_tower` 变 | card-system §7.2.2 |
| **升级塔**（波次间也可） | MVP 射程固定 → **不改链接**；仅 `h_j` 变 → 邻居 `E_i` 重算（走 T3 `E_dirty`） | §2.5.3 CD-4（射程固定）· card-system §4.4 需回写 |

> 🔴 **职责切分铁律**（card-system §4.3）：战斗内只做**轻决策**（买/刷/锁/放置），波次间安全窗才做**重决策**（弃卡/卸下/拆塔/转型）。本系统的重算链对两者一视同仁（都是事件驱动），但**触发时机**受此约束。

## 6. 边界与失败（Edge Cases & Failure Modes）

> 不少于 3 类是输出规范，本节给 **9 类**。

| # | 边缘情况 | 处理规则 |
|---|---|---|
| **E1** | **空塔位**（无塔） | 无射程 → 无链接、`CoverageScore_i = 0`、不進邻接表 |
| **E2** | **单塔无链接**（`N(i) = ∅`） | `E_i = 0` → `Resonance_i = ×1.00`（🔴 必须显式写此边界，calibration-v03 §5.3 陷阱 1） |
| **E3** | **塔升级导致射程变化 → 链接增减** | `_topology_dirty = true` → 下一物理帧重建邻接表；`E_i` 与共鸣视觉（光弧亮度/粗细）同步刷新；链接消失给**衰减动效**（非静默，card-system E6） |
| **E4** | **塔卡层数 `h_j` 变化但拓扑未变** | 🔴 **不重建邻接表**，只让邻居 `E_i` 通过 `E_dirty` 失效重算（§2.5.3 T3，最易漏） |
| **E5** | **拆塔** | 塔位释放 → `_topology_dirty`（链接减少）+ 邻居 `E_i` 重算；`N_tower` 变 → 全场 κ 重算（card-system §5.2，非本系统算） |
| **E6** | **两塔距离恰好等于阈值**（`d == 0.65(R_i+R_j)`） | **判为链接**（`≤` 含等号，避免浮点边界抖动导致链接闪烁） |
| **E7** | **射程重叠但水平面 vs 高度错位** | 链接只判 **XZ 水平距离**，不判 Y 高度（射程是水平半径）；等距下塔有高度但射程圆始终在地面 |
| **E8** | **重算与减速时钟耦合**（放置模式 0.25×） | 🔴 `LinkGraph`/`CoverageScore` 重算走**事件驱动、不受 `time_scale` 影响**（calibration-v03 §7.4）；若放进 `_process`+计时器，减速时会漏帧 |
| **E9** | **逐塔几何覆盖直接喂管线**（§2.4.2 冲突） | 🔴 **禁止**在重标定完成前把逐塔几何 `CoverageScore_i` 当伤害乘区上线（会让两条路径都起不来）；MVP 沿用聚合常量 0.78/0.95 |

**失败模式（系统级）**

| 失败模式 | 判据 | 兜底 |
|---|---|---|
| 链接图饱和成完全图（`k` 失去意义） | 用了系数 1.0 而非 0.65 | 🔴 C-1 红线强制 0.65（§2.5.1） |
| 每帧重算链接导致帧率崩 | 未用事件驱动、每帧 O(n²) | 🔴 C-2 红线事件驱动（§2.5.3） |
| 多塔流前期领先后期被单核反超过度 | 覆盖率模型切换未重标定 | §2.4.2 处置：MVP 沿用聚合常量，切换需整体重标定 |
