## 0. 结论前置（给赶时间的人）

### 0.1 一句话

> **怪物不再沿一条折线排队进场，而是从场外一圈随机方向直插核心；塔从"沿路一字排开"改成"核心周围环形布防"。**
> 作者状态量从「沿弧剩余时间 `t_remain`」读出的东西变了（弧长 `s` → 极径 `ρ`），但 **`t_remain` 本身仍是唯一权威状态量**，金标本的结算循环**一行不改**。

### 0.2 🔴 三个最重要的实证发现（本文档的依据）

| # | 发现 | 严重度 | 位置 |
|---|---|---|---|
| 🔴 **F-R1** | **「四面八方」与「共鸣网络 k̄」在几何上互斥。** 塔位一旦真正铺满 360°，两两距离被拉开 → 链接度 `k̄` 从定稿的 **3.667** 塌到 **1.4~2.0**（随机搜索实测：`k̄` 可达范围 0.33~3.0，均值仅 1.445）；反之要保住 `k̄`，塔位必须相对聚拢 → 又变回"守一侧"。**解法不是二选一，而是「半径分档 + 角距不均」的非均匀环** —— 本文档给出了一组可行解（布局 **R1**），它在三档阈值下的 `k̄` 与方案 A **逐位相同**。 | 🔴 高（已给出解法，但需拍板） | §2.4 |
| 🔴 **F-R2** | **径向模型把「塔挨打」整体稀释了约 3 倍。** 路径模型下每只怪都要走完"危险路"（4 座暴露塔 `ExposureArc` 合计 53.13 unit，W1 累计 **52.6 怪秒**）；径向模型下每座塔只守住一个角向楔形（11%~27% 的来袭方向），单怪在其危险圈内只停留 ~1.4s → 布局 R1 全场 W1 累计仅 **17.19 怪秒**，稀释 **3.06×**。→ **`ATTRITION = 1.50` 在径向模型下会让塔死亡频率显著下降，V-1 判据 T-A（苟活期 ≥1 座/局）大概率破线 → 必须重扫。** | 🔴 高（需重扫，不阻塞迁移） | §6.3 |
| 🔴 **F-R3** | **「零暴露的绝对安全位」在径向模型下不存在。** 路径模型有 S4/S5 两个 `d_path > AGGRO_R` 的绝对安全位；径向模型下**任何塔位都有非零的暴露楔形**（只要它不在核心正上方）。→ `mechanics-tower-life-death` §2.2 的硬约束「任何地图必须保证 ≥1 个塔位在 `AGGRO_R` 之外」**必须改写为相对口径**。 | 🔴 高（定稿硬约束需修订） | §2.6 |

### 0.3 🟢 最重要的好消息：金标本 DPS 管线与几何**几乎完全解耦**

我逐行核过 `corebound_sim_v03.py` 的 `compute_dps`，几何依赖只有**一处**：

| 管线环节 | 是否依赖几何 | 径向迁移后 |
|---|---|---|
| `B7 Coverage_i` | ❌ **不依赖** —— MVP 走 `coverage_mode="path"` 聚合常量 **A 0.78 / B 0.95**（`sim:357-360`；逐塔几何模式是 opt-in，定稿基线**没用**） | ✅ **零改动** |

| `C1 AoE` | ❌ **不依赖** —— 只看带 Tag 塔的层数（`sim:367-368`） | ✅ **零改动** |
| `B4 Resonance_i = (1+κ_r)^{E_i}` | ✅ **依赖** —— `E_i` 来自 `geo.links()`，而 `links()` **只用塔位两两距离**（与路径无关） | 🔴 **须保住逐对链接拓扑，而非仅保平均度 `k̄`；旧 R1 已证明只匹配 `k̄` 会使定稿 B 失效** |

## 1. 系统目标（System Goal）

### 1.1 一句话

> **把"守一条走廊的尽头"改成"守一座被环抱的核心"**：怪物从场外一圈的随机方向直插核心，塔在核心周围环形布防，玩家的落位决策从「贴路 vs 离路」变成「**站多远（径向）× 守哪边（角向）**」。

### 1.2 与四支柱的兑现关系

| 支柱 | 现状（固定路径） | 径向模型 | 判定 |
|---|---|---|---|
| **P1 不动如山** | 站位三维：覆盖 × 链接 × 暴露 | 站位三维变为：**径向轴（覆盖↔暴露） × 角向（链接 + 防向） × 原型（射程→全向/定向）** | 🟢 **兑现，但维度的"形状"变了**（§3.1） |
| **P2 雪崩无上限** | DPS 管线与几何解耦 | 完全保留（§0.3） | ✅ **不受影响** |
| **P3 每局一个新解** | 6 个生成变量 | 新增「**来袭方向格局**」可选随机维度（Q-R5） | 🟢 **持平或增强** |
| **P4 零操作高密度** | APM=0，决策密度高 | 新增"径向 × 角向"的联合决策，APM 仍 0 | ✅ **不受影响** |

### 1.3 本系统的三条设计红线（自检用）

| # | 红线 | 说明 |
|---|---|---|
| 🔴 **R-CS1** | **金标本零扰动优先** | 任何改动若威胁 `WaveSim.simulate_wave` 的逐位等价性，必须走**诊断开关**（默认关闭），与 `prototype_split_enabled` / `elite_waves_enabled` / `tower_aggro_enabled` 同款哲学 |

## 2. 新空间模型定义

### 2.1 五要素总览与依赖方向

```
核心 Core（静态）── 地图几何中心 (28, 28)                    ← 由"路径终点"改为"地图中心"
  │
  ├─→ 出生环 SpawnRing（静态，半径 R_s）── 怪物从环上随机角 θ 出生，直插核心
  │
  ├─→ 塔位环 SlotRing（静态，6 位 · 半径分档 · 角距不均）
  │     ├─ 半径 r_i  → 覆盖 / 暴露（径向轴）
  │     └─ 角向 θ_i  → 链接度 k / 防向（角向轴）
  │
波次导演 WaveDirector（时间轴权威 · 结构不变）
  │
怪物 Monster（极坐标推进；ρ = 到核心距离）
  ├─ Marching   → ρ 单调减小（直插核心）
  ├─ AggroTower → 停下（v = 0），攻击最近的塔     ← 三态完全保留
  └─ Leaked     → ρ = 0 → Core.hp -= 50
```

> **依赖方向铁律（沿用 `wave-spawner` §2.1）**：`Core / SpawnRing / SlotRing` 是**静态舞台**（地图加载即定）；`WaveDirector` 是**时间轴权威**；`Monster` 是运行时实体。**下游只读事件，不反向写回。**

### 2.2 核心 `Core`（M1 · 位置变更）

| 项 | 现状（方案 A） | 径向模型 |
|---|---|---|
| 坐标 | `(55, 25)` = **路径终点**（在地图右边缘） | **`(28, 28)`** = 逻辑地图 55×55 的**几何中心** |
| HP / 漏怪伤害 | 1000 / 50 | **不变**（N1 / N2 定稿） |
| 失败条件 | HP ≤ 0 → 立即失败（Q5） | **不变** |

> 🟢 **顺带修好一处已接受的视觉取舍**：`core-defense` §5.4.1 明确记载"方案 A 的 6 个塔位全部堆在核心左侧（Δsx 全为负），与视觉锚点 1「核心居中俯视」不一致"，当时为保 P1 **显式接受**了这个取舍。径向模型下核心必然居中 → **该取舍自动消失**，叙事回到"**守一座被环抱的核心**"。

### 2.3 出生环 `SpawnRing`（🆕）

```
R_s             = 出生环半径（unit）—— 🟡 PLACEHOLDER，推荐 55.0（Q-R2）
θ_i             = 第 i 只怪的出生角（radian）
spawn_pos(i)    = Core.pos + R_s × (cos θ_i, sin θ_i)
t_reach         = 10.0   （🔴 恒定，与出生环半径无关）
v₀              = R_s / t_reach     （派生量，非新数值）
```

| `R_s` | `v₀` (u/s) | 单怪在内环塔危险圈内停留 | W1 全场累计挨打 | 相对基线的稀释 | 备注 |
|---|---|---|---|---|---|
| **101.0** | **10.10** | 1.35 s | 17.19 怪秒 | **3.06×** | = 现状 `L`，`v₀` 与现状逐位相同 |
| **55.0** ✅ | **5.50** | 2.48 s | 31.57 怪秒 | **1.68×** | 🟢 **推荐**：稀释最小 + 出生点刚好在可视区外 |
| 40.0 | 4.00 | 3.41 s | 43.41 怪秒 | 1.22× | 出生点几乎贴脸，怪物移动感偏慢 |

> 🟢 **`R_s` 是纯演出参数。** 金标本 sim 里没有"位置"概念（§0.3），`v₀` 也不进任何公式 → **改 `R_s` 不构成任何数值重扫**。但它在实时版里会影响"怪物何时进入 `AGGRO_R`"→ 🔴 **实时版与批处理镜像 `WaveSimAggro` 必须用同一个 `R_s`**，否则塔死亡时机会分岔（这与现状"仇恨破坏逐位等价"是同一条旧账，已被 `tower_aggro_enabled` 开关隔离）。
>
> 🎯 **推荐 `R_s = 55.0`**：① 稀释倍数最小（1.68×，`ATTRITION` 上调压力最小）；② 出生点落在可视区外一点点，符合吸血鬼幸存者"从屏幕边缘涌入"的手感 —— 而这正是用户点名的参考作品。

### 2.3.1 出生角 `θ_i` 的规则（🔴 涉及金标本对齐，必读）

| 方案 | 定义 | 判定 |
|---|---|---|
| ✅ **① 黄金角低差异序列（推荐）** | `θ_i = (θ₀ + i × 137.508°) mod 360°`；`θ₀ = (w × 37°) mod 360°`（每波换起始相位） | 🟢 **确定性、零 RNG 消费** → 金标本零扰动；视觉上准随机铺满 360°；每波格局不同（喂 P3） |
| 🟡 **② 独立 PyRandom 流（T1 备选）** | `θ ~ U(0, 2π)`，用**独立实例** `PyRandom(run_seed ^ 0x5A5A5A5A)` | 🔴 **必须与商店发牌的 RNG 流物理隔离**，否则发牌序列被污染 → 金标本逐位对齐当场失效 |

> → `coverage_of(slot_xy, radius)` 的**函数体一行不改**，只是喂进去的点集从"折线"换成"扇形射线族"。这是本次迁移中**最干净的一处对齐**。

### 5.4 🟢 为什么"外环钉子"不会成为主导策略（径向版的诚实论证）

> **风险**：径向模型下所有怪都**必经外环塔**，且停下攻击的怪不漏怪 → 玩家能不能把一座深塔放在外环当"钉子"，让整波的怪都停在它前面 → **零漏怪 → 必胜**？

**不会，四条机制保障**（沿用并强化 `wave-spawner` §2.6.4 的论证）：

1. **伤害叠加（R10）**：塔 HP ∝ `h^0.6`（次线性），攻击它的怪**线性叠加**。W20 有 8 只 Tank 同时围上 → 塔必死。
2. 🔴 **楔形是硬的**：外环塔只吸住 **11%~27% 的来袭方向**（§2.6.2）→ **73%~89% 的怪根本不从它身边过** → 漏怪压力必然存在。🟢 **这一条在径向模型下比路径模型更强**（路径模型下 union 暴露 52.6%，径向只有约 11%~27%/塔）。
3. **塔死了就不吸了**：`Disabled` 塔被排除出候选集（R5）→ 怪恢复前进。
4. 🆕 **内环塔是第二道闸**：即使外环塔被绕过，怪仍要穿过内环塔的射程才能碰到核心；且内环塔 `r ≤ R` → **全向覆盖**。

> ✅ **结论**：外环肉盾是**正当的战术收益**（玩法② 的地基），不是漏洞。

```
  dmg_to_tower  = ATTRITION × HP0 × m_dps(proto) × dt               [HP]

```
