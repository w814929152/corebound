## 0. 结论前置

四句话：

1. **能做，但必须挂在「购买/装配」事件上，不能挂在战场量上。** 上一轮判死的是「上波击杀 ≥ K」这类**时间轴上的门**（`n(w)` 单调 → 门只开一次）。等级链的门是 `h ≥ 3`，而 `h` 是**玩家账户里的量**，可以停、可以拆、可以只养一座 → 门能反复跨越。**这是两回事。**
2. **万象棋的三分之所以不爆，靠的是回合数；守核不需要这个限制，因为 `h` 的收益是次线性的（`h^0.6`）。** 原型必须收着做，我们反而可以放开 —— 这是守核比原型更适合做等级链的地方。
3. **链的成员必须是「你本来就要买的卡」，不能是额外加的卡。** 三分的精髓不是「凑 4 张新牌」，而是「你已经在买周瑜和曹操，现在它们互相触发」。所以每个阵营只加 **1 张引子卡**，其余靠给已有卡打 `echo` 标签。
4. **`echo` 只能改三个结构性量（`h` / 卡层数 / 门槛判定），禁止碰任何数值量。** 这条是硬的 —— 一旦 `echo` 能加伤害，它就是 §2.4 那个被否掉的第三台雪崩引擎。

## 1. 三分阵营的机制还原

万象棋的三分只有两个动作：

| 原型 | 窗口 | 效果 |
|---|---|---|
| 周瑜 | **登场** | 全队 +1 级 |
| 曹操 | **整备**（战后） | 随机触发一次「三分英雄的登场」 |

合起来：`打曹操` → `触发周瑜登场` → `全队 +1 级`。玩家看到的不是「我买了一张牌」，而是「我买了一张牌，它又替我打了一张牌」。

抽象出来只有一条公式：

```
一次付费操作 → 触发另一张卡的「入场效果」→ 该效果再抬升一个可被消费的结构量
```

守核里能对应上的事件流只有一条：**波间的购买 / 装配**。它不是每秒触发，但每局有 **40–80 次**，比万象棋的 20 回合更密 —— 这正是它比「战场触发」更可用的原因。

> 🔴 **不能用战场量做触发源。** 上一轮的定理说的是：`n(w) = 8 + 1.6w`、`HP(w) = 16·1.30^(w−1)` 都随波单调递增，所以 `{w : 量 ≥ K}` 只能是后缀区间 `[w_K, 20]` —— **一局只开一次**。`h` 不满足这个前提：它是玩家的投资余额，可以一直不投、可以拆塔清零。

## 2. 边界澄清：等级门 vs 击杀门

这是本文最重要的一张表。它决定了「哪些触发式设计还能做」。

| 维度 | 击杀门（已判死） | 等级门（本文） |
|---|---|---|
| 量的来源 | 系统生成（`n(w)`） | 玩家投入（`h`） |
| 随时间的行为 | **单调递增，不可逆** | 可增可减可停 |
| 门的可跨越次数 | **1 次**（`[w_K, 20]`） | 任意次（拆塔即回落） |
| 是否由玩家携带时机 | ❌ 系统决定 | ✅ 玩家决定（P-D 合规） |
| 触发频率/局 | ≈ 1 | 与购买次数同阶（40–80） |
| 判决 | 🔴 退化为常驻乘区 | ✅ 可做 |

**一句话**：**时间轴上的门只能开一次，账户里的门可以开无限次。**

> 📌 这也是为什么 `Charge`（击杀门）必须回炉、而等级链（等级门）可以做 —— 它们长得像，但一个量由系统产生，一个量由玩家持有。

## 3. `echo` 规范（硬约束）

`echo` = 一张卡在**被装配**或**被叠层**时结算的一次性效果。它取代万象棋的「登场」。

### 3.1 六条硬约束

| # | 约束 | 理由 |
|---|---|---|
| **E-1** | 触发源只有两种：`Attach`（装配到塔）、`Stack`（叠层 +1） | 战场触发已被定理判死（§2） |
| **E-2** | `echo` 只能修改三个结构性量：`h` / 某张卡的层数 `n` / 门槛判定输入 | 这三者会被已有乘区消费，天然受那些 cap 约束 |
| **E-3** | 🔴 **禁止**修改：伤害、攻速、`κ`、`StackCap`、`Crossfire` 计数 | 改这些 = 绕过所有 cap = 第三台雪崩引擎 |
| **E-4** | 链深 ≤ 3；**每波 ≤ 1 次传播**；**每局 ≤ 8 次** | 万象棋「每回合一次」的等价闸门 |
| **E-5** | 触发记忆键 = **塔位索引**，`histmax` 同规范**只增不减** | 堵「拆了重建再触发」（同 F-2 兜底①） |
| **E-6** | 默认关闭。关闭时所有 `echo` 返回 0，**逐位等于现状** | 金标本零偏移（沿用 `trigger_pack` 纪律） |

### 3.2 为什么 `h` 可以放开来给

`h` 的收益链条一共三条，**全部是次线性或封顶的**：

| 出口 | 公式 | 对 `h` 的敏感度 |
|---|---|---|
| `Base` | `base_dps × h^0.6` | 次线性：`h` 翻倍 → 伤害 ×1.52 |
| `Focus` | `1 + 0.06·L·min(1, h/8)` | **在 `h = 8` 封顶**，之后完全无收益 |
| `E_i` | `Σ(1 + h_j)` | 线性 |

对比万象棋：等级 10 / 40 / 100 是**三次技能形态跃迁**（指数），所以它必须用回合数压住。守核没有形态跃迁，`h` 只是 `h^0.6` —— **给 40 点 `h` 也只值 9.1 倍，而给 134 点（定稿 B 的 `Arrow`）才 18.9 倍**。

> ✅ **结论：等级链在守核里的上限是数学封住的，不需要额外闸门。** 这也是本文敢做「链」而 `Charge` 不敢做的根本原因。

## 4. 三条链（每阵营一条，形状互不相同）

### 4.1 熔炉「归火」— 垂直（层 ↔ 等级 互换）

> 你买的每一张火焰卡，都在给下一张火焰卡上膛。

**引子卡 `Bellows` 风箱**（单塔效果 · 🔥 · 9 分）

| 项 | 内容（`[PLACEHOLDER]`） |
|---|---|
| 常驻 | 本塔每装配 2 张火焰单塔效果卡，本塔 `h` +1，**每塔位上限 +2** |
| `echo` | 本塔 `h` 增加时，本塔 `Incendiary` +1 层（**每塔位限 1 次**） |

**成员卡获得 `echo`**：

| 卡 | `echo` |
|---|---|
| `Incendiary` 燃烧弹 | 装配时若本塔 `h ≥ 3`，`Overclock` +1 层（每塔位 1 次） |
| `Overclock` 超频 | 装配时若本塔 `h ≥ 5`，本塔 `h` +1（每塔位 1 次） |
| `Backdraft` 爆燃 | 装配时若本塔 `Incendiary ≥ 5` 层，本塔 `h` +1（每塔位 1 次） |

**链**：`叠火焰卡` → `Bellows 把层数换成 h` → `h 过 3 / 5` → `成员 echo 反向给层数或 h`

**为什么闭环但不过热**：环的每一步都要**先付一张卡**。没有免费入口 —— 环的能量来自你继续买火焰卡，而不是来自时间。

**自限闸门**：`Focus` 在 `h = 8` 封顶 + `Base(h^0.6)` 次线性 → 链条在 W12 前后自然减速。

**病灶**：**槽位饥荒**。熔炉本来要占 `Incendiary + Overclock + Backdraft` 三槽，`Bellows` 是第四槽，塔只有 5 槽 → 等于主动放弃一个乘区。这条链的代价就在这儿。

### 4.2 霜序「链冻」— 横向（条件满足，赠予邻居）

> 减速不只是控制，它是这条链的燃料。

**引子卡 `RimeLock` 霜锁**（单塔效果 · ❄ · 9 分）

| 项 | 内容 |
|---|---|
| 常驻 | 本塔 `CryoBite` 每 +2 层，**所有相邻冰霜塔** `h` +1，**每塔位上限 +3** |
| `echo` | 本塔装配到**已有 `Stasis`** 的塔上时，所有相邻塔的 `Stasis` +1 层（每塔位 1 次） |

**成员卡获得 `echo`**：

| 卡 | `echo` |
|---|---|
| `CryoBite` 霜蚀 | 装配时若本塔 `h ≥ 3`，本塔 `Stasis` +1 层（每塔位 1 次） |
| `Stasis` 凝滞 | 装配时若本塔减速 ≥ 45%，相邻塔 `h` +1（每塔位 1 次） |
| `Frostburst` 霜爆 | 装配时若本塔 `Stasis ≥ 6` 层，本塔 `CryoBite` +2 层 |

**链**：`减速层累积` → `RimeLock 把减速换成邻居 h` → `h ≥ 3` → `Stasis 层` → `减速更强` → 回到第一步

**自限闸门**：`T5` 的减速 **cap `60%` 早已定稿** —— 到 60% 后第一步直接断掉，环自己停。**不需要新闸门，旧 cap 就是闸门。** 这是最省的一处设计。

**病灶**：**横向传播依赖站位**。`RimeLock` 只给"相邻"塔送 `h`，所以冰霜塔必须挤在一起 → 与 P1（位置策略）同向，但也意味着**远离核心的塔拿不到**。

### 4.3 枢网「桁架」— 广度（零和搬运）

> 不生产等级，只转移等级。

**引子卡 `Link` 连杆**（单塔效果 · — · 9 分）

| 项 | 内容 |
|---|---|
| 常驻 | 本塔 `h` 增加时，可在本波内把 1 点 `h` 转给**链接上 `h` 最低的塔**（净零） |
| `echo` | 本塔装配时：链接上 `h` 最低的塔 `h` +1、本塔 `h` −1 |

**成员卡获得 `echo`**（复用中立卡）：

| 卡 | `echo` |
|---|---|
| `ArrowTower` 箭塔 | 装配到该塔位时，若该塔位已有 ≥2 条链接，相邻最低塔 `h` +1 |
| `Beacon` 信标塔 | 装配后，本塔在**共鸣门槛**判定中视作 `h = 3`（不改真实 `h`） |

**链**：`高塔 h −1` → `低塔 h +1` → `过 h ≥ 3 门槛` → `E 的有效边增加` → `(1+κ_r)^E`

**这条链的特殊性**：`E_i = Σ(1 + h_j)` 里的**求和**对分配不敏感（总量守恒 → `Σ` 不变），但**双向门槛 `h_i≥3 ∧ h_j≥3` 对分配极其敏感**。所以：

> **均压的全部价值，集中在「让更多节点跨过 3」这一件事上。** 一旦全员 `≥3`，继续搬运就是零收益 —— 自限是**结构性的**，不需要 cap。

**病灶**：**零生成 = 零上限**。这是三条链里最安全、也最弱的一条。它不会让枢网突破 `B/A < 1` 红线，但也救不了枢网的绝对强度。

## 5. 定价：`+1 h` 到底值多少分

`echo` 是**免费送量**，所以必须有一个当量表，否则每个人都会往自己那张卡上多写一点。

### 5.1 当量表（`[PLACEHOLDER]`，依据 §3.2 的敏感度）

> 🔴 **v0.3 校准（2026-11-07，据 `v11-chain-report.md` §2）**：下表按 `h^0.6` 的**相对收益**推导，没有计入**机会成本**。实测 W12-A：`+1 h` 的每分效 = 439.7 DPS/分，`+1 层` = 925.1 DPS/分 → **比值 0.475**。
> 结论：**`8 分/点` 只在 `h ≤ 4` 成立**；主塔进入两位数后应按 **4 分甚至更低**计价（`h` 的经济寿命 ≈ 4）。
> 任何以 `h` 为产物的方案，都必须先用这张表的下半区（4 分）算，不能用上半区。

| 给什么 | 当量 | 推导 |
|---|---|---|
| `+1 h`（目标塔 `h ≤ 4`） | **8 分** | `3^0.6 → 4^0.6` = +19% 伤害；建筑卡 12 分/张。**仅此区间成立** |
| `+1 h`（目标塔 `h > 7`） | **4 分** → 实测应更低（≈3.3） | `8^0.6 → 9^0.6` = +7.4%；且 `Focus` 已封顶；实测每分效仅 `+1 层` 的 47.5% |
| `+1 层单塔效果卡` | **9 分** | 与卡价 1:1 |
| `+1 条有效共鸣边` | **6 分** | `ΔE = 1+h` 进 `(1.05)^E` |
| 门槛穿越（1 座塔从"无效"变"有效"） | **5 分/座** | 边际边数 × 复利 |
| 减速 `+5%`（未到 60% cap） | **4 分** | 延长驻留，条件复利的输入 |

### 5.2 预算规则

> **一张 9 分的卡，其「常驻 + `echo`」的合计当量 ≤ 18 分。**
> **一张 12 分的建筑卡 ≤ 24 分。**
> **全局卡（10 分）≤ 20 分。**

以及一条总量闸门：

> **`echo` 每局上限 8 次（E-4），单次最高当量 9 分 → 全局上限 ≈ 72 分。**
> 参照：W20 玩家的累计投入约 **960 分**（`shop-reroll` §5.3）→ 占比 **7.5%**。

这两条一起，把「等级链」的总收益锁在 7.5% 以内。它足够让玩家感觉到「我的牌在互相帮忙」，但不足以让任何人靠它绕过 `κ` 或 `StackCap`。

## 6. 冲突自查

| 系统 | 判定 | 说明 |
|---|---|---|
| **T-R1 / T-R2**（拆建不得套利） | ✅ | `echo` 记忆键在**塔位**上、只增不减（E-5）→ 拆了重建不再触发。且 `Link` 是零和，`Bellows`/`RimeLock` 是每塔位 cap |
| **`N_tower_histmax` / κ 广度折价** | ✅ | 等级链**不改变塔数**，折价项不动 |
| **`StackCap`** | ✅ | E-3 禁止改；且 `echo` 只加层数，层数仍受 `StackCap` 约束 |
| **`Salvage` 返还 50%** | 🟡 **需明确** | 返还 = 50% × 累计**投入分**。`echo` 送来的层数/`h` **不计入投入** → 拆塔返还不虚高。必须写进实现口径 |

| **`B/A < 1` 红线** | 🟡 | 三条链里只有「归火」会抬 A，「桁架」会抬 B。**必须保证 B 的增幅 > A 的增幅**，否则红线更远 |
| **P1（位置即策略）** | 🟡 | 「链冻」和「桁架」都奖励挤团 → 需验证终局塔间平均距离不跌破定稿画像 |
| **P4（决策归玩家）** | ✅ | `echo` 的触发时机 = 买卡那一刻，玩家完全掌控 |
| **卡池稀释** | 🟡 | 每阵营 +1 张引子卡（8 → 9）→ 按 v10 斜率约 A −1~2pp。**只有引子卡进池，成员 card 的 `echo` 是标签不是卡** |

## 7. 风险

| # | 风险 | 判断 | 处置 |
|---|---|---|---|
| **R1** | **槽位饥荒被低估** | 🟡 每条链都要占 1 个额外强化槽，而塔只有 5 槽。玩家可能算完发现"不如再买一张 `Incendiary`" | 先做纸面：W8 时 5 槽怎么分配，看引子卡是否被挤掉 |

| **R4** | **链深 3 仍不够表达「三分」** | 🟡 万象棋是 3 张互相触发，我们是"1 引子 + 3 成员" | 若实测太浅，把 `E-4` 的每波 1 次放宽到 2 次，**不要**加深链 |
| **R5** | **`ArrowTower` 的 `echo` 与 `N_tower_histmax` 交互** | 🟡 建塔触发 → 建塔本身也在抬 `N_tower_histmax` → 折价加深 | 需确认 `echo` 的 `h` 增益不被算进"新建塔"事件 |

| **P0** | 纸面：W8 / W12 的 5 槽分配表 | 槽位饥荒是 R1，最可能让整个方案作废 |
| **P1** | `sim` 加 `echo` 钩子（默认关闭，逐位自检） | 与 `trigger_pack` 同规范 |
| **P2** | 只开「桁架」（零和，最安全） | 先拿一个"不生成量"的对照组 |
| **P3** | 开「归火」+「链冻」 | 这两条会生成量，需单独隔离影响 |
| **P4** | 三链同时开，看 `B/A` 是否破 1 | 红线检查 |

### 8.2 失败信号

| 信号 | 观测 | 判定 |
|---|---|---|
| **A · 引子卡必买** | 三条链各自的首购率 > 85% | 定价过强 → 砍 echo 次数或提高条件 |
| **B · 链不起作用** | 首购率 < 25% | 定价过弱 → 加 cap 而非加次数 |
| **C · 红线** | `B/A ≥ 0.85` | 立即关「桁架」的 `Beacon` echo |
| **D · 挤团** | 终局塔间平均距离显著低于定稿画像 | P1 失效 → 「链冻」改远端联动（同 `keyword-adaptation` §5.2） |
| **E · 前期崩盘** | 带链路线的 W1–W5 核心掉血 > 基线 1.5 倍 | 加"`h < 3` 时引子卡给 `h` 而非给层数"的兜底 |

## 9. 明确不做

| 不做 | 理由 |
|---|---|
| 战场内触发（击杀/命中触发等级） | 已被门单调性定理判死（§2） |
| `echo` 直接加伤害/攻速/`κ` | E-3，第三台雪崩引擎 |
| 等级上限突破（999 级那种） | 守核 `h^0.6` 次线性，堆到 999 只有 48 倍，反而浪费玩家注意力 |
| 新增"等级"货币 | `h` 就是等级，第四套货币 = 第三个雪崩引擎 |
| 链深 > 3 | 深度增加的是"算不清"，不是"想得深" |
| 把引子卡做成全局卡（不占强化槽） | 免掉槽位成本 = 免掉整条链的代价 |
