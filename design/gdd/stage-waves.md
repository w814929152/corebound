## 0. 结论前置

四句话：

1. **现在的 10 关，波次构成逐位相同。** `wave_tag` 是死字段，`monster_stats(w)` 是唯一出怪函数 —— 1-1 的第 3 波和 9-1 的第 3 波是同一波。这不是"关卡内容少"，是**关卡之间根本没有内容差异**。
2. **波型在现有引擎里只有三条真通道**：只数（→ 经济 + 漏怪致死）、三原型重甲占比（→ 对塔伤害）、速度分布（→ 到场节奏）。所谓"考 AoE / 考单体爆发"目前**在结算上不成立**（§1）。任何声称"这关考 AoE"的波表，都是在骗自己。
3. **所以波表的设计律是「整关总血量守恒，单波形状自由」。** 一关打完消耗的总血量与基准曲线逐位相同 —— 改的只是这份血量**分成几份、每份多重、多快到场**。这样"这关更难"永远只能归因于形状，不能归因于暗改数值。
4. **上一版「`S` 越高波数越多」必须废弃。** HP 是 `1.42^(w-1)`，多打一波末尾就贵 42%，S=7 时同一关末尾被抬高 **2.86 倍**（§5.0）。改成"S 把喘息波换成潮涌波"：波数固定、总血量固定，**压力上升的同时经济也上升**，反而顺手解决了"救得多=被惩罚"的失败信号。

一句话：**波表不是难度旋钮，是形状旋钮；难度靠关卡长度一档一档给，形状靠波型一波一波换。**

> 🟢 **实测后追加一句（§11）**：这条律在**已校准口径**（aggro OFF）下完全成立 —— 十关通关率 100%、总血全 `1.000×`。
> 在**产品实机口径**（六开关全开）下部分成立：基准表 71%，十关落在 `26%–89%`，**没有硬墙**，
> 但排序不单调（1-1 89% 高于起点 0-1 的 79%；8-1 87% 高于 7-1 的 62%）。
> 用**同长度对照**（§11.7）拆开后：**长度几乎不改难度**（对照全落在 71–84%），
> 硬度几乎全来自形状 —— `9-1` 形状效应 `−45 pt`、`8-1` 只 `+3 pt`、`1-1` `+7 pt`。
> 总血逐关仍 `1.000×`：改的只是分成几份、多重、多快到场。

## 1. 先泼一盆冷水：波型在这套引擎里能改什么

读 `wave_director.gd` 的 `_substep` 与 `_apply_pool_live`，结论很硬：

```
① 伤害是**全场聚合池**：每 tick 把所有塔的 DPS 汇总成一个数，按 t_remain 升序填怪。
② **溢出结转**：一只怪打死了，剩下的伤害继续填下一只，不浪费。
③ **不判射程**（W-A4）：塔摆哪都一样，塔位只影响仇恨与地形观感。
```

推论（三条都反直觉，但都成立）：

- **"考 AoE"不存在。** 打 1 只 1000 血的怪，和打 10 只 100 血的怪，聚合池 + 结转下结果**逐位相同**。没有过杀损失，AoE 与单体在结算上是同一个数。
- **"考爆发"不存在。** 同上，爆发只是"这一 tick 的 DPS 高"，结算里没有时间窗粒度。
- **"肉 vs 脆"只在两处有区别**：漏怪伤害按**只**算（每只扣 50），以及击杀奖励按**只**发（每只 `2+0.5w` 废料）。

所以能真正改变结果的，只有三条：

| # | 通道 | 引擎字段 | 玩家能感知的后果 |
|---|---|---|---|
| **A** | **只数 `n`** | `interval = spawn_span / n`、`leaked_count += 1` 各扣 50、`scrap += spk` 每杀一只 | 怪多 → **废料多**（构筑更快成型）、但**漏 20 只就死**（核心 1000 ÷ 50 = 20 只的固定预算） |
| **B** | **重甲占比（comp）** | `M_DPS` = Rush 0.80 / Swarm 0.60 / **Tank 2.20** → 对塔伤害复合比 | 重甲多 → **塔被打掉**（缺口输出永久下降）；潮涌型重甲少 → 塔几乎不掉血 |
| **C** | **速度分布（comp）** | `M_SPD` = 1.33 / 1.00 / 0.67 → 到场节奏 | 快怪多 → 同一 tick 内更挤、更早到核心；慢怪多 → 拖长单波 |

> 🔴 **这条约束决定了整份文档的写法**：每个波型只承诺上表三条通道里的后果，**不承诺"战术感受"**。想真的要"AoE 关 / 爆发关"，得先给引擎加射程或过杀损失 —— 那是另一件事，不在波表里。
>
> 🟡 顺带一个必须记住的常数：**核心 1000 HP ÷ 漏怪 50 = 20 只**。任何一波 `n > 20`，全漏必死；`n ≤ 20` 的波**全漏也打不死你**。这条使"潮涌波"和"铁壁波"的失败方式完全不同（§2）。

| 码 | 型 | `n` 乘数 | 血量偏置 | 构成 R/S/T | 经济 | 漏怪致死 | 对塔伤害 | 一句话 |

| `n` | **常规** | 1.00 | 1.00 | 40/40/20 | 1.00× | 1.00× | 1.00× | 基准，不作弊 |

| `s` | **潮涌** | **1.45** | 1.00 | 55/35/10 | **1.45×** | **1.45×** | 0.87× | 峰：钱最多，也最容易死 |
| `b` | **铁壁** | 0.65 | 1.10 | 15/25/60 | 0.65× | 0.65× | **1.59×** | 少而重甲：**拆你的塔** |
| `t` | **涓流** | **0.40** | 1.05 | 10/30/60 | **0.40×** | 0.40× | 1.58× | 极稀重甲：钱几乎断流 |
| `e` | **处刑** | 1.00 | 1.15 | 40/40/20 | 1.00× | 1.00× | 1.00× | 峰 + 精英（2.5× HP） |
| `E` | **处刑·基准** | 1.00 | 1.00 | 40/40/20 | 1.00× | 1.00× | 1.00× | 仅 0-1 用：与金标本逐位等价 |

三种峰谷的失败方式完全不同，这是本表最重要的一栏：

- **潮涌**：`n` 大到 39–55 只，漏 37% 就死。它问的是"**你的总 DPS 够不够在它们走到核心之前清完**"—— 一场纯粹的清场速度考试。
- **铁壁 / 涓流**：`n` 只有 6–23 只，**全漏也打不死你**（≤ 1000）。它不考清场，它考**塔的存活**：1.59× 的对塔伤害会一座一座拆掉你的输出，拆到某波你突然清不动了 —— 慢性的、延迟的失败。
- **处刑**：`n` 不变，但 2.5× 血量的精英分散在波内，等于把同一波血量压在少数几只身上。**在聚合池模型下这和常规波没有区别**（§1），它唯一的真实作用是精英的 `sapper` 锁塔增伤 —— 所以处刑波的压力也落在"塔"上，而不是"手速"上。

> 🟡 **诚实说明：`b` 与 `t` 在机制上是同一个型的两档。** 两者 comp 都是 60% 重甲，归一化后的单只乘数几乎相同（m_hp 0.302 vs 0.303），差别只在 `n`（0.65 vs 0.40）与血量偏置。保留两个名字是因为叙事不同（铁壁=重装推进，涓流=零星渗透），但**不要指望它们在战斗里手感不同** —— 它们只是"钱更少"的两个刻度。若要它们真的分化，得先有 §1 里缺的那两件事。

## 3. 守恒律：整关总血量不变

### 3.1 为什么必须是"整关守恒"而不是"逐波守恒"

逐波完全守恒的话，波表就退化成纯换皮（总血量、只数、塔损三样都可以被算死）。而一关的难度感来自**峰谷**。所以取中间档：

```
约束：Σ(本关所有波的总血量) ≡ Σ(基准曲线同波数)      ← 硬约束，误差 0
自由：单波总血量可±25% 起伏                            ← 峰谷
```

这样改波表**不会改这一关的难度总量**，只改它的节奏形状。任何"这关变难了"的反馈，都能确定是形状（而不是总量）造成的 —— 这是本项目"金标本零扰动"纪律在关卡层的延伸。

### 3.2 算式（可直接实现）

```
n_w   = max(1, round(n_base(w) × n_mult))              # 只数由波型定
raw_w = n_base(w) × hp_base(w) × hp_bias                # 本波"想要的"血量
k     = Σ base_w / Σ raw_w                              # 整关归一化（唯一全局量）
hp_w  = raw_w × k / n_w                                 # 反解单只血量 → 总血量精确守恒
```

`k` 是唯一的关级参数，取值 0.90–1.00（因为波型的偏置均值略大于 1）。它保证**你不看表也能确定：这关的总血量没变**。

## 5. `S` 的修订（v2.1 纠错）

### 5.0 为什么必须改

上一版写的是 `wave_count = 基线 + floor(S/2)`。当时没算，现在算了：

| `S` | 加波 | 同关**末波**单只血量倍率 |
|---|---|---|
| 0–1 | +0 | 1.00× |
| 2–3 | +1 | **1.42×** |
| 4–5 | +2 | **2.02×** |
| 6–7 | +3 | **2.86×** |

因为 `hp = 16 × 1.42^(w-1)`，**加一波就是末端贵 42%**，而且加的是最末尾那几波（曲线最陡的地方）。S=7 的玩家打同一张 1-1，会比 S=0 的玩家多面对近 3 倍的末波血量 —— 这不是"难度递增"，这是**同一关换了个 Boss**。

同时它还破坏了本份文档最重要的性质：**波表是闭合的**。如果波数会变，那"12 波的波表"就只是"前 12 波"，第 13、14 波没有形状可依，只能回落到金标本常规波 —— 又变回"每关都一样"。

### 5.1 新机制：`S` 换形状，不换长度

```
k = floor(S / 3)            # S = 0..2 → 0 ; 3..5 → 1 ; 6..7 → 2
```

| 派生 | 规则 | 通道 |
|---|---|---|
| **喘息波升级** | 该关**最早 k 个**「试探」波 → 升级为「潮涌」 | 只数 ↑：经济 ↑ **且** 漏怪致死 ↑ |
| **处刑加压** | 处刑波的精英只数 `+k`（上限 `floor(n/4)`） | 精英 2.5× HP 集中度 ↑、sapper 锁塔 ↑ |
| **波数** | **不变**（= 该关波表长度，完全闭合） | — |
| **单只血量** | **不变**（整关守恒照旧） | — |

三个好处，一个比一个重要：

1. **压力与收益同源。** 潮涌波 1.45× 废料 —— 玩家救得越多，统序投的单元越多，**他也就越富**。"救得多 = 被惩罚"的失败信号 C 被同一个机制顺手解决，不需要再加一个"每区 +5% 废料"的补丁。
2. **没有断崖。** 精英从 2 只变 3 只是 50% 的增量，但作用在单一波上；潮涌化一个试探波是 2.07× 的只数增量，作用在波表里唯一一个谷上。两者都是"某个波更难了"，而不是"整个末尾 ×2.86"。
3. **效果按关自然衰减。** 8-1 的波表里**一个试探都没有**（它本来就无喘息），所以它对 `k` 的唯一反应是"处刑精英 +k"。这不是漏洞，是设计：**打到 8-1 的玩家 S 必然 ≥5，它已经在加压的终点了。**

各型的单只乘数（comp 归一化后的结果，供 `_build_spawn_table` 直接用；40/40/20 时三列分别为 `M_HP` / `M_SPD` 原值，即金标本口径）：

> 归一化口径：`k_hp = 1 / Σ(p·M_HP)`、`k_spd = Σ(p/M_SPD)`。前者保 **C-1 总 HP 守恒**，后者保 **C-3 在场时间守恒**。`M_DPS` **故意不归一化** —— 它就是"重甲占比 → 对塔伤害"这条通道本身，归一化掉等于废掉 B 通道。

```gdscript
# 单只乘数 = 基值 × 归一化系数（40/40/20 时系数恰为 1.0000 → 逐位等于 MonsterData）
static func proto_mult(comp: Dictionary) -> Dictionary:
	var kh := 0.0
	var ks := 0.0
	for p in comp:
		kh += float(comp[p]) * float(_MonsterData.M_HP[p])
		ks += float(comp[p]) / float(_MonsterData.M_SPD[p])
	var hp := {}
	var spd := {}
	for p in comp:
		hp[p] = float(_MonsterData.M_HP[p]) / kh
		spd[p] = float(_MonsterData.M_SPD[p]) * ks
	return {"hp": hp, "spd": spd}
```

处刑波的精英只数**必须**沿用引擎现有的那条式子，不许另造一个新的：

```
elite = clamp( max(2, round(0.10 × n)) + k , 2 , floor(n / 4) )     # k = floor(S/3)，仅 e 加、E 不加
```

> 🔴 为什么强调：0-1 的锚点等价性就卡在这里。第一版草稿用了 `2 + floor((w-1)/7)`，在 0-1 的 W10（`n=24`）算出 3 只，而 `MonsterData.elite_count` 给的是 2 —— **一只精英的差就让 0-1 不再逐位等于金标本**。附带一个必须一起改的点：`elite_conserve(n, n_e) = (n − 2.5·n_e) / (n − n_e)` 对任意 `n_e` 都保总血量守恒（`n_e·2.5 + (n−n_e)·c ≡ n`），所以**加精英不需要另配血量补偿**，但 `n_e` 必须 `< n / 2.5` 否则 `c` 会变负（`n=24` 时是 `n_e ≥ 10`）—— 这就是 `floor(n/4)` 上限的来源（0.25n 远离 0.4n 的临界）。

`_elite_count_wave()` / `_is_elite_wave_at()` 是防漂移的单一入口：

```gdscript
func _elite_count_wave() -> int:
	if not elite_waves_enabled:
		return 0
	if not cur_spec.is_empty() and not bool(cur_spec.get("neutral", false)):
		return int(cur_spec.get("elite", 0))          # 波表说了算（含 S 加压）
	return _MonsterData.elite_count(w, n)             # 无表 → 金标本 w%5 周期

			return int(sp.get("elite", 0)) > 0
	return _MonsterData.is_elite_wave(pw)
```

### 8.3 纪律（违反任何一条，本轮改动作废）

- 🔴 `stage_waves_enabled` **默认 false**。默认路径与改前**逐位相同** —— 这是本项目所有新机制的入场条件（同 `prototype_split_enabled` 的处理）。

### 11.6 这一轮最重要的方法论教训

`probe_stage_death.gd` 最初把 `rng` 建在循环**内** → 每局同一条随机流 →「24 局」实为**同一局跑 24 次**。
于是把一个 n=1 的读数当成了通过率，一度得出"难度双稳态、没有中间带"的错误结论，
并差点据此停掉波表修改。修好后同一版本是 27.5%（11/40），与 MC 的 36% 一致。

> **任何"通过率"读数，先确认 rng 在循环外、且 n ≥ 40。** 这条比任何设计结论都值钱。

**教训二（同一天晚间补）**：镜像**少实现一个产品开关**，整张表会**同向偏移**，而偏移量小到
单波看不出来（P4：30 个探针只有 3 个变，每次只差 2~3 只怪），大到整关能差 32 个百分点
（6-1：36% → 68%）。原因是**漏怪预算只有 20 只**——低幅但持续的偏差会被累积放大。

> **顺序铁律：先证镜像 == 真身（全开关 × 全关卡 × 多波），再读难度。**
> 探针要报"效果量"，不只是报"`|d|=0`"——`|d|=0` 只说明两边一样，不说明这个开关重不重要。

### 11.8 真身端到端：MC 曲线不是玩家难度（2026-11-09）

前面所有读数都来自**批处理镜像**。镜像与真身只在**单波**上做过逐位对拍（SW7/SW8），
**没有任何东西验证过"真身能从 W1 走到这关最后一波"**。本节补这一段，用的是真引擎真帧：

```
<godot> --headless --path . --script res://tests/playtest_driver.gd -- stage <关卡 id>
```

驱动照搬 `boot.gd` 的三步注入：`set_stage(sid, S)` → `set_active_packs(已守 ∪ 借用)` →
`start_new_run()`；自动打法是"能买就买、买完就摆、每波安全窗修复所有停机塔"。

| 关 | 波 | 卡池 | 实机结果 | 残血 |
|---|---|---|---|---|
| 0-1 | 10 | core（10 张） | 通关 | 95% |
| 2-1 | 12 | core + rime（20 张） | 通关 | 100% |
| 6-1 | 16 | core + cinder + rime（30 张） | **改前：W14 十塔全灭、核心 1000→0** · 改后：通关 | 0% → 80% |
| 8-1 | 19 | 3 包（30 张） | 通关 | 100% |
| 9-1 | 20 | 3 包（30 张） | 通关 | 95% |

**读数一：MC 的绝对读数不能当玩家难度。** 实机的塔上限是 `tower_cap = 10`（镜像 MC 是
`n_slots = 6`），卡池是 3 包 30 张（镜像是金标本 7 张），落子是**自由摆放**（镜像是 6 个固定槽）。
三个差异叠加后，同一关在真身里几乎不掉血，在镜像里却只有 26–68%。→
**镜像曲线的用途只剩"关与关之间的相对次序"，不是"这一关玩家会不会过"。**

**读数二（真缺陷）：战斗内复活在实机上等于没开。** 6-1 W14 处刑波一次打停 10 座塔，
诊断是 `revive_diag = {fired: 0, elig: 0, refused: 10, nonexp_death: 7, carry_death: 3}`
—— **没有任何一座塔获得复活资格**。根因是资格闸门硬依赖 `is_exposed`，而：

- `is_exposed` 的判据是 `expo_frac = asin(R/d)/π ≥ EXPO_SAFE_MAX(0.15)`；
- 17 格阵地的 r 全落在 **18–42**，`expo_frac` 全挤在 **0.073–0.159** → **17 个格心只有 1 个**算暴露位；
- 镜像用的 `Geo6.SLOTS6` 是 **4/6 暴露** → 镜像里复活总能成交，实机里几乎永远不成交。

于是实机每一次塔被打停都是**本波永久损失**：处刑波打停全场 → 输出归零 → 20 只漏怪预算
（1000 ÷ 50）在一波内用完 → 核心归零。这就是"要么零伤害、要么瞬间死"的锯齿来源。

**处方（已落地）**：给阵地几何单独标定阈值 —— `EXPO_SAFE_MAX_SITES = 0.085`，由
`PathGeometry.expo_safe_max_for(sites_active)` **唯一分派**；8 槽口径 `0.15` 一字不动
（AC-S6-3 的 4 暴露 / 4 安全仍成立，回归里 E-S1/E-S6 守着）。标定依据不是凑数：
