## 1. 系统目标（System Goal）

### 1.1 一句话

> 卡牌是玩家**唯一的输入物**。它必须把「空间配置」（放哪）与「投资分配」（投给谁）两种决策，压缩进一次点击。

### 1.2 与支柱的兑现关系

| 支柱 | 本系统如何兑现 | 若不满足则 |
|---|---|---|
| **P1 不动如山** | 建筑卡落**塔位**（空间决策）；单塔效果卡落**具体某座塔**（归属决策）。玩家从不操作单位 | 若卡牌需要"对单位下令" → 违反 P1 |
| **P2 雪崩无上限** | 单塔效果卡提供**深度复利**（`×(1+κ)^n`，单核引擎）；建筑卡提供**广度复利**（共鸣 `E_i`，多塔引擎） | 若两类卡都只是加法 → 起飞数学不成立（v0.3 已实证） |
| **P3 每局一个新解** | 三类卡的**稀缺维度互不相同**（塔位 6 / 强化槽 5 / 全局槽 3）→ 投资决策是三维取舍；Tag 档位决定复利率 | 若某类卡在所有局面下都最优 → 主导策略 |
| **P4 决策而非动作** | 每张卡都是**不可逆的取舍**（弃卡降层、拆塔销毁、塔位不可逆） | 若卡可无痛重来 → 决策退化为假选择 |

### 1.3 本系统的三条设计红线（自检用）

| # | 红线 | 出处 |
|---|---|---|
| 🔴 C-1 | **每张单塔效果卡都必须「可叠且叠了有用」** | R11 卡池第一红线 |
| 🔴 C-2 | **全局效果卡禁止叠层复利**（只能饱和/加法） | 本 GDD 新增，见 §2.4 |
| 🔴 C-3 | **商店只标事实，不标推荐** | §2.1 C2 / Discovery 美学 |

### 1.4 🆕 🔴 塔移除的反通胀红线（T-R1 / T-R2）

> **出处**：`mechanics-tower-life-death` **v1.0 定稿 §1.5**（该节给出完整的通缩三步数学证明：① 退币非铸币 ② 单次「买塔 12 → 卖塔返 6」循环净亏 6 分、严格亏损 ③ 同一座塔只能被移除一次、不可重复套利）。**本 GDD 只登记红线本身**，供卡池扩展（T1）时自检。

| # | 红线 | 理由 |
|---|---|---|
| 🔴 **T-R1** | **任何情况下，塔移除的返还系数 ≤ 100%，且不得存在「买入折扣」与「移除返还」同时生效的组合** | 一旦 `买入价 × 折扣 < 返还价`，上述第 ② 步的"严格亏损"被翻转 → 出现**无限套利环** → 经济崩溃 |
| 🔴 **T-R2** | **不得新增任何"以移除塔为触发条件的铸币效果"**（如"每拆一座塔 +10 分"的全局卡） | 它把"退币"变成"铸币"，直接绕过 **M5「局内唯一货币 Scrap 仅从击杀获得」**（概念 §2.1），且会与 **G1 回收协议**（击杀积分 +50%）叠乘 |

> ✅ **MVP 生效范围**：仅**主动移除（`Salvage`）分支**受此二条约束（返还 **50%**，Q-C3 原文）。
> 🔒 **被动移除（`Destroyed`）分支**（返还 **0%**）**实现进 T1**，届时**同样受 T-R1 / T-R2 约束** —— 本条即刻登记，防止 T1 卡池扩展时开出"送死套利"（把塔放最暴露位让它被打死换钱）。

## 2. 核心机制（Core Mechanics）

### 2.1 分类树（唯一权威定义）

```
卡牌 Card
│
├─ 建筑卡 StructureCard            【落塔位 · 不占强化槽 · 可叠层 → 塔等级/谐波层】
│   ├─ 用法A 新建 Found  → 占 1 个空塔位，生成该原型塔 Lv1
│   └─ 用法B 升级 Upgrade → 选一座场上已有的同原型塔，level +1（= 谐波层 h_j +1）
│
└─ 效果卡 EffectCard
    ├─ 单塔效果卡 TowerEffectCard  【装配到具体某座塔 · 占强化槽(5) · 叠层复利】
    │   └─ 装配目标 = 主塔(默认) 或 玩家点选的任意塔
    └─ 全局效果卡 GlobalEffectCard 【全场生效 · 不占强化槽 · 占全局槽(3) · 饱和不自叠复利】
```

### 2.2 与概念文档 M7 的映射（**本 GDD 的核心对齐表**）

| 用户的新术语 | M7 旧术语（概念文档） | 落点 | 占什么槽 | 复利形式 |
|---|---|---|---|---|
| **建筑卡** | 塔卡 | 塔位（6） | ❌ 不占强化槽 | `∝ level^0.6`（次线性）+ 向链接塔供 `h_j` |
| **单塔效果卡** | 强化卡 | 具体某座塔 | ✅ 强化槽（5） | `×(1+κ)^n`（指数） |
| **全局效果卡** | 经济卡 + 全局 Buff | 全局 | ✅ 全局槽（3）🆕 | 饱和 / 加法（**禁止复利**） |

> ✅ **映射是 1:1 的，没有卡被重新归类，也没有卡被凭空创造。** 用户提的「挂件」不是一类卡，而是**塔的一种状态**（见 §2.3）。

### 2.3 「挂件」的正确落点（对用户原话的解读与澄清）

**用户原话**：「建筑卡可以在场上放置一座防御塔，其他的作为挂件，或者升级多座防御塔。」

这句话有两种解读，我**明确采用解读 A** 并说明理由：

| 解读 | 内容 | 我的判断 |
|---|---|---|
| **A（✅ 采用）** | 建筑卡放下塔；该塔**之后投不投单塔效果卡**决定它成为主塔还是挂件；重复买到建筑卡用于**升级**塔 | **挂件是涌现状态，不是卡的固有属性** |
| B（❌ 否决） | 建筑卡本身就分「主塔建筑卡」和「挂件建筑卡」两种 | 会把"挂件"写死卡的固有属性 → **剥夺涌现性**，直接违反 §2.4.2「主塔是涌现的，不是声明的」，也让玩家失去"这局临场决定哪座塔是主塔"的自由 |

**落地规则（沿用 §2.4.2，零新增）**：

| 塔的状态 | 判定 | 说明 |
|---|---|---|
| **主塔 `CoreTower`** | `argmax(该塔的单塔效果卡层数)` | **自动判定，涌现**；塔顶徽章 + 底座发光 |
| **挂件塔 `AuxTower`** | 单塔效果卡层数 = 0（或远低于主塔） | 价值来自基础功能：减速 / 光环 / 凑 Tag / 占位 / 供谐波层 |
| **副塔** | 层数 > 0 但非最高 | 多塔流的主体 |

> 🎨 **给林绘澄的卡面提示（可选，不强制）**：建筑卡卡面可标注一个**客观的角色倾向**（`主塔向` / `挂件向` / `通用`），例如 Frost 标"挂件向"。
> ⚠️ 这是**塔原型的客观属性**（Cannon 就是 AoE、Frost 就是减速），**不是系统替玩家算出的最优解** → 不违反 C-3「只标事实不标推荐」，且能显著降低 R10 认知过载。

### 2.4 🔴 全局效果卡为什么禁止叠层复利（本 GDD 最重要的一条设计判断）

**问题**：用户说"效果卡可以针对全局生效"。如果照搬单塔效果卡的 `×(1.10)^n` 复利给全局卡，会发生什么？

| 维度 | 单塔效果卡 | 若全局卡也复利 |
|---|---|---|
| 占的槽 | 强化槽 5（**有上限**） | 全局槽 / 无上限 |
| 占的塔位 | 需先有塔（**有前置成本**） | 不需要 |
| 装配风险 | 投错塔 = 沉没（**有决策风险**） | 无风险，买了就全场生效 |

→ **全局卡复利 = 一台零成本、零风险、无上限的第三台雪崩引擎。** 玩家最优解会退化成"无脑刷全局卡" →

- ❌ 违反 **P2**「失控必须被 earned」—— 免费送的爽不算爽；
- ❌ 违反 **P3** —— 卡位 5 槽这个刹车被绕过；
- ❌ 违反 **§2.4.7** —— 刚刚花大力气把 Tag 的杠杆放大到 ×40.6，一个全局复利会把它重新稀释成噪音。

**✅ 本 GDD 的定义**：全局效果卡是「**油门**」，不是「**引擎**」。

- 它的价值是**让玩家更快到达起飞点**（更多积分 = 更多刷新 = 更快凑够 Tag / 更快深叠），
- 它**不直接产出指数输出**。

> 用一句话说：**经济卡缩短你"earn"的时间，但不替你"earn"。** 这样 P2 的「earned」与 P3 的「刷商店张力」同时保住。

**实现形式**：统一采用 **饱和曲线**（与 v0.4 已验证的 `Aux` 模型同族，复用参数、无需重新扫参）：

```
effect(n) = cap × (1 - e^(-n / τ))        τ = 8（默认），cap 见逐卡定义
```

> 饱和曲线的三个好处：① 叠了有用但**边际递减** → 天然自限，不需要额外槽位上限；② 第 n 张的收益 UI 可直读（"再买一张 +4%"）→ 支撑 C-3 的"只标事实"；③ 与 v0.4 的 `aux_tau=8, cap=1.5` **同一参数族**，程基岩可直接复用代码。

### 2.5 三类卡各自的「投资标的」与「指数出口」（与塔 Build 分支的咬合）

> 这是 §2.4.4 两条主干的**直接延伸**：每条主干必须有自己的复利标的，否则必然坍缩（R9 已实证）。

| 塔分支 | 主要买什么卡 | 复利引擎 | 数学形态 | 天花板（刻意保留） |
|---|---|---|---|---|
| **单核流 `MonoCore`** | **单塔效果卡**（集中投主塔） | `Stack` 深度复利 `×(1+κ)^n` | **指数** | 并发数=1 → 撞数量墙，**怕海** |
| **多塔流 `Distributed`** | **建筑卡**（铺塔位 + 升级提 `h_j`） | `Resonance` 广度复利 `(1+κ_r)^E_i` | **一次投入被放大 k 次 → 指数** | 塔挤一起 → **怕分流/多路径** |
| **挂件（修饰层）** | **建筑卡**（Frost/Beacon 升级） | `Aux` 饱和乘区（v0.4 已打开，cap 1.5） | **饱和（非指数）** | cap 1.5 → MVP 挂件是"地基"不是"引擎"（其指数出口 `Empowerment` 按 Q11 留 T1） |

**咬合结论（三条，必须写进 GDD 的原因）**：

1. **单塔效果卡服务"主塔"**：它是指数引擎，但**只有集中投入才吃满利率**（κ 见 §5.2）。分散投 → 利率掉档 → 这正是"集中 vs 分散"张力（张力来源 5）的**数值表达**。
2. **建筑卡服务"多塔流"**：建筑卡的直接收益 `∝ level^0.6` 是**次线性**的（深叠单塔会衰减），但它的**谐波层 `h_j` 向所有链接塔供 `×(1+κ_r)` 是指数的** → **一次投入被放大 k 次**。这就是"多塔 = 用放大倍数 k 换更低单层利率"的机制化。
3. **建筑卡服务"挂件"**：Frost/Beacon 的**建筑卡层数**喂 `Aux` 饱和乘区（v0.4 已打开）→ **挂件塔在 MVP 就有自己的投资出口**，不需要等 T1 的 `Empowerment`，Beacon 不会沦为废卡。

> 🟢 **一个额外的正向发现**：v0.4 报告说"理性贪婪 AI 两条路径都不主动建 Frost，故 Aux=1.00，这是 AI 不建而非 Aux 失效"。
> 在新分类下这变成了**一个可被设计主动引导的决策** —— 建筑卡卡面标"挂件向"+ 商店高亮 `Aux` 预估收益数字，玩家就有理由主动建 Frost。**这是本分类带来的、v0.4 尚未验证的一条新收益，建议列入试玩观察项。**

## 3. 数据模型（Data Model）

### 3.1 卡牌基表 `CardDef`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | String | 唯一标识符 |
| `kind` | Enum | `Structure` / `TowerEffect` / `GlobalEffect` |
| `name_zh` / `name_en` | String | 展示名 / 代码名 |
| `tags` | Array[Tag] | MVP：`Fire` / `Frost`；建筑卡可为 `[]`（中性，不计入 Tag 池） |
| `price` | Int | 建筑 12 / 单塔效果 9 / 全局 10（§8.1 沿用） |
| `stackable` | Bool | 建筑卡 `true`（=塔等级上限受软 cap）· 单塔效果 `true` · 全局 `true` |
| `compound` | Enum | `Exponential` / `Additive` / `Saturating` |
| `params` | Dict | 见 §3.2–3.4 |
| `tower_role_hint` | Enum | 仅建筑卡：`Main` / `Aux` / `Flex`（**卡面客观标注，非推荐**） |

### 3.2 建筑卡 `StructureCard`

| 字段 | 说明 |
|---|---|
| `prototype` | `Arrow` / `Cannon` / `Frost` / `Beacon` |
| `base_dps` | 原型基础 DPS（Lv1） |
| `level_curve` | `DPS = base_dps × level^0.6`（**次线性**，v0.3 §8.2 定稿） |
| `harmonic` | **`h_j = level_j`** —— 塔 j 的建筑卡层数即其谐波层数（M17） |
| `resonance_gate` | `h_j ≥ 3` 才把 `(1+h_j)` 计入邻居的 `E_i`（v0.4 定稿"共鸣门槛 Lv3"） |
| `tag` | 原型 Tag：`Cannon = 🔥Fire` / `Frost = ❄Frost` / **`Arrow` 与 `Beacon` = `null`（中性，无 Tag）** |
| `kr_basis` 🆕 | 该塔的 `κ_r` 取档依据 —— **MVP：以 flat `0.050` 全场统一施加，中性塔同值 `0.050`**（§5.4 / §5.4.1）。原「无 Tag / 中性塔恒取基准档 `0.045`」是**档位制补丁**，MVP flat 制下**作废**，保留为 **T1 若恢复按 Tag 取档时的扩展位** |
| 特殊 | `Frost` 自带减速 30%；`Beacon` 0 DPS，提供 `Aux` 光环乘区 |

> 🔴 **给程基岩的实现要点（v0.2 新增）**：`κ_r` 的档位输入是「**Tag 投入层数**」，而共鸣的驱动者是「**谐波层 `h_j`**」—— **两者不是同一个量**。v0.4 定稿多塔 B 的共鸣主引擎是无 Tag 的 `Arrow(h=133)`。若不给无 Tag 塔打这条恒取基准档的补丁，它会被永久钉在最低档 → 工程实测 W20 仅 `0.16`（定稿 `1.66`），**直接起飞不了**。
> 🆕 **v1.1.1 口径**：**MVP 以 flat `0.050` 全场统一施加 → 中性塔同值 `0.050`**，上述"被钉在最低档"的风险在 **MVP flat 制下不存在**；该实测是**档位制**下的对照，保留为 T1 若恢复按 Tag 取档时的依据。

### 3.3 单塔效果卡 `TowerEffectCard`

| 字段 | 说明 |
|---|---|
| `host_tower` | 装配目标塔的引用（**必填，不可为全局**） |
| `stack_n` | 该卡在该塔上的层数 |
| `compound` | `Exponential`（吃 κ 复利）/ `Additive`（加法可叠，有饱和 cap）/ `Saturating` |
| `kappa_source` 🆕 | **不逐卡存利率**。κ 由 `κ_tag`（该卡所属 Tag 的档位基准利率，§5.4）与**本局历史最大塔数 `N_tower_histmax`** 共同决定，是**逐塔当前值**（§5.2）；🆕 **v1.1.5 兜底①**：`N_tower_histmax` **只增不减** → **仅"新建塔刷新历史最大值"时全场重算，拆塔不改变 κ**（E11） |
| `slot` | 占用 1 个强化槽（**5 槽 = 5 个"卡种"槽，不是 5 层** —— 见 §3.6） |

### 3.4 全局效果卡 `GlobalEffectCard`

| 字段 | 说明 |
|---|---|
| `scope` | `Global`（全场 / 全局经济 / 全局上限） |
| `stack_n` | 层数 |
| `compound` | **强制 `Saturating` 或 `Additive`，禁止 `Exponential`** 🔴 |
| `tau` / `cap` | 饱和参数（默认 `tau = 8`） |
| `slot` | 占用 1 个全局槽（**3 槽** · **Q-C2 已定稿** ✅） |

### 3.5 运行时状态

```
Run {
  towers:      Array<Tower>          // ≤ 塔位数 6
  enh_slots:   Array<TowerEffect>    // ≤ 5（每格 = 1 个卡种 + 其层数 + 宿主塔）
  global_slots:Array<GlobalEffect>   // ≤ 3（Q-C2 定稿 ✅）
  pending_structure: Array<Card>     // 🆕 待放置建筑卡队列（见 §4.2）
  scrap:       Int
}
Tower {
  prototype, level(=h), coverage_score,
  attached: Array<TowerEffect>,      // 装配到本塔的效果卡
  links: Array<Tower>,               // 射程重叠自动建立
}
```

### 3.6 🔴 必须澄清的一条口径：**「5 槽」是 5 个卡种，不是 5 层**

> 这是实现时最容易写错的一处。
> 同一张单塔效果卡**反复购买 → 层数 +1 → 不占新槽**。5 槽意味着玩家最多同时**持有 5 种**单塔效果卡，而非最多 5 层。
> 否则 5 层就满、复利根本叠不起来（`1.10^5 ≈ 1.6×`，与 §8.2 目标 `1.10^100` 相差 4 个数量级）。

## 4. 交互流程（Interaction Flow）

### 4.1 购买三路径（输入次数是硬指标）

| 卡种 | 流程 | 输入次数 | 备注 |
|---|---|---|---|
| **单塔效果卡** | 点击购买 → **默认直接投给主塔** | **1 次** | 若玩家已点选了某座塔 → 投给该塔。装配切换 = 点击槽位上的卡再点塔（共 2 次） |
| **全局效果卡** | 点击购买 → 立即全场生效 | **1 次** | 零后续操作 |
| **建筑卡** | 点击购买 → **入「待放置」队列** → 玩家择机点图标进入放置模式 → 点目标 | 2 次（可分时进行） | 见 §4.2 |

### 4.2 🆕 建筑卡的「买 / 放」解耦（本 GDD 新增，为实时化服务）

> **问题**：商店是**不暂停**的（方案 D）。若"买建筑卡"立刻强制进入战场放置模式，会形成「商店 → 战场 → 商店」的**焦点跳跃**，直接加剧 R5′（手忙脚乱）与 R6（可读性）。
>
> **✅ 解法**：把「买」与「放」拆成两个动作。

```
[购买] 建筑卡 → 进入 HUD 上的「待放置队列」（右下角蓝图图标，显示张数）
                  ↑ 此时不占塔位、不进战场，玩家可继续刷商店（0 决策压力）
[放置] 玩家点队列图标 → 进入放置模式（全局自动降到 0.25×，比商店的 0.35× 更慢）
        → 战场自动高亮所有合法目标：
            · 空塔位  → 绿光脉冲（= 新建）
            · 同原型塔 → 金光脉冲（= 升级，显示 Lv_n → Lv_n+1）
        → 单次点击落子 / Esc 取消（取消不退款，卡留在队列）
```

- **为什么这符合 P1**：放置塔是**建造**，属于 build 层，不是"操作单位移动/释放技能"。玩家依然从不碰任何一个单位。
- **为什么这缓解 R5′**：玩家永远可以在**自己选择的时刻**才去放置，实时压力被完全拿掉。
- ⚠️ **放置模式的减速口径需程基岩确认**：建议复用 `DilationBudget`（同一预算池，不新增资源），但倍率取 `0.25×`（与 W1–W5 新手保护一致）。

### 4.3 重决策区：卸下 / 弃卡 / **塔移除**（= **拆塔** = **售卖 `Salvage`**）（**仅在波次间安全窗**）

| 操作 | 代价 | 依据 |
|---|---|---|
| **卸下**单塔效果卡（换宿主塔） | 该卡 **降 1 层** | Q8 / §2.4.2 已定 |
| **弃掉**整张单塔效果卡（腾槽） | 该卡及其**全部层数**销毁，槽位释放 | §5 MVP「满槽需弃卡（不可回收）」 |
| **塔移除结算器**<br>`TowerRemove(tower)`<br>（✅ **售卖 ≡ 拆塔**） | 🆕 **术语统一（Q-T1 = A′ 已定稿）**：「售卖」与「拆塔」是**同一个动作、同一套规则、同一个确认弹窗**，只是玩家侧的叫法不同 → **UI 统一为「拆除并回收 `Salvage`」**。<br>**· 主动移除 `Salvage`（玩家发起 · ✅ MVP）**：返还 **50% 累计投入**（该塔累计的建筑卡分 + 装配卡分，向下取整），该塔装配的**全部单塔效果卡及层数销毁**；🔴 **必须二次确认**；仅**波次间安全窗**可操作 —— 🔴 **Q-C3 原文，一字不改**。<br>**· 被动移除 `Destroyed`（被怪物摧毁 · 🔒 T1，此处仅登记口径）**：返还 **0%**；装配卡随 `Disabled` **冻结**（仍占强化槽）；玩家选择「拆除」时才按 Q-C3 **全销毁**。 | Q-C3 ✓ · 完整规则见 §7.2.2 · E8 / **E8-b** · §5.8 A16<br>出处：`mechanics-tower-life-death` v1.0 |

> ⚠️ **职责切分（§2.1 C3 铁律）**：战斗内只做**轻决策**（买 / 刷 / 锁 / 放置），波次间安全窗才做**重决策**（弃卡 / 卸下改投 / **塔移除** / 分支转型）。
> 🔴 **补充红线 T-C1（登记口径，出自 `mechanics-tower-life-death` v1.0 §2.2）**：**战斗内完全禁止任何与塔存活相关的操作**（不能修 / 不能卖 / 不能加固 / 不能撤退）。塔的损伤只用**运动 + 亮度**编码（余光可感知），🔴 **禁止**做成需要精确读数的数字血条。

### 4.4 状态变化后的重算链（工程交接要点）

```
建筑卡放置/升级 → level 变化
   ├─→ 射程可能变化 ──→ 🔴 链接重算（Resonance 几何判定，塔位/射程变化时触发）
   ├─→ h_j 变化 ─────→ 邻居 E_i 重算（含 Lv3 门槛判定）
   └─→ Frost/Beacon ──→ Aux 饱和乘区重算
单塔效果卡装配 → n_i 变化
   ├─→ StackMult_i 重算（含软 cap 分段）
   ├─→ Focus_i 重算
   ├─→ CoreTower 重算（argmax）
   └─→ AllIn 判定重算（主塔占比 ≥60%）
```
> ⚠️ **射程随等级变化 → 链接需重算**，这是 `Resonance` 最易漏的一处，务必交接给程基岩（概念文档 §11.4 已列为架构对齐项，此处再次确认）。

### 4.5 🆕 商店 pity 起飞保底（**Q-C6 方案① 的核心机制 · v1.0 定稿**）

> **为什么需要它（先说清因果，避免被当成"数值不够就加保底"）**：摘除 `synergy_mult = 1.5` 后，单核 A 的起飞率从 64.0% 掉到 **47.0%**（跌破 60% 红线）。`q-c6-verify.md` §3 实测：A 的失败**不是被平衡压下去的，是被发牌 RNG 压下去的** —— 300 局里被打爆的 110 局**全部**终局强化层数 < 10（整局没抽到几张 FireUp，深度引擎根本没启动），死亡波高度集中在 **W10–13 的起飞悬崖**（W11 独占 80 局）。
> → **真问题是「成败归因滑向运气」，直接违反概念 §4.1 的胜任感原则。** pity 保底是**修归因**，不是修数值 —— 这也是我选方案① 而非方案②（降 `hp_growth`）的根本理由。

#### 4.5.1 规则（定稿）

| 项 | 规则 |
|---|---|
| **触发范围** | **每波开始时生成的「初始商店」**（3 商品位）**必含 ≥1 张**与主塔同 Tag 的**单塔效果卡** |
| **手动 reroll** | ❌ **不保证**（reroll 后的商店为纯随机）。→ 保底只保证"每波**至少买得到 1 张**"，**不剥夺刷商店的张力**，G2 供应链（刷新 -50%）仍然值得买 |
| **占位方式** | 保底**改写 1 个未锁定的商品位**（把其中一个位替换为该 Tag 卡），**不额外增加第 4 个位**。若该波自然刷出已含 ≥1 张目标 Tag 卡 → **保底不干预**（不重复占位） |
| **与锁定的关系** | 🔴 **不得覆盖玩家锁定的商品位**（锁定是玩家已付代价的显性决策），保底只在未锁定位中改写 —— 见 E15 |
| **与 E9 的关系** | **E9 优先**：场上无塔时 pity 不生效（无宿主的强化卡无意义） |
| **生效时机** | 玩家做出**第一笔 Tag 投资**后的**下一波**起生效（理由见下） |

#### 4.5.2 兜底链：主塔未定 / 主塔无 Tag 时怎么办（**我定的口径**）

判定自上而下，**命中即停**：

| 序 | 条件 | pity 行为 |
|---|---|---|
| **P1** | **主塔存在**（`CoreTower = argmax(单塔效果卡层数)`，§2.3）**且该塔原型有 Tag** | 出 **该 Tag** 的单塔效果卡（在该 Tag 的 3 张中等概率随机） |
| **P2** | 主塔存在但**原型无 Tag**（`Arrow` / `Beacon`）**且全场已有 Tag 投入**（`max_Tag(L_tag) ≥ 1`，口径同 §5.4） | 出 **`argmax_Tag(L_tag)`** 的单塔效果卡。默认投主塔；玩家可先点选副塔再购买来改投（§4.1，2 次输入） |
| **P3** | 主塔存在但无 Tag，**且全场 Tag 投入为 0** | ❌ **pity 不生效**（商店全随机） |
| **P4** | **场上无塔** | ❌ **pity 不生效**（E9 优先） |

> **为什么 P3 定「不生效」而不是「随机选一个 Tag 保底」**：此时玩家**还没做出"这局走火焰还是冰霜"的决策**。保底若替他选，就是**系统替玩家定路线** → 违反 P4（决策归玩家）与 P3（每局一个新解）。
> 玩家只要买下**第一张**带 Tag 的效果卡（或建起第一座有 Tag 的塔），主塔即定、pity 从下一波起生效 —— **这是玩家自己的第一笔投资在回报他，不是系统在施舍。**

#### 4.5.3 两个细节（防「保底变成 0 收益 / 抖动」）

1. **排除已满卡**：若目标 Tag 的 3 张卡中有卡已达饱和 / 加法 cap（如 T5 霜蚀 60%、T2 超频 +80%），保底**只从仍有边际收益的卡中随机**（与 E7 同口径）。若 3 张全满 → 退化为该 Tag 任意一张，卡面标"已达上限 (+0%)"（见 E13）。
2. **平局排序**：`argmax_Tag` 并列时取**先达到该层数**的 Tag（稳定排序，同 E4 主塔平局口径，避免每波抖动）。

> 🔴 **给程基岩的确认点（§8 交接点 5）**：本 GDD 定的是「**仅初始商店保底、reroll 不保底**」。若 v0.3 已实现的 `pity` 是「**每次刷新都保底**」，则它会与 G2 供应链（-50% 刷新成本）叠乘 → 需重跑一次起飞率与 W20 倍数确认不过热（预计方向安全：A 起飞率更高，但雪崩倍数可能上抬）。**确认回来前 `shop-reroll` 按本 GDD 口径实现。**

#### 5.7.1 为什么「摘除」不等于「重标定」

| 观测项 | 实测值 |
|---|---|
| ×1.5 生效范围 | 单核 A 命中 **1** 座塔（有效 `×1.5000`）、多塔 B 命中 **4** 座（有效 `×1.4998`）→ **两条路径实质上 100% 的输出都吃到它** |
| 生效时机 | `fire` 塔建筑卡层数在 **W1 即 ≥3** → ×1.5 **几乎从第一波就在生效**（不是后期触发的局部增益） |
| 移除后的 DPS 比 | A `16,355,148 → 10,903,440`（**÷1.50000**）；B `3,949,421 → 2,633,250`（**÷1.49983**） |
| 数学等价性检验 | 「移除 ×1.5」≡「`hp_base ÷ 1.5`」：多塔 B **逐位复原**（W20 `7.886 → 7.887`，仅浮点截断）；单核 A 近似复原但 **+5.89%**（差异来自**经济反馈环**，非乘区） |

→ **它是一个「全局恒定的 ÷1.5」，对伤害侧已被其它系数完全吸收。** 这正是它在 v0.4 扫参时**完全隐形**的原因：只扫 `hp_growth` 根本看不出它的存在。

**✅ 因此定稿为「口径修正」而非「重标定」：`hp_growth = 1.42` / `hp_base = 16` / `focus_per_layer = 0.06` / `κ` / `κ_r` 一个都不改。**

**Tag 的作用改由三条路径表达（概念 §2.4.7 早已这么写，是引擎没跟上）**：

1. `κ_tag` 档位 → 单塔效果卡复利**基准**利率（§5.4）；

3. `StackCap` 档位 → 软 cap 上限（50 / 100 / 150，§5.2）。

> 🔴 **一句话给程基岩**：`Syn` 乘区**删除**；Tag 不再直接乘 DPS，只通过 `A6 TagTier → κ / κ_r / StackCap` 三条路径间接起作用。

> 🆕 **v1.1.4 术语统一（Q-T1 = A′ 已定稿）**：**售卖 ≡ 拆塔**。两者是**同一个动作、同一套规则、同一个确认弹窗**，只是玩家侧的叫法不同 → **UI 统一为「拆除并回收 `Salvage`」**。
> 本文档此后统一称 **`TowerRemove(tower)`（塔移除结算器）**，按**触发源**分为两个分支：

| 触发源 | 谁发起 | 时机 | 返还 | 装配卡 | 塔位 | 🔴 落地批次 |
|---|---|---|---|---|---|---|
| ✅ **主动移除 `Salvage`**（售卖 / 拆除） | 玩家 | 仅**波次间安全窗** + **二次确认** | **50% 累计投入**（Q-C3 原文，一字不改） | **全销毁**（Q-C3 原文） | 立即释放 | ✅ **MVP** |
| 🔒 **被动移除 `Destroyed`**（被怪物摧毁） | 系统 | 战斗中触发，**波次间结算** | **0%** | 随 `Disabled` **冻结**（仍占强化槽）；玩家选择「拆除」时才按 Q-C3 **全销毁** | **不释放**（`Disabled` 仍占位 → `N_tower` 不变 → κ 不变） | 🔒 **T1 —— 本 GDD 仅登记口径** |

> 🔴 **MVP 只实现「主动移除」分支**；下表为 **Q-C3 原文定稿规则，一字不改**。被动分支的**全部具体参数**（塔 HP / 仇恨半径 / 修复价格等）**设计已在 `mechanics-tower-life-death` v1.0 冻结、实现进 T1**，本 GDD **不承载其任何数值**。

**主动移除（`Salvage`）分支的定稿规则（Q-C3 原文）**：

| 项 | 定稿规则 |
|---|---|
| **返还** | 该塔**累计投入的 50%**（该塔花费的建筑卡分 + 其上装配的单塔效果卡分之和，向下取整） |
| **装配卡** | 该塔装配的**全部单塔效果卡及其层数全部销毁** 🔴（不可回收，与"弃卡"同口径 §4.3） |
| **塔位** | 释放，可再建新塔 |
| **重算链** | 🆕 **v1.1.5 兜底①**：`N_tower_histmax` **刷新（仅新建塔可刷新）** → **全场 κ 立即重算**（E11）；**拆塔不触发 κ 重算**；链接重算（E6）；`Aux` 重算；`CoreTower` 重算（E4） |
| **确认** | 🔴 **必须二次确认**（不可逆），弹窗列出"返还 **X** 分 / 销毁 **N** 张卡（共 **M** 层）" |
| **时机** | 仅**波次间安全窗**（§4.3 职责切分铁律：战斗内只做轻决策） |

> **为什么选「可拆 + 返还 50%」而不是「不可拆」**：
> ① 「不可拆」会让"建错塔"变成**不可挽回的沉没成本**，失败归因滑向"我开局点错了"，违反概念 §4.1；
> ② **50%（而非 100%）** 保留了 **P4 的不可逆性** —— 认赔要有代价，但代价可承受；
> ③ **「装配卡全销毁」让拆塔产生一个真实取舍**：拆掉一座深叠塔 = 放弃它的全部复利 → **"何时认赔"这个决策的来源正在于此**，而不是来自返还比例本身。

> 🔒 **被动移除（`Destroyed`）分支 · v1.1.4 登记口径**（🔴 **实现进 T1，MVP 不实现；本 GDD 不承载其任何数值**）：
> - **返还 0%**（被摧毁 = 颗粒无收）→ 与主动移除的 50% 形成**风险定价**：**主动管理回收一半，被动挨打颗粒无收**。
> - **装配卡**：塔 HP 归零 → 进入 **`Disabled`（停机）中间态**，装配的**单塔效果卡冻结保留、继续占着强化槽**；玩家在下一个波次间安全窗三选一 —— **修复**（花 `repair_cost`，HP 回满、**装配卡全部保留**）/ **拆除**（走本结算器，此时按 Q-C3 **装配卡全销毁**）/ **放着不管**（继续占位、不输出）。
> - **不算失败**：塔阵亡**不算失败**（沿用 **Q5**：只有核心 HP 归零才失败）；全塔 `Disabled` 也🔴 **不新增任何"塔"相关的失败判定** —— 它会**自然**导致漏怪 → 核心掉血。
> - **战斗内零操作**（红线 **T-C1**）：塔挨打 / 停机期间，玩家**不能**修、不能卖、不能加固、不能撤退。
> - **断输出不断链**：`Disabled` 塔**仍占 `N_tower`、仍供 `h_j`** → `κ` / `E_i` / `Crossfire` / `CoreTower` **全部不变**（保住 `κ_r = 0.050` 的标定基础），只需在 `Raw_i` 末尾乘一个 `Disabled_i ∈ {0.0, 1.0}` 的**结构性因子**（不进 7 乘区清单）。
> - 📌 **本分支的全部具体参数**（`HP0` / `AGGRO_R` / `repair_cost` 等）见 `mechanics-tower-life-death` **v1.0 定稿 §2**，均为 `PLACEHOLDER` 且**实现进 T1**。

## 11. 验收标准（本系统的，非全局）

1. ✅ 玩家能在**不看说明**的情况下说出"建筑卡放塔、效果卡要么给某座塔要么给全场"（试玩后口头提问）。
2. ✅ 10 局试玩中，**没有一张卡出现率为 0 或 100%**（主导策略审计的 MVP 版）。
3. ✅ 玩家至少有一次**主动弃卡或改投**决策，且能说出理由。
4. ✅ 全局效果卡的总贡献在终局 DPS 中**占比 < 30%**（验证"油门不是引擎"）。
5. ✅ 试玩中玩家能说出"我把塔放在一起会变强"（建筑卡 → 共鸣链路被感知，不需要能解释 `E_i` 公式）。
6. 🆕 ✅ **κ 折价是可感知的取舍，不是隐形陷阱**：玩家在建造第 3 座塔之前，能说出"建塔会让我的复利率下降"（验证 E11 的 κ 折价披露生效、R-C1 未发生）。若玩家事后才发现 → 触发 §5.2 兜底 2（④b 逐层锁定）。🔴 **v1.1.5 兜底①后本条是硬验收项**：折价**永久生效、拆塔不退**，E11 的折价预告必须同时披露"**建了就退不回来**"这一事实（C-3 事实标注），否则 R-C1 加剧风险无从观察。
7. 🆕 ✅ **pity 保底是"回报投资"而不是"施舍"**：玩家能在第 2–3 波说出"商店总会给我火焰卡，因为我这局在走火焰"（验证 §4.5 的 P1/P2 生效）。若玩家描述为"商店随机给我卡" → **保底的可读性不合格**，需给商店加"本波保底：🔥火焰"的**事实标签**（C-3 允许：只标事实不标推荐）。
8. 🆕 ✅ **塔移除（= 拆塔 = 售卖 `Salvage`）是可用但昂贵的反悔**：10 局试玩中至少出现 1 次塔移除，且玩家能说出"我认赔一半、换回一个塔位"（验证 Q-C3 ② 的 50% 返还产生了真决策，不是摆设）。补充：玩家能认出「拆除并回收 `Salvage`」这一个按钮即同时是"卖"与"拆"（验证 v1.1.4 术语统一未造成认知分叉）。
