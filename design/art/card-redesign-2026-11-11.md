# 守核 · 卡牌重制美术规格 · 2026-11-11

> 依据用户提供的一张「箭塔」整卡参考图，重做游戏内商店卡牌。
> 本文是**唯一风格来源与验收口径**；提示词、生成脚本、接线与测试都以本文为准。

## 0. 结论先行

1. **结论分档：重做**（结构层），不是小改。当前商店卡是「深底 + 白字压插画 + 细线框」，参考图是「金属斜切外框 + 深色插画区 + 米白信息区」三段结构，靠调色补不回来。
2. 本轮**只重做商店三卡**（视觉主体、玩家决策界面）；图鉴卡（320×126）与背包卡（120×132）尺寸不同族，列入第二批，只先统一色板。
3. 一套**通用卡框模板**服务全部 82 张建筑卡：框与装饰是静态贴图，卡名 / 价格 / 类型 / 描述一律字体渲染，稀有度与悬停用单层描边贴图 `modulate` 染色——不出 5 张稀有度框、不出 82 张整卡图。
4. 保持 `SLOT_SIZE = 210×340`、三卡同构、整卡点击购买、金标本与数值一律不动。

## 7. 验收标准

1. 缩到 10% 仍能认出「一张有米白下半区的卡」；转灰度后插画区与信息区明度可分（差 ≥ 4 档）。
2. 三张卡逐像素同尺寸、同结构；信息区所有文字对比度 ≥ 4.5:1，无溢出、无相互覆盖。
3. 82 张建筑卡任意一张都能套用本模板，不出现卡名截断失控或价格错位。
4. `--headless --import` 后 `run_shop_overlay_asserts` / `run_shop_interaction_asserts` / `world` / 默认全量回归退出码 0。
5. 窗口实机截图目检：框、插画、信息区、费用胶囊、徽章五要素齐全。
6. 顶部编号 / ▲ / 锁头 / ✓ / 价格不得因压在米白插画上而不可读；10% 缩略图下顶部功能带仍能与插画区分。

### 11.2 两处必须说明的取舍

**① 2 行摘要 vs §9.1「最小 16px」红线**
说明要求摘要 13–14px、最多两行。14px 的 Noto Sans SC 行高 24px，两行 = 48px；
若沿用 16px，两行要 48–50px，加上 28px 卡名（行高 41）与类型条，信息区至少要 113px
（卡高 33%），与「信息区约 30%」直接冲突。
→ 结论：**卡面按 14px 落地**，`_fixed_label()` 对 < 16 的字号做显式覆盖（`_Style.label()`
仍对 HUD 强制 ≥16）；`run_ui_style_asserts` 把「卡面类型/摘要」从 16px 判定中排除，
改为 13–14px 单独判定，其余 35 个 Label 继续守 16px。
→ **这是 §9.1 P0 的唯一例外，已在测试与本节双处标注；若策划不批，改回 16px 单行即可**
（把 `CARD_DESC_LINES` 设 1、字号 16，信息区高度回 92）。

**② 插画 70% 的口径**
卡高 340 里含上下外框（上 8、下 ~5），信息区 102px = 30%。因此插画窗只能到 220px
（整卡 64.7% / 内区 68%）。说明写「约 70%」，与参考图实测（插画 8–224、面板 228–330）一致，
差异来自外框算在谁头上；断言按**内区**判定，避免把框厚算成插画变窄。

## 12. v3.4 · 两个元件改走 AI 生图（2026-11-11，用户口径）

> 用户：「我用红线圈出中心和右上角的样式都不对，重新修改」→「用 AI 生图去做，不要程序化出图」。

### 12.1 产线（`tools/ai_badge_postprocess.py`）

1. **生成**：ImageGen，纯品红底（生成器实际输出带暗角的品红 ≈ 230,20,90），
   1024² / 1536×1024，prompt 用 §2 风格锚点 + 主体描述 + 画布 + 技术约束四段；
2. **抠图**：按色相判底（`r>135, g<100, 40<b<205, r-g>85`）转透明，硬边；
3. **裁边**：按 alpha bbox trim；
4. **合成**：`tools/gen_card_frame_v3.py::paste_ai()` 等比缩放后 alpha_composite 进 8x 超采样画布；
5. **双版本**：纯色底版留在 `output/imagegen/*_solid.png`（可复核），透明底版进 `art/2d/ui/ai/`。

生成时底部 15% 先裁掉——生成器在右下角压了「AI生成」水印，白字会让抠图出脏边。
