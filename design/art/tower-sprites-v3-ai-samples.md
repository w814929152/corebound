## 1. 为什么先出样张

上一轮 v2 用程序化产线补齐了塔贴图，胜在**尺寸统一、透明底、风格 100% 一致、
81+ 张可一键复现**；代价是几何感强、缺少材质质感。本轮改用图像生成模型补风格探索，
但存在三个必须先验证的工程前提：透明底能否直出、俯视剪影能否守住、缩到战场尺寸后还能否读清。
因此先各出一张，不直接铺量。

## 2. 三风格对照

| 风格 | Prompt 方向 | 源图 | 抠底归一 | 落地评估 |
|---|---|---|---|---|
| **A 蓝图几何风** | 正俯视八边形基座、冷钢蓝 + cyan 硬边线稿、细铆钉与刻度、一丝朱红 | `ai-v3-samples/…00-35-34.png` | `sp_tower_arrow_ai_a.png` | **最贴现行**：正俯视、八边形剪影、抠底干净。但斜向箭矢探出剪影，48px 下细节偏碎 |
| **B 厚涂 3D 质感** | PBR 拉丝金属、倒角装甲、发光内芯、戏剧化轮廓光 | `ai-v3-samples/…00-35-48.png` | `sp_tower_arrow_ai_b.png` | 质感最强，但**等距透视**导致八边形不对称；整体偏暗，48px 缩成一团深灰 |
| **C 像素风** | 16-bit 有限冷色板、硬抖动、块状像素 | `ai-v3-samples/…00-35-58.png` | `sp_tower_arrow_ai_c.png` | 与现行几何风**冲突最大**：生成的是正面视角「小人 + 底座」，非俯视；归一后左右留白大，48px 几乎不可读 |

三张 prompt 均已做脱敏：只描述物件、视角、材质与配色，不引用任何真实游戏、角色或艺术家。

## 3. 落地体检（关键结论）

| 检查项 | 实测 | 影响 |
|---|---|---|
| 透明底 | `background=transparent` **未生效**，三张均为 1024² 不透明 RGB | 必须后处理抠底，否则接进战场会带白底/黑底方块 |
| 背景 | A/C 白底 + 淡网格分块；B 深灰暗角渐变 | 单一色键抠不干净，需径向背景场估计 |
| 水印 | 三张右下角均有模型水印 | 靠「只保留与画布中心连通的前景」自动剔除 |
| 视角 | 只有 A 是正俯视；B 等距、C 正面 | B/C 直接落地会破坏战场视角一致性 |
| 48px 辨识度 | **三版均比 v2 更暗、更碎** | v2 的高饱和青色块面在小尺寸下仍最清晰 |

**策划结论**：就「战场可摆放贴图」这一目标，当前三版都不建议直接替换 v2。
A 可作为唯一候选继续打磨；B 更适合卡面 / 图鉴 / 商店大图；C 等于整体换风格，需先评估全项目美术重做成本。

## 4. 抠底管线（可复现）

`tools/ai_sprite_cutout.py`，仅依赖 numpy + Pillow：

1. 只用画布外圈采样，按到中心半径分箱取亮部中位数，构造径向背景色场（兼容白底分块与暗角渐变）；
2. 逐像素颜色距离生成软 alpha，白底样张与暗底样张使用不同阈值；
3. 256² 缩略图上两次 4-连通 flood fill：从边界标外部背景、从中心标塔连通域 ——
   内部高光空洞填实，水印与网格线因不连通被丢弃；
4. 放大回原尺寸、羽化、裁到塔 bbox、居中归一到 **128² RGBA**。

```bash
py -3 tools/ai_sprite_cutout.py
```

输出文件名 `sp_tower_arrow_ai_<style>.png` 与运行时拼名契约
`sp_tower_<ctype>_v1.png` 不同，故 `monster_layer.gd` 不会加载，不影响任何回归断言。

## 5. 若要真正落地，还差三步

1. **统一剪影**：叠八边形 alpha 蒙版（v2 做法），或走 ADR 修订美术圣经 §3.1 的八边形红线；
2. **提亮 + tag 双通道**：AI 图整体偏暗且无 tag 编码，需补高饱和块面与 tag 形状/颜色，
   否则小尺寸下既看不清、也违反 §9.2「不得仅靠颜色区分」；
3. **风格一致性验证**：先小批量 3–5 塔试产，确认同族不撞脸，再决定是否铺到全部原型。
