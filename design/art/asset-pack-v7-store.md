## 2. 为什么不另画一张，而是从 `keyart_hero_v1` 派生

`keyart_hero_v1` 是居中的「核心 + 同心环」蓝图曼陀罗，构图对称、边缘自然生成塔群 ——
它本身就是为**多比例裁切**准备的。店铺素材要的是"同一张画的多个画幅"：另画一张，
不同尺寸之间立刻不像同一个游戏（art-bible §2.1 家族一致性）。所以这里的工序是
**裁切 + 版式 + 锁版**，不是重新生成。

曼陀罗核心的精确位置由金色核心密度窗口实测得出：**`CORE = (920, 540)`**（1920×1080 坐标系）。
所有裁切窗都对齐它，所以任何画幅里主体都不会偏移。

## 3. 版式：横幅式（画在上、暗带在下）

**第一版做错了，记在这里免得再犯。** 第一版把标题直接叠在画面上 + 竖向压暗渐变：

- 标题正好压在金色核心上 —— 把画面主体盖掉了；
- 压暗蒙版不够黑，字浮在亮青色环纹上，"贴纸感"很重；
- 把蒙版从 0.82 提到 0.93 再提到 0.985，都还是在跟环纹打架 —— **问题不在强度，在版式**。

现在改成横幅式：

```
┌──────────────────────────┐
│                          │
│        画区（裁切）        │   ← 核心完整保留
│                          │
│  ~~~~~~~~ 底边 alpha 渐隐 ~~│   ← 沉入黑暗，不是硬切
│ ──────────────────────── │   ← 钢灰发丝线（两端各留 8%，不画满）
│        守 核              │   ← 暗带 (BG 近底色)
│      C O R E B O U N D    │
└──────────────────────────┘
```

暗带高度按画幅类型定：横胶囊 34% / 主胶囊 30% / 竖版与库胶囊 19% / 库主视觉 26%。
标题块在暗带内**垂直居中**，不写死像素。

## 5. 技术要点（都是踩过的）

1. **核心坐标实测，不靠估**：先用金色密度滑窗求核心中心，再让所有裁切对齐它。
   `CORE` 是生成器的唯一构图真源，换主视觉只需改这一个常量。
2. **超采样按画幅预算**：默认 2× 渲染再 LANCZOS 降采样（小尺寸笔画不灰）；
   但 float32 中间数组是 `O(4·w·h·ch)`，4K 走 2× 直接吃掉 380MB × 数个数组 →
   `SS_BUDGET_PX = 12M` 以上自动退 1×。**这是实测 OOM 换来的阈值，不是猜的。**
3. **库 Logo 不能"画满再抠底"**：第一版把整幅曼陀罗画在画布上再按"接近 BG 就透明"抠，
   结果主体全留在 alpha 里，等于叠了第二张画。现在走独立路径：**全透明画布 + 只画锁版**。
4. **`.ico` 必须是真 ico**：Steam 客户端图标只收 `.ico`，不能塞 png 改名。
   多档尺寸（16/24/32/48/64/128/256）由 PIL 一次写出。
5. **发丝线不画满**：两端各留 8%。画满会读成 UI 表格线，不是蓝图刻线。
6. **`art/store/.gdignore`**：发行素材不进引擎 —— 否则 Godot 会把 3840px 大图全导一遍，
   既不参与运行时，又白白撑大 pck。

## 7. 还没做的两件（需要另开条件）

1. **游戏截图 1920×1080**：Steam 列表页要求至少 5 张真实游戏画面。这要跑真机、摆好阵型、
   关掉调试 UI 再截，和本包（纯图像派生）不是同一条流水线。项目里已有 `tools/shoot_*.gd`
   系列窗口截图脚本可复用，但**画面内容需要人工挑局**，不建议脚本自动扫。
2. **成就图标 64×64**：项目未接 Steamworks，成就表还不存在。**没有成就 ID 就没有图标清单**，
   先画等于瞎猜数量。等成就表落定后，可按本包同一套语言（暗底 + 单色符号 + 蓝图刻线）批量出。
