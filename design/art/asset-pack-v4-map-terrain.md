# 资产包 v4 · 关卡地图地形贴图（asset-pack-v4-map-terrain）

> 状态：🟢 已落地 · 生成器 `tools/gen_map_terrain_v1.py` · 10 张变体图可逐字复现
> 前置：资产包 v1（界面件）、v2（HUD）、v3（航图节点）、keyart v1、卡面包
> 接入点：`scripts/ui/monster_layer.gd` → `_draw_map_layer()`

---

## 1. 为什么做这一包

战场地形此前 **100% 程序化**，而且只有"三层色块"的复杂度：

| 元素 | 改前实现 | 观感 |
|---|---|---|
| 三档材质 | 3 个 `draw_circle`（×1.18 / ×1.00 / ×0.84 明度） | 三个同心色块，没有"地"的质感 |
| 岩脊 | `draw_colored_polygon` 深色 + 1.5px 冷描边 | 一块黑斑，读不出"这里不能站"是个坎 |
| 10 张变体 | 只差岩脊角度/阵地布局 | 换图**看不出换了图** |

本包把「地表材质 + 岩脊」烘焙成位图，**不动任何几何、布局、玩法**：
几何仍由 `scripts/data/map_variants.gd`（SSOT）决定，贴图只是**同一份几何的材质层**。

**不在本包内的**：出怪口土带、阵地台（可建格）、同心环/放射刻度/出生环、放置网格。
它们由玩法数据或状态驱动（换图、建塔、放置态），烘焙会把"状态"焊死在图里。

## 2. 锚点（冻结）

| 常量 | 值 | 出处 |
|---|---|---|
| `R_TEX` | 60.0 u | 贴图覆盖半径；战场材质到 44u、岩脊 `r1 ≤ 58u`，留 2u 余量 |
| `TEX_PX` | 1024 | 1024 / 120u = 8.53 px/u ≈ 1080p 实机 `sc ≈ 8.5` 的 1:1 |
| `MAP_BAND_R` | 16 / 30 / 44 u | `monster_layer.gd` 常量（🔴 两边必须同值） |
| 角度口径 | 0° = +x（东）· 顺时针（y 向下为正） | 与引擎 `_dir(a) = (cos a, sin a)` 一致，贴图**不做任何翻转** |
| 数据来源 | `scripts/data/map_variants.gd` | 生成器**正则解析**，不手抄；解析后按 `validate_arcs()` 同口径自检 |

> 🔴 生成器会在出图前打印 10 张变体的「脊宽和 / 弧宽和 / 开口」，与
> `MapVariants.validate_arcs()` 算术同源。对不上直接退出 —— 宁可不出图，不出错图。

## 3. 调色契约（🔴 本包最关键的决定）

贴图是**灰度值图**（R=G=B），运行时 `draw_texture_rect(tex, rect, false, tint)` 乘上
`tint = env.field × (255 / 161)`。这样做的三个理由：

1. **4 档环境换装自动跟随**（`env_palette.gd` 的 T0~T4 场地色）。写死颜色的贴图会在
   换装到「血夜」时与场地圆脱色，看起来像贴图没加载；
2. **地形永远不会比场地底色更亮**（art-bible §2.5「克制底色」）—— 除了崖唇高光；
3. **8bit 有上限**：想画"比底色亮"的元素，必须先把基准压下去。所以生成器里所有灰度
   **一律按「场地底色的倍数」声明**（`gr(ratio)`），而不是写死 0~255：

| 元素 | 倍数 | 灰度 | 说明 |
|---|---|---|---|
| 外环 · 荒原 | ×0.84 | 134 | 与改前 `frame ×0.84` 同源 |
| 中环 · 石板 | ×1.00 | 161 | **基准档**，等于 `env.field` |
| 内环 · 焦土 | ×1.18 | 190 | 与改前 `×1.18` 同源 |
| 崖唇高光 | ×1.52 | 255 | 全场最亮的地形元素（岩脊的"棱"） |
| 裂谷底 | ×0.56 | 90 | 比改前的 `#0E1020` 略亮，能看清里边 |
| 谷底贴壁暗边 | ×0.30 | 48 | 近壁投影 |
| 散石体 | ×0.55 | 89 | — |

`G_MAX_RATIO = 1.58`（灰度 255 对应的倍数）。运行时倍率 = `255 / 161 ≈ 1.584`
→ `monster_layer.MAP_TEX_GAIN`。**这两处是跨语言契约，改一侧必须改另一侧。**

> 归一化：生成器先量出中环实测灰度，再用一条 LUT 把它拉回 161（`_band_base()` 末尾），
> 所以颗粒/特征怎么加，运行时倍率都不会漂。

- 命名：`<类别>_<标识>_<变体>_v1.png`（art-bible §10.2），变体 id 的 `-` 换成 `_`
  （`tri-fissure` → `map_terrain_tri_fissure_v1.png`），由 `_map_tex()` 现场换算。

材质特征（内环热裂 / 中环石板缝+錾边 / 外环碎砾）+ 全部岩脊（断崖裂缝）+ 近场与远景散石。
**不含**：出怪口土带、阵地台、同心环/刻度/出生环、可建网格。

## 6. 接入方式（`_draw_map_layer`，零布局改动）

```gdscript
const MAP_TEX_R := 60.0                 # 与生成器 R_TEX 同值
const MAP_TEX_GAIN := 255.0 / 161.0     # 与生成器 G_BAND_MID 同源
const MAP_TEX_DIR := "res://art/2d/maps/"
```

1. `_map_tex(map_id)`：按 map_id 懒加载 + 缓存（`_draw` 每帧跑，**禁止**每帧 `exists + load`）。
2. 贴图存在 → **一次** `draw_texture_rect`（`tint = field × MAP_TEX_GAIN`，尺寸 `120u × sc`），
   跳过原来的三个 `draw_circle` 与岩脊填充；
3. 贴图缺失（headless / 新加变体没出图 / 资产被删）→ **逐字回落**原来的
   「三圆 + 深色多边形 + α0.75 冷描边」，画面与改前一致；
4. 贴图生效时**不再描**岩脊的逻辑扇区边（见 §7 第 3 条），出怪口土带与阵地台照旧程序化绘制。

## 7. 踩坑记录（都是实机/生成图里看出来的）

1. **预览必须走乘法**。第一版把灰度贴图直接 alpha 叠在底色上，整张图变成"发白的银盘"，
   与实机完全不是一回事 —— 险些按错误的预览下结论。`_on_field()` 就是为此写的。
2. **"分块岩面"读作铁皮 / 木板**。岩脊在数据上是一条又长又薄的环扇（宽 2~28°、长 24~58u），
   按"石头表面"切块 + 加棱线，实机就是一块折起来的金属板。改成**断崖裂缝**（深谷底 +
   受光唇线 + 崖口碎石）后才读得对 —— 也和设计里「东南断崖 / 西断墙 / 北短脊」的命名一致。
3. **只抖圆弧不抖端墙 = 一根直溜溜的长边**。轮廓抖动必须四条边全抖，否则短边会把
   "石头"立刻拉回"板子"。另外贴图态**不要**再描逻辑扇区边：烘焙轮廓是锯齿的（±0.45u），
   亮线会有一段露在岩体外，读成"石头里埋了根亮线"。
4. **裂纹的角度步要按弦长算**。r ≈ 50u 时 20° 的弦长就是 18u —— 一步跨出去就是一条横穿
   岩脊、扎到外面的长直线（首版实机伪影的元凶）。改为逐点 4° 步进 + `_in_sector()` 约束。
5. **单位混用**：散石顶点的抖动项漏乘 `PPU_SS`，结果"石头"只有 6px，整层几乎不可见，
   排查半天以为是 `_in_sector()` 把它们全筛掉了。
6. **冒烟截图的窗口尺寸会骗人**。Windows DPI 缩放让窗口实际是 1080 高以外的尺寸，
   `sc` 掉到 6.7 → 贴图被缩小 2.5 倍，细节全糊。`shoot_map_terrain_smoke.gd` 开头
   `DisplayServer.window_set_size(1920×1080)` 必须先钉死，否则目检结论不可信。
7. **改图后必须重新 `--import`**。否则 Godot 仍加载 `.godot/imported/*.ctex` 的旧内容，
   会看到"改了参数但画面没变"的假象。

## 9. 后续（本包未做）

1. **章节材质差异**：目前 10 张变体共用一套材质语言（灰阶），差异只来自几何。
   若要熔炉"熔渣"、霜序"冻岩"、枢网"金属格栅"的材质区分，需在生成器里按章节换特征笔刷
   （值仍走灰度，色相交给环境档）。
2. **出怪口土带贴图化**：现在是 1 条低α弧 + 2 根端柱，可换成"踩秃的土路"贴图。
3. **地形亮度整体上抬**：当前三档严格等于引擎既有色（保证"换装"与观感一致）。
   若要更强的"地面感"，需要主理人拍板把战场底色调亮一档（属设计决策，不在美术包内改）。
4. **塔/怪可读性回归**：地形变有材质后，需要在百怪同屏场景下复测一次
   「1 秒分清我/敌/可交互物」（art-bible 第一原则）。
