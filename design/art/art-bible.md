## 1. 整体美术风格（Art Style）

### 1.1 方向定位 —— 🔴 v0.2 改写：**2D 程序化俯视径向**

**主方案（v0.2 定稿）：2D 正交俯视径向 + 程序化几何绘制**

- 战场为**正交俯视**：核心居中，怪物从**出生环**（半径 `R_s`）沿径向直插核心；塔位分布在核心周围的暴露/安全环带上（`scripts/geo/space_model.gd`）。
- 一切视觉元素由 `Node2D` 的 `draw_circle / draw_colored_polygon / draw_polyline / draw_arc` **程序化生成**（`scripts/ui/monster_layer.gd`）——**无模型、无贴图、无材质**。
- 渲染器 = **`gl_compatibility`**（`project.godot`）：后处理能力受限，高级后处理（色差/径向模糊/景深）不可用，需用 2D 手段替代（见 §4.3）。
- 世界→屏幕映射 = **等比缩放 + 居中**（`_to_screen()`），**非等距投影**；二维平面无 3D 深度缓冲，层级靠**显式绘制顺序**（见 §7.2）。

> ~~原 v0.1 主方案：Low-Poly 3D + Toon/Cel 分层着色（"3D 体块，2D 观感"）~~
> → **标注：不适用（已由 2D 程序化绘制替代）。** 原方案依赖 Godot 3D 管线、MultiMesh、GPU 粒子、Inverted Hull 描边、Toon 材质——均未在 MVP 落地，也不再是本项目路径。

### 1.3 风格红线（明确不做）

- ❌ 写实 PBR、高精度法线细节、真实比例——成本与 Solo 产能不匹配。**（v0.2：已无材质/光照系统，天然隔离）**
- ❌ 纯像素等距——卡牌 UI 与像素风混搭会撕裂。
- ❌ 暗色糊成一团的"写实暗黑风"——本作需要百怪同屏仍可读，暗色低对比是自杀。
- ❌ 无描边的柔和渲染——**描边是本作可读性的生命线，不可省**。
- ❌ **高饱和的战场底色**——底色越静，爆发越响（见 §2.5 锚点2）。
- ❌ **任何遮挡塔轮廓或核心 HP 条的特效**（见 §8 锚点4）。

> ✅ **v0.2 状态确认**：风格红线**全部仍然有效**；且"已无 3D/材质管线"使前两条（禁写实 PBR、禁暗色糊）**从"要避免"变成"结构上不可能发生"**。

## 2. 配色方案（Color Palette）—— ✅ v0.2 保留（已落地）

> ✅ **v0.2 状态：本节目标全部已落地**。色板精确 hex 已写入 `scripts/ui/monster_layer.gd:77-92` / `scripts/ui/hud.gd:21-29` / `scripts/ui/core_hp_bar.gd:16-20`。**本节的"青橙双极"是本项目最被低估的成就——静态可读性的地基。**

### 2.1 核心原则：**青 / 橙 双极对立**

全场只存在两个"阵营色极"，所有配色围绕它们组织：

- **玩家极 = 冷（青蓝 Cyan）**：中心核心、防御塔、友方投射物、可建造范围、增益光环。
- **敌人极 = 暖（橙红 Orange）**：怪物、敌方投射物、来袭路径、威胁标记。

> 为什么是青 vs 橙：这是**红绿色盲（Deutan / Protan）下仍然可分的色对**（蓝-黄轴），同时天然符合"冷=后方/安全，暖=前方/危险"的直觉。颜色是**第一编码**，形状是**第二编码**（见 §3/§9）。

### 2.5 锚点 2 · 克制底色，高饱和特效（Muted Base, Loud Effects）⭐

场景用**低饱和冷灰 / 沙褐色**，让后期满屏的火焰、闪电、爆炸成为画面里**唯一的高饱和**。
**为什么**：数值爆炸的爽感必须靠对比才能成立——**底色越静，爆发越响**。如果场景本身就五颜六色，后期弹幕只会变成一坨糊。
**硬要求**：场景饱和度上限设定为 特效饱和度的 **1/3 以下**。

## 3. 形状语言（Shape Language）—— ✅ v0.2 保留（已落地）

> ✅ **v0.2 状态：本节目标已落地**（塔=八边形 / 怪=不规则 blob+尖刺 / 描边 / blob 影 / rim）。**RADIAL 塔原型分化已于 S5 补齐**（内芯原型徽记，见 §3.1 厘清）。

### 3.1 阵营形状对立（第二编码）

| 属性 | 玩家侧（塔/核心） | 敌人侧（怪物） |
|---|---|---|
| 轮廓走向 | **垂直向上**、重心高、塔状/柱状 | **径向扑向核心**、重心低、团状 + 尖刺 |
| 对称性 | **严格 8 重旋转对称**（八边形） | **不对称**（12 边确定性扰动） |
| 基础几何 | 正八边形（外接圆）/ 中心圆 | 圆形 blob + 朝核心的尖刺扇 |
| 边缘 | 直线、硬折角、整齐 8 顶点 | 锯齿、参差、
不规则 |
| 底座环 | **规则八边形环**（青） | 无（以尖刺/摆动替代） |
| 运动 | 呼吸缩放、形态递进（8 重对称） | **squash & stretch 摆动**（相位由位置派生） |
| 一句话 | **"人工、稳定、对称"** | **"生物、混乱、扑来"** |

> 🔴 **v0.2 厘清（S5 落地后）· 「严格 8 重」的边界**：本表「**严格 8 重旋转对称**」**限定于塔的「外轮廓 / 剪影」**（八边形外框 `_oct8`、8 重护角、形态递进等**轮廓构件**）。
> **「内芯原型徽记」= 允许的第二编码**：S5 在塔内芯按原型加徽记 —— **Arrow = 三角(3 边) / Cannon = 方形(4 边) / Frost = 六边形(6 边)**，**服务 §9.2①「不得仅靠颜色」的形状冗余**（与原型色**冗余**，非替代）。徽记边数 3/4/6 **本就不要求 8 重对称**，故**不构成对「严格 8 重」的违反**（该约束只管轮廓）。
> **⚠️ 红线（未来实现者必守）**：① **外轮廓必须始终 8 重对称** —— 徽记**不得**改变外框形状 / 顶点数；② 徽记**不得突破塔位半径**（不侵占相邻塔位）；③ 徽记是**形状编码**，须与颜色**冗余**而非替代。视觉复核见 `docs/phase6/s2-s5-visual-review.md`。

### 3.2 剪影辨识度规则（强制）—— ✅ 已落地

1. **剪影测试**：任何新单位/建筑，导出纯色剪影，须能被正确归入「我方 / 敌方」——通不过即打回重做。
2. **禁止撞形**：敌我双方不得使用相近的基本几何体（玩家塔=八边形；怪物=不规则 blob）。
3. **体量分层**：同屏单位按体型分层（杂兵 / 精英）：
   - 杂兵：`BODY_SWARM 0.85` / `BODY_RUSH 0.65`（细长）/ `BODY_TANK 1.30`（宽扁）
   - 精英：`ELITE_SCALE 1.35` + 噬品红环
   > 🔴 **v0.2 已知缺口（B3）**：Rush(0.65)↔Swarm(0.85) 层间差仅 **+31% < 40%** 红线。优先级 **P2-7 / 低**。
4. **底部投影（Blob Shadow）**：所有单位强制投射双层同心圆软影（左上光源→影落右下），把单位"钉"在地面上，避免俯视下的漂浮感与位置歧义。**已落地**（`_blob_shadow`）。
5. **描边（Outline）强制**：所有单位外扩描边，颜色为**极深色而非纯黑**（塔 `#0E2430`，怪 `#2E1008`）——保持与本体色的关联。**已落地**（`draw_polyline` 外扩，替代原 Inverted Hull）。

### 3.3 投射物形状 —— 🔴 **已知缺口（未落地）**

- 友方投射物：**细长梭形/箭形**，尖端朝飞行方向，带一条渐隐尾迹（青）。
- 敌方投射物：**圆球/液滴/不规则碎块**，体积更大、速度更慢（橙）。
- 判定：任何投射物在最小尺寸下，其**长宽比 ≥ 2:1 = 友方，≈ 1:1 = 敌方**。

> 🔴 **v0.2 已知缺口（B2）**：投射物层**完全为空**（`_draw_projectiles` 依赖 snapshot `projectiles` 字段，该字段不存在）。优先级 **P1-1**。
> ✅ **契约已评估**（`docs/phase6/vfx-contract-feasibility.md`）：玩法为 **hitscan 瞬时聚合、无投射物实体** → **无需给 snapshot 新增 `projectiles` 字段**；正确做法是**渲染层纯派生装饰弹**（塔位 + 怪位 `t_remain` 均现成），观感与真实 DPS 解耦。

### 3.4 UI 卡牌形状

- 统一 **1:1.4 竖版圆角矩形**，圆角半径 = 宽的 6%。
- 顶部为插图区（正方形），底部为文字区。稀有度越高，卡面装饰越多。
- 卡牌在牌组中**轻微扇形堆叠**，在商店中**平铺一行**（牌组 -3°，商店 0°）。

### 3.5 锚点 3 · 机械 vs 有机（Clockwork vs Flesh）

- **塔 / 核心 = 精密机械**：八边形、硬折角、8 重对称、发光内芯。

## 7. 战场空间规范（俯视径向）—— 🔴 v0.2 **重写**（原「2.5D 等距规范」）

### 7.1 网格与坐标

- 世界空间：**XZ 平面为地面**（与 `SpaceModel` 一致），核心居中。

- **折线模式（PATH，保留/legacy）**：5 段折线路径 + 路径点，核心在终点。

| 核心 | `U_CORE 1.90`（最外环） | 全场唯一轮廓 |

- **防堆叠（关键）**：所有单位启用**分离力**，保证任意两单位中心距 ≥ 两者半径和的 85%。
- 塔位以**钢灰色八边形环**标示；暴露位加**红 X**、安全位加**绿盾**（决策期）；来袭方向以**橙色威胁楔**（8 扇区）标示。

### 7.4 高度与遮挡

- 本项目为 **2D 俯视，无真实高度**；"体量"由 §7.3 的视觉体宽表达。
- 高价值单位（核心、主塔）通过**层序 + 描边 + 外环**保证不被混淆；不做 3D「遮挡淡出」。

## 8. VFX / 反馈原则（VFX & Juice）—— 🎯 v0.2 保留为**目标**（🔴 **本作最大缺口**）

> 🔴 **v0.2 状态警示**：本节是 P2「雪崩」支柱的画面载体，但**当前几乎全未实现**。铁证：W16（雪崩期）截帧 `docs/phase3/ux-p0p1c-w16-20261010.png` 屏幕仅 ~4 怪 + **零弹幕 + 零伤害数字**。详见 `asset-audit.md` §2.4。

### 8.1 四层反馈模型

| 层 | 触发 | 表现 | 时长 | 状态 |
|---|---|---|---|---|
| **L1 微观** | 单次命中 | 受击体闪白 1–2 帧 + 伤害数字弹出 + 火花 + 微击退 | 0.1s | 🔴 缺（怪无命中闪） |
| **L2 中观** | 击杀 | 掉落 + 地面冲击环 + 掉落物；精英/Boss 加 hitstop | 0.3s | 🔴 缺 |
| **L3 宏观** | 购买/升级 | 卡牌飞向牌组 + 塔升级光柱 + UI 弹跳 | 0.6s | 🟡 部分（塔形态递进 ✅） |
| **L4 超宏观** | Build 成型 / 数值爆炸 | 见 §8.4 超载 | 持续 | 🔴 缺 |

### 8.2 Juice 随数值升级（核心机制）

**同一动作的反馈强度必须随玩家当前数值增长。** 玩家 1 级和 30 级杀死同一只杂兵，演出必须不同。

| 指标 | 弱（早期） | 中 | 强（后期） |
|---|---|---|---|
| 命中火花粒子数 | 3 | 8 | 16 |
| 击杀碎片数 | 5 | 12 | 24 |
| 击退距离 | 0.05 | 0.15 | 0.35 |
| 冲击环半径 | 0.5 | 1.0 | 2.0 |
| 屏幕震动 | 无 | 1 级 | 3 级 |
| hitstop | 无 | 40ms | 80ms（仅精英） |

实现方式：全局 `JuiceScale`（由玩家 DPS / 连击 / 波次推导，0–1），所有 VFX 参数乘以 `1 + JuiceScale * k`。**🔴 未实现（P1-4）**。

### 8.3 伤害数字分级表（Visual Damage Tiers）

| 单次伤害占目标最大血量 | 字号倍率 | 颜色 | 动画 |
|---|---|---|---|
| < 10% | 1.0× | 白 `#FFFFFF` | 上浮 + 淡出 |
| 10–30% | 1.3× | 淡金 `#FFE38A` | 弹出 + 轻微缩放 |
| 30–60% | 1.7× | 辉金 `#FFC94A` | 弹出 + 旋转抖动 |
| 60–100% | 2.2× | 橙金 `#FF8A2B` | 弹出 + 冲击环 + 1 级震屏 |
| **超杀 / 溢出** | **3.0×** | **彩虹流光** | 弹出 + 彩虹色文字 + 字号弹跳 + 一次性亮环（**2D 替代，见下注**） |

> 🔴 **超杀档红线规避（v0.2 补 · 与 `docs/phase6/vfx-art-spec.md §2.1` 一致）**：原「全屏色差 + 慢动作 0.35×」**已降级** —— ① `gl_compatibility` **无 Bloom/色差**；② **慢动作 = 写 `Engine.time_scale`，其唯一写入者须为 `TimeDirector`**（触碰「时间轴权威」架构红线，与 P1-3b hitstop 同源）→ 改用 **2D 替代**：**彩虹色文字 + 字号弹跳 + 一次性亮环**（**不碰 `time_scale`**）。

**同屏数字上限 40 个**，超出时合并为聚合数字（"×127"）并升级一档表现。**🔴 未实现（P1-2）**。

### 8.4 超载状态（Overload）—— 核心爽点演出

**触发条件**：单秒击杀数 ≥ 阈值 / 连击 ≥ 25 / 单帧总伤害 ≥ 阈值 / 玩家 DPS 突破里程碑。

- **进入（0.4s）**：时间缩放降至 0.35×；亮度/饱和提升；屏幕四边亮起**金色能量边框**；低频"充能"音效起（**阮和鸣负责**）。
- **持续**：伤害数字 +1 档；敌人死亡改**连锁爆散**；连击计数器居中；地面能量裂纹。
- **退出（0.6s）**：参数缓动回落，边框向内收束。
- ⚠️ **冷却 ≥ 6s，持续上限 8s**——目的是让"爆炸"成为**稀缺的高光时刻**，非常态噪音。

**🔴 未实现（P2-1）**；注意 `gl_compatibility` 下 Bloom 不可用，需 2D 叠加替代（见 §4.3）。

> 🔴 **时间轴红线警示（v0.2 补）**：§8.4 的「时间缩放降至 0.35×」与 §8.5 的「慢动作触发冷却」**实施时须经 `TimeDirector`，不得由 UI/VFX 直写 `Engine.time_scale`**（`time_scale` 的**唯一写入者** = 时钟权威，见 `wave_director.gd:42-44`）。本项属**未决拍板项（B4）**——此处**仅登记约束、不改设计**；若立项须单独走 ADR + 红线复核。

### 8.5 防过载与性能护栏

| 护栏 | 值 |
|---|---|
| 同屏活跃粒子系统上限 | 48 |
| 单粒子系统最大粒子数 | 64（普通）/ 256（精英） |
| 同屏投射物上限 | 300（超出转为光束/链式表现） |
| 同屏伤害数字上限 | 40（聚合升级） |
| 屏幕震动等级上限 | 5 级，且设置中可关闭 |
| 慢动作触发冷却 | 3s（⚠️ 须经 `TimeDirector`，禁 UI 直写 `time_scale`，见 §8.4 警示） |
| 目标帧率 | 1080p / 60fps；掉到 45fps 自动降一档粒子预算 |

所有 VFX 必须**对象池化**，禁止运行时 instantiate。

### 8.6 锚点 4 · 信息即美术（Readable Chaos）⭐

后期满屏弹幕，**塔的可读性 必须 > 特效的华丽度**。**硬性规则**：

1. 任何特效**不得遮挡塔的轮廓与核心 HP 条**。
2. 伤害数字使用**固定网格排布**，禁止随机乱飞重叠。
3. **每个塔必须有唯一剪影**——关掉特效后仍能一眼分辨塔的原型。
   > 🔴 **v0.2 已知缺口（B1）**：RADIAL 下三塔（Arrow/Cannon/Frost）**画成同一八边形**，仅靠形态递进（h 层）区分强弱、**不区分原型**。优先级 **P0-3**。
   > ✅ **已补（S5）**：内芯原型徽记（Arrow=三角 / Cannon=方 / Frost=六边）。见 §3.1 厘清。
4. **余光可读性（Peripheral Readability）**：玩家看商店时战场靠**余光**维持。人眼周边视觉只对**运动与亮度**敏感 → **战场关键告警必须编码为「运动 + 亮度」**：核心告急 = 屏幕边缘**红光脉冲**（✅ `threat_pulse` 骨架已建）；怪物突破 = 路径上**高频闪烁**。
   > **禁止**把"核心 HP 数字"作为唯一告警手段。
