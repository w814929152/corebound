## 1. 为什么做这一包

`stage_select_overlay.gd` 是下一个"零贴图整屏"：10 个关卡节点全是
`draw_colored_polygon` + `draw_polyline` 裸画（纯色块 + 1.5px 细描边），终局核心
节点与普通节点毫无视觉区分，左上章节目录用的是文字字形「◆」。
航图是玩家每次开局必经的第一屏，识别度收益与 HUD 包同级。

**本包不动任何布局与交互**：`NODE_R=27 / HIT_R=38 / LABEL_GAP=30 / RING_FRAC /
ANGLE_*` 全部冻结；贴图按既有常量出图，接入只加绘制。

**染色策略（红线）**：主节点件把"要变的环"烤成**白色**、填充烤成近黑
`#0E1220` → modulate 染色时环精准命中章节色，填充只被轻微暖化（暗色×彩色仍是暗色）。
这是 §2.2「不做运行时发明色」与「面板不做 modulate」的折中：面板底是中间调会被染花，
节点填充足够暗则安全。

## 4. 接入方式（`stage_select_overlay.gd`，零布局改动）

- `_ht()` 纹理缓存（与 hud.gd 同款：`_draw` 每帧跑，禁止每帧 `load + exists`）。
- **判空降级**：贴图缺失（headless / 文件丢失）→ 逐项退回旧 `_hex / draw_arc / "◆"` 路径，
  画面与改前逐位一致。
- **旧件让位**：贴图生效时旧 `_hex` 不再绘制；状态符号（锁 / 勾 / 三角）仍由代码画在
  节点中心 —— §9.2 红线：颜色不是唯一信息通道，形状通道保留。
- 章节目录：徽记贴图生效 → `HBox[TextureRect 20×20 + Label]`；缺失 → 回落「◆」文字行。
- 核心底座只在 `chapter==4` 的节点（4-1）下层画。
