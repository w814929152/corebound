## 0. 三句话结论（给赶时间的人）

1. 🟢 **补上了 `sapper-balance-review` §4-处置 C 请求的"玩家反制臂"** —— 在**实机几何（RADIAL 八槽）**下测出「**AI 地板 → 玩家上限**」区间：**B 多塔 `[0.747, 0.813]`，跨度 `+0.067`**（N=300 · seed=20261002 · `run_loop_proto_aggro` · proto+elite+aggro 全开）。

2. 🔴 **反制窗口是"达标必要条件"（本口径下）** —— AI 地板 `T0 = 0.747 < 门禁 0.80`（破线）、玩家上限 `T1（保主力塔）= 0.813 ≥ 0.80`（达标）→ **只有玩家动用反制工具箱，本口径才够着门禁；AI 什么都不做则破线**。这正是"惩罚从运气变成决策"的量化证据（`mechanics-tower-life-death` §3 归因链）。

3. 🟡 **一个须交设计侧解读的事实** —— 五臂里**唯一把 B 抬过门禁的是 T1「保主力塔」（protect_core）**；而 **T2「理想肉盾」（bulwark 真挪塔）`0.680` 与 T4（肉盾+复活）`0.683` **低于 AI 地板 `0.747`** → 本口径下"真挪塔"型反制**反向**。🔴 此为**测量事实**，**判读（是否设计意图 / 是否要调）归文策渊**，本文档只报数。

## 1. 测量设计

### 1.1 口径（与既有诊断件对齐 + 补实机几何）

| 项 | 取值 | 说明 |
|---|---|---|

| 镜像 | `run_loop_proto_aggro`（proto + elite + aggro 全开） | **实机口径忠实镜像**（与 `boot.gd` 产品路径同款开关组） |
| 样本 | `N = 300` 局 / 臂 | 沿用 `scan_sapper` 处置 A 的 N=300 纪律（N=60 会误判档位） |
| 随机种子 | `seed = 20261002` | 与 `scan_bulwark` / `scan_protect_core` **同 seed**，便于对拍 |

| 判据 | `takeoff_wave(rows)` ≥ 0 且存活（`core_hp > 0`）= 起飞；门禁红线 `0.80` | 与 C-8 MC 同款 |

### 1.2 五条反制臂（玩家"合理反制"四人工具箱 · `mechanics-tower-life-death` §3）

| 臂 | 名称 | 玩家动作 | 实现参数 |
|---|---|---|---|
| **T0** | AI 地板 | **无反制**（金标本 AI 纯 DPS 贪心，主力塔落暴露枢纽位） | `protect=false, bulwark=false, revive=false` |
| **T1** | 保主力塔 | 主力塔隐身，怪跳过它（**升 HP / 保塔**的近似） | `protect_core = true` |
| **T2** | 理想肉盾 | 主力塔真挪安全位，安全位塔换暴露位扛伤（**插肉盾**） | `bulwark = true` |
| **T3** | 复活 | 战斗中即时被动复活（**修复 M-1**） | `repair_on_disable = 9` |
| **T4** | 肉盾 + 复活 | 组合上限 | `protect + bulwark + revive` 全开 |

> 🔴 **口径注**：本文的 `revive` 臂走 `repair_on_disable = 9`（批处理镜像只能这么表达战斗内复活）—— 与产品路径新增的 `combat_revive_enabled` **语义等价**（`_revive_mode()` 打开时即返回 9）。批量诊断件不占用产品开关。

### 1.3 产出定义

- **区间** = `[AI 地板 (T0), max(T1..T4)]`（B 多塔主口径）；A 单核作 INFO。
- **"反制窗口价值"判据**：`地板 < 门禁 ≤ 上限` → 反制窗口是**达标必要条件**（玩家反制确有价值）；`地板 ≥ 门禁` → 反制窗口是**冗余余量**（安全但非必要）；`上限 < 门禁` → 用满工具箱仍破线（惩罚过重 → 对接处置 D）。

## 2. 实测结果（N=300 · seed=20261002 · exit 0 · 8m52s）

### 2.1 B 多塔（主口径 · RADIAL 八槽）

| 臂 | 起飞率 | 存活率 | 中位起飞波 | 局数 |
|---|---|---|---|---|
| **T0 AI 地板** | **0.747** | 0.900 | 13.5 | 224/300 |
| **T1 保主力塔** | **0.813** 🏆 | 0.960 | 12.0 | 244/300 |
| **T2 理想肉盾** | 0.680 ⚠️ | 0.843 | 13.0 | 204/300 |
| **T3 复活** | 0.777 | 0.897 | 14.0 | 233/300 |
| **T4 肉盾+复活** | 0.683 ⚠️ | 0.893 | 14.0 | 205/300 |

### 2.2 A 单核（INFO）

| 臂 | 起飞率 | 存活率 | 中位起飞波 | 局数 |
|---|---|---|---|---|
| T0 AI 地板 | 0.203 | 0.203 | 8.0 | 61/300 |
| T4 肉盾+复活 | 0.517 | 0.517 | 8.0 | 155/300 |

> 🟢 A 单核"地板 0.203 → 上限 0.517"（跨度 +0.314）符合 V-2「单核高风险画像」设计预期：A 的可操作空间**远大于** B（B 已接近高位，天花板空间小）。

### 2.3 区间与判定

```
▶ 玩家反制区间（B 多塔）：AI 地板 = 0.747  →  玩家上限 = 0.813   跨度 = +0.067
   · T0 地板 ≥ 门禁 0.80 ：❌ 破线（AI 地板不动红线，靠玩家反制抬升）
   · 玩家上限 ≥ 门禁 0.80 ：✅ 达标
   · 结论：AI 地板破线、玩家上限达标 → 反制窗口是达标必要条件（玩家反制确有价值）
```

| 判据 | 结果 |
|---|---|
| AI 地板（T0） vs 门禁 0.80 | 🔴 **0.747 < 0.80 → 破线** |
| 玩家上限（max T1..T4） vs 门禁 0.80 | ✅ **0.813 ≥ 0.80 → 达标** |
| 反制窗口价值定性 | 🟢 **达标必要条件**（非冗余余量） |
| 最大反制臂 | 🏆 **T1 保主力塔**（唯一越线臂） |

## 4. 须交设计侧解读的事实（🟡 判读归文策渊）

| 事实 | 数值 | 🟡 待判读 |
|---|---|---|
| **T2「理想肉盾」/ T4 反向** | T2 `0.680` / T4 `0.683` **< AI 地板 `0.747`** | 「真挪塔」型反制在 **RADIAL 八槽 · B** 下是否**非最优/反向**？与 V-4（六槽 A 理想肉盾有益）口径不同 → 建议设计侧联判：是**口径差异**（A/B · 六/八槽）还是 **build 偏置**（`sapper-balance-review.md` §3.3「反广度·亲集中」同族）？ |
| **T1 是唯一越线臂** | `0.813` | 「保主力塔/升 HP」是**主导解**吗？（R-S2 主导策略风险）→ 须确认 T2/T3/T4 是否仍有独立价值（否则反制工具箱退化为单解题） |
| **T3 复活净效应为正但不足越线** | `0.777`（+0.030 vs 地板） | 与 V-8 B1「复活结构改善真实、零胜率代价」一致（本口径下复活**正向但不单独达标**）→ 佐证复活是**辅助臂**而非主解 |

> 🔴 **工程侧不做此判读**：本文档只提供**测量事实**与**口径纪律**；是否调整 `bulwark` / 升 HP 落点，属设计侧（`mechanics-bulwark-cycle.md` / `sapper-balance-review.md`）职责，且**任何数值改动须另立批次**。

## 5. 纪律与边界（本文不做什么）

| 🔴 不做 | 理由 |
|---|---|
| **不改任何数值 / 不改任何代码** | 任务红线；诊断件恒 `quit(0)`，只读分析 |
| **不把八槽 T0 `0.747` 与六槽门禁 `0.850` / 金标本相减** | 几何不同（PATH 六槽 vs RADIAL 八槽）→ 混用即重犯跨口径错误（`v7-baseline-retraction.md` §1.1） |
| **不拿"机制活动量"当胜率代理** | 沿用 `mechanics-bulwark-cycle.md` L-4：本表`起飞率`是**结果量**可作主判据；不引入塔死存量等中介量 |
| **不据本测量下"削/加 bulwark"结论** | 判读归设计侧；本件只报数 + 标口径 |
| **不把 T3 的 `repair=9` 当"产品开关已开"** | 产品路径走 `combat_revive_enabled`（C-1/C-2），批处理诊断仍走 cfg —— 二者语义等价但**入口不同** |
