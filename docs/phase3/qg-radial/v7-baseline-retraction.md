　🟢 **可接受**：它的语义是「PATH 几何下塔死亡**确实会发生**」（防止判据因 B 的结构性免疫而恒真），一次 FAIL 的代价 = 人工判读，很低。
　🔴 **纪律**：**连续两次 FAIL 才允许判为回归**；单次 FAIL 须先人工判读是 Poisson 噪声还是真实回归。

🔴 **同时自曝的统计量缺陷（T-A′-2 结构性弱点，登记不修）**：
`hit_fail` 的**分子由塔死亡决定、分母由起飞率决定** → 任何只影响起飞率的变更（与塔死亡无关）都会让这条闸门翻红/翻绿。
→ 🟡 **判读纪律**：T-A′-2 FAIL 时**必须同时看 T-A′-1**，两条一起判，不得单凭 `hit_fail` 下结论。

## 4. 🔴 追加登记：质量门漏检 + 新纪律

### 4.1 漏检事实

> 定档时 `X_form` 的分布是 **0:212 / 2:6 / 3:8 / 4:64 / 5:9 / 6:1**，即**有 64 局（21%）单局出现 4 次塔死**。
> 而 A 路径 `max_towers = 2`（`shop_ai.gd:155`）——**一座塔最多只能被打停 2 次**（除非它复活后再被打停）。
> 🔴 **「单局 4 次塔死」与「全场只有 2 座塔」在结构上矛盾。** 这个矛盾在 R-2 阈值定档时**本应被质疑**，却一路放行到"全绿转正"。
> 事后看，那个 4-簇**正是 `rest()` 免费复活 → 同一座塔反复死**的直接指纹（修复后 4-簇消失，分布塌成严格的 `{0:243, 2:57}`）。

**漏检归类**：这是**"数据自洽性检查"缺失**，不是统计量选错、也不是裕度算错。三类检查里我们做了后两类（统计量错配 / 阈值裕度），**漏了第一类（这个数是否可能）**。

### 4.2 ✅ 新纪律（补进 `r2-criteria-revision.md` §6，编号续 ⑦）

> **⑧ 🔴 判据定档前，须先证「被测 artifact 无缺陷」。**
> 一条判据只在**产生它的代码路径可信**时才可能有效。定档/回填实测值前，必须先跑一次**数据自洽性检查**：
> - **① 结构性上界检查**：实测值是否可能？例：`X_form` 的最大值不得超过 `max_towers × 可被打停次数上限`；`Σ dis_new` 不得超过局数 × 塔数 × 波数。
> - **② 分布形态检查**：出现"不可能的簇"时（如本例 4-簇），**先怀疑 artifact，再怀疑设计**。
> - **③ 独立复跑**：判据的实测值须由**非实现者**独立复跑确认（本次即如此，才没让程基岩的自述成为唯一证据）。
> 🔴 **违反后果**：发现的矛盾未澄清前，判据**不得定档、不得转正**。
> 🟢 **与 §6-③ 的关系**：§6-③ 防"把阈值贴到实测值身边"（已知有噪声时）；**§6-⑧ 防"实测值本身是假的"**（更上游）。
