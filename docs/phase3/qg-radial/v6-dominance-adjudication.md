## 2. 对象混淆审查（本次裁决的核心）

V-6 原文（`radial-core-siege-draft.md` §7.3）：

> **V-6** | **外环肉盾是否变成必胜解** | 观察"**外环高 HP 塔** + **波末残留消失**"组合下的漏怪数 | 若 W13+ 漏怪恒为 0 且起飞率 ≥0.98 → 判定为主导 → 收窄 §2.9 残留规则或上调 `ATTRITION`

质量门 §3.3-⑦ 用来触发它的是：**"B 路径 W13–W20 leaked 全 0"** + **"起飞率 1.000"**。

### 2.1 错配①——对象错配：B 路径不是"外环肉盾"构筑

| | V-6 问的对象 | 质量门测的对象 |
|---|---|---|
| 构筑 | **外环高 HP 肉盾塔**（主动堆 HP，吸仇恨当墙） | **B = 多塔清场流**（金标本参考路径，`cfg_of("B")`，8 槽 × `max_actions=12`） |
| 建造者 | **玩家**（一种主动 build 决策） | **金标本 `shop_ai`**，🟢 已确认是 **DPS 贪心**（`mechanics-bulwark-cycle.md` §13：「金标本 AI 是 DPS 贪心」；同文 R-B18′ 亦指出"故意让塔死着/不修"这类肉盾玩法**需玩家行为，金标本 AI 覆盖不到**） |
| 目标量 | 肉盾构筑下的漏怪数 | 多塔 DPS 流下的漏怪数 |

→ **金标本 AI 是 DPS 贪心，它永远不会建造"外环高 HP 肉盾"。** 用 B 路径去回答 V-6，等于用一个**根本不包含被测对象**的样本去判定该对象的性质。

**V-6 的真实对象有没有被单独测过？没有。** 现存最接近的是 `run_slice_bulwark8.gd`，但它测的是"主力塔是否被移到径向安全位"（`B-G8-1/2/3`，暴露度语义兑现），**不是肉盾构筑的胜率**。

### 2.2 错配②——机制错配：B 路径波末**没有残留怪**，§2.9 一次都没触发

质量门自己引的探针原文（`quality-gate-radial-migration.md` §2.3 L92–95）：

```
[RADIAL 多塔 B 路径 attrition=1.5]  逐波 leaked: W1..W20 全为 0，kills 全 = n
    → 全程累计 dis_new=0 · 末波 core_hp=1000.0
[RADIAL 多塔 B 路径 attrition=50（33×）] 逐波同上
```

🔴 **`kills 全 = n` 是决定性的**：B 路径每波的 `n` 只怪**全部被打死**。

- `killed = n` 且 `leaked = 0` ⟹ 波次硬性结束时刻（`D + t_reach`）场上**残留怪数 = 0**；
- ⟹ §2.9「波末残留怪直接移除」这条规则**在 B 路径上从未执行过一次**；
- ⟹ B 路径"漏怪恒 0"的因果解释是 **「后期 DPS 足够把全场清光」**，**不是**「肉盾吸住怪 → 拖到波末 → 残留消失」。

**V-6 的因果链第二个环节（"波末残留消失"）在 B 路径上根本不存在。** 这正是主理人提示的那处混淆，且**探针日志本身（`kills 全 = n`）就是硬证据**。

> 换个说法：V-6 担心的是"**打不过但拖得起**"。B 路径展示的是"**打得过**"。这是两件不同的事，后者不构成 V-6 意义上的主导解——它只是数值强度问题，而"多塔流比单核流强"是自 V-0′ 起就已登记的金标本既有画像（`B/A < 1` 是 S5-D1 的**判据**，不是缺陷）。

### 2.3 错配③——判据口径错配：`起飞率 B = 1.000` **不是起飞率**

🔴 这一条是我在读码时发现的，质量门 §3.3-⑤ 已把它登记为 R-5，但**它没有被回扣到 V-6 的判定上**。

`tests/run_slice_attrition8.gd` L127–128：

```gdscript
if (not out["rows"].is_empty()) and float(out["rows"][-1]["core_hp"]) > 0.0:
    takeoff_b += 1
```

→ 它把「**末波 `core_hp > 0`**」记为 `takeoff`，这是 **W20 存活率**，不是起飞率。
旁证：同脚本 A 侧"起飞率" = `0.617`（缺陷期）/ `0.597`（修复后），**与 A 存活率同值**。

规范的起飞率是 `RunLoopAggro.takeoff_rate`（`run_loop_aggro.gd` L147–173，走 `_Stats.takeoff_wave(rows)`），也是六槽金标本 `slice2` 的口径。

**同一条 B 路径，两个定义给出两个答案**：

| 定义 | 实现 | B 实测 | vs V-6 阈值 **≥0.98** |
|---|---|---|---|
| `attrition8` 自算（实为**存活率**） | `core_hp > 0.0` | **1.000** | ✅ 通过 |
| **规范起飞率**（金标本口径） | `RunLoopAggro.takeoff_rate` / `_Stats.takeoff_wave` | 🟡 **0.913–0.917**（修复后 MC；`slice2` 定稿 0.917/0.990；`slice5` 0.917） | ❌ **不通过** |

> 数据来源：`v8-default-regression-final.log`（**10-09 12:05，修复后**）L986–987「B：起飞率 **91.3%** 存活率 100.0%」、L1789「B：起飞率 **91.7%**」。
> ⚠️ **诚实标注**：这两个数是**六槽金标本**（seed `20260930`）口径，`attrition8` 的 1.000 是**八槽 RADIAL**（seed `20261002`）口径 —— **配置不同，不可直接相减**。但它们已经足够说明一件事：**V-6 的 `≥0.98` 阈值在规范起飞率口径下没有任何一个读数支持**。而 R-5（统一到 `RunLoopAggro.takeoff_rate`）至今未闭合 → **这个判据目前不具备稳定的可测量性**。

### 3.3 "波末残留消失 = 必胜解"是否成立

**在现有证据下：不成立，且当前不可证伪。**

1. **B 路径：规则从未触发**（`kills ≡ n` → 波末残留 = 0）→ 见 §2.2。
2. **A 路径／肉盾路径：规则即使触发，代价是对称的** —— 被拖住的怪没有漏，但**吸住它的那座塔整段时间没有输出**（§2.9 L419 自带论证），且径向模型下外环塔暴露度更高、会死（V-4 实测肉盾 0.580 在红线之下）。
3. 🔴 **最要命的一条：目前没有任何计数器度量 §2.9 是否在做功。** 全场搜不到"波末残留怪数"这一埋点 —— 既没有 `residual_cleared`，也没有等价量。**V-6 目前是一个不可测量的命题**：它的核心机制量不存在，所以任何"已触发/未触发"的判定都只能是代理推断。质量门的判定正是这样一次代理推断。
4. `ATTRITION` 上调已证伪（33× 无效）→ 只能说明 **B 路径不掉塔**，**不能**说明"残留规则导致了必胜"。

## 4. 裁决

### 4.1 裁决结论：🟢 **(b) V-6 未触发 / 证据测错对象**

**V-6 保持开放观察（🟡 T1），不立项缓解，不动 `ATTRITION`，不动 §2.9，不动几何 / `AGGRO_R` / 怪物 HP。**

理由链（四步，每步都有硬证据）：

1. **判据二不成立**：V-6 的 `起飞率 ≥0.98` 在**规范起飞率口径**下 B ≈ 0.913–0.917，**不达标**；达标值 1.000 来自一个**把存活率标成起飞率**的脚本分支（§2.3），而该口径分歧（R-5）至今未闭合 → **判据本身不具备稳定可测量性**。
2. **判据一测错对象**：`W13+ 漏怪恒 0` 观测自 B 多塔 DPS 清场流，**不是**外环高 HP 肉盾构筑，且金标本 AI（DPS 贪心）**不可能**建造该构筑（§2.1）。
3. **判据一测错机制**：B 路径 `kills ≡ n` → 波末残留 = 0 → §2.9 **一次都没触发**，"漏怪 0"的成因是 **DPS 清场**而非"残留消失"（§2.2）。V-6 因果链的第二个环节在样本中不存在。
4. **反向实证**：肉盾本体的存活率在所有已测形态下为 **0.5709–0.5919**，且 V-4「A 理想肉盾」在修复后**从 0.623 降到 0.580** —— 肉盾在**变弱**，不是一个 58% 胜率的东西能叫"必胜解"（§2.5）。

> 🔴 **同时必须诚实标注**：本次裁决的结论是「**质量门没有证明 V-6 触发**」，**不是**「V-6 已被证明安全」。V-6 的正确对象（外环高 HP 肉盾）**至今一次都没被测过**。两者不能混为一谈。

### 4.2 为什么不选 (a)（真触发 → 立项缓解）

- 触发判据依赖的三个数字里，**两个口径错配、一个对象错配**（§2.1–2.3），不足以支撑一个 🔴 P1 立项。
- 立项后能动的三类杠杆（几何 / `AGGRO_R` / 怪物 HP）**全是已定稿数值**，而**现有证据连"问题存在"都没建立**。在事实基础未建立前动定稿数值，是**双重错误**（与 `v7-final-adjudication.md` 拒绝在 V-7 INCONCLUSIVE 时改 §2.3 定性同一纪律）。
- `ATTRITION` 上调已被证伪；剩下三条杠杆里没有一条有"当前读数支持它必要"的证据。

### 4.3 为什么不选 (c)（触发但可接受）

- (c) 的前提是"触发成立"。**前提不成立**（§4.1）。
- 但 (c) 的**论证本身是有效的备用兜底**，我把它留在文档里：**即便未来用正确对象测出"外环肉盾零漏怪"，在当前设计哲学下也不必然要修** —— 现定哲学是「肉盾 = 消耗品/弹药（死了 = 打完）、复活 = 补给/重新装填、玩家情绪 = 死得值（非别死）」，M-1 复活已采纳（T-E1 合规）。在这个框架里，外环肉盾"扛住一波"是**它的职责被兑现**，而不是机制被绕过。**若 §6 的重验真的触发，建议优先走 (c) 路线而非动定稿数值。**

### 4.4 🔴 一条不该被忽略的观察（诚实标注，不进裁决）

金标本 MC 里 **B 路径存活率 = 100.0%**（`v8-default-regression-final.log` L987，修复后），而 A 只有 69.3%。**"多塔流几乎必生还"**这件事是真的，**但它自 V-0′ 起就是金标本的既有画像**（`B/A < 1` 是 S5-D1 的判据项，`slice2` 定稿即如此），**不是径向引入的新问题，也不是 V-6 的对象**。
→ 如果主理人真正担心的其实是"**多塔流整体太安全、单核流没有生存空间**"，那是一个**不同的命题**，应单独立项（建议名 `V-6′`：多塔流安全裕度过厚），**不要挂在 V-6 名下** —— 挂错名字会让正确的杠杆也被带偏（V-6 杠杆 = 肉盾续航/§2.9 残留规则/`ATTRITION`；多塔安全性问题杠杆 = 后期压力源：怪物曲线/几何/数值）。

> ✅ **2026-10-09 主理人拍板 Q-V6-2 = (a) 单独立项 `V-6′`**（四项拍板之②，"按推荐"采纳）。
> 📄 **立项规格已落地：`docs/phase3/qg-radial/v6prime-multitower-margin.md`**。要点：
> · **命题校准** —— 真正该问的不是「B 能不能活下来」，而是「**B 的活下来是不是付了钱**」（对价 = `B/A` W20 ratio 显著 <1，即 A 仍是后期 carry）；
> · **杠杆归属** —— V-6′ 杠杆 = **后期压力源（怪物曲线 / 几何 / 数值）**，与 V-6 的肉盾续航/§2.9 杠杆**分案，不得合并**；
