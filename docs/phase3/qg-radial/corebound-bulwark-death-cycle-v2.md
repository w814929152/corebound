## 0. 三句话结论（给赶时间的人）

1. 🟢 **用户的二分是对的，而且它把 v1 的头号风险（R-B1 空窗期）从"半波 + 整个波次间隔"压缩到"复活延迟 N"** —— 量级下降一到两个数量级。🔴 **但没有归零，且它的形态与我 v1 建模的不同**：空窗期的危害**不是**"怪物转向 carry 把 carry 点掉"，而是"**怪物解锁 → 恢复前进 → 直接漏向核心**"（`:140` 冻结 vs `:351` 解锁，见 §2.1）。→ 🟢 这反而**更好处理**：它变成一个**纯参数问题（N）**，而不是一个需要新机制（残骸嘲讽）才能解决的结构问题。**Q-B3 可以降级。**
2. 🔴 **T-C1 裁决：战斗内即时复活不触碰 T-C1** —— T-C1 的约束对象是**玩家输入**（"塔被打时玩家**不能**修/卖/加固/撤退"），而 GDD §2.6 自己就把"塔挨打、反击、停机"全列为**自动行为**。🟢 **但它必须过三层检验**（L1 输入 / L2 注意力 / L3 语义），其中 **L3 是安全红线**：资格判定（暴露位 & 非 carry）一旦误判，carry 会在战斗中被反复重启 → 那不是"弱化惩罚"，那是**取消塔死亡机制**（§3）。
3. 🟢 **与 FREE 臂的本质区别不但仍成立，而且更硬了** —— v1 我诚实说过"时序结构本身没有区别"（§3.3）；**时点修正之后，时序结构有了区别，而且这个区别的符号由角色决定**：同一个"战斗内即时复活"，施加在 carry 上**比波首复活更糟**（同波内反复重启、反复归零 DPS、96.78% 再暴露被拉满），施加在肉盾上**显著优于波首复活**（仇恨在线率从"半波+"提升到"1 − N/波时长"）。→ **两者不是程度差异，是方向相反。**（§4）

## 2. R-B1 空窗期重估（任务 1）

### 2.1 🔴 首先：空窗期的真实机制形态（v1 建模不准确，必须更正）

我读了 `wave_sim_aggro.gd` 的怪物状态机，v1 §3.3 的"空窗期谁扛伤 = carry"这个建模**机制上是错的**：

| 代码事实 | 位置 | 含义 |
|---|---|---|
| `if int(m[2]) == 1: alive.append(m); continue` | `:140` | **AggroTower 怪 = 完全冻结**：停下、`t_remain` 冻结、**不前进、不漏怪**。→ 🟢 **肉盾吸火 = 完全中和该怪**，这是机制价值的来源 |
| `if not _aggro_target_valid(...): m[2] = 0; m[3] = -1` | `:351` | 目标塔一旦 `Disabled` → 怪**立即回 Marching**（恢复前进）→ 🟢 **不是"换目标打 carry"，是"解锁并继续走"** |
| `if t == null or bool(t.disabled): return false` | `:462` | Disabled 塔**不在仇恨候选池** |
| `if bool(t.disabled): continue` | `:443` | 同上，`_nearest_exposed_tower` 跳过 Disabled 塔 |
| 每个 `DT` 步进都重跑 `_nearest_exposed_tower` | `:344` | 🟢 **重获取是每帧连续的** → 复活生效后**后续**的怪会自动重新锁它 |

> 🔴 **结论（v1 更正）**：**空窗期的危害不是"carry 暴露"，而是"怪物解锁 → 恢复前进 → 漏向核心"。**
> 在 **bulwark 口径**下这一点更强：carry 要么被 `protect_core` 直接跳过（`_nearest_exposed_tower` 的 `core_slot` 排除），要么被 `_relocate_carry_to_safe` 挪到 `d_path > AGGRO_R` 的安全位 → **carry 根本进不了仇恨候选池**。→ 肉盾一倒，**候选池为空** → 怪物一路走向核心。
>
> 🟡 **这同时意味着 v1 §7.2 定的机制主判据 `carry_exposure_time` 是无效的** —— 它在 bulwark 口径下恒 ≈ 0，测不出任何变化（§7）。

### 2.2 空窗期的量级：从"半波 + 波次间"压缩到"N 秒"

| | v1（波首复活） | v2（战斗内即时复活） |
|---|---|---|
| 空窗期时长 | **半波 + 整个波次间隔**（≈ 20–30 s + 间隔） | **复活延迟 `N`**（× 波内死亡次数） |
| 量级 | 🔴 波次时长的 **40–60%** | 🟢 `N / wave_dur`（`wave_dur = 28.0 + 2.2w`，W6≈41 s / W12≈54 s）→ 若 `N ≈ 4 s`，约 **8–10%** |
| 是否引入新时序问题 | — | 🟡 **是，两个**（§2.3） |

> 🟢 **量级下降约一个数量级** → R-B1 从"🔴 最高·可能致命"降为"🟠 中·但成为核心扫参对象"。

### 2.3 🆕 引入的两个新时序问题

**(a) 复活延迟内"已经流过去的水收不回"（R-B1′）**
解锁的怪在 `N` 秒内前进 `N / t_reach` 的路径比例。若一只怪被锁时剩余时间 `T`：
- `N < T` → 不漏，但**推进了 `N` 秒**；复活后若它还在 `AGGRO_R` 内则重新被锁，若已走远则**永久漏过**（`AGGRO_EXIT` 迟滞带不会让它回头）
- `N ≥ T` → **直接漏怪**（核心 −50/只）

→ 🟢 **这给出一个天然的、极好的张力**：**肉盾死得越晚（怪已推进越深、`T` 越小），同样的 `N` 越致命。** 玩家要管理的不是"肉盾会不会死"（它一定会死），而是"**它会不会死在错的时刻**" → **P1 / P3 直接兑现**（站位与耐久投资决定了它死在哪个时刻）。

**(b) 仇恨重定向的时点抖动（R-B1″）**
复活生效瞬间，该塔重新进入候选池 → 正在 `AGGRO_R` 内的怪会**改锁它**（🟢 这是机制目的）。但：
- 若此时**另一座塔**（如副 carry）也在 `AGGRO_R` 内且更近 → 仇恨会先锁那座 → 肉盾复活**当波可能白复**
- 若复活时 `AGGRO_R` 内已无怪（怪全走远）→ 复活**当波零收益**

→ 🟡 判据影响：`bulwark_aggro_share`（实际吸火）会被"怪是否恰好经过"这个**无关因素**污染 → 必须新增**上游量** `bulwark_uptime`（§7）。

### 2.4 复活速度 ≥ 消耗速度（v1 §2.3 前提 2）的重估

v1 前提 2：每波复活 1 次 vs 每波消耗 1 次 = 打平；**若一波内肉盾死两次则打不平**。

时点修正后，这个问题**消失了**：波内即时复活可以发生 `K` 次 → **消耗速度被 `K+1` 条命覆盖**。
→ 🟢 **但它换成一个更需要警惕的问题**：`K` 越大，肉盾越接近**永动机** → **塔死亡机制在 A 路径失去牙齿**（§6 R-B10）。→ 🔴 **`K` 与 `N` 是同一枚硬币的两面：`N` 是代价，`K` 是上界，必须双闸。**

## 3. 🔴 T-C1 协调裁决（编排者点名，任务 3 的核心）

### 3.1 T-C1 的原文与它的约束对象

| 出处 | 原文 |
|---|---|
| GDD §2.2 硬约束表 | 🔴 **T-C1 战斗内零可操作** —— 「塔被打时玩家**不能**修/卖/加固/撤退。所有响应压缩到波次间安全窗。→ 塔死亡是 **build 风险**，不是**操作考验**」 |
| `card-system` §4.3 补红线 | 「战斗内完全禁止任何与**塔存活相关的操作**（不能修 / 不能卖 / 不能加固 / 不能撤退）」 |
| GDD §2.6 对 P1 的论证 | 「玩家是否会因此操作单位？✅ **不会** —— 塔**挨打、反击、停机全部是自动行为**」 |
| GDD §2.6 对 P4 的论证 | 「波次内新增 **0 输入**」 |

> 🟢 **关键读法**：T-C1 的**约束对象是玩家的输入**，不是系统的状态机。GDD §2.6 自己就明确把"塔挨打 / 反击 / **停机**"列为**战斗内的自动行为**并判定"不违反 P1"。**战斗内自动重启与"自动停机"是同一类东西** —— 都是系统对塔状态的自发转移。

### 3.2 🏆 裁决：三层检验

| 层 | 检验项 | 判定 |
|---|---|---|
| **L1 · 输入层**（T-C1 **字面**） | 战斗内是否新增**玩家输入**？ | ✅ **0 输入** → **合规**。判据 = §2.6 的「波次内新增 0 输入」这一硬指标 |
| **L2 · 注意力层**（T-C1 **立意**："塔死亡不会把注意力从商店拉回战场"） | 战斗内是否需要玩家**观察 / 等待 / 择时**才能受益？ | 🟢 **若做成"无声自动重启、无倒计时、无择时提示" → 合规**。<br>🔴 **若做成"复活倒计时 / 看准时机触发 / 战斗中提示玩家确认" → 字面合规但立意违规**（注意力被拉回战场 = T-C1 要防的那个伤害）。→ 🔴 **列为实现红线**：战斗内**不给**任何需要读数的 UI（同时受 T-C2 约束） |
| **L3 · 语义层**（§2.3 理由 5「惩罚依然真实且沉重」/ 支柱漂移） | 是否稀释"塔死亡惩罚真实"？ | 🟢 对**肉盾**：**这是设计意图**（消耗品，损失是预期的）→ 豁免成立。<br>🔴 对 **carry**：**致命** → 那不是稀释惩罚，是**取消塔死亡机制**。→ 🔴 **资格判定 = 安全红线**（§3.3） |

> 🏆 **裁决（一句话）**：
> **战斗内即时复活（系统自动、零玩家输入、零择时提示）不触碰 T-C1。但它是对 §2.3 理由 5 的一次「定向豁免」—— 豁免范围必须严格限于「暴露位 且 非 carry 的塔」，并由资格判定这道闸门守住。**
>
> 🔴 **这不是"T-C1 破例"，是"T-C1 的约束对象未被触及"**：T-C1 管玩家，本机制管系统。二者不在同一个主语上。
> 🟡 **但我建议显式登记这条豁免**（Q-B0‴）—— 否则后续评审会反复在"这违反 T-C1 吗"上打转。

### 3.3 🔴 安全红线：资格判定（v1 §4.1 (iii-a) 升级）

v1 的推荐是「复活资格 = 死在**暴露位** 且 **非 `h` 最高**（非 carry）」，零新字段，复用 `slot_exposure[_radial].is_exposed` 与 `h` 最高判定。

**时点修正后，这条从"设计选择"升级为"安全红线"**：

| | v1（波首复活）下误判的后果 | v2（战斗内即时复活）下误判的后果 |
|---|---|---|
| carry 被误判为肉盾 | 🟠 carry 复活后**下一波**又被打停 → 弱化惩罚 | 🔴 carry 在**同一波内**被反复重启 → DPS 反复归零 → **塔死亡机制对 A 路径被实质取消**（且 V-7 已证：carry 一停 ⟹ 失守 100%，这里的后果是**反向**的：它不停了，**机制没了**） |

> 🔴 **实现要求**（列入 §9 交接点）：**`revive_misqualify`（非暴露位 或 carry 却触发了战斗内重启的次数）必须恒 = 0，并在 V-8 里作为硬断言跑出来。非 0 → 该臂作废，修后重跑。**

### 3.4 🟡 与 V-7 终审 (b2)「自动重启」的关系（必须诚实登记）

V-7 终审 §4.3 给了 (b) 的三条子形态，我把 **(b2)「缩短 Disabled 持续 / 自动重启」排在最末**（`(b3) > (b1) > (b2)`），理由：「可能让塔死亡失去'真损失'重量（§2.3 理由 5）」。

**用户本轮的澄清，实质上指向 (b2)。** 我必须说明为什么这不构成翻案：

| | (b2) 在 V-7 的语境 | 本轮的语境 |
|---|---|---|
| 作用对象 | **所有塔**（金标本口径，死的就是 carry） | 🔴 **仅暴露位 & 非 carry**（bulwark 口径） |
| 反对理由「失去真损失重量」 | 🔴 **成立**（carry 的损失是真损失） | 🟢 **不成立**（肉盾的损失是**预期内的职责完成**；v1 §1.2 范畴错误诊断的直接推论） |
| 反对理由「稀释惩罚」 | 🔴 成立 | 🟡 **部分成立** → 由 **`N`（延迟代价）+ `K`（次数上界）双闸**兜住 |

> 🟢 **这不是翻案，是限定作用域**：**(b2) 对 carry 仍然不采用（V-7 排序不变）；对暴露位肉盾可以采用，但必须带 `N` 与 `K` 两道闸。**
> 🔴 且两道闸**缺一不可**：只有 `N` 没有 `K` → 长波里可以刷无限次复活 → 永动机；只有 `K` 没有 `N`（`N=0`）→ 无缝重启 → 同样接近永动机。

## 4. 与 FREE 臂的本质区别是否仍成立（任务 3）

### 4.1 🟢 成立，而且更硬：时序层现在是第三层区别

v1 §3.3 我诚实写过：**「时序结构本身没有区别」**（FREE 臂与肉盾循环的空窗期都是"半波 + 波次间隔"）。这句话是 v1 里最危险的一句 —— 它意味着在时序维度上两者同构。

**时点修正之后，时序结构有了区别，且符号由角色决定：**

| | **FREE 臂**（波首复活 carry） | **肉盾循环 v2**（战斗内即时复活肉盾） |
|---|---|---|
| 死亡时刻 | 波 `w` 中 | 波 `w` 中 |
| 复活时刻 | 波 `w+1` 首 | **波 `w` 内 · `N` 秒后** |
| 空窗期 | **半波 + 整个波次间隔** | **`N` 秒** |
| 空窗期危害 | carry 暴露挨打 | 🔴 **怪物解锁 → 漏向核心**（§2.1） |
| `⊖` 重新暴露 | 🔴 致命（V-7：96.78% 修完又被打停） | 🟢 **功能**（暴露 = 履职） |
| **若把"战斗内即时复活"施加到 carry** | — | 🔴🔴 **比波首复活更糟**：同一波内反复重启 → DPS 反复归零 + 每次重启都重新暴露 → **把 ⊖ 的触发频率从"每波一次"拉到"每波 K+1 次"**（v1 §3.1 已论证 FREE 臂的病灶正是"把 ⊖ 的频率拉到满"） |

> 🔴 **强结论**：**同一个"复活时点"参数，对 carry 与对肉盾的符号相反。**
> - 对 **carry**：战斗内即时复活 **<** 波首复活 **<** 不复活
> - 对 **肉盾**：战斗内即时复活 **>** 波首复活 **>** 不复活
>
> 🟢 **这把 v1 §3.1 的核心论证（`⊖` 的符号由角色决定）从"价值函数层"扩展到了"时序层"** —— 现在**价值函数和时序函数的符号都由角色决定**。
> → **与 FREE 臂的区别因此更硬，不是更软**：FREE 臂的病（对"暴露 = 事故"的对象施加必然暴露）在战斗内即时复活的形态下会**更严重**，而肉盾循环在**同一形态**下**更有效**。→ **两者不是程度差异，是方向相反。**

### 4.2 但 ⊖ 的符号偏向 feature 到什么程度？（任务 3 的第 3 问）

上一轮的结论是「对肉盾，`⊖` 从副作用翻转为功能」。时点修正后：

| 量 | v1（波首复活） | v2（战斗内即时复活） | 变化方向 |
|---|---|---|---|
| `⊕₂` 仇恨吸收能力恢复 | 每波恢复一次，**在线率 ≈ 50–60%** | 每波恢复 `K+1` 次，**在线率 ≈ 1 − (K+1)·N/波时长** | 🟢🟢 **大幅提升** |
| `⊖` 重新暴露 | 🟢 功能 | 🟢 功能（**更强** —— 暴露得更频繁 = 履职得更充分） | 🟢 **进一步偏向 feature** |
| 新增 `⊖′` 复活延迟内的漏怪 | 不存在（复活在安全窗） | 🔴 **全新成本项** | 🔴 **新增**（这是 `N` 的本质） |

> 🟢 **净判定**：符号**进一步偏向 feature**，但**不是无代价地偏向** —— 新增的 `⊖′`（延迟漏怪）是它的对价，且 `⊖′` 完全由 `N` 一个参数控制。
> → 🏆 **这正是好设计的形状**：**一个机制的收益（`⊕₂`）与成本（`⊖′`）被收敛到同一个旋钮上**，扫这一个参数就能定档。这是 v1 完全没有的性质（v1 里收益与成本是两个机制、两套代码）。

### 4.3 🔴 反面：它必须仍然"有牙齿"（防止过度修正）

时点修正让机制变强了。必须防它强过头：

| 失效模式 | 表现 | 判据 |
|---|---|---|
| **永动机** | 肉盾几乎全程在线 → A 路径塔死亡**不再产生任何后果** | `bulwark_uptime → 1.0` 且 `n_td_form → 0` |
| **后果** | 🔴 塔死亡机制（本 GDD 的主体）在 A 路径被架空 → 与 FREE 臂"架空 §2.3"是**同类错误**（v1 §1.3 / §3.4） | 🔴 **预注册为独立否决分支**（§7.5 "过度" 分支） |

> 🔴 **一句话**：**机制的目标不是"让肉盾不死"，而是"让肉盾的死变成一种节奏"。若肉盾变成不死，机制就失败了 —— 而且是比 v1 那种失败更隐蔽的失败（v1 是"太弱看不到效果"，v2 是"太强把机制取消了"）。**

## 5. 两个机制的分别设计（任务 2）

### 5.1 🆕 M-1 · 战斗中复活（即时 / 被动 / 系统发起）

> 🔒 全部参数 `PLACEHOLDER`，需 V-8 扫参定档。🔴 默认 off，off 时逐位不变。

#### (1) 触发条件

| 方案 | 机制 | 判定 |
|---|---|---|
| **(R1) 固定延迟 `N` 后自动重启** | 塔 `Disabled` → 计时 `N` → 自动清 `disabled` + `hp = hp_max`（复用 `_clear_disabled`，`:283` 已有该 helper） | 🏆 **推荐** —— 唯一把收益与成本收敛到同一旋钮的方案（§4.2） |
| **(R2) 消耗完即复活（`N = 0`）** | HP 归零瞬间重启 | 🟡 **若用户坚持"即时 = 0 延迟"** → 🔴 **必须把代价移到 HP 折损上**（见 (2)），否则 R-B10 失控 |
| **(R3) 条件触发**（怪清空 / 波内第 k 次） | — | ❌ 不推荐（条件不可读 → T-C2 违规风险；且引入新状态） |

**`N` 的参数化建议（🟢 scale-free）**：
`N` 的语义是"解锁怪在复活延迟内前进的路径比例 = `N / t_reach`"。→ 🟢 **建议用 `N` 占 `t_reach` 的百分比参数化**（跨波次尺度无关），而不是用绝对秒数。

#### (2) 代价与次数限制（🔴 防无限循环，本轮最关键的设计约束）

v1 的代价方案是「占 1 个波次间动作位」—— 🔴 **这个代价在战斗内不成立**（动作位在波次间，时序不对）。必须换代价体系：

| 代价 | 机制 | 是否时序同构 | 判定 |
|---|---|---|---|
| 🏆 **(i) 复活延迟 `N` 本身就是代价** | 延迟内怪物解锁 → 推进 → 可能漏怪 | 🟢🟢 **完全同构**（代价就在空窗期里） | 🏆 **推荐（主）** |
| 🏆 **(ii) 波内次数上限 `K`** | 每波每塔最多重启 `K` 次 → `K` 用尽后不再重启，保持 `Disabled` 到波次间 | 🟢 **同构**（封住上界） | 🏆 **推荐（辅，必选）** |
| 🟡 **(iii) 每次重启 HP 折损**（如 ×0.6 几何衰减） | 重启后越来越脆 → 自然收敛 | 🟢 同构 | 🟡 **备选**：若用户选 `N = 0`，**(iii) 升为必选**；否则可省（省一个扫参维度） |
| 🔴 **(iv) 战斗中扣 Scrap** | — | 🔴 **否** | ❌ **不推荐**：战斗中扣钱但玩家没操作 → **归因模糊**（违反概念 §4.1），且逼近"战斗内经济决策"（T-C1 / 职责切分铁律的边缘） |
| 🔴 **(v) 无条件无限次** | — | — | 🔴🔴 **否决** = 永动机 = 取消塔死亡机制（§4.3） |

> 🏆 **推荐组合：`N`（主代价）× `K`（上界）双闸，`K = 1` 起步，HP 满血重启。**
> 🟡 **条件分支**：若用户拍 `N = 0`（真正的"即时"），则改为 **`N=0` × `K=1` × HP 折损必开**，否则机制无代价。

**🔴 `K` 用尽后的语义衔接（🟢 这是本设计最好的一个性质）**：
`K` 用尽 → 塔保持 `Disabled` → 波次间走 **§2.3 三选一**（修 / 拆 / 放着）。
→ 🟢 **"这波它两条命都用完了 → 现在轮到玩家决定要不要花钱修它"** —— 一个**两层消耗品循环**：
- **第一层（战斗内 · 自动）**：`K` 次免费重启 = 它自己撑住的
- **第二层（波次间 · 玩家决策）**：`Repair` 花钱占动作位 = 玩家决定要不要继续供它

→ 🟢 **用户 P-1（波次间 = 决策窗）与 P-2（每波 = 一次检测）全部兑现**，且**两套代价体系各就各位、互不混淆**。

#### (3) 与仇恨机制（`:443` / `:464`）的交互

| 问题 | 答案 | 依据 |
|---|---|---|
| 重启后能否重新吸火？ | 🟢 **能，且零新代码** —— 每 `DT` 步进都重跑 `_nearest_exposed_tower`（`:344`），清 `disabled` 后该塔自动重回候选池 | `:443` / `:344` |

| 重启瞬间会不会造成"怪物原地反复打一座塔"的怪循环？ | 🟢 **不会**（同上，迟滞带 + 每帧重获取） | — |
| 🔴 **本轮是否改 `:443` / `:464`？** | 🔴 **不改**（与 v1 §8-4 同纪律：只读确认）。本机制**只改"谁会在战斗中解除 Disabled"**，不改仇恨规则 | v1 §8-4 |

> 🔴 **必须登记的物理上限**：**`Disabled → 重启` 期间，怪物是"解锁并前进"的，不是"等待"的。复活不是"无缝续挡"，而是"重新插一根柱子 —— 已经流过去的水收不回"。**（§2.3 (a)）

#### (4) 如何保持"肉盾是消耗品"的语义

| 项 | 规则 | 依据 |

| 重启**不是"复活"是"重启 / 重新装填"** | 措辞对齐消耗品语义 | v1 §1.2 |
| 重启**只在暴露位 & 非 carry** 生效 | 双闸门 | §3.3 安全红线 |
| 🔴 战斗内重启 **≠ §2.3 的 `Repair`** | 对象不同（肉盾 vs carry）· 时点不同（波内 vs 波次间）· 发起者不同（系统 vs 玩家） | §5.3 |

### 5.2 🟢 M-2 · 波次间重新部署（玩家主动）—— **不是新机制，是既有 P1 的延伸**

用户明确说这是**重新部署，不是复活**。所以：

| 项 | 内容 |
|---|---|
| **它是什么** | 波次间玩家移动塔位 / 重建塔 / 拆塔重放 / 调整"谁站暴露位" —— **这是玩法①「暴露度」的既有操作空间** |
| **成本** | 🟢 **零新机制**（若"移动塔位"尚未落地，那是另一个独立拍板项，不属本机制范围） |
| **🔴 与复活的关系（用户点名问的）** | **战斗内复活 = 原塔位原地重启**（同一塔对象的状态恢复，塔位不动，系统行为，不涉及部署）<br>**波次间部署 = 玩家改变"谁在暴露位"**，从而改变**下一波**谁有复活资格 |
| 🏆 **耦合点在"资格"，不在"位置"** | 🟢 **战斗内复活永远在原地**（不能靠移动来逃）→ 锁定"这座塔这座位就是消耗品"的语义<br>🟢 **波次间部署给玩家"我要不要换一个消耗品 / 换一个位置"的自由**<br>→ **P1 与 P4 同时被强化** |

**🟡 一个必须定的歧义（新拍板项 Q-B13）**：**`Disabled` 塔在波次间能否移动？**

| 方案 | 后果 | 判定 |
|---|---|---|
| 🏆 **(a) 不可移动** | 资格在死亡时刻就锁定（死亡时 `is_exposed` 快照），无需处理"移动后复活在哪" | 🏆 **推荐**：① 实现最简单；② 物理直觉正确（"停机 = 结构受损，拖不走"）；③ 🟢 **避免 V-8 数据被污染**（玩家把肉盾挪到安全位再复活 → 复活后不再吸火 → 机制失效但无害，会稀释样本） |
| **(b) 可移动** | 需定"复活位置 = 新位置"还是"原位置"；且"把死肉盾挪到安全位再复活"会成为规避手段 | 🟡 备选 |

> 🟢 **推荐 (a)，且它天然给出一个清晰规则**：**复活资格 = 死亡时刻的 `is_exposed` 快照 且 非 carry；复活位置 = 它当时站的位置（不可移动 ⇒ 恒等）。**

### 5.3 🔴 与 §2.3 的边界再收紧一条（v1 §6.1 的加强）

v1 §6.1 已划界：「预期内死亡（暴露位肉盾）→ 走复活循环；事故死亡（carry）→ 走 §2.3 三选一」。时点修正后需**再收紧一条**：
