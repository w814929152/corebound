## 0. 三句话结论（给赶时间的人）

1. 🔴 **这个设定不是"≈ FREE 臂"，它在批处镜像里与 FREE 臂逐位等价** —— 三处结构同构 + 两处措辞差异经核对**无任何数值后果**（§1.2）。因此 V-7 加跑（1480/臂双侧）的 FREE 臂结论**直接、完整地适用于它**：`Δ_free = −3.85pp`（z = −2.11，双侧显著，CI 上界 −0.003 < 0）、修好的塔 **96.78% 后续波又被打停**、`restore-events = 0`、`n_td_form` 319 → **403（+26%）**。→ 🟡 **它是 V-7 已测三个形态里实测最差的那个形态**，我不建议直接采用。
2. 🟢 **但用户的真实意图是可以救的** —— 意图是"让塔死亡不那么致命 / 给玩家翻盘机会"（胜任感诉求，概念 §4.1）。自动复活兑现的是 **charity（系统施舍）**，而不是 **agency（玩家补救）**：它不给玩家任何决策 → 归因破裂、胜任感反而保不住。数据也支持这个区分：**有条件/有代价的 PRICED 臂（+1.08pp）方向为正，无条件免费的 FREE 臂（−3.85pp）显著有害** —— 「越无条件越糟」是本次评估最硬的一条经验规律。
3. 🟡 **兼容性结论是分裂的**：它**加强** §2.5「不死锁」、🟢 **不触发** §3.6 支柱漂移警戒（实测 A 更差 0.5385，离 0.817 漂移线极远，反直觉但数据明确），🔴 但**架空 §2.3 的三选一结构**（`Repair` 分支失去对象、`repair_cost` 定稿失效）且**与 R-T10 的处置目标背道而驰**（它是加剧螺旋，不是打断螺旋）。→ ✅ 推荐走 **改良变体**（§4）：**复活 + 降再暴露（护盾）** > **条件复活（玩家付代价/占决策）** > **限次复活** > 延迟复活；❌ 部分复活（降输出）是**错方向**（⊖ 不变、⊕ 变小）。

## 1. 设定还原与等价性判定

### 1.1 用户原话与最小形式化

> **原话**：「加一个设定，在每波怪物攻击中死亡的塔，会在下一波开始的时候自动复活」

形式化：**对每座在波次 `w` 中进入 `Disabled` 的塔，在波次 `w+1` 开始时清 `disabled` 标记并回满 HP（不消耗资源、不占安全窗动作、不需要玩家输入）。**

### 1.2 🔴 等价性判定：**与 V-7 的 FREE 臂逐位等价**（不是"近似"）

| 维度 | V-7 FREE 臂（`repair_on_disable = 1`） | 用户设定（波首自动复活） | 是否等价 |
|---|---|---|---|
| **触发时机** | `run_loop_aggro.gd:96-107`：波 `w` 的 `shop_phase` **之后**清全部 Disabled | 波 `w+1` 波首清 | 🟢 **等价** —— 两者之间不存在任何其它事件（无 RNG、无结算），且波首 `_init_tower_hp`（`wave_sim_aggro.gd:78 → :255`）会对所有非 disabled 塔重算 `hp_max = HP0 × h^0.6` 并回满 → **HP 数值完全相同** |
| **覆盖范围** | `_clear_all_disabled(player)`：**全部** Disabled 塔 | 字面是"本波死亡的塔" | 🟢 **等价** —— 在本设定下，任何 Disabled 塔都必然是"上一波刚死的"（每波都复活 ⇒ 没有塔能 Disabled 超过一波）→ 两个读法收敛为同一集合 |
| **代价** | 不扣预算、**不计 `max_actions`**（`E-V7`：否则"免费"会挤占动作预算） | 不消耗任何资源、不占动作 | 🟢 **等价** |
| **对 `shop_ai` 的可见性** | 清标记发生在 `shop_phase` **之后** → 本波安全窗内 `shop_ai` 看到的仍是 Disabled | 复活发生在下一波波首 → 本波安全窗内同样是 Disabled | 🟢 **等价**（决策路径逐位一致） |
| **不动的量** | 不动 `h` / `attach` / `n_hist_max` | 未提及 → 同 | 🟢 等价 |

> 🔴 **判定**：**用户设定 ≡ V-7 FREE 臂**，且是**逐位等价**（不是"机制相似"）。因此 V-7 加跑对 FREE 臂的全部实测结论**无需任何外推即可直接引用**。
> 🟡 **唯一保留**：V-7 只在**金标本 AI 口径**下测过（`shop_ai` 纯 DPS 贪心、不保塔、不重定位）。**玩家口径**（暴露度 UI + 保塔/肉盾）下的符号**未知**（§5.3 给出该口径的验证分支）。这是"需重跑"的第二个理由，不是推翻等价性的理由。

### 1.3 与 FREE 臂对比的"唯一实质差异"：**没有**

不存在任何实现细节能让"波首自动复活"跑出与 FREE 臂不同的数字 —— 除非同时改动下列三者之一（那它就不再是本设定，而是 §4 的变体）：

| 若额外改动 | 变成什么 | 归属 |
|---|---|---|
| 复活后塔**不**重新进入仇恨池（临时豁免/降权重） | §4 变体 **B1**（复活 + 降再暴露） | 本评估推荐 #1 |
| 复活需要**玩家付代价 / 占决策** | §4 变体 **B2**（条件复活）≈ PRICED 臂 | 本评估推荐 #2 |
| 复活**有次数上限** / **隔 N 波** / **降阶** | §4 变体 **B3 / B4 / B5** | 见 §4 |

## 2. 与 V-7 数据的一致性：**直接适用，且落在最差的一端**

### 2.1 实测数字（1480/臂 · A 路径 · seed 20261002 · 双侧 · 参数锁死）

| 臂 | `surv` | `n_td_form` | `n_td_any` | `hit_surv`（X_form 主口径） | `Δ` vs OFF | z | 95% CI |
|---|---|---|---|---|---|---|---|
| **OFF** | **0.5770**（854/1480） | 319 | 626 | **0**（0/854） | — | — | — |
| 🔴 **FREE（≡ 用户设定）** | **0.5385**（797/1480） | **403（+26.3%）** | **683** | **0**（0/797） | **−0.0385** | **−2.11 [sig]** | [−0.07427, **−0.00276**] |
| **PRICED** | **0.5878**（870/1480） | 356 | 627 | **0**（0/870） | **+0.0108** | +0.60 [ns] | [−0.02472, +0.04634] |

**机制计数（决定性）**：

| 计数 | FREE | PRICED |
|---|---|---|
| `n_repair_eligible` | 683 | 627 |
| `fired`（修复成交次数） | 2975 | 2849 |
| `then_redied`（修好后续波又被打停） | **661** | 605 |
| **`then_redied / eligible`** | **0.9678** | 0.9617 |
| **structural restore-events**（修完活过 ≥1 整波） | **0** | 35 |

> 🔴 **四条结论，逐条适用于用户的设定**：
> 1. **显著有害**：Δ = −3.85pp，z = −2.11，CI 上界 −0.00276 < 0（C1 成立，V-7 终审 §3）。
> 2. **修了也白修**：96.78% 的复活塔在后续波又被打停；**0 次**"复活后活过一整波"。
> 3. **复活制造更多死亡**：`n_td_form` 319 → 403（**+26%**）→ 复活不是减少塔死，是**增加塔死事件**。
> 4. **越无条件越糟**：`d_free < d_priced`（单调性已撤除，非 bug）→ **无条件全修是三臂中最差的一臂**，而用户的设定正是"无条件"的极端形态。

### 2.2 🟡 诚实标注：**这个"有害"的证据强度是边际的，不要过度解读**

| 事项 | 说明 |
|---|---|
| **显著性勉强** | z = −2.11 刚过 1.96；CI 上界 −0.00276 几乎贴 0。它是**真实信号**但不是"巨大灾害"（相对降幅 ≈ −6.7%）。🟢 我的建议仍然是"不直接采用"，但理由是"**有证据有害 + 无证据有益 + 架空 §2.3**"，不是"灾变"。 |
| **机制未完全分解** | V-7 只坐实了"符号 + 计数"，**未分解 −3.85pp 的因果链**。下面三条是待验证假设（§5.4 的验证方案须把三者分开）： |
| 🟠 **H1（主假设 · R-T11）** | **再暴露螺旋**：复活的塔满血重入仇恨池（`wave_sim_aggro:443/:464` 只跳过 `disabled`）→ 再被打停（96.78%）→ 每次打停 = 该波内 DPS 崩一次 → 漏怪增加。指纹 = `n_td_form` +26%。 |
| 🟠 **H2（时间账）** | AggroTower 态**冻结 `t_remain`、不漏怪**（`wave_sim_aggro` 主循环 ③）→ 按理是好事；但若塔很快再死，停怪只是**把漏怪延后到同波后半段**，而那时 DPS 已崩 → 净效果 ≈ 0 甚至更负。🟢 可检验（看 `leaked` 的波内时间分布）。 |
| 🟠 **H3′（投资锁死 · 解释 FREE 为何差于 PRICED）** | 复活让该塔在**后续**安全窗重新参与 `shop_ai` 的 `gain/cost` 排序 → 资源被反复引向一座"注定再死"的暴露位塔（沉没成本陷阱），挤占对 carry 的投资。PRICED 臂因**要花钱 + 参与性价比排序**，会拒绝一部分无效修复 → 反更好。🟢 这是"`d_free < d_priced`"的唯一自洽解释，也是"**条件复活优于无条件复活**"的直接依据。 |

### 2.3 适用边界：**只在金标本 AI 口径下成立**

- V-7 三臂全部跑在 `shop_ai` 金标本 AI 下（纯 DPS 贪心、不保塔、不重定位）。
- 🟡 **玩家口径未知**：在"玩家把 carry 放安全位 + 副塔当肉盾"的口径下，复活的是**肉盾**而非 carry → H1 的 ⊖ 可能大幅减弱，甚至转正（肉盾自动重生 = 恰恰是玩家想要的）。**这是用户直觉中"对的部分**，也说明该设定**不是本质邪恶，而是放错了塔位角色**。
- 🔴 但这**不构成"直接采用"的理由**：① 金标本口径下已测为有害；② 玩家口径无数据；③ 即便在玩家口径下有效，它仍架空 §2.3（§3.1）。→ 必须先验证（§5），再谈采用。

## 3. 与 §2.3 / §2.5 / §3.6 及支柱的兼容性（逐条给结论）

### 3.1 🔴 与 §2.3「可恢复挫折」：**表面吻合、实质冲突**

| 检验项 | 判定 | 论证 |
|---|---|---|
| 是否兑现"可恢复"？ | 🔴 **否（伪实现）** | §2.3 的价值主张是「把战斗内事故翻译成**波次间可归因决策**，胜任感保住」。自动复活**取消了波次间关于死塔的决策**：塔反正下一波自己回来 → `Repair` 分支**失去对象**（谁会花钱修一座马上免费复活的塔？）→ Q-T8 定稿的 `repair_cost = ceil(0.30 × 累计投入)` **在机制上失效**（不是被改数值，是没人会用它）→ 「三选一」塌成「拆 / 放着」**二选一**，决策密度下降（P4 反受损失）。 |
| 是否保住"可归因"？ | 🔴 **否** | 补救由**系统**无条件执行 → 玩家没有"我做对了什么"的归因 → 结果好坏都归因于系统 → **胜任感反而保不住**（概念 §4.1）。这正是"charity ≠ agency"的核心。 |
| 是否让"修"真的能补救？ | 🔴 **否（数据证伪）** | `hit_surv = 0`（0/797）、`restore-events = 0`、96.78% 再死 → 它把玩家锁在螺旋里**多转几圈**，没有脱出。V-7 终审 §4.2：问题在机制结构，而这个设定**没有修结构**。 |
| 🟢 唯一吻合处 | 字面 | "塔死亡不是永久损失" 与 §2.3 的"可恢复"措辞字面相符 → 🟡 这是**措辞陷阱**：§2.3 要的是"**玩家**有一条能爬回来的路"，不是"系统把挫折抹掉"。 |

### 3.2 🟢 与 §2.5「不算失败 / 不死锁」：**兼容且加强**

- 自动复活**强化**了 §2.5 的兜底（"永远有出路，不死锁"）：死塔会自己回来，玩家不会被锁死在无输出状态。
- 🔴 **但 §2.5 已明确"不死锁 ≠ 能翻盘"**（2026-10-09 补登记）。自动复活恰好**只兑现了前一半**，且容易被误当成 §2.3 的"可恢复" → 🟡 **概念混淆风险**：它把 §2.5 的兜底伪装成 §2.3 的恢复。**若采用，必须在 GDD 里显式写清这条区别**（否则后续会被反复误读为"§2.3 已兑现"）。

### 3.3 🟢 与 §3.6 / V-2「单核高风险画像」：**反直觉 —— 不触发支柱漂移**

| 检验项 | 判定 | 论证 |
|---|---|---|
| A 是否会逼近 B（分化消失）？ | 🟢 **不会**（实测） | 漂移警戒线 = `surv_A ≥ 0.817`（`v7-repair-on-disable-spec` §3.6，即 Δ ≥ +0.20）→ **FREE 实测 0.5385、PRICED 0.5878，均远低于** → 未触发。 |
| 方向 | 🟢 **反直觉**：复活**加剧**了 A 的劣势，而不是抹平 | 因为复活把塔重新喂给仇恨（H1）→ A 更差 → **风险画像分化反而被加强**（A 更高危 / B 仍免疫：`n_repair_eligible = 0`）。 |
| 🟡 反向警戒（给变体用） | **成功的变体才可能触发漂移** | 若 §4 的变体把 `surv_A` 抬到 ≥0.817 → 必须复查 §3.6 分化是否消失。→ **这是 V-8 验证的必带判据**（§5.2）。 |

### 3.4 🔴 与 R-T10 / R-T11：**背道而驰**

| 风险 | 关系 | 判定 |
|---|---|---|
| **R-T10**（塔死亡 = 正反馈螺旋的不可脱出环节） | R-T10 的处置目标是「找一条**可脱出**路径」 | 🔴 **背道而驰**：`n_td_form` +26% + 96.78% 再死 → 自动复活是**给螺旋加油**，不是打断它 |
| **R-T11**（修复是双向操作：⊕ 恢复 DPS ⊖ 重新暴露仇恨） | 用户设定 = 每波**必然**触发一次 ⊕ 与 ⊖ | 🔴 **最坏形态**：把 ⊖ 的触发频率**拉到满**（每波必复活 = 每波必再暴露），而 ⊕ 被 96.78% 的再死抵消 → 只剩 ⊖。→ 这正是 §4 变体要切掉的东西 |

### 3.5 与硬约束 T-C1 / T-C2 / T-C3 及四支柱

| 项 | 判定 | 说明 |
|---|---|---|
| **T-C1** 战斗内零可操作 | 🟢 不违反 | 复活发生在波首，战斗内无输入 |
| **T-C2** 余光编码 | 🟢 不违反 | 但需新增"复活演出"（塔重新点亮的动效），🟡 属美术工作量 |
| **T-C3** 不得产生"必须现在处理"的压迫 | 🟢 不违反（甚至更好） | 塔死了不会永久损失 → 无压迫 |

| **P3** 每局一个新解 | 🟢 中性 | — |
| **P4** 决策而非动作 | 🔴 **受损** | 波次间决策由三选一 → 二选一（§3.1）→ 决策密度下降 |

## 4. 变体设计空间：保住用户意图、撞开 FREE 臂陷阱

### 4.0 先还原用户的真实意图（这是本节的设计前提）

> 用户的诉求大概率不是"我要一个免费复活"，而是：**「塔死亡不该那么致命 / 我想有翻盘的机会」** —— 即**胜任感**（自我决定论 competence）+ §2.3 的"可恢复挫折"体验。
>
> 🔴 **设计原则（本节全部变体的筛选器）**：
> **给 agency，不给 charity。** 一个不经过玩家决策的自动恢复，既不产生归因（胜任感保不住），也不产生取舍（P4 受损），而且**数据上是最差的形态**（FREE 臂）。
> 🟢 因此所有推荐变体都满足：**① 结果由玩家的选择/投资决定；② 切掉 ⊖（再暴露）而不是加强它；③ 保留"塔死是真损失"的重量（§2.3 理由 5）。**

### 4.1 变体清单与逐个体评估

| # | 变体 | 机制草案（🔒 全部 `PLACEHOLDER`，需扫参） | 对 ⊕/⊖ 的作用 | 与 FREE 臂的关键区别 | 预测 | 我的判定 |
|---|---|---|---|---|---|---|

| **B1** | 🏆 **复活 + 降再暴露**（护盾 / 低仇恨权重） | 复活的塔获得 `AGGRO_SHIELD_W = N`（建议 N ∈ {1, 2}，`PLACEHOLDER`）波仇恨豁免：期间 `_nearest_exposed_tower` 跳过它（或降到最低优先级）；🟡 建议**不豁免 Sapper**（保住玩法⑤ 的可读威胁） | **只切 ⊖，保留 ⊕** | FREE 臂的塔复活即满血重入仇恨池 → B1 把它挡在池外 N 波 | 🟢 **唯一直接命中 R-T11 根因的形态**；若 ⊖ 真是主因，符号应翻正 | ✅ **推荐 #1** |

### 4.2 🏆 排序与理由（我的推荐）

> **B1（复活 + 降再暴露） > B2（条件复活） > B3（限次复活） > B4（延迟复活） >> B0（直接采用） > B5/B5′（部分复活）**

| 排序理由 | 说明 |
|---|---|
| **为什么 B1 第一** | ① 它**唯一**直接命中 V-7 挖出的根因（R-T11 的 ⊖ 再暴露项）——其余变体都在调"量"，B1 在调"符号来源"；② 它保住用户意图最强（塔不会永久损失 + 复活后有真实窗口可用）；③ 它不破 §2.3 理由 5（塔死仍损失 N 波内的输出与一次处置决策）；④ 它不动任何定稿数值，只新增 1 个参数 `AGGRO_SHIELD_W`。 |
| **为什么 B2 第二** | 唯一**已被数据正向验证**的形态（PRICED +1.08pp）且**保住 agency**（玩家决策 → 归因 → 胜任感）。缺点：金标本 AI 口径下"付费"会挤占预算，Δ 仍不显著 → 需 B1 的 ⊖ 削减才能真正变正。 |
| **为什么 B3 第三** | 最好地命中"给一次翻盘机会"的字面意图 + 戏剧性最强；但它不解决 ⊖ 的性质，只是封顶总量 → 🟡 建议**与 B1 叠加**（B1+B3 = "每塔 2 次带护盾的复活"，这是我心中最优组合）。 |
| **为什么 B5/B5′ 必须否决** | 🟠 **关键论证**：仇恨选目标（`wave_sim_aggro:443/:464`）**只看"最近的未 Disabled 塔"，不看 DPS** → 降输出**一点都不会减少再暴露**，只会减少复活的收益 → **严格劣于 FREE**。这是一个容易踩的设计陷阱，显式登记。 |
| **为什么 B4 只是保底** | 它等价于"OFF 与 FREE 的线性插值"，期望上限就是 OFF（0.5770）→ 用户得不到任何"翻盘"体验，只得到更少的惩罚。 |

## 7. 边缘情况（≥3 类是输出规范，本节给 7 类）🔒 **若拍板实现则进 T1**
