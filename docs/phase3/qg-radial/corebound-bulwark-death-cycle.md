## 0. 三句话结论（给赶时间的人）

1. 🟢 **用户的框架是对的，且它比上一轮的框架更深刻** —— 上一轮我问的是"要不要复活"，答案"不要"（FREE 臂实测 −3.85pp）；用户问的是"**塔死亡能不能成为玩法**"，这是一个**不同的问题**，答案"**能，而且肉盾塔是唯一能承载它的角色**"。🔴 **上一轮的结论不作废**：FREE 臂（所有塔无条件复活）仍然有害、仍不采用；作废的只是**把它套在用户设定上的那个框架**。
2. 🔴 **本质区别不在"复活对象不同"，在"时序结构与价值函数不同"** —— 我用 R-T11 的三项账算清楚了：对 carry，修复 = `⊕₁ 恢复 DPS` + `⊖ 重新暴露仇恨`，而 carry 一暴露就被点掉（V-7：塔死 ⟹ 失守 **57/57 = 100%**）→ **净负**；对肉盾，`⊕₁ ≈ 0`（它本就不产 DPS）、`⊖` 从"副作用"**变成"功能"**（暴露就是它的职责）→ 且多出 FREE 臂没有的第三项 **`⊕₂ 仇恨吸收能力恢复`** → **净正**。（§3）
3. 🟡 **但它有一个必须先解决的空窗期问题，否则它就是 FREE 臂换了个名字** —— 肉盾死在**波中**，复活在**波首**（或波次间）→ **中间那半波 + 整个波次间隔是无人扛伤的**，怪物转向 carry。在 A 单核流（2 塔）下这就是致命的。**这是 V-8 必须验的头号命题，也是本机制唯一可能翻车的地方。**（§4）→ ✅ 我给的完整方案是 **「肉盾循环 + 动作位成本 + 空窗期管理」三件套**（§5），并建议 🔴 **不沿用 `hit_surv` 作主判据**（它答错了问题，§7.2）。

## 1. 框架修正：上一轮错在哪，为什么这不是"原谅 FREE 臂"

### 1.1 用户澄清原文与我的还原

> **用户原话**：「不是自动复活，每波间隔是给玩家调整部署策略的时间，每一波战斗都是对玩家部署策略的检测，有些塔就是来吸引怪物仇恨的，塔的死亡也是机制的一种，塔死亡在战斗中复活也是一种玩法，后续可以围绕做设计」

**还原成四条设计命题**：

| #       | 命题                                    | 与上一轮框架的关系                          |
| ------- | ------------------------------------- | ---------------------------------- |
| **P-1** | **波次间隔 = 决策窗**（玩家调整部署的时间），不是"复活窗口"    | 🔴 上一轮把它当成"复活时机"读过去了 → **这是误读的起点** |
| **P-2** | **每波战斗 = 一次检测**（对部署策略的检验），不是"一次损耗"    | 🟢 全新维度：上一轮完全没有"检测/反馈循环"的概念        |
| **P-3** | **存在一类塔，其职责就是吸引仇恨**（肉盾塔）              | 🟢 = GDD §3 玩法② 已定稿的 `Bulwark`     |
| **P-4** | **塔死亡是机制、是玩法，不是失败状态**；肉盾的死亡-复活是可设计的循环 | 🔴 与 §2.3「可恢复挫折」是**两个不同命题**（§6.1）  |

### 1.2 范畴错误（category error）：FREE 臂用错了语义

> 🔴 **这是本次框架修正的核心诊断。**

上一轮我判定"用户设定 ≡ FREE 臂"，这个**等价性判定本身仍然成立**（批处镜像下逐位等价，无一例外）。但它只证明了「**按上一轮那种读法实现出来，会跑出 FREE 臂的数字**」，**没有证明「用户的意图就是 FREE 臂」**。

真正的错在这里：

|               | FREE 臂（上一轮的读法）               | 用户意图（本轮的正确读法）                                 |
| ------------- | ---------------------------- | --------------------------------------------- |
| **塔的本体论**     | 塔 = **资产**（asset），死了 = 资产损坏  | 肉盾塔 = **消耗品 / 弹药**（consumable），死了 = **弹药打完了** |
| **死亡的语义**     | 死亡 = **事故 / 挫折**，需要补救        | 死亡 = **预期内的职责完成**（"它把仇恨都吃完了"）                 |
| **复活的语义**     | 复活 = **修复**（restore，把资产修回原状） | 复活 = **补给 / 重新装填**（reload，让它下一波继续履职）          |
| **玩家的情绪目标**   | 别死（avoid）                    | 死得**值**（spend well）                           |
| **对应 GDD 定性** | §2.3「可恢复挫折」                  | 🆕 **新命题：可循环的职责消耗**（§6.1）                     |

> 📌 **一句话**：**FREE 臂的错误是范畴错误 —— 它用"资产修复"的语义，去实现一个本质是"消耗品循环"的机制。** 资产损坏要修复（修复失败 = 有害）；弹药消耗要补给（补给当然有益）。同一个"复活"动作，在两种语义下的符号**可以相反**。
>
> 🟢 **这也解释了上一轮最难解释的那条数据**：`d_free < d_priced`（越无条件越糟）。在"资产修复"语义下它反直觉；在"消耗品"语义下它完全正常 —— **免费修复让资产失去了重量（没人珍惜），而免费补给让消耗品失去了成本（刷消耗品）**。两者都糟，但**糟的机制不同**。

### 1.3 🔴 但上一轮的实测结论不因框架修正而作废

必须显式说清，否则本文档会被误读为"给 FREE 臂翻案"：

| 上一轮结论                                                                                  | 本轮状态                                                                 |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 🔴 用户原话的**字面设定**（波首无条件复活**所有**塔）≡ FREE 臂，Δ = **−3.85pp**（z = −2.11，CI 上界 −0.00276 < 0） | ✅ **维持，不翻案**。🔴 **不采用**                                              |
| 🔴 修好的塔 **96.78%** 后续波又被打停；`restore-events = 0`；`n_td_form` 319 → 403（+26%）            | ✅ **维持**。这是 **carry 复活**的实测画像，对肉盾**不可直接外推**（§3）                      |
| 🔴 无条件复活架空 §2.3 三选一（`Repair` 废按钮）                                                      | 🟡 **部分修正**：无条件复活**所有塔**仍架空 §2.3；但**只复活暴露位肉盾**给 §2.3 **划清了边界**（§6.1） |

| 🟡 玩家口径（保塔/肉盾）下符号未知                                                                    | 🔴 **这就是 V-8 要补的洞**，且它是本轮全部结论的**唯一验证途径**（§7）                         |

> 🔴 **一句话**：**上一轮测的是"对所有塔无条件复活"；本轮评估的是"对肉盾塔有条件循环"。这是两个不同的机制，不是同一个机制的两次评估。**

## 2. 重新定位：与既有设计的关系（逐条给结论）

### 2.1 🟢 与 V-4 肉盾塔：**这是 V-4 缺的那一块，不是推翻 V-4**

**V-4 现状（新基线）**：A 无保护 **0.277** / A 主力塔隐身 **0.580** / **A 理想肉盾 0.580（< 0.60 未过线）** / B **0.817**；`Δ（隐身 vs 理想肉盾）= 0.00`。

**为什么 Δ = 0.00（关键诊断）**：  
`scan_bulwark.gd` 的建模是「carry 真挪到安全位（**E 降 → DPS 降**）+ 副塔换到暴露位当肉盾」。它测的是 **"肉盾挡一次"**：

- ⊕ 保命收益 = carry 不再挨打
- ⊖ DPS 代价 = carry 离开枢纽位（度 5 → 度 3）+ 肉盾不产 DPS
- → **正好抵消，Δ = 0**

而 V-4 建模里 **肉盾死了就死了**，没有第二步。

> 🟢 **本机制的增量 = V-4 缺的那半步**：V-4 测「肉盾挡**一次**」，本机制给「肉盾**每波**都回来重新挡」。  
> **预测**：`surv_A(bulwark + 肉盾循环) > surv_A(bulwark 单独)`。🔴 **这是 V-8 的头号命题**（P-1）。

**🔴 但必须有反面论证（诚实标注）**：  
肉盾复活**只在"肉盾能扛住相当一部分波次时长"时才有价值**。若肉盾在波初 10% 就死，复活它只是"让它再死一次" → Δ 仍 ≈ 0，甚至因占动作位而更差。  
→ 🟢 **所以 V-8 必须新打两个 V-7 从未打过的量**：`bulwark_aggro_share`（肉盾吸收仇恨的时长占比）与 `carry_exposure_time`（carry 暴露时长）。**这两个量决定机制价值，而 `surv` 只是它们的下游结果**（§7.2）。

### 2.2 🟢 与 V-2 单核高风险画像：**是它的"续集"，且首次有机会给它实测支撑**

- V-2 定稿：承认「单核高风险画像」为**设计预期**；A 无保护 0.277 → 保塔 **0.580**（Δ = **+0.303**，新基线反而更强）。
- V-2 定稿处置里有一句**预判**：「0.580 是**金标本 AI 上限**，不是**玩家上限**；真实玩家应 > 0.580、大概率越过 0.60」。🟡 **这句至今没有数据支撑，只是预判。**
- 🟢 **本机制是第一个可能把它变成实测的机制**：`bulwark + 肉盾循环` 正是一种"AI 做不到、玩家做得到"的操作（AI 不保塔、不复活、不换位）。
- 🔴 **若 V-8 实测 `surv_A ≥ 0.60`**：① V-2 的预判**首次获得数据**；② A 单核流**首次过红线**（新基线以来从未过）；③ 🟢 **不触发 §3.6 支柱漂移**（漂移警戒线 = `surv_A ≥ 0.817`，即逼近 B 的水平；0.60~0.65 离 0.817 极远 → **分化仍在，反而更健康**）。
- 🟡 **若 V-8 实测仍 < 0.60 但机制量显著改善**：→ 属"体验向收益"，需用户单独拍板是否采纳（🔴 不得凭机制量好看就宣布有效，也不得凭 `surv` 不显著就否决，§7.3）。

### 2.3 🟢 与 R-T10（塔死亡正反馈螺旋）：**它是一个精准解，且打断的是特定一环**

R-T10 的机制链：`塔死 → DPS 崩 → 漏怪 → 核心掉血 → 剩余塔承担更多仇恨 → 更多塔死`。

| 环节        | 本机制是否打断                                     | 论证                                                                          |
| --------- | ------------------------------------------- | --------------------------------------------------------------------------- |
| 塔死        | ❌ 不阻止（**设计上就不该阻止** —— 用户：死亡是机制）             | —                                                                           |
| DPS 崩     | 🟢 **打断**（肉盾不产 DPS → 它死与活对 DPS 影响极小）        | 这是与 carry 死亡**最本质的差别**：carry 一停 DPS 就崩（V-7：塔死 ⟹ 失守 57/57）；肉盾一停 DPS **几乎不动** |
| 剩余塔承担更多仇恨 | 🟢 **打断**（肉盾复活 = 仇恨有了去处 → carry 不被波及）       | 这是本机制的核心价值                                                                  |
| 更多塔死      | 🟢 **重定向**（塔死继续发生，但**发生在可再生消耗品上**，不再发生在资产上） | 🔴 注意：`n_td_form` **不会下降，反而会上升** → 🟡 **这不再自动是坏消息**（§7.2 判据重定义）             |

> 🟢 **一句话**：**本机制不阻止塔死，它给塔死一个"去处"** —— 把螺旋从「资产被逐一点掉」重定向为「消耗品被反复消耗」。这正是用户说的"塔死亡是机制的一种"。

**🔴 成立前提（必须显式登记）**：

1. **肉盾必须先于 carry 被选中** —— 仇恨选「最近的未 Disabled 塔」（`wave_sim_aggro:443/:464`）→ 肉盾必须在**更暴露**的位置 → 这由**站位**保证，不是由机制保证。
2. **复活速度 ≥ 消耗速度** —— 每波复活 1 次 vs 每波消耗 1 次 = 打平；**若一波内肉盾死两次，则打不平** → 🟡 需 V-8 打"肉盾死亡波次分布"确认。

### 2.4 🟡 与 §3 玩法②「肉盾塔」的一处**方向性冲突**（新发现，需登记）

GDD §3 玩法② 原文：「🟢 **天然耦合多塔流**；🔴 **对单核流是纯成本**（单核只有 2 塔，牺牲一座输出塔去当肉盾代价极高）」。

**但在八槽径向几何下，这个判断翻转了**：

| ----------- | ------------------- | ----------------------------------------------------------------------- |
| B 多塔流会不会掉塔  | ✅ 会                 | 🔴 **不会** —— V-1′ 实测 B 路径 `dis_new = 0`，`attrition` 扫到 50（33×）**仍全程免疫** |
| 肉盾在 B 路径有用吗 | 🟢 有（有塔会死 → 需要挡刀）   | 🔴 **没有** —— 塔根本不会死 → 不需要挡刀 → **肉盾在 B 路径是纯成本**                          |

> 🔴 **登记**：§3 玩法② 的「肉盾天然耦合多塔流」是在**六槽 PATH 几何**下写的判断；在**八槽 RADIAL** 下因 B 路径结构性免疫而**翻转**为「肉盾是单核流的专属工具」。

> 🔴 **本文档不改 GDD**，仅登记；若 V-8 拍板通过，此条需在 `mechanics-tower-life-death` §3 玩法② 同步修订（列入 §9 Q-B8）。

## 3. 🏆 与 FREE 臂的本质区别（本节是本评估的核心论证）

### 3.1 用 R-T11 的账逐项算：为什么 carry 复活净负、肉盾复活净正

R-T11 定稿：「修复是**双向操作** —— `⊕` 恢复该塔 DPS + `⊖` 把该塔重新暴露给仇恨」。  
🟢 **但对肉盾塔，这张账是三项的**（第三项是 FREE 臂没有的）：

| 项                 | 对 **carry 塔**（V-7 实测画像）                                                                                               | 对 **肉盾塔**（用户框架）                                                                              |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **`⊕₁` 恢复 DPS**   | 🟢 **大** —— carry 常占 30–60% 输出                                                                                        | 🔴 **≈ 0** —— 肉盾本就不产 DPS（这是它的定义）                                                             |
| **`⊕₂` 恢复仇恨吸收能力** | 🔴 **不存在** —— carry 不该被暴露，它没有这个"能力"                                                                                   | 🟢🟢 **大（本机制的真收益）** —— 肉盾复活 = 重新获得"替 carry 挡刀"的能力                                            |
| **`⊖` 重新暴露仇恨**    | 🔴🔴 **致命** —— carry 一暴露就被点掉，且它一停 DPS 就崩。<br />实测铁证：V-7 `塔死 ⟹ 失守 57/57 = 100%`；FREE 臂 `then_redied/eligible = 0.9678` | 🟢 **≈ 0（副作用）→ 实际上是功能** —— **暴露就是肉盾的职责**。它被选中 = 它正在工作。用户原话："对肉盾塔，修好即重新暴露仇恨不是 bug 而是 feature" |
| **净和**            | 🔴 **净负**（实测 Δ = −3.85pp）                                                                                             | 🟢 **净正**（`@ ⊕₂` 主导）                                                                         |

> 🔴 **这就是本质区别的定量表述**：**`⊖` 这一项的符号，取决于"暴露对这座塔是职责还是事故"。**  
> 对 carry，暴露是**事故** → `⊖` 是纯成本；对肉盾，暴露是**职责** → `⊖` 从成本项**翻转**为收益项（`⊕₂` 的前提条件）。  
> **FREE 臂之所以有害，是因为它对一个"暴露 = 事故"的对象（carry）施加了"必然暴露"的操作，每波一次，从不间断**（上一轮 §3.4：把 ⊖ 的触发频率拉到满）。

### 3.2 第二层区别：投资锁死（H3′）为什么对肉盾不生效

上一轮 H3′ 假设（FREE 为何差于 PRICED）：**复活让该塔在后续安全窗重新参与 `shop_ai` 的 `gain/cost` 排序 → 资源被反复引向一座"注定再死"的暴露位塔（沉没成本陷阱），挤占对 carry 的投资。**

|                   | carry 复活                                            | 肉盾复活                                                                             |
| ----------------- | --------------------------------------------------- | -------------------------------------------------------------------------------- |
| 玩家/AI 的投资逻辑       | 复活让它重新变成"高性价比候选"（DPS 回来了）→ **持续投资一座注定再死的塔** → 🔴 锁死 | 🟢 **投资逻辑天然是"够用就好"** —— 肉盾不产 DPS，投资它的**唯一回报是耐久** → 玩家会把它控制在"刚好能扛住"的档位，**不会过度投资** |
| 沉没成本陷阱            | 🔴 成立                                               | 🟢 大幅减弱                                                                          |
| 🟢 **反而新增一个正向取舍** | —                                                   | 🟢🟢 **"投资一座贵的肉盾让它少死" vs "用便宜肉盾让它死了自动复活"** —— 一个**全新的、真实的**资源分配决策（§5.2）          |

> 🟢 **这是本机制第二个设计价值**：它把 H3′（FREE 臂的死因之一）**反向转化**成了一个决策维度。

### 3.3 第三层区别：时序结构（🔴 最关键，也是唯一可能翻车的地方）

|                  | FREE 臂                      | 肉盾循环                                                                            |
| ---------------- | --------------------------- | ------------------------------------------------------------------------------- |
| 死亡时刻             | 波 `w` **中**                 | 波 `w` **中**                                                                     |
| 复活时刻             | 波 `w+1` 首（波次间之后）            | 波 `w+1` 首（或波次间玩家发起）                                                             |
| **空窗期**（死亡 → 复活） | **半波 + 整个波次间隔**             | **半波 + 整个波次间隔（同样存在！）**                                                          |
| 空窗期谁扛伤           | 🔴 **carry**（它就在旁边，且它已在暴露位） | 🔴🟢 **取决于部署** —— 若 carry 已放安全位（bulwark 口径）→ 空窗期**无害**；若 carry 也在暴露位 → **同样致命** |

> 🔴 **诚实结论**：**时序结构本身没有区别。区别在于"空窗期的受害者是谁"，而这由玩家的部署决定，不由机制决定。**
>
> 🔴 **因此**：**肉盾复活机制如果不解决空窗期，它就是 FREE 臂换了个名字** —— 复活了肉盾，但肉盾死的那一刻起 carry 就已经在挨打了，而 V-7 已证明 carry 一挨打就是 100% 失守。
>
> 🟢 **但反过来**：**一旦解决了空窗期（carry 在安全位 + 肉盾及时补位），肉盾复活就从"有害"变成"有益"** —— 这正是"用户的框架能避开螺旋、FREE 臂不能"的**唯一机制理由**。
>
> 📌 **判定**：用户直觉正确的那部分（"肉盾复活是 feature"）**成立的条件是 carry 不在暴露位**。而 carry 在不在暴露位，**恰恰就是玩家在决策窗要做的部署决策** → 🟢 **这就把"空窗期风险"本身变成了"部署策略检测"的检测项**。用户 P-2 的"每波都是对部署策略的检测"，在机制层精确落到了这里。

### 3.4 为什么 FREE 臂不能靠"同样的论证"脱罪（防止本文档被误用）

有人可能问：既然"空窗期受害者由部署决定"，那 FREE 臂只要玩家把 carry 放安全位，是不是也就无害了？

🔴 **不是**，三条理由：

1. **FREE 臂没有角色区分** → 它复活 carry。而 carry 复活的 `⊖`（重新暴露）**对 carry 永远是致命的**（V-7：57/57）。肉盾复活的 `⊖` 是功能。**`⊖` 的符号由角色决定，不由部署决定。**
2. **FREE 臂不占代价** → 无 rationing → H3′ 投资锁死**照常发生**（§3.2）。
3. **FREE 臂取消了决策** → 玩家没有"要不要复活"这个动作 → P4 受损、归因破裂（charity ≠ agency，`corebound-tower-revive-setting` §4.0）。**本机制必须保留这个决策**（§5.2）。

> 🔴 **一句话**：**FREE 臂的病是"无角色区分 + 无代价"；肉盾循环的药是"角色区分（暴露位/肉盾）+ 代价（动作位）"。缺任何一味，就退回 FREE 臂。**

### 7.2 🔴 判据重定义：`hit_surv` **不能**作主判据

V-7 终审 §2 已确立「主口径 = `hit_surv`（X_form 成型期 W6–12 存在性）」。🔴 **本轮必须换判据**，理由：

| **分母语义崩塌**   | `hit_surv` = "掉了塔 → 复活 → 爬回 → 存活"。在肉盾循环下，**塔死亡是每波的预期事件** → `n_td_form` 会暴涨，但那些塔死**不是挫折** → 分子/分母的语义都变了                    |
| 🔴 **答错了问题** | `hit_surv` 的命题是"**从挫折中恢复**"；肉盾循环下**没有挫折**（死亡是预期的）→ 用一个"从挫折恢复"的判据去测一个"无挫折的循环" = **循环论证**（与 V-7 终审 §2.2 裁 X_any 的**同一条纪律**） |

### 7.5 预注册判读线（🔴 跑之前写死，跑后不得改）

| 结论                       | 判读条件                                                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| ✅ **机制成立（可采纳）**          | Δ 双侧 CI **下界 > 0** **且** `carry_exposure_time` 显著下降 **且** `surv_A < 0.817` **且** `n_td_form` 涨幅 < +26% |

## 12. 一句话给程基岩（🔴 用户拍板 Q-B0~Q-B4 之后才执行）
