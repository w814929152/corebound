## 0. 三句话结论（给赶时间的人）

1. **GDD §2.3 把塔死亡设计为「可恢复挫折」（修/拆/放着三选一），但实测它是「致命诊断」** —— `hit_surv = 0.0000`（0/185）、`hit_fail = 0.7652`（88/115）→ 塔死 ⟹ 失守 **88/88 = 100%**。叠加 `shop_ai` **没有修复分支** → 「修复」这条分支在金标本口径下**从未被走过**，`Repair` 可能是废按钮。这是**产品级**问题，不是测试瑕疵。
2. **处置 = 加一个默认 off 的诊断开关 `repair_on_disable`，跑三臂对照（baseline / 免费修 / 定价修）× 300 局 A 路径**，看存活率相对基线 **0.617** 的回升 **Δ**。🟢 结构上 **Δ ∈ [0, 0.2933] 且不可能为负**（无塔死的 212 局逐位不变、不可能翻向失败）→ **单侧检验是结构正当的，不是为了通过而取单侧**。
3. 🔴 **但用户给的「Δ ≥ +0.05」在 n=300 下有检验力问题，我必须如实标出来**：按保守的独立两比例口径 `SE_Δ ≈ 0.0391`，Δ=+0.05 只有 **1.28 SE**（单侧 p≈0.10）→ 落在**灰区**，点估计够门槛但不足以定性。好消息是**同 seed 配对设计**能把 `SE_Δ` 压到 **≈0.0118**（Δ=+0.05 → **4.24 SE**）→ 判据能否成立**取决于配对是否真的成立**。故本规格把「配对校验」写成**强制前置**，并给出灰区的样本量纪律（加跑到 **≈1140 局/臂**），🔴 **禁止在灰区用点估计宣布"废按钮坐实"**（那正是 §6-③ 明令禁止的「把阈值贴到实测值身边」）。

## 1. 问题陈述

### 1.1 设计意图：§2.3 把塔死亡设计成「可恢复挫折」

GDD `mechanics-tower-life-death.md` §2.3（**Q-T4 已定稿 = ① Disabled 中间态**）的原文定性：

| 出处 | 设计措辞 |
|---|---|
| §2.3 定稿 ① | HP 归零 → 塔进入 `Disabled`：**停止输出**、但**仍占塔位 / 仍持有装配卡 / 仍供 `h_j`**；在**下一个波次间安全窗**，玩家三选一：**修复 / 拆除 / 放着不管** |
| §2.3 理由 2 | 「它给了玩家一条**可归因的补救路径**：『我那座塔被冲掉了 → 我选择花 X 分修它 / 我选择放弃它把卡位腾出来』→ 归因于决策，**胜任感保住**」 |
| §2.3 理由 5 | 「惩罚依然真实且沉重……→ 塔死是**真损失**，不是挠痒」（隐含：**不是致命的**） |
| §2.3 关键价格关系 | 🔴 「**必须成立，否则会出现废按钮**」：`repair_cost < 重建同层塔的代价`；一座 `h=1` 杂兵塔修 **3.6→4 分** vs 重建 **12 分** → **三个按钮都有存在意义，无废按钮** |
| §2.5（Q-T7） | 🔴 **红线**：塔死亡**不算失败**；全塔 Disabled 也**不新增失败判定**，只允许通过漏怪→核心掉血**自然**导致失败 |
| §2.6 对 P4 | 「**没有"必须现在点"的压力**」——塔死了不会立刻输，处置只在安全窗 |

→ **一句话概括设计意图**：塔死亡 = **玩家在下一个安全窗可以做点什么的事故**，而不是"看到它就知道这局完了"。

### 1.2 实测：它是「致命诊断」

`docs/phase3/qg-radial/r2-criteria-revision.md` §4.4 的 per-run 实测（N=300，seed 20261002，八槽 RADIAL，`ATTRITION=1.50`，`WARMUP=2`，`max_actions=12`）：

| 量 | 实测 | 读法 |
|---|---|---|
| A 存活率 `surv`（末波 `core_hp > 0`） | **0.617**（185/300） | 失败率 0.383（115/300） |
| A 塔死局数（`X_form ≥ 1`） | **88**（88/300 = 0.2933） | 成型期 W6–12 发生塔被打停事件 |
| `hit_surv = P(塔死 \| 存活)` | **0.0000**（0/185） | 🔴 **起飞的局一座塔都没掉** |
| `hit_fail = P(塔死 \| 失败)` | **0.7652**（88/115） | 失败局里 76.5% 走了塔死路径 |
| 塔死 ⟹ 失守 | **88/88 = 100%** | 🔴 **充分条件** |

→ **塔死亡是 A 单核流失守的「充分不必要条件」**：掉塔的局 **100%** 输；输的局 **76.5%** 是掉塔输的。

🔴 **由此派生一条 GDD 未覆盖的事实**：**没有任何一局是"掉了塔、然后靠修/拆/放着从塔死亡里爬回来并起飞的"** —— 因为塔死局的存活率是 **0**。§2.3 设想的那条"补救路径"，**在金标本口径下从未被走过一次**。

### 1.3 为什么这是产品级问题（不只是测试瑕疵）

三条独立理由，任一条都够立项：

| # | 理由 | 严重度 |
|---|---|---|
| **①** | **废按钮（主导策略风险）**：`shop_ai` **无修复分支**（`r2-criteria-revision.md` §4.3 已确认：镜像内 `disabled = false` 只存在于实时版 `shop_runtime.gd:1012`，批处理镜像 `shop_ai.gd` 没有修复分支）。若"修了也救不回来"，则 `Repair` 在单核流下永远不是正解 → §2.3「修复永远比放弃便宜 → 三个按钮都有存在意义」的定价论证**失去事实基础** → 🔴 **一个玩家永远不会点的按钮 = 废按钮**（`card-system` §1.2 否决方案 B 的第一条理由就是"会让拆塔变成废按钮"） | 🔴 高 |
| **②** | **玩家挫败感 / 归因断裂**：§2.3 理由 2 承诺"胜任感保住"。若塔死 = 100% 失守，玩家的实际体验是"看到塔停 ⟹ 这局没了"，**安全窗的"修/拆/放着"变成一个走过场的仪式** → 与概念 §4.1「归因清晰」直接冲突；且 R-T4 已登记的"我什么都做不了"无力感风险会被**放大**（R-T4 的兜底是"提前给余光预警"，但预警对一条 100% 致命的事件是**无效安慰**） | 🟠 中高 |
| **③** | **GDD 措辞与实测不一致，会误导后续所有设计**：§2.3 的措辞支撑着 Q-T8 定价、E-T4「永不死锁」兜底、§3 玩法②肉盾塔 / ⑤Sapper 的设计空间。若塔死亡其实是致命的，这些下游全部建立在错误前提上 | 🟠 中高 |

🟢 **但也有必须如实登记的正面事实**：`hit_fail = 0.7652` 意味着 **76.5% 的失败走的是 GDD §2.2 设计的因果链**（塔停 → DPS 崩 → 漏怪 → 核心失守）→ **「可归因」这个设计目标其实达成了**（R-T6-a 已据此判定为"口径局限"而非"缺陷"，就地关闭）。V-7 要验的不是"因果链对不对"，而是**这条链的终点能不能被玩家扳回来**。

## 2. 诊断干预设计

### 2.1 开关定义

| 项 | 规格 |
|---|---|
| **名字** | `repair_on_disable`（建议落在 `cfg` 字典：`cfg["repair_on_disable"]`） |
| **取值** | 🔴 **三档枚举，不用 bool**：`0 = OFF（默认）` / `1 = FREE（免费修，结构探针）` / `2 = PRICED（按 `repair_cost` 定价，与 build/up 竞争预算）` |
| **默认** | **`0 = OFF`** —— 🔴 **不进金标本、不进默认回归口径、不进 `golden_reference`** |
| **生效时机** | 仅**波次间安全窗**（`shop` 决策期），🔴 **战斗内绝不生效**（红线 T-C1 / Q-T9） |
| **生效范围** | 仅 `disabled == true` 的塔（见 §2.4 的口径澄清） |
| **效果** | `disabled = false` + `hp = hp_max`；**不动 `h`、不动装配卡、不动 `N_tower` / `n_hist_max`**（与实时版 `shop_runtime.repair_tower()` 同口径：E-T6「修复只恢复 HP，不改任何层数」） |
| **同类先例** | 与 `prototype_split_enabled` / `elite_waves_enabled` / `tower_aggro_enabled` / `SpaceModel.mode` **同款哲学**：全局诊断开关，默认 off = 金标本等价口径（见 `scripts/geo/space_model.gd:8` 的自述） |

### 2.2 🔴 这是诊断开关，不是产品功能

必须在代码注释与本文档同时钉死：

> **`repair_on_disable` 是一个诊断工具，不是 T1 的功能交付。**
> 它的唯一用途是回答"§2.3 的可恢复挫折设计成不成立"。
> · **默认 OFF**，任何默认口径（含 `run_tests.gd` 无参运行 / 金标本对照 / `golden_reference`）下它**必须恒为 OFF**；
> · 🟢 **若 V-7 判定 §2.3 成立**，修复分支才作为**正式功能**走 T1 正常批次（含 UI、演出、E-T1~E-T10 边缘情况）；
> · 🔴 **若 V-7 判定成立但 Δ 过大**（见 §3.6 支柱漂移观察项），则修复**要重定价**而不是直接转正；
> · 🔴 **若 V-7 判定废按钮**，本开关**不得转正**，且 GDD §2.3 措辞必须改（见 §3.5 判据表"分支 C"）。

### 2.3 三臂对照设计（🔴 本规格的核心方法学决定）

只跑一个"开修复"臂**不够**——它无法区分"修复机制无效"与"修复定价太贵"。故拆成三臂：

| 臂 | 开关 | 修复成本 | 预算竞争 | 回答的设计问题 |
|---|---|---|---|---|
| **臂 0 · 基线** | `0 (OFF)` | — | — | 复现 `surv = 0.617`（185/300），并提供**配对基准**（逐局 `fail` 标记） |
| **臂 1 · FREE** | `1 (FREE)` | **0 分** | **不占预算**（在 `shop_phase` 之外执行） | 🔴 **结构问题**："把 DPS 还回去"本身能不能救回一局？——**与定价无关的结论** |
| **臂 2 · PRICED** | `2 (PRICED)` | `ceil(0.30 × invested_est)` | 🔴 **与 build/up/reinf 竞争同一预算**（做成 `shop_ai` 的一个候选动作） | 💰 **经济问题**：修复作为一个**花钱的决策**是否值得？——§2.3 定价论证是否成立 |

**为什么必须有 FREE 臂**：它是 Δ 的**结构上限探针**。
- 若 `Δ_free ≈ 0` → **即使白送也救不回来** → 塔死亡就是致命的，**与定价无关**，§2.3 措辞必须改（判据分支 C）；
- 若 `Δ_free > 0` 而 `Δ_priced ≈ 0` → **修复机制本身有效，但定价/预算挤占杀死了它** → 这是**经济设计问题**（调 `repair_cost`），不是机制问题；
- 若 `Δ_priced ≥ 判据门槛` → **废按钮指控撤销，§2.3 成立**。

🔴 **单调性不变量（可作 sanity check）**：结构上 `0 ≤ Δ_priced ≤ Δ_free ≤ 88/300 = 0.2933`。
🟡 **若实测违反此式 → 实现有 bug，不要判读结果**（例如 FREE 臂漏了"修复后 DPS 未重算"）。

### 2.4 口径澄清：V-7 的修复对象**只有 Disabled 塔**

任务书写的是"把**受损/Disabled** 塔修满"。核对实现后必须收窄：

> 🔴 **批处镜像里不存在"跨波受损但未停机"的塔。**
> `wave_sim_aggro._init_tower_hp()`（:255）与实时版 `wave_director._init_tower_hp()`（:248）**都在波首把未 Disabled 的塔重置为满血**（`if not bool(t.disabled)`）。
> → 波次间唯一处于非满血状态的塔 = **Disabled 塔**。
> → **V-7 的修复对象 = Disabled 塔，且"修满"在下一波波首会自动发生**（修复的意义是清 `disabled` 标记、恢复 DPS，不是补 HP 数值）。

🟡 **开放问题（不在 V-7 scope）**：若要验"修**受损但未停机**的塔"，必须先改波首重置口径（让损伤跨波累积）——🔴 **那会动金标本战斗结算，属另一个立项**，本规格明确排除。

### 2.5 🔴 工程陷阱：`repair_cost` 在批处镜像里会算出 **0 分**

这是我在核对代码时发现的一个**必须先解决的前置**，否则整个 PRICED 臂的数据无意义：

| 事实 | 出处 |
|---|---|
| `repair_cost = ceil(0.30 × invested)` | `shop_runtime.gd:1003`（实时版真身，`REPAIR_RATE = 0.30`，:880） |
| `invested` 字段"🔴 **只在玩家手动路线（`shop_runtime.gd`）侧记录与维护**；金标本 AI 路线（`shop_ai.gd apply_action`）**不读不写**此字段" | `player_state.gd:32-34` |
| 核对：`shop_ai.gd` **全文无 `invested`**（`apply_action` 的 `build`/`up`/`reinf` 三个分支都不写） | `scripts/engine/shop_ai.gd:237-281` |

→ **若直接套 `repair_cost = ceil(0.30 × t.invested)`，批处镜像里 `invested ≡ 0.0` → `repair_cost ≡ 0` → PRICED 臂退化成 FREE 臂，且被误读为"定价修复有效"。** 这是本任务最危险的一个假阳性通道。

**处置（规格要求）**：PRICED 臂必须显式补一份**AI 侧的累计投入估算**，与实时版记账同式：

```
invested_est(t) = PRICE["tower"] × h  +  PRICE["reinforce"] × Σ(attach 层数)
                = 12.0 × t.h          +  9.0 × L_i                        （PRICE 见 tower_data.gd:27）
repair_cost(t)  = ceil(0.30 × invested_est(t))
```

🟢 **与 GDD §2.3 的算例对得上**：`h=1` 裸塔 → `ceil(0.30 × 12) = 4` 分（GDD 原文："修 **3.6→4 分** vs 重建 **12 分**"）✓
🟢 与实时版 `shop_runtime` 记账**同式**（实时版每次 build/up 记 12、每次 reinforce 记 9）。

🔴 **但同时必须登记**：这是一个**近似**（不含 `wave_price_step` 涨价、不含 reroll 花费、不含已被 `drop_from` 卸下的历史投入）→ 真实玩家的 `invested` **≥** `invested_est` → 本规格的 `repair_cost` 是**偏低的** → **PRICED 臂的结论偏乐观**。🟡 判读时必须带上这个方向性偏差（偏乐观 = 若 PRICED 臂 Δ 仍 ≈0，则"定价过高"的结论**更硬**；若 PRICED 臂 Δ 达标，则**仍需一次敏感性复核**，见 §6 开放问题 Q3）。

### 2.6 修复如何与预算竞争（PRICED 臂的决策语义）

| 项 | 规格 |
|---|---|
| **动作形式** | 在 `shop_ai.enumerate_actions` 中新增一个候选动作 `["repair", <tower>, slot, null]`（仅当该塔 `disabled == true` 时枚举） |
| **估价** | 沿用 `action_value` 同款口径：`gain = ΔDPS(修复前 → 修复后)`，`cost = repair_cost`，按 `gain / cost` 参与 `shop_phase` 的贪心排序 → 🔴 **修复只有在"性价比高于同预算的 build/up"时才会被选中**（这正是"废按钮"命题的正确检验：废按钮 = 它永远排不进最优） |
| **扣费** | 从 `shop_phase` 的 `budget` 中扣（与 `build`/`up`/`reinf` 同源），🔴 **不新开货币、不动 `income_mult`** |
| **买不起** | 静默跳过（E-T4 同款：允许"放着不管"，永不死锁）→ 🟡 **必须计数**（见 §3.7） |

### 2.7 边缘情况（≥3 类是输出规范，本节给 8 类）

| # | 边缘情况 | 处理规则 |
|---|---|---|
| **E-V1** | **多座塔同时 Disabled** | 按 `gain/cost` 逐个竞标；🔴 **不要求一次全修**（与 E-T2「合并为一个列表弹窗」是 UI 层要求，AI 侧逐座决策不冲突） |
| **E-V2** | **预算不足** | 跳过该塔，保持 `disabled`；计入 `n_no_money` 计数器；🔴 **不得**为修塔透支或赊账 |
| **E-V3** | **修复后又在同一波被打停** | 允许（`dis_new` 毛流量语义会再计一次）→ 🟢 这正是"修了也白修"的**直接证据**，必须能被测到 |
| **E-V4** | **Disabled 塔在修复前被 `drop_from`（`reinf_swap`）移出 `player.towers`** | 塔已不在数组 → 修复动作不再枚举 → 该槽位视为"已重建"；🔴 **不得**对已消失的塔报错（R-T7 同族陷阱） |
| **E-V5** | **A 路径 `max_towers = 2`（`shop_ai.gd:155`）** | A 路径只有 2 座塔 → 一座 Disabled 意味着 **50% 输出归零** → 🟢 这解释了为什么 A 塔死必失守，也意味着 **A 是修复收益最大的画像**，选 A 路径做主战场是对的 |

## 3. 验证判据

### 3.1 🔴 主判据量的口径澄清（先对齐"0.617 是哪个量"）

任务书写的是"起飞率相对基线 0.617"。核对后必须钉死：

> **0.617 是 A 路径 300 局的「存活率 `surv`」（末波 `core_hp > 0`，185/300），不是 `rate`（起飞率）。**
> 出处：`tests/run_slice_attrition8.gd:137` 与 :145 —— 该脚本的 `takeoff_a` 实际统计的是 `float(outa["rows"][-1]["core_hp"]) > 0.0`，打印行（:151）却标为"起飞率 B/A"。
> 这是 **R-5 正在追的"同一个起飞率两个定义"**的同一个坑（`scan_attrition8.gd` 用"存活 AND 曾达 ratio≥1.0"，`run_slice_attrition8.gd` 用"仅存活"）。

| 量 | 定义 | V-7 中的角色 |
|---|---|---|
| **`surv`** | `#{末波 core_hp > 0} / N` | 🔴 **主判据量**（与基线 0.617 同口径，`r2-criteria-revision.md` §4.1 已定 `fail[i]` 用存活口径） |
| `rate` | `#{存活 AND takeoff_wave ≥ 0} / N` | 🟡 **副指标**，一并打印不进判据（避免与 R-5 的第二定义混用） |

→ **V-7 的 Δ 定义为 `Δ = surv_arm − surv_base`（存活率差），单位 = 比例点。**

### 3.2 🟢 一个能大幅简化判据的结构事实：Δ 不可能为负

由 `hit_surv = 0.0000` 可直接推出：

| 推论 | 论证 |
|---|---|
| **① 无塔死的 212 局在三臂间逐位相同** | 修复分支只在 `disabled == true` 时枚举 → 这 212 局的 `enumerate_actions` 产出与基线**完全一致** → 决策序列、RNG 消费、战斗结算逐位相同 → 结局相同（185 存活 + 27 失败） |
| **② 只有那 88 局塔死局可能翻盘** | 基线存活的 185 局全部无塔死（推论①）→ 它们在干预臂**必然仍存活** → 不存在"干预后从存活翻成失败" |
| **③ `Δ = (被救回的塔死局数) / 300`，且 `Δ ∈ [0, 0.2933]`** | 上限 = 88 局全部救回 = 88/300 = **0.2933**；下限 = 0（不可能为负） |
| **④ 🔴 单侧检验是结构正当的** | 不是"为了通过而取单侧"——**负向效应在结构上被排除**。🟢 这让我们在同等 α 下拿到更多检验力 |

→ **Δ = +0.05 的设计语义换算**：`0.05 × 300 = 15` 局被救回 = **88 局塔死局中的 17.0%**（`r_rescue = 15/88 = 0.1705`）。
→ 换个说法更好懂：**「掉塔的局里，至少约六分之一能靠修爬回来」= 修复不是废按钮。**

### 3.4 SE 与样本量纪律（🔴 本节是本规格最需要用户过目的一段）

Δ 的 SE 有两种模型，**必须都打出来，用哪一个取决于配对是否真的成立**：

| 模型 | 公式 | 假设 | n=300 时 `SE_Δ` | Δ=+0.05 的 z |
|---|---|---|---|---|
| **保守 · 独立两比例** | `SE_Δ = √(p₀(1−p₀)/n + p₁(1−p₁)/n)` | 两臂独立 | **0.0391** | **1.28 SE** → 单侧 p ≈ **0.10** ⚠️ |
| **配对 · 同 seed 配对差** | `SE_Δ = √(88·r(1−r))/300`（仅 88 局可能翻转） | 两臂同 seed、仅在修复触发点后分叉 | **0.0118**（r=0.1705） | **4.24 SE** ✅ |

**推导用的实测数（全部来自 `r2-criteria-revision.md` §4.4）**：

| 量 | 值 |
|---|---|
| 基线 `p₀ = surv_base` | **0.617**（185/300）· `SE(p₀) = 0.0281` |
| 失败局 `n_fail` | **115** |
| 塔死局 `n_td`（`X_form ≥ 1`） | **88**（全部落在 115 失败局内） |
| 无塔死局 | **212**（= 185 存活 + 27 失败但无塔死） |
| `Δ` 结构上限 | **0.2933**（88/300） |
| `Δ = +0.05` 等价 | **15 局救回** = `r_rescue = 15/88 = 17.0%`（`SE(r) = 0.0401`，95% CI ≈ [0.092, 0.249]） |
| 保守口径单侧临界（α=0.05） | **Δ ≥ 0.064** 才算显著 |
| 保守口径双侧临界 | **Δ ≥ 0.077** |

#### 3.4.1 🔴 强制前置：配对校验（决定用哪个 SE）

配对不是免费的——修复一旦触发，它消耗预算 → `shop_phase` 的动作数/reroll 数变化 → **RNG 消费序列分叉** → 分叉点之后的 build 序列实质独立。因此**必须实测配对强度**，不能假定：

| 输出量 | 定义 | 判读 |
|---|---|---|
| `n_identical` | 三臂间**逐波 `rows` 完全逐位相同**的局数 | 🟢 **≥ 200**（≈212）→ 配对成立 → **用配对 SE（0.0118）判读** |
| `n_discordant` | `300 − n_identical` | 🔴 若 `n_identical < 200` → 配对破功 → **退回保守 SE（0.0391）判读** |

> 🔴 **纪律**：**先证配对，再选 SE**。禁止先跑出结果再挑一个更漂亮的 SE（那是 §6-② 明令禁止的"假装它是闸门"的同款错误）。

#### 3.4.2 样本量纪律（灰区加跑规则）

若判读落在**分支 B（灰区）**，只有三条合法出路（🔴 **第四条"把门槛降到刚好通过"不合法**）：

| 出路 | 成本 | 适用 |
|---|---|---|
| **① 加跑** | 每臂 **≈1140 局**（单侧 α=0.05、power=80%、检出 Δ=0.05、`p̄ ≈ 0.642`）；双侧则需 **≈1450 局/臂** | 🟢 **推荐**。批处镜像是确定性的纯计算，`run_loop_aggro` 单局成本极低 → 1140×3 臂在小时级 |
| **② 换统计量** | 改用 `r_rescue = 救回局数 / 88`（分母固定、配对性更强，`SE = 0.0401`，17% 对应 **4.26 SE**） | 🟢 **推荐作为主判据的并列读法**：它把"88 局里救回几局"直接摆出来，比 Δ 更好解释 |
| **③ 承认无判别力** | 降级为事实登记，挂观察项，🔴 不得假装它是结论 | 仅在加跑预算不可得时 |

**样本量算式（留给复核）**：`n/臂 = 2·p̄(1−p̄)·(z_α + z_β)² / Δ²`
　单侧：`2 × 0.2299 × (1.645+0.8416)² / 0.05² = 1137` → **≈1140**
　双侧：`2 × 0.2299 × (1.96+0.8416)² / 0.05² = 1444` → **≈1450**

### 3.5 🔴 新增的一条纪律（补进 `r2-criteria-revision.md` §6）

> **⑦** **对照实验的判读门槛必须同时满足"效应量门槛"与"显著性门槛"。**
> 只给一个 Δ 阈值（如 +0.05）是不够的 —— 它回答"多大算有设计意义"，但没有回答"多大算测得到"。
> 判读必须给出 **Δ 点估计 + 单侧 95% CI + z**，并按 §3.3 三分支判读；落在灰区时**必须加跑或换统计量**，🔴 **禁止用点估计宣布结论**（这与 §6-③「禁止把阈值贴到实测值身边」是同一条原则在对照实验上的应用）。

### 3.6 🟡 支柱漂移观察项（Δ 不是越大越好）

`V-2` 已定稿"承认单核高风险画像为**设计预期**"（A 破线 = 单核流的高风险，B 免疫 = 多塔稳健流的奖励）。若修复把 A 抬得太高，会把这条**风险画像分化抹平**：

| 观察量 | 警戒线 | 含义 |
|---|---|---|
| `surv_A(priced)` | 🔴 **≥ 0.817**（即 `Δ ≥ +0.20`）→ 触发复核 | A 逼近 B（`surv_B = 1.000`）→ **风险画像分化消失 → 支柱漂移**（概念 §2.4.6「每局一个新解」的画像维度塌一格） |
| `rate_A / rate_B` 比 | 与六槽金标本 `B/A` 关系对照 | 若 A 追平 B，§3 玩法①「单核怕主力被点掉，多塔怕群体被清场」的分化叙事失效 |

→ 🟡 **判读时把 Δ 与"画像分化是否仍在"一起看**：Δ 达标**且** A 仍显著低于 B = 理想结果（修复给了玩家出路，但没抹掉单核的高风险）。

### 3.7 必打的诊断计数器（🔴 没有这几个数，Δ=0 无法解释）

`Δ = 0` 有两种完全不同的原因，**必须能分开**：

| 计数器 | 定义 | 用途 |
|---|---|---|
| `n_repair_eligible` | 出现过 ≥1 座 Disabled 塔的局数（应 ≈ 88） | 分母 |
| `n_repair_enumerated` | 修复动作被 `enumerate_actions` 产出的局数 | 区分"塔死了但动作没枚举"（实现 bug） |
| `n_repair_fired` | 修复**实际成交**的次数 | 🔴 **核心**：`Δ=0` 且 `n_repair_fired=0` = **"从没修成"**（定价/预算问题）；`Δ=0` 且 `n_repair_fired>0` = **"修了也没用"**（机制问题） |
| `n_no_money` | 想修但预算不足的次数 | 定价过高的直接证据 |
| `n_repair_then_redied` | 修复后在同一波/下一波**再次被打停**的次数 | "修了也白修"的直接证据（E-V3） |
| `n_repair_lost_to_drop` | Disabled 塔在可修前被 `drop_from` 移出的次数（E-V4） | 修复窗口被 AI 自身行为吃掉的比例 |
| `spend_repair_total` | PRICED 臂累计花在修复上的分数 | 经济影响量（对照 §4 红线：是否挤占 DPS 投入） |

## 8. 一句话给主理人

> **V-7 要回答的是一句话：GDD §2.3 承诺的「塔死了你还可以在安全窗修它」到底是真设计还是纸面设计——因为实测显示掉塔的局 100% 输，而 `shop_ai` 根本没有修复分支，这条路径一次都没被走过。**
> **处置是一个默认 off 的三臂诊断开关（OFF / 免费修 / 定价修），跑 300 局 A 路径看存活率相对 0.617 的回升 Δ；Δ = +0.05 的语义是"掉塔的局里约六分之一能爬回来"。**
> 🔴 **两件需要你拍板的事**：**① +0.05 这个门槛我算出来在 n=300 下只有 1.28 SE（灰区），要么接受"加跑到 1140 局"的纪律，要么把门槛抬到 +0.077**；**② 若真判成废按钮，是改 GDD 措辞承认"塔死亡 = 致命诊断"，还是改机制让它真的可恢复——这是设计哲学，我不替你定，建议等数据出来再拍。**
> 🟢 **另外提醒一个实现陷阱**：AI 侧 `invested` 恒为 0，直接套 `repair_cost` 会算出 0 分免费修、把 PRICED 臂做成假阳性 —— 已写进 §2.5 并给了 `invested_est = 12h + 9L` 的替代记账。
