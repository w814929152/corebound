## 2. 口径分歧裁决 —— **以 X_form（成型期 W6–12）为准**

### 2.1 分歧本身

| 口径 | 定义 | 三臂结果 | 显著性 |
|---|---|---|---|
| **X_form（成型期 W6–12）** | 主口径（baseline hit=0.1900 / hit_surv=0/179 同口径，纵向可比） | 三臂全 0 | ns |
| **X_any（全程 W1–20）** | 副口径（多抓雪崩期晚死塔） | PRICED 17/627 | **sig（z=+4.16）** |

问题：§2.3「可恢复挫折」的"恢复"，到底指**成型期（W6–12，机制主场）**还是**全程**？

### 2.2 裁决：**主口径 = X_form，X_any 为交叉验证**（复述加跑规格 §Q9 已拍板口径，并用新数据坐实）

**理由一（设计定义层）：§2.3 的机制主场就是成型期，"可恢复"必须发生在机制被设计为致命的地方。**
- §2.3 / V-1′ 判据族（T-A′-1/-2）一律以**成型期 W6–12**为塔死亡机制的验收窗口——这是"塔死亡作为对单核赌狗的风险惩罚"被设计生效的区间（`mechanics-tower-life-death` §4.2 V-1′ 行）。
- 「可恢复挫折」的命题是：*在机制本应致命的主场，玩家有一条能爬回来的路*。若只在苟活期掉塔能爬回、成型期掉塔全死，那恰恰**证伪**了 §2.3 在主场的设计意图——不能用一个"机制没上场"的窗口（苟活期掉塔本就轻）来替它背书。

**理由二（数据层 · 决定性）：那 17 局全部是 W3 苟活期掉塔，成型期救援率 = 0.0000。**
加跑日志 DIAG 块 (B)/(D)/(C) 给出程基岩正在补的波次分布：

```
(B) first-death bucket over X_any>=1 games:
    PRICED  627 |  W1-5=306   W6-12=321   W13-20=0  |  survived: W1-5=17  W6-12=0  W13-20=0  | rescue rate: b1=0.0556  b2=0.0000  b3=n/a
(D) [PRICED] over the 17 climb-back games:
    first tower death : b1=17  b2=0  b3=0      <- 17/17 首次塔死都在 W1-5
    last  tower death : b1=17  b2=0  b3=0
    first restore wave: b1=14  b2=3  b3=0
(C) 逐局：17 局的 W_first_death 全部 = 3
```

→ **17/17 的首次塔死发生在 W3（W1–5 苟活期），成型期（W6–12）救援率 = 0.0000（三臂一致，b2 列 survived=0）。**
→ 这 17 局的画像：苟活期掉了一座塔 → 修了 → 之后**成型期再没掉过塔** → 侥幸活到末波。它们**不是**"成型期掉塔被救回并起飞"，而是"成型期根本没经受考验"。作为 §2.3 主场证据，**它们分母为 0**。

**理由三（统计诚实层）：X_any 的显著性是"真信号但答错了问题"，不得自动取更漂亮的一个。**
- 加跑规格 §Q9 已预裁："主口径 = X_form；🔴 若两者给出不同分支结论 → 不得自动取更漂亮的一个，须回报二次判读。" 本裁决即该二次判读。
- X_any 的 17 局是**真实存在**的（不是口径造假），但它把"苟活期掉塔"这个**轻症**混进了分母——苟活期掉塔本就更容易爬回（塔死得早、螺旋还没起来、修完后面风平浪静）。X_any 显著，恰恰是因为它纳入了大量"机制没发力"的窗口。**用它判 §2.3 = 用机制不致命的窗口证明机制可恢复 = 循环论证。**

### 2.3 口径裁决结论

> 🔴 **§2.3「可恢复挫折」的"恢复"= 成型期（W6–12）口径**。判据以 `hit_surv`（X_form）为准。X_any 全程口径**仅作交叉验证保留**，其 PRICED 17 局显著性**不改变主口径结论**——它们是苟活期（W3）掉塔的爬回，不是成型期机制主场的证据。
> 🟢 这与加跑规格 §Q9 已拍板口径**完全一致**，本文件只是用 DIAG (A)–(E) 的新数据**坐实**了"两者给出不同分支结论时取 X_form"这一预裁。

## 3. 分支判读终审 —— V-7 落在 **C1（FREE 显著有害）+ B 灰区（PRICED）的分裂**

按加跑规格 §4 的 A/A′/B/C 分支逐臂判：

| 臂 | n_rescue（X_form） | Δ 双侧 | 分支 |
|---|---|---|---|
| FREE | 0/403 | **−3.85pp，z=−2.11，CI 上界 −0.003 <0** | **C1：显著有害** |
| PRICED | 0/356 | +1.08pp，z=+0.60，CI 含 0 | **B：灰区（不显著）** |

**程基岩初判（FREE 落 C1、PRICED 落 B）—— ✅ 终审确认，判读正确。**

### 3.1 为什么整体不判 C（致命诊断），而判"分裂"

加跑规格 §4 分支 C 要求**两臂** n_rescue 均 0 **且** Δ_free 与 Δ_priced **双侧 CI 上界均 <0**。
- FREE 满足（C1 成立）。
- **PRICED 不满足**：Δ_priced CI = [−0.025, +0.046]，**上界 +0.046 > 0**，且 z=+0.60 不显著。
- → **分支 C（全称性"两臂都致命"）不成立**，降级。

### 3.2 为什么也不判 B（单纯 INCONCLUSIVE）

B 要求"两臂 n_rescue 均 0 且 Δ 双侧 CI 含 0"。但 **FREE 的 Δ 显著为负**（不含 0）→ 不满足"两臂都灰区"。
- FREE 臂是**明确的有害证据**（无条件免费修让存活率掉 3.85pp，且 96.78% 修完又被打停）。

### 3.3 终审分支判读

> 🔴 **V-7 落在「C1 成立（FREE 显著有害）× PRICED 灰区（B）」的分裂态**：
> - **FREE 臂 = C1 坐实**：无条件修复**显著有害**，塔死亡是正反馈螺旋的**不可脱出环节**（R-T10 坐实：修好→重新暴露仇恨→又被打停，96.78%）。
> - **PRICED 臂 = B 灰区**：定价修复**方向为正但不显著**（+1.08pp，CI 含 0），**不能宣布有效，也不能宣布致命**。那 17 局 X_any 爬回（W3 苟活期）给它一点微弱正信号，但**在主口径 X_form 下 = 0**，不足以翻案。
> - **脚本自评的 "B / C-FATAL" 是保守下界**；终审精化为上述**分裂判读**——FREE 已越过 B 进入 C1，PRICED 仍在 B。

## 4. Q-A 最终推荐 —— **(b) 改机制**（非 (a) 承认失效）

用户预注册：hit_surv 仍 0 → 推荐 (b)。数据支持此预注册。

### 4.1 三选项对照

| 选项 | 含义 | 数据支持度 | 我的推荐 |
|---|---|---|---|
| (a) 承认"失效判决"，§2.3 降为止损操作 | 塔死=致命，修/拆/放着只是"死缓"，不再宣称可恢复 | 🟡 数据支持"当前机制下修不回来"，但 (a) 等于**把设计缺陷合法化** | ❌ 不推荐 |
| **(b) 改机制**（Disabled 保留部分输出 / 缩短 Disabled 持续 / 自动重启） | 让"修"真的能改变结局——给塔死亡一个**可脱出的螺旋** | ✅ FREE 有害 + 96.78% 再暴露 + restore-events=0 → **当前 Disabled 全停 + 永久暴露 = 螺旋不可脱出**，必须改 | ✅ **推荐** |
| (c) 不动 | 维持现状 | 🔴 FREE 显著有害已被证，不动 = 放任一个被证有害的机制进 MVP | ❌ 不推荐 |

### 4.2 为什么是 (b) 而不是 (a)

1. **数据指向"机制结构有问题"，不是"塔死亡本质致命"。** FREE 臂 96.78% 的"修完又被打停" + restore-events=0（修完连一整波都活不过）→ 问题出在 **Disabled 的当前定义**（全停输出 + 修完**重新完全暴露**给仇恨），而不是"塔死亡这个事件本身不可救"。这正是 R-T11 的双向操作 ⊖ 重新暴露仇恨的**极端体现**。
2. **(a) 是"把缺陷写成特性"。** §2.3 的定稿价值主张是"把战斗内事故翻译成波次间可归因决策，胜任感保住"（概念 §4.1）。(a) 承认失效 = 放弃这条支柱（支柱漂移）。而 (b) 是**保留支柱、修机制**：让"可归因的补救"真的能补救。
3. **(b) 与已定稿的 §2.6「风险可归因 + 可预先管理」替代论证同向**（撤回声明已把"机制自限"论证改写为"风险可管理"）——(b) 是把"可管理"落到机制层，而非仅在文案层。

### 4.3 (b) 的三条候选子形态（🔴 具体选哪条 = 用户拍板，见 §5）

| 子形态 | 机制 | 优点 | 风险 |
|---|---|---|---|
| **(b1) Disabled 保留部分输出** | 停机但保留 h_j· 部分 DPS（如残骸余热） | 直接给"修 vs 不修"一个连续杠杆；共鸣网不塌（保 §2.4 ①） | 可能弱化惩罚 → 需重扫 ATTRITION/κ_r |
| **(b2) 缩短 Disabled 持续 / 自动重启** | Disabled 只持续 N 波后自动恢复（或安全窗未修则自动重启） | 给塔死亡一个"自然脱出"的兜底，破螺旋 | 可能让塔死亡失去"真损失"重量（§2.3 理由 5） |
| **(b3) 修复降低再暴露度** | 修好的塔获得临时护盾 / 仇恨权重降低（修完不立刻被集火） | 精准打击 R-T11 的 ⊖ 重新暴露项，保留惩罚框架 | 实现最重，需新增仇恨修饰 |

> 🟡 **我的排序倾向**：**(b3) > (b1) > (b2)**——(b3) 最精准地针对数据挖出的根因（再暴露），且不破 §2.3 惩罚重量与 §2.4 共鸣；(b2) 的"自动重启"最可能稀释惩罚、触发支柱漂移。**但这是设计哲学选择，最终由用户拍板。**
