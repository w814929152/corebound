## 0. 三句话结论（给赶时间的人）

1. **T-A′ 的命题是"玩家在一局里能不能感知到塔死亡"，所以它的统计量必须是 per-run 的命中率，不能是 300 局均值** —— 均值口径既错配命题，又只有 12.5% 裕度（95% CI ≈ [0.96, 1.32]，下界已破 1.0）。我推荐改成**双判据**：「存活性下限」+「失败局伴随率」。
2. **T-D′ 必须降级为「事实登记」，同时新增一条可证伪的阳性对照 T-D″**（同一套数值切 PATH 几何跑 B，必须出现塔死；实测 = 3）。这样把 T-D′ 的零信号换成一条真闸门——它能抓"塔死亡代码整体失效"这类回归。
3. **GDD 的"推荐落点 2.52"必须作废**：V-1′ 实测扫描 `ATTRITION ∈ [1.0, 6.0]` 11 点全 PASS 且非单调 → 扫描对该参数**无鉴别力**，`ATTRITION` 沿用 1.50 的真实理由是**金标本零改动**，不是"扫描甜点"。此项已回写 GDD。
4. ✅ **R-T7 已结案（不是 bug）**：`dis_new` 是「塔被打停**事件**」的毛流量，`towers_disabled` 是存量；`drop_from`（`reinf_swap` 换宿主塔）会把 Disabled 塔移出数组 → 存量降流量留。铁证：PATH B 对照 W4–W6 累计 **3 次事件**而末波存量 **0**。→ **这个语义对"可感知性"命题恰好是更好的度量单位**（每次事件 = 玩家目睹的一次）。我在 v1 里写的恒等式断言已作废。

## 1. 先钉死：T-A′ 到底在问什么（这是口径之争的根）

质量门把 T-A′ 的问题定性为"统计量错配"。要选对统计量，必须先回答一个**设计问题**，而不是统计问题：

> **塔死亡机制，是一个「每局都该发生的常态机制」，还是一个「条件触发的风险惩罚」？**

两种读法导出完全不同的判据：

| 读法 | 设计命题 | 正确的统计量 | 隐含的设计世界观 |
|---|---|---|---|
| **甲 · 常态机制** | 每个玩单核流的玩家，每局都该看到塔死 | **中位数 ≥ 1**（等价于"过半局发生"） | 塔死亡是"税"，均匀摊在每局上 |
| **乙 · 条件惩罚**<br>（**我的判断**） | 当单核赌狗**赌输**时，玩家必然看到塔死，且能归因 | **条件命中率** `P(塔死 ≥1 \| 该局失败)` + 无条件**存活性下限** | 塔死亡是"风险"，集中在失效局上 |

### 1.1 为什么我判断是「乙 · 条件惩罚」

四条依据，全部出自已定稿的文档，不是我的新解读：

1. **V-1′ 自己的措辞就是条件式的**：GDD §4.2 V-1′ 原文 —— 「T-A′ 机制对**高风险画像**可感知」「定稿处置③：塔死亡机制定位**重定义**为『**对单核赌狗的风险惩罚 + 对多塔稳健流的奖励**』」。它约束的是**画像**，不是**每一局**。
2. **它与 §2.5「机制自限」自洽**：GDD §2.5 已定稿「雪崩期 DPS ≫ 怪物 HP → 怪在路径前段被清光 → 塔在 W13+ 几乎不再受创 → 机制自然退场」。一个**会自然退场**的机制，天生就不可能是"每局均匀发生"。
3. **它与 V-2 已定稿的「单核高风险画像」自洽**：V-2 已拍板「承认单核高风险画像为**设计预期**」「A 破线是 AI 局限的产物，不是单核流不可玩的证据」。若塔死亡是每局的均匀税，那 A 就不是"高风险画像"，而是"稳定受损路径"——与 V-2 定稿冲突。
4. **「甲」在当前几何下不可达，只能靠重开机制**：探针已证 `attrition=50`（33×）下 B 仍 `dis_new=0` → B 的免疫来自"怪根本没机会接触塔"，不是"伤害不够"。想让 A 过半局都挨打，唯一可用的杠杆是**几何 / `AGGRO_R` / 怪物 HP**（`ATTRITION` 已被证伪）→ 那是 **R-3 / V-6 立项**的 scope，不是本次"改判据口径"能做的事。

> 🔴 因此：**本次 R-2 的任务边界 = 把「乙」这条设计命题用一条听得懂、算得出、可证伪的统计量表达出来。**
> 若用户认为应该是「甲」，那不是改判据，而是**立项重开机制**（并入 R-3 / V-6），本文 §3 方案 B 会说明代价。

### 1.2 一个我从数据里读出来的、必须登记的设计事实

把已知数字摆在一起：

| 数字 | 值 | 出处 |
|---|---|---|
| A 路径 300 局**存活率**（末波 `core_hp > 0`） | **0.617** → 失败率 **0.383** | `run_slice_attrition8.gd` |
| A 成型期 W6–12 塔死 **300 局均值** | **1.143** | 同上 |
| A 单局探针塔死 | **4**（W10=2, W11=2，末波 `core_hp=0.0`） | `probe_radial_aggro.gd` |
| 粗估的单局命中率 | **≈0.30**（严守真估；本文 §4 给出实测方案） | 质量门 §3.3-①(ii) |

**1.143 ÷ 0.383 ≈ 2.98** —— 即"失败局平均掉约 3 座塔"，与探针单局的 4 同量级。
→ **强烈提示：塔死亡几乎只发生在"最终失守"的那 38% 局里；成功起飞的 62% 局基本不掉塔。**

这个事实是**双刃**的，必须如实登记：

- 🟢 **正面**：塔死亡 = 单核赌狗**失败的失效路径**，因果链清晰（塔被打停 → DPS 崩 → 漏怪 → 核心失守）→ 玩家能**归因于决策**（概念 §4.1 胜任感），正是 §2.2 定稿 ①「可归因」要的。
- 🔴 **负面（新风险 · 我登记为 R-T6）**：若 `P(塔死\|失败) ≈ 1` 且 `P(塔死\|起飞) ≈ 0`，则塔死亡是**失败的症状**而非**独立的机制**——它不携带增量信息。在**金标本 AI（不保塔）**口径下，它就是"输的另一种说法"。
  🟢 **但这个负面只在 AI 口径下成立**：`scan_bulwark` 已实测 **A 无保护 0.393 → A 理想肉盾 0.623**（+0.23）→ 在**玩家保塔口径**下，塔死亡是一个**可被操作改变的风险**，有实打实的玩法分量。
- 📌 **结论**：「可感知性」这个设计命题，**最终应该在玩家保塔口径下验证**（V-2/V-4 的延续），而不是在金标本 AI 口径下。本次 R-2 只负责把金标本口径的判据修成"算得对、有裕度、可证伪"，**并把这个口径局限显式登记**。

## 2. 决策点 1：T-A′ 统计量怎么改

### 2.1 三个方案（供用户拍板）

| # | 方案 | 判据表达式 | 改动量 | 修了什么 | 没修什么 |
|---|---|---|---|---|---|
| **A**<br>✅ **用户已拍板** | **条件风险惩罚口径**（双判据 + per-run 分布） | **T-A′-1** `P(单局 X_form ≥ 1) ≥ 0.15`（存活性下限）<br>**T-A′-2** `P(单局 X_form ≥ 1 \| 该局失败) ≥ 0.60`，护栏 `n_fail ≥ 30` | 中（需 per-run 采集 + 直方图） | ✅ 统计量错配<br>✅ 裕度（预计 ≥3.8 SE）<br>✅ 可证伪<br>✅ 直接回答"玩家能不能感知" | 仍依赖"失败局"这个分母（若 A 变强到几乎不失败 → INCONCLUSIVE，有护栏） |

| **C** | **下调均值阈值 + 登记口径**（最小改动） | 保留 300 局均值，阈值 `≥1.0 → ≥0.7`，GDD 明写"这是聚合口径，不代表单局可感知性" | 极小（改一个数 + 文档） | ✅ 诚实性（口径已登记）<br>✅ 裕度（(1.143−0.7)/0.08 ≈ **5.5 SE**） | 🔴 **统计量错配没修**——仍是"跨局均值判单局命题"。它现在能告诉你的只有"塔死总量没归零"，**分辨不出"多数局可感知"与"少数局尖峰"** |

### 2.2 我的推荐：方案 A，理由三条

1. **它唯一直接回答了设计命题。** "机制可感知"是 per-run 属性，只有 per-run 命中率是同单位的度量。方案 C 是给一条错配的判据贴标签——诚实，但没修好。
2. **它同时保住了"机制不是死代码"这条底线。** 单靠条件判据（T-A′-2）在"A 变得几乎不失败"时会失去分母；T-A′-1 的无条件下限兜住这个洞。两条一起才是一个完整的命题。
3. **它的裕度是结构性的，不是碰巧的。** 预计实测 `hit ≈ 0.30`（n=300 → SE ≈ 0.0265）→ 阈值 0.15 落在 **≈5.7 SE** 之外；`hit_fail` 预计 ≥0.75（n_fail ≈ 115 → SE ≈ 0.040）→ 阈值 0.60 落在 **≈3.7 SE** 之外。**而现行判据只有 1.6~2.0 SE。**

### 2.3 为什么我不推荐方案 C 作为终态，但同意它可以做"过渡"

如果主理人/用户希望**先把 P1 解掉、把 per-run 排到 Phase 6**，那方案 C 是一个可接受的**过渡态**（改一个数即可，5.5 SE 裕度够了）。
🔴 但必须同时：**① per-run 采集照做**（它在 A / C 两个方案下都需要，见 §4）；**② GDD 登记"这是过渡口径，per-run 命中率出来后必须换成 T-A′-1/-2"**。否则 R-2 只是被贴了标签，没被关掉。

> 🔴 **给程基岩的关键提示**：**§4 的 per-run 分布统计输出在 A / C 两个方案下都是必需的**（B 方案下更是必需）。**它可以先于用户拍板开工**，不需要等决策。

## 3. 决策点 2：T-D′ 怎么定位

### 3.1 三个选项

| # | 选项 | 评价 |
|---|---|---|
| ① | **删除 T-D′** | ❌ 不推荐。它登记的"B 结构性免疫"是一个**真实且有信息量的设计事实**（V-1′ 定稿处置③ 里"对多塔稳健流的奖励"就靠它支撑）。删了就没人再记录它。 |
| ② | **保留为「事实登记」**（明确标注非闸门） | 🟢 **采纳一半**。修掉了"给人'B 已被验过'的错觉"这个真问题。但**只做这一半，闸门总数从 4 条降到 3 条，信号更少了**。 |
| ③ | **改成可证伪的判据** | 🟢 **采纳另一半**，但不是把 T-D′ 改成"干预下 B 必须死塔"（那是在测干预，不是在测机制）——而是见 §3.2 的**阳性对照**。 |

### 3.2 我的拍板：**② + ③ 合并 —— T-D′ 降级为事实登记，新增 T-D″ 阳性对照**

**T-D′（新定位）＝ 事实登记 · 非闸门**
- 从 `_fail` 计数中移除，改打印为 `〔事实登记〕B 全程塔死 = 0.000（径向结构性免疫 · 恒真 · 零信号 · 若将来 FAIL 需人工判读是回归还是设计演进）`。
- 语义保留：它是 V-1′ 定稿处置③「多塔稳健流的奖励」的**证据留档**。

**T-D″（新增 · 真闸门）＝ 阳性对照**
> 在一个**已实测能打破 B 结构性免疫**的对照配置下，B 路径**必须**出现塔死。

| 项 | 规格 |
|---|---|
| **对照配置** | 同 `ATTRITION=1.50` / `HP0=120` / `h^0.6` / `AGGRO_R=9.0` / 八槽 B 路径 / `WARMUP=2` / seed 20261002，**唯一改动 = `SpaceModel.mode = PATH`**（六槽折线几何，怪沿路径穿过塔的覆盖区） |
| **判据** | 单局全程 `Σ_w dis_new ≥ 1` |
| **实测** | **3**（W4 / W5 / W6 各 1，末波 `core_hp = 1000.0`）—— 出处：`probe_radial_aggro.gd` 输出行「PATH 多塔 B 路径 attrition=1.5（对照）」 |
| **裕度** | 实测 3 vs 阈值 1 → **3× margin**（确定性单局，固定 seed，不会 flaky）。🔴 若实测掉到 1 → margin 归零 → 打印 `⚠️ T-D″ 裕度归零` |
| **为什么是几何对照而不是调 `ATTRITION`** | 探针已证 `ATTRITION=50`（33×）在径向下 B 仍 `dis_new=0` → `ATTRITION` **不是**能打破免疫的杠杆（用它做对照 = 恒假，等于没做）。几何才是：**同一套伤害代码、同一套数值，只换怪物是否走到塔前** → 若 PATH 下塔死也归零，说明**塔死亡代码本身死了**，而不是"免疫"。 |

> 🎯 **这就是 T-D″ 的价值**：它把 T-D′ 那条"零信号"的断言，换成了一条**能抓真回归**的闸门 —— 只要有人改坏了仇恨 / 对塔伤害 / `Disabled` 状态机 / DPS 重算，`T-D″` 会立刻变红，而 `T-D′` 永远绿。

### 3.3 T-C′ / T-B′ 的连带修订（🟡 次要，一并处理）

| 判据 | 现状问题 | 我的修订建议 |
|---|---|---|
| **T-C′** | 只查 B 雪崩期 → 与 T-D′ **高度冗余**（B 全程都 0，雪崩期当然 0） | **降级为观察项**，并把 A 路径雪崩期**一并打印**（不进 fail 计数）。⚠️ **A 侧有删失偏倚**：A 失败局在 W11 就 break（`run_loop_aggro.gd`：`if core_hp <= 0.0: break`），根本没有 W13+ 的行 → A 雪崩期天然为 0。**这不能当作"退场"的证据，只能当作"无数据"**。→ 若要真验"退场"，需按"W13 时仍有存活塔的局"分层（诊断项，非闸门）。 |
| **T-B′** | 上界 `≤4` 来自 n=1 探针值，既测不到失控也没定义失控 | 改为**尾部控制**：`P(单局 X_form ≥ 5) / N ≤ 0.05`（等价于 **p95 ≤ 4**）。语义："一局掉 5 座以上塔必须是罕见的"。🔴 阈值同样须按 §6 标定纪律复核。 |

## 4. per-run 分布统计输出规格（🔴 给程基岩的实现规格）

> **本节是 A / B / C 三个方案共用的前置**，可以先于用户拍板开工。
> 目标：把"塔死亡分布"从黑箱里拿出来。判据永远建立在能被看见的分布上。

### 4.1 采集（每局 i，路径 `p ∈ {A, B}`）

沿用现有调用（`run_slice_attrition8.gd` 的口径，`SpaceModel.mode = RADIAL`，`n_slots=8`，`max_actions=12`，`aggro=true`，`exp=0.6`，`attrition=1.5`，`warmup=2`，`rng=PyRandom(20261002)` A/B 各一）：

| 字段 | 定义 | 备注 |
|---|---|---|
| `X_surv[i]` | `Σ_{w ≤ 5} dis_new` | 苟活期 |
| **`X_form[i]`** | `Σ_{6 ≤ w ≤ 12} dis_new` | 🔴 **主判据量**（整数） |
| `X_snow[i]` | `Σ_{w ≥ 13} dis_new` | 雪崩期（注意删失，见 §3.3） |
| `X_all[i]` | `X_surv + X_form + X_snow` | 全程 |
| `w_end[i]` | `int(rows[-1]["w"])` | 实际跑到第几波（核心失守则提前 break） |
| `fail[i]` | `float(rows[-1]["core_hp"]) <= 0.0` | 🔴 **失败 = 存活口径**（与 `run_slice_attrition8` 的 `takeoff` 同口径；🔴 **不要**用 `scan_attrition8` 的"存活 AND 曾达 ratio≥1.0"口径 —— 那是 R-5 待修的第二个定义） |
| `reached_w10[i]` | `w_end[i] >= 10` | 是否真正进入塔死亡的集中发生窗 |
| `act13[i]` | `w_end[i] >= 13 ? rows[12]["towers"] − rows[12]["towers_disabled"] : -1` | W13 时存活塔数（供 T-C′ 分层诊断） |

### 4.2 聚合输出（打印 + 供判据消费）

```
N = 300

直方图   hist[k] = #{i : X_form[i] == k}  , k = 0..8
         hist[9+] = #{i : X_form[i] >= 9}
集中趋势 mean   = Σ X_form / N
         median = 中位数(X_form)
         p90 / max
命中率   hit      = #{i : X_form[i] >= 1} / N
         hit_w10  = #{i : X_form[i]>=1 ∧ reached_w10[i]} / #{i : reached_w10[i]}
         hit_fail = #{i : X_form[i]>=1 ∧ fail[i]}        / #{i : fail[i]}          ← 护栏 n_fail ≥ 30
         hit_surv = #{i : X_form[i]>=1 ∧ ¬fail[i]}       / #{i : ¬fail[i]}
失控尾   tail5    = #{i : X_form[i] >= 5} / N
对照     n_fail   = #{i : fail[i]}   ;  n_reach10 = #{i : reached_w10[i]}
```

🔴 **B 路径同样输出一份**（`X_form` 的直方图与 `hit`）—— 它是 T-D′ 事实登记的数据支撑，也是将来监测"B 免疫是否被打破"的基线。

🟡 **`scan_attrition8.gd` 的扫参表请新增一列 `hit`（A 路径无条件命中率）**：现行扫参表只有均值，而均值对 `ATTRITION` 已被证明**无鉴别力**（1.0→6.0 只在 1.000~1.483 非单调浮动）。**命中率是否更有鉴别力，值得一测**——若命中率对 `ATTRITION` 单调且跨度大，则 §3.3-②「扫参器无鉴别力」这条可被部分翻案，未来调参也有了个能用的旋钮。

### 4.3 ✅ `dis_new` 语义定稿（R-T7 已结案 · 2026-10-08）

🔴 **结论：`dis_new` 是「**塔被打停事件**」的毛流量（flow），不是「当前 Disabled 塔数」的存量（stock）。二者本就不应恒等。我在 v1 规格里写的恒等式断言 `Σ dis_new == towers_disabled` 是**错的，已作废**。**

**判定依据（代码 + 实测双证）**

1. **代码**：`wave_sim_aggro._damage_tower` 里 `dis_new_box[0] += 1` 只在塔**由未 Disabled 转为 Disabled** 的那一次触发（`if t == null or bool(t.disabled): return` 守卫），且镜像内 `disabled = false` **只存在于实时版** `scripts/gameplay/shop_runtime.gd:1012`（支付 30% 累计投入的修复），批处理镜像 `shop_ai.gd` **没有修复分支**。→ Disabled 一旦发生，在该塔身上**不会**被清除。
2. **但塔本身会离开 `player.towers`**：`shop_ai.drop_from()`（`shop_ai.gd:220-230`）按 `ctype` **移除** `player.towers` 中的塔，被 `reinf_swap`（换宿主塔：卸下旧塔型 → 之后以新塔型重建）调用。Disabled 塔被卸下 → 它从数组消失 → **存量下降、流量保留**。
3. **实测（决定性）**：`docs/phase3/qg-radial/qg-probe.log` 的 PATH B 对照逐波表 ——

   | W | 3 | 4 | 5 | 6 | 7 |
   |---|---|---|---|---|---|
   | `dis_new` | 0 | **1** | **1** | **1** | 0 |
   | `塔存`（=towers − disabled） | 8 | 7 | 7 | 7 | **8** |

   → W4–W6 累计 **3 次**被打停事件，而末波 `towers_disabled = 0`。**存量归零、流量保留** —— 与 `drop_from` + 重建的解释完全吻合。

**因此 `X_form` 的语义定稿为：**

> **`X_form[i]` = 第 i 局 A 路径在 W6–12 期间发生的「塔被打停事件」次数**（含同一槽位重建后再次被打停的重复计数）。单位 = **次/局**。上界不受塔位数限制（可 >8）。

🟢 **这个语义对本次设计命题是正合适的，甚至是更好的**：T-A′ 问的是"玩家能不能**感知**到塔死亡"，而**每一次被打停事件都是一次玩家亲眼目睹的时刻** —— 事件次数正是"可感知性"的正确度量单位。若用存量，"死了又被换掉"的经历会被抹掉，反而低估感知。

**替换掉那条错误断言后的输出规格（诊断，非闸门）：**

```
每局打印：  X_all[i]（流量） · rows[-1].towers_disabled（存量）· rows[-1].towers（总塔数）
恒真不变量（弱，可作 sanity check）：
    X_all[i] >= rows[-1].towers_disabled        # 流量 ≥ 存量
    rows[-1].towers_disabled <= rows[-1].towers # 存量 ≤ 总塔数
诊断量：    X_all[i] - rows[-1].towers_disabled  # = 被打停后被卸下/重建的事件数（应 ≥0）
```
🔴 **不要**把 `X_all == towers_disabled` 当断言 —— 它在有 `reinf_swap` 的局里会**假 FAIL**。

## 6. 🔴 阈值标定纪律（防止再次造出 12.5% 裕度的判据）

本次事故的根因不是"阈值定错了"，而是**阈值被定在了实测值身边**（1.143 vs 1.0，差 1.6~2.0 SE）。立一条规矩：

> **①** 任何判据阈值必须落在实测值下方 **≥3 个标准误**（比例型：`SE = √(p(1−p)/n)`；均值型：用扫参点间非单调摆动反推）或 **≥3 倍**（计数型 / 确定性单局）。
> **②** 实测出来后，若设计语义要求的阈值**无法**满足 ≥3 SE 裕度，只有两条合法出路：
> 　· **出路一**：承认该判据当前无判别力 → **降级为「事实登记」**并挂观察项，🔴 **禁止**假装它是闸门；
> 　· **出路二**：**立项改机制**（改的是设计/几何/数值，不是阈值）。
> **③** 🔴 **禁止"把阈值下调到刚好通过"** —— 那正是本次 12.5% 裕度的成因，它会让闸门在下一次 A 路径构筑微调时毫无预警地翻红。
> **④** 每条判据必须在输出里**打印它自己的裕度**（`(实测 − 阈值)/SE`），让脆弱性可见。

### 6.1 ✅ T-B′ 定档：断崖型分布下的阈值选型（2026-10-08）

#### 6.1.1 三个选项的逐项裁决

| 选项 | 裕度 | 检出能力 | 裁决 |
|---|---|---|---|
| **①** `P(X≥5) ≤ 0.07` | **3.54 SE** ✅ | 断崖整体迁移 → `tail5 = 0.2467`，`z = +7.10` → **必红** ✅ | 🟢 **采纳** |
| **②** `P(X≥6) ≤ 0.05` | 14.0 SE ✅✅ | 🔴 **完全失明**（见 6.1.2） | ❌ **否决** |
| **③** 降级为事实登记 | — | — | ❌ **否决**（见 6.1.3） |

#### 6.1.2 🔴 为什么否决选项②（这是本次最关键的一条判断）

选项②的裕度是三个选项里最漂亮的（实测 0.0033 vs 阈值 0.05 → **14 SE**），但它是**以牺牲检出能力为代价换来的**——它把检测点从断崖（k=4→5）**挪到了断崖右侧的空区**（k=6）。

按实测 hist 做劣化推演：

| 劣化情景 | `P(X≥5)`（选项①观测量） | `P(X≥6)`（选项②观测量） | ① 判定 | ② 判定 |
|---|---|---|---|---|
| 当前（实测） | 0.0333 | 0.0033 | PASS | PASS |
| 4-簇整体迁移到 5 | **0.2467** | 0.0033 | 🔴 **FAIL** ✅ | 🟢 **PASS（漏检）** ❌ |
| 全部非零局 +1 次 | **0.2467** | 0.0333 | 🔴 **FAIL** ✅ | 🟢 **PASS（漏检）** ❌ |

> 🔴 **结论：即使塔死亡分布整体 +1（每一局都多掉一座塔），`P(X≥6)` 也只从 0.0033 涨到 0.0333，仍然 ≤ 0.05 → 选项② 全程绿灯。**
> 它是一条**对唯一真实劣化路径完全失明**的闸门 —— 14 SE 的裕度是"它永远不会误报"，而不是"它有效"。
> 📌 **方法学教训（写进 §6 纪律）**：**裕度是必要不充分条件**。① 只保证"不会因噪声翻红"；必须先证明判据**对目标失效模式有检出能力**，再谈裕度。选项② 是把 §6-① 当成了唯一标准，属于**误用纪律**。

#### 6.1.3 为什么否决选项③（降级为事实登记）

§6-② 的出路一（降级）只适用于「**该判据当前无判别力**」。T-B′ 不满足这个前提：

- 它有**真实且很大的动态范围**：当前 0.0333 ↔ 劣化后 0.2467 = **7.4×**；
- 对比 T-D′（恒真 · 动态范围 0）与 T-C′（与 T-D′ 冗余 + 删失偏倚）——那两条才是真的零信号，**T-B′ 不是**。

→ 降级会把一条**唯一能抓「塔死规模失控」的闸门**主动拆掉，闸门总数从 4 降到 3。❌ 否决。

#### 6.1.4 为什么是 **0.07**，而不是别的数

纪律 §6-① 给出的**地板**是 `0.0333 + 3 × 0.0104 = 0.0644`。0.07 是在地板之上取的一个**留出可见余量（+0.54 SE）的整齐值**。

但真正决定 0.07 / 0.09 / 0.14 之间取舍的，是**部分迁移的灵敏度** —— 断崖不会一夜之间整体迁移，更可能是渐进的：

| 4-簇迁移比例 | `tail5` | SE | 阈值 **0.07** | 阈值 0.09 |
|---|---|---|---|---|
| 25%（16/64 局） | 0.0867 | 0.0162 | `z=+1.03` → 检出率 ≈85% | `z=−0.21` → 🔴 **完全漏检** |
| 50%（32/64 局） | 0.1400 | 0.0200 | `z=+3.49` → ≈99.98% | `z=+2.50` → ≈99% |
| 75%（48/64 局） | 0.1933 | 0.0228 | `z=+5.41` | `z=+4.53` |
| 100%（64/64 局） | 0.2467 | 0.0249 | `z=+7.10` | `z=+6.29` |

> 🎯 **选择 0.07（断崖区间的低端），而不是几何中点 ≈0.09 或算术中点 ≈0.14，理由**：
> 断崖型分布下，抬 high 阈值的**唯一收益**是进一步压低误报率，而 0.07 的误报率已经 ≈0.02%（单侧），再压是**收益递减**；
> 抬高阈值的**代价**却是线性的——每抬 0.01，就多放过约 6 局的塔死规模迁移。**在误报已可忽略的区间里，灵敏度是唯一还在变化的量** → 取满足纪律的最低整齐值。
> 这与 §6-③「禁止把阈值下调到刚好通过」**不冲突**：那条针对的是**下界判据**（调低 = 更容易过）；T-B′ 是**上界判据**，本次是**上调**阈值（更难过），方向相反。

#### 6.1.5 🟡 由此新增的一条纪律（补进 §6）

> **⑤** **先证检出，再谈裕度。** 定阈值前必须先用实测分布做一次**劣化推演**（把目标失效模式套进 hist，看观测量动不动）。若观测量对目标失效模式不敏感，🔴 **裕度再大也是假闸门** —— 按 §6-② 出路一处理（降级或换统计量），🔴 **禁止**靠抬阈值把裕度做漂亮。
> **⑥** **断崖型（阶跃）分布的阈值取"满足纪律的最低整齐值"**，不放几何中点。理由：此类分布下误报率在跨过 3 SE 后即饱和，继续抬高的唯一效果是**线性损失灵敏度**。

### 12.2 🔴 判读：新基线是"第一次测到事实"，不是"机制变弱了"

这是我本次定档的**核心判断**，必须先立住，否则后面每一步都是在改尺子掩盖问题。

**`snap()/rest()` 缺陷的机理**：`snap()` 只存 `[slot, ctype, h, attach]` → 探针 `rest()` 用 `make_tower` 重建塔（`disabled` 默认 `false`）→ **每次评估一个探针动作就免费复活一次死塔** → 同一座塔的死亡被**重复计为多次 `dis_new` 事件**。

**证据链（三重自洽）**：

1. `hist` 从 `4:64` 变成 `2:57` —— 缺陷期"一次死 4 座"变成修复后"一次死 2 座"，而 A 路径**全程只建 2 座塔**（逐局 `stock=2 towers=2`，见 `r4-attrition8-after.log` 逐局行）。**2 正是 A 的塔数上限** → 缺陷期的 4 = 2 座塔各被重复计一次。
2. 均值 0.380 与 `2 × 0.19 = 0.38` **逐位相等** → 修复后 `X_form ∈ {0, 2}` 是严格双峰，均值完全由 `hit` 决定，不携带独立信息。
3. `hit_surv ≡ 0`（0/179）与"塔死 ⟹ 失守 57/57 = 100%"**跨越修复前后两期不变** → **因果链（塔停→DPS 崩→漏怪→核心失守）完好**，机制从未失效。

> 🟢 **结论：修复后 A 路径"塔死亡频率更低"是真实的 —— 但它是把虚高的重复计数去掉后的真值，不是机制被削弱。** 真值说：**每 5 局里有 1 局（19%）单核流会双塔尽没，且那一次必死（100% 致命）**。这是一个**强、可感知、惩罚明确**的机制，不是死代码。

**逐条理由：**

- **T-A′（均值）→ 事实登记**：① 修复后 `X_form ∈ {0,2}` 严格双峰，**均值 = 2 × `hit` 恒等**（0.380 = 2 × 0.19）→ 它与 T-A′-1 是**同一个量**，保留两条等于重复计票；② 均值 ≥1.0 等价于要求 `hit ≥ 0.50`（一半的局要双塔尽没），这个强度**从未有过论证**，它只是缺陷期 1.143 的倒推；③ R-2 §3.2 对 T-D′ 用的就是同一处置（恒真/零信号 → 降事实登记）。🔴 **这不是"删掉一条 FAIL 来过关"，是去掉一条与 PASS 中的 T-A′-1 数学等价的重复闸门。**

- **T-A′-1 0.15 → 0.12**：旧阈值下只剩 **+1.77 SE**，低于 §6-① 的 ≥3 SE 地板（地板 = 0.1900 − 3×0.02265 = **0.1220**）→ 取 **0.12**（+3.09 SE）。🔴 **灵敏度未失守**：机制若真变死代码（`hit → 0`），0.12 下 margin = **−5.3 SE** 必红。

- **T-A′-2 0.60 → 0.30**：旧阈值下 **−2.84 SE（FAIL）**。但 0.60 是**在虚高的 0.7652 上标定的**，从未有过有效事实基础（`v7-baseline-retraction.md` §3 裁决二）。新真值 0.4711 的设计含义是 **「47.1% 的单核流失守走塔死因果链，且塔死 100% 致命」** —— 这是**强耦合**，不是脱钩。✅ 取 **0.30**（+3.77 SE，地板 = 0.4711 − 3×0.04538 = **0.3350**）。🔴 **联判纪律维持**：T-A′-2 的分子由塔死亡决定、分母由起飞率决定 → **FAIL 时必须同时看 T-A′-1，不得单凭 `hit_fail` 下结论**。

- **T-B′ → 事实登记**：`hist` 变严格双峰 `{0:243, 2:57}` → `P(X≥5)` **结构恒 0**，永久零信号，§6.1.5-⑥「先证检出再谈裕度」下它已无检出能力 → 符合降级前提。

- **T-D″ → 3 seed 累计 ≥3**：1 seed 实测 1（margin = 0，脆）→ 扩 3 seed。🟡 诚实标注：`Poisson(λ=3)` 下 `P(X≥3) ≈ 0.58`，属**存在性阳性对照**；🔴 **连续两次 FAIL 才允许判为回归**。
