## 0. TL;DR —— 五条硬结论 + 三个待拍板项

### 🔴 五条硬结论

1. **金标本（MVP）不消费任何空间信息 —— 径向重构对金标本可以做到「逐位零改动」。**
   `WaveSim.simulate_wave` 的怪物结构就是 `[hp, t_remain]`，循环体只做 `t_remain -= DT` 与按 `t_remain` 稳定排序，**不读位置、不读速度、不读几何**（已用全仓 grep 证明：`wave_sim.gd` / `wave_sim_proto.gd` / `shop_ai.gd` / `run_loop*.gd` 对 `PathGeometry` 零引用；只有 `wave_sim_aggro.gd` 与 `wave_director._apply_aggro` 消费位置）。
2. **`t_remain` 不用重新定义 —— 它本来就是「到核剩余时间」，不是「弧长位置」。**
   `s = L − v₀·m_spd·t_remain` ⟺ 剩余距离 = `v₀·m_spd·t_remain` ⟺ `到核 ⟺ t_remain ≤ 0`。径向模型下只是把「沿弧的剩余距离」换成「沿半径的剩余距离」，**同一个状态量、同一条递减路径、同一个 IEEE754 累加序列**。W-A2「距核心最近优先」的排序语义也**完全保住**（径向下单值单调：`dist = v₀·m_spd·t_remain`）。
3. **真正的成本不在「怪物怎么走」，而在「塔位放哪」。**
   塔位坐标一变 → `Geo.dist` 矩阵变 → `geo.links()` 共鸣拓扑变 → `E_i` 变 → `Resonance = (1+κ_r)^E` 变 → **DPS 变 → 金标本 `Delivered 4,991,136` 作废 → 16 条判据 + MC 300×2 全部重扫**。这是唯一的"大出血点"，且是**设计决策**（见 §3.3：D-A′ / D-B 二选一；折中方案 D-C 已被实测否决）。
4. **均匀正圆环会杀死两个已定稿玩法。**
   实测（§7）：均匀 6 位环 r=15 → 共鸣度向量 `Cannon [2,2,2,2,2,2] / Arrow [4,4,4,4,4,4]`（**无枢纽 → P1「位置即策略」退化**），暴露度 6 位全等 `0.205`（**无安全位 → AC-S6-3 硬约束破产、玩法①暴露度 UI 失去区分度**）。→ **必须用「非均匀 / 双层环」**。
5. **出生角绝不能消费金标本 RNG 流。**
   金标本 MC 的商店序列是 `PyRandom(MT19937)`。若出生角从同一流取随机数 → 商店序列整体移位 → MC 起飞率漂 → 逐位对齐崩。→ **出生角必须走确定性准随机序列（黄金角/Vogel 螺旋，按 spawn index 取值），零 RNG 消费**（§5.2）。

## 4. Q3 —— 寻路 / 性能方案

### 4.1 先纠正一个前提：当前冻结口径下同屏怪数只有个位数~十几只

实测（按冻结的 `N(w)=round(8+1.6w)` / `D=28+2.2w` / `spawn_window` / `t_reach=10`）：

| 波次 | N | interval | **同屏峰值 ≈ t_reach/interval** |
| --- | --- | --- | --- |
| W1 | 10 | 0.906 | **11.0** |
| W5 | 16 | 0.731 | **13.7**（全场峰值） |
| W10 | 24 | 1.250 | 8.0 |
| W15 | 32 | 1.906 | 5.2 |
| W20 | 40 | 1.800 | 5.6 |

→ **「300+ 怪同屏」不在当前冻结口径内**；要 300 同屏必须改 `N` / `spawn_window` / `t_reach`，那本身就破金标本。**按当前口径，性能不是问题。**

### 4.2 推荐实现：**径向直进（O(1)/怪/子步），不用 A\*、不用导航网格、不用 flow field**

理由：
1. 地图**无静态障碍**（核心是终点、塔是可攻击目标但不阻挡移动 —— 现状 `MARCHING` 怪无视塔直冲核心）。
2. 移动语义 = 「朝核心的匀速直线」+「机会型仇恨停下」—— `WaveDirector` 现状已如此，只是方向从「沿折线」变「沿半径」。
3. 🔴 **任何寻路/避障都会改变「到核时间」→ 直接破坏 I-1 → 金标本等价破产**。这是架构红线，不是性能权衡。

**避障策略（含一条硬纪律）**：

| 需求 | 方案 | 是否影响金标本 |
| --- | --- | --- |
| 怪物互相穿插（视觉重叠） | **只允许渲染层做视觉分离**（按 `index` 的确定性微偏移，如黄金角抖动），**逻辑位置严格走径向** | ❌ 不影响（逻辑位置不变） |
| 逻辑层 boids / 分离力 | 🔴 **禁止** | ✅ 会破 I-1 |
| 塔体阻挡 | 现状即「仇恨停下」，不需要物理阻挡 | — |
| 将来的地形 / 障碍 | **flow field**（512×512 网格，地图加载烘焙一次，每怪每帧 O(1) 查询） | 🔴 需重扫（改变到核时间）→ 明确「**现在不做**」 |

### 4.3 性能预算（按 300 只同屏的悲观上界估算）

| 项 | 每子步（0.1s）成本 | 300 只估算 | 预算 | 判定 |
| --- | --- | --- | --- | --- |
| 位置推进（`pos = CORE + dir·r`） | 300 × ~4 flops | ~1.2k flops | — | 忽略 |
| 仇恨判定（`_nearest_exposed_tower`：怪 × 塔） | 300 × 6 = 1800 次 `distance_squared_to` | ~9k flops | — | 忽略 |
| 🔴 **集火稳定排序（插入排序 O(n²)）** | 最坏 45k 次比较 | ~45k 比较 | 1ms/子步 | **最大项，约 1–3ms** |
| 渲染（immediate `draw_circle` × N） | 每帧 300 条 CanvasItem 命令 | ~300 cmd | 3ms/帧 | 🟡 需实测探针 |
| 内存（`Monster` RefCounted ≈ 200B） | — | ~60 KB | — | 忽略 |

**预算结论**：60fps = 16.67ms/帧；逻辑子步 10 次/秒 × 3ms = 30ms/s ≈ **3% CPU**（300 只的悲观上界）→ **可接受**。渲染侧需补一个「300 怪帧时间探针」（仿 `tools/probe_layout_1920.gd`）实测；若 >3ms/帧 → 换 `MultiMeshInstance2D` 或 `RenderingServer` 批绘制（**渲染层优化不影响任何数值**）。

**排序优化（免费且逐位安全）**：插入排序 → **稳定归并排序**。
证明：稳定排序在给定严格比较器 `a.t_remain > b.t_remain` 下输出**唯一确定**，任何稳定排序实现结果同序 → 逐位相同。→ 可在 `monsters.size() > 200` 时切换，**零数值风险**。

## 5. 出生几何的工程口径（新 SSOT）

### 5.1 `scripts/geo/radial_geometry.gd`（新文件，与 `path_geometry.gd` 并列）

```gdscript
const CORE_POS := Vector2(55.0, 25.0)   # 🔴 沿用现状核心坐标（不动 → 所有 CORE_POS 消费点零改）
const SPAWN_R  := 45.0                  # 🟡 D-1 待拍板（= 出生环半径 = 世界尺度）
const GOLDEN_ANGLE := 2.399963229728653 # 黄金角（Vogel 螺旋），rad

## 🔴 `seq` 必须是**整局累计出生序号**（不是波内序号）—— 否则每波第 1 只都从同一方向来，
##    视觉上会看出"每波同样的队形"。`WaveDirector` 增 `spawn_seq_total: int`（确定性计数，零 RNG）。
static func spawn_dir(seq: int) -> Vector2:        # 第 seq 只怪的出生方向（确定性，零 RNG）
	var a := float(seq) * GOLDEN_ANGLE
	return Vector2(cos(a), sin(a))

static func dist_remain(t_remain: float, m_spd: float, v0_: float) -> float:
	return v0_ * m_spd * t_remain                  # ★ 与 arc_of_t 同构：剩余距离 = 速度 × 剩余时间

static func pos_of(t_remain: float, m_spd: float, v0_: float, dir: Vector2) -> Vector2:
	return CORE_POS + dir * dist_remain(t_remain, m_spd, v0_)
```

### 5.2 出生角为什么必须是确定性的（🔴 硬约束）

- 金标本 MC 的商店序列 = `PyRandom(20260930)`（MT19937）。**多消费 1 个随机数 → 后续序列整体移位** → 起飞率漂、逐位对齐崩（control-manifest §2/§3 的 P1/P2/P3 全是为这条服务的）。
- 出生角用**黄金角序列**（`θ_i = i × 2.39996…`）→ 零 RNG 消费、分布均匀（低差异序列）、**headless 与实机完全一致**。
- 🟡 观感待确认：黄金角序列在视觉上是"均匀铺开"而非"随机感"；若要随机感 → 必须用**独立 RNG 实例**（`PyRandom.New(独立种子)`），🔴 绝不能复用主流。

## 7. Q4 / Q5 —— 暴露度与塔位几何的技术重建口径

### 7.1 径向下暴露度的解析解（闭式，可单测逐位）

设塔位 `P` 距核心 `d`，出生方向 `θ` 与 `P` 方向夹角 `Δ`：

```
怪的行进线段 = 从 SPAWN_R·u(θ) 到核心 O
  |Δ| ≤ π/2（P 在来向一侧）：垂足落在线段上 → 距离 = d·|sinΔ|
  |Δ| >  π/2（P 在核心背后）  ：最近点是核心   → 距离 = d
⟹ exposure（方向覆盖率）
  d ≤ R  →  1.000（所有方向的怪都会进入 R）
  d > R  →  asin(R/d) / π
```

**实测表（`AGGRO_R = 9.0`，可抄进单测）**：

| `d_core` | 6 | 9 | 10 | 12 | 15 | 18 | 20 | 22 | 26 | 30 | 40 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `expo_frac` | 1.000 | 1.000 | 0.356 | 0.270 | 0.205 | 0.167 | 0.149 | 0.134 | 0.113 | 0.097 | 0.072 |

### 7.2 `d_path` 重算成什么 —— 工程口径

| 现状（路径模型） | 径向模型 | 说明 |
| --- | --- | --- |
| `d_path`（塔到路径最短距离） | **`d_core`（塔到核心距离）** | 第一手数据；`dist_to_path()` → `dist_to_core()` |
| `ExposureArc`（路径落入 R 圆的弧长，∈[0,101]） | **`expo_frac`（方向覆盖率，∈(0,1]）** | 闭式解如上；`exposure_intervals` / `union_arc` 在径向**无对应概念**，改为「方向扇区并集」 |
| `is_exposed = d_path ≤ 9`（天然二值） | **连续量 → 需新阈值 `EXPO_SAFE_MAX`**（🟡 D-3） | 🔴 这是**新设计参数**，必须文策渊定稿并冻结 |
| 可选补充 | **`expo_time`**（期望停留时长 = `(1/2π)∫2√(R²−perp²)/v₀ dθ`） | 更贴 `ATTRITION` 的实际口径，建议与 `expo_frac` 同时登记 |

`slot_exposure()` 新返回结构：

```gdscript

```

### 7.3 🔴 两个必须让设计侧知道的几何后果

**① 均匀正圆环 = 无差异 = 两个已定稿玩法失效**（实测）：

**② 径向模型天然产生「遮挡（shielding）」—— 肉盾塔玩法②从"涌现"升级为"几何必然"**：
怪沿半径由外向内 → **必然先撞上更外侧的塔** → 外环塔天然为内环塔挡刀。
真正的暴露量 = **该塔的 Voronoi 方向扇区 ∩ 自身 `AGGRO_R` 扇区**。
→ 建议新增 `expo_eff`（有效暴露度 = 扣除被更外侧塔遮挡的方向），这是肉盾塔机制的直接量化量，也是 H10 UI 最诚实的"会挨打/安全"判据（SR-R2 只标事实）。

### 7.4 覆盖率口径警告（🔴 别踩）

`coverage_mode = "geometry"` 在径向模型下**退化**：所有怪最终汇聚到核心，任何 `range ≥ d_core` 的塔都覆盖 100% 的方向 → 覆盖率失去区分度。
→ 🔴 **MVP 必须继续冻结 `coverage_mode = "path"`（常量 0.78/0.95）**；`geo.gd::_build_cov()` 的路径采样在径向下**无意义**，应标注 `geometry` 口径在径向模型中禁用（或改定义为 `expo_time` 型口径）。

| --- | --- | --- | --- |
| **A（推荐）全径向直进** | 出生环均匀取角，直线奔核心 | ✅ 完全兑现用户意图；✅ O(1)/怪；✅ `t_remain` 语义零变更 → **金标本零改动**；✅ 天然产生"外环挡内环"的肉盾几何 | 视觉上"来向"极多，占位渲染需重画；出生角不能用 RNG |

### ADR-0004：出生参数的随机性 —— 确定性准随机序列 vs 独立 RNG 流

- **状态**：🟡 待拍板（推荐前者）
- **上下文**：径向出生需要"方向"；若从 `PyRandom` 主流取随机数，会整体移位 MC 的商店序列（control-manifest §3 P1–P3）。
- **备选**：① **黄金角确定性序列**（推荐，零 RNG 消费，逐位可复现，headless/实机一致）；② 独立种子 `PyRandom` 实例（有随机感，但需登记新种子为冻结参数，且 headless 与实机需同一实例序列）；③ 🔴 复用主流（**否决**，破 I-2）。
- **决定（建议）**：**①**；若设计侧要求"随机观感"，再升级到 ② 并把新种子写进冻结清单。
- **后果**：新增常量 `GOLDEN_ANGLE`；新增源码探针「金标本路径不消费出生 RNG」。

### ADR-0005：塔位是否环化 —— 冻结坐标（保金标本）vs 环化（重扫金标本）

- **状态**：🟡 待拍板（**这是本项目最贵的一个决定**）
- **上下文**：塔位坐标一变 → `Geo.dist` → `links()` → `E_i` → `Resonance = (1+κ_r)^E_i` → DPS → 金标本 `4,991,136` 与 16 条判据作废。而用户想要的"塔环绕核心"恰恰要求移动塔位。
- **关键实测（否决了折中方案）**：
  - 邻接是**塔型的函数**（all-Arrow 11/15 链接 vs all-Cannon 7/15）→ 「冻结邻接表」不是等价替换，是语义变更。
  - 75 组双层环候选搜索：**无一组合**能复现现状邻接（最优总失配 30/75 对）。
  - 只迁核心不改塔位：共鸣逐位不变（塔-塔距离未变），但现状塔位群是扇形而非环（最小二乘拟合半径极差 20.03）→ **做不出均匀环**。
- **备选**

| 方案 | 描述 | 金标本 | 设计贴合度 | 成本 |
| --- | --- | --- | --- | --- |
| **D-A′（建议）** 塔位坐标冻结 + 核心迁位 | 保留 `SLOTS6`；核心迁到设计指定的围攻中心（共鸣不受影响） | ✅ **零改动** | 🟡 构图改善，但塔不是均匀环 | 最低（含在 P1–P4 内） |
| **D-B** 塔位环化 + 共鸣随几何 | 双层环（内 3 / 外 3），共鸣自动重算 | 🔴 **全链重扫 + 16 判据重定稿** | ✅ 真均匀环，最贴合 | +2~3 切片 |
| ~~D-C 冻结邻接表~~ | 环化 + `LINKS6` 静态表 | 🔴 仍需重扫 | ✅ | — | **已否决**（实测①②） |

- **决定（建议）**：**先 D-A′ 交付**（用户先看到"四面八方涌来"的完整效果，金标本零风险）；**D-B 作为独立的第二阶段决策**，由用户确认"愿意为均匀环接受全链重扫 + 判据重新定稿"后再启动。
- **后果**：D-A′ → 新增冻结常量 `CORE_POS_RADIAL`（核心新坐标，成为 SSOT）；D-B → 派生 `corebound_sim_v09_radial.py` + GEO SSOT 一致性探针 [E] + 16 判据重定稿（需主理人/文策渊签字）。
