# ADR-0001：κ_r 取档口径 —— `tier`（中性塔 0.045）还是 `flat`（全场 0.050）

- **状态**：✅ **已拍板 —— 方案 A（`tier`，中性塔取基准档 0.045）**（主理人 2026-09-30 签）
- **日期**：Phase 3 MVP 切片1（提出）／切片1 收尾（拍板）
- **作者**：程基岩（工程主理人）；拍板：主理人
- **影响面**：`scripts/engine/mvp_config.gd :: cfg_of(kr_mode=...)`、`damage_engine.gd` 的 `kr[]`
- **关联**：`damage-pipeline` GDD §9 **D-4**、§10.1 金标本基准、`q-c6-verify.md` §5.1、`card-verify.md` Q-C5

---

## 1. 上下文

把 Python 金标本（`corebound_sim_v08_salvage.py :: compute_dps_v8`）移植成 GDScript 时，
为了拿到「GDD §10.1 的 B 路径 `Delivered = 4,991,136`」这个验收值，我实跑了金标本的两种 `kr_mode`：

| `kr_mode` | B 路径 `Delivered`（W20 决定性跑） | 主 Cannon 的 `κ_r` | 无 Tag 的 Arrow 的 `κ_r` |
| --- | --- | --- | --- |
| `tier`（档位口径） | **4,991,135.6102341395** | 0.050（`fire` 投入 58 层 → 深度档） | **0.045**（`kr_neutral`） |
| `flat`（全场统一） | **4,991,174.0708633149** | 0.050 | **0.050** |

→ **GDD §10.1 的 `4,991,136` 只与 `tier` 口径对得上**（相对差 `7.8e-8`，纯属文档取整）。
→ 但 `v08.cfg_of()` 的**默认**是 `kr_mode="flat"`（文件头 `KR_FINAL=0.050` 写的是「MVP flat 0.050 全场统一」）。

也就是说：**GDD §10.1 的验收值和 v08 脚本的默认口径不是同一个** —— 这正是本项目已经栽过 4 次的
「文档定 A、引擎跑 B」的同型问题，必须在写死之前挑明。

### 差额从哪来（已定位到根因，不是浮点噪声）

两条路径的**每一个**派生量都逐位相同，唯一差别是 0 号塔 `Arrow(h=133)`（Tag = `None`）的共鸣率：

```
E[0] = 9            （两口径相同）
res[0] = (1+κ_r)^9
      tier: 1.045^9 = 1.4860951404142546  → dps = 265.51019635384966
      flat: 1.050^9 = 1.5513282159785162  → dps = 277.1649324678542
Δsubtotal = 11.6547358138
Δtotal    = 11.6547358138 × 2.2 × 1.5 = 38.4606281855     ← 与 4,991,174.07 − 4,991,135.61 = 38.46 完全吻合
```

→ **主塔（Cannon）在两种口径下 `κ_r` 都是 0.050**，`damage-pipeline` §10.1 写的
「B 的 `κ_r`(主 Cannon) = 0.050、`Resonance = 1.05^134`」**两种口径都成立** ——
文档里那句话分辨不出到底用了哪个口径，这是它没写清楚的地方。

## 2. 备选方案

### 方案 A（当前 MVP 默认）：`kr_mode = "tier"`

- κ_r 走 GDD §5.4 三档 `[0→0.040, 3→0.045, 20→0.050]`，**无 Tag 的中性塔恒取基准档 `kr_neutral = 0.045`**。
- 出处：`card-verify.md` Q-C5 定稿原文「`κ_r` 档位 … **0.040 / 0.045 / 0.050（阈值 3 / 20 层）+ 中性塔恒取 0.045**」。
- ✅ **唯一能对上 GDD §10.1 验收值 `4,991,136` 的口径**（相对差 7.8e-8）。
- ✅ 语义自洽：中性塔不吃 Tag 协同，本来就该拿基准档 —— 与 `κ_tag` 的「中性塔 → 0.06 未协同档」同构。
- ⚠️ 与 `v08.cfg_of()` 的默认值不一致；后续若以 v08 为新基线跑回归，B 的值会跳 `+38.46`（+7.7e-6）。

### 方案 B：`kr_mode = "flat"`

- 全场统一 `κ_r = 0.050`（v08 文件头 `KR_FINAL`，v1.0.4 D-9/D-11 复扫的定稿口径）。
- ✅ 与 `v08.cfg_of()` 默认逐位一致，`selfcheck_engine()` 的自检基线也是它。
- ✅ `damage-pipeline` v1.0.4 §9 D-9 写的「`κ_r` 定稿 0.050（深度档）维持不动」更像在说这个。
- 🔴 **对不上 GDD §10.1 的 `4,991,136`**（差 7.6e-6，超出任务书给的 `<1e-6` 验收阈值）。
- ⚠️ 语义上略怪：中性塔也吃深度档 0.050，等于白送一层 Tag 协同。

### 方案 C（不推荐）：改金标本期望值

把 §10.1 的 `4,991,136` 改写成 `4,991,174`。
🔴 **不做** —— 那是「拿实现改文档」，正是本项目要避开的坑。文档与实现谁对，应由主理人拍板，不由我单方面改。

## 3. 决定

**✅ 拍板：方案 A（`kr_mode = "tier"`）为 MVP 唯一默认口径。** 主理人 2026-09-30 签。

拍板前主理人亲自回溯了原始扫参报告 `mapA-kappaR-sweep.md`（237 行）核验口径来源，
结论链如下（**这是拍 A 而非拍 B 的决定性依据**）：

1. **§10.1 验收值 `4,991,136` 的来源已锁定**：`mapA-kappaR-sweep.md` §2 表格
   「旧口径·κ_r档位(v0.6定稿)」一行 —— B 起飞 **W12**、W20 **9.97**、`B/A 0.458` ——
   其口径列明确写「档位(深度档 0.050)」。§5 换算表进一步坐实：
   「定稿档位 `(0,0.040)(3,0.045)(20,0.050)`」对应 B 起飞 W12 / `B/A 0.458`。
   → **§10.1 的 `4,991,136` 就是档位（tier）口径的产物**，中性塔（Arrow h=133, Tag=None）
   取基准档 `0.045`，与本工程实测的 `tier` 逐位一致（相对差 `7.8e-8`，纯文档取整）。

2. **扫参报告 §4.1 的「最小 flat 值 = 0.045」是另一套口径**：那是「全场统一 0.045」的
   flat 制，对应 B 起飞 **W13** / `B/A 0.242`（§2 的「新口径·flat κ_r=0.045」行），
   **不是** §10.1 的验收值来源。报告 §4.2 的工程建议「定稿档位表维持不动」恰恰指向 tier。

3. **文档表述张力已澄清**：`card-verify.md` Q-C5 定稿原文「0.040 / 0.045 / 0.050
   （阈值 3 / 20 层）+ **中性塔恒取 0.045**」= tier；`damage-pipeline` v1.0.4 §9 D-9
   「κ_r 定稿 0.050（深度档）维持不动」说的是**深度档上限值**，二者不冲突 ——
   深度档 0.050 是 tier 三档的最高档，中性塔只是不占这一档而已。

`kr_mode` 作为**显式参数**继续保留在 `MvpConfig.cfg_of()` 里，`flat` 一行可切回
（回归/敏感性用），自测对**两套都做逐位断言**（`tests/test_suite.gd` 的 `[3]` / `[4]` 两节）。
**MVP 生产路径、金标本验收、GDD §10.1 三者口径统一为 `tier`。**

## 4. 后果

- **若拍 A**：MVP 数值与 GDD §10.1 完全一致；需把「v08 默认 `flat` 与定稿口径不一致」回写给策划，
  建议 `damage-pipeline` §10.1 补一句「本表 B 行为 **κ_r 档位口径**（中性塔 0.045）」，
  并建议 v08 侧把 `cfg_of` 的默认 `kr_mode` 改成 `"tier"`（或至少加断言）。
- **若拍 B**：GDD §10.1 的 `4,991,136` 需改写为 `4,991,174`，且该表下方「`B/A 0.458`」等派生判据需重跑确认未破线
  （Δ 只有 7.7e-6，起飞波次 / `B/A` 大概率不受影响，但**必须由策划签字**，不由工程改文档）。
- **两种都不阻塞后续切片**：差别只影响「无 Tag 塔的共鸣率」这一个乘数，
  波次模拟 / 商店 / AI 等模块不依赖这个选择。

   手算式给出 `≈4,991,135`，与模拟逐位一致，所谓「0.2%」来自第 1 条的 `691.9`。
