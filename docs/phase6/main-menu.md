# 主界面 + 卡组图鉴（2026-11-07）

> 需求：**在游戏中增加主界面，在主界面中可以查看所有卡组的卡牌。**
>
> 落地：`scripts/ui/main_menu_overlay.gd`（单文件两页）+ `boot.gd` 接线。

---

## 0. 结论前置

1. **主界面是启动第一屏，不是"多一层菜单"**：它把「开始游戏 / 卡组图鉴 / 退出」三个入口
   放在同一屏，`开始游戏` 之后仍走既有的「选关 → 选包 → 开局」流程，**没有新增任何玩法状态机**。
2. **图鉴必须一遍看到全部**：8 包 × 10 张 = **80 个卡位 / 80 座不同的塔**（一卡一包）。
   未解锁的包**压暗但仍可见** —— 解锁是节奏阀，不是内容保密。
3. **分层纪律不变**：主界面只发 `start_requested` / `quit_requested`，真正的流程由 `boot.gd`
   决定；卡池生效仍由 `ShopRuntime.set_active_packs()` 负责。UI 零玩法写入。

---

## 1. 为什么图鉴不能"按解锁进度藏"

选包界面每局只有 3 个格子（`PICKS_PER_RUN = 3`），而卡包是「一条完整 build」。
如果玩家看不到 8 个流派各自长什么样：

- 选包就退化成**盲选**（只能凭包名猜）；
- 「解锁」会被读成「内容被锁」，而不是「节奏解锁」；
- 卡包 v0.2 的核心前提「选包 = 选一条 build」不成立。

所以图鉴的口径是：**全部可见，未解锁压暗 + 明写解锁条件**。
这与 `card_packs.gd` 文件头「每包是一条能独立成型的流派」是同一件事的两面。

## 2. 两页结构

```
MainMenuOverlay (CanvasLayer, layer 200)
├── ColorRect        不透明底（压住下面的战场 HUD，防"幽灵界面"）
├── Backdrop         同心环 + 72 方位刻度 + 确定性星点（零 RNG 自绘）
├── 页 1 菜单
│   ├── 「守 核」72px display + CORE BOUND
│   ├── 分隔线 + 一句话定位
│   ├── ▶ 开始游戏（primary）
│   ├──   卡组图鉴（normal）
│   ├──   退出游戏（ghost）
│   └── 最佳波次 / 已解锁包读数 + 版本行
└── 页 2 图鉴
    ├── 标题 + 读数（15 座塔 · 8 包 · 48 卡位）
    ├── 返回（ghost）· 滚轮浏览 / Esc 提示
    └── ScrollContainer
        └── 8 × 卡包块（序号 + 徽记 + 包名 + tag_line + 解锁状态）
            └── 6 × 卡面（278×126）
                ├── 卡名（18px Medium）
                ├── 稀有度 ▲ 角标（形状 + 颜色双通道）
                ├── Tag 电路符号（§5.5，与商店卡面同一套）
                └── 3 行说明（`card_text.describe()`，只读 SSOT）
```

### 2.1 为什么一行 6 张

`6 × 278 + 5 × 12 = 1728 ≤ 1776`（1920 − 2×72）。
一行 = 一个卡包 = 一条 build，玩家扫一眼就能把「这一包就是这 6 张」对上
选包界面里的双列卡名网格 —— 两屏的信息结构是同一套，不需要重新学习。

### 2.2 卡面信息从哪来

| 元素 | 来源 | 说明 |
|---|---|---|
| 卡名 | `card_packs.PACKS[].cards` | 卡包的唯一权威表 |
| 3 行说明 | `card_text.describe()` | 机制 / 数值（现取 `tower_data`）/ 标记 |
| 稀有度 | `card_text.rarity()` → `ui_style.RARITY` | 由商店权重机械映射，不手写 |
| Tag 符号 | `card_text.tag_of()` → `ui_style.TAG_GLYPHS` | 与商店卡面同一套字形/颜色 |

🔴 图鉴**不写任何数值**：改 `TOWERS` / `WEIGHTS`，图鉴自动跟随（与商店卡面同一管法）。

## 3. 交互

| 操作 | 菜单页 | 图鉴页 |
|---|---|---|
| 鼠标 | 悬停高亮（焦点 ▶ 跟随）+ 点击进入 | 滚轮浏览 |
| `↑` / `↓`（或 `W`/`S`） | 移动焦点（循环） | — |
| `Enter` / `Space` | 执行焦点项 | — |
| `Esc` | 无（主界面没有上一级） | 返回菜单 |

🔴 **按键一律吃掉**：主界面压着一局尚未开始的战场，未消费的 `Tab` / `R` / `1-3`
会漏到 `battle_shop._unhandled_input`（打开抽屉 / 刷新 / 买卡）—— 那时玩家看不见，
却会改变局内状态。所以菜单页把未知按键也 `set_input_as_handled()`。

## 4. 接线（`boot.gd`）

```
主界面 →（开始游戏）→ CAMPAIGN_ENABLED ? 选关 → 选包 → 开局 : 选包 → 开局
```

- 改动前：`_ready` 直接 `call_deferred("_open_stage_select")` / `_open_pack_select`；
- 改动后：`call_deferred("_open_main_menu")`，选关/选包由 `start_requested` 触发；
- **「再来一局」不经过主界面**（`restart_hook` 仍直连选关/选包）—— 换构筑要快，
  结算 → 重开不该多一次点击。

### 4.1 截帧探针

`--open-library`（窗口模式）让游戏直接落在图鉴页，用于 UI 评审录帧：

```bash
godot --path . --write-movie shots_lib/frame.png --quit-after 90 -- --open-library
```

不传该参数时走正常路径（先进主界面）；CI / headless 路径永不进入 `_ready` 的窗口分支。

## 5. 结构断言（`tests/run_ui_style_asserts.gd` §L）

进默认回归（`run_tests.gd` → uistyle），共 14 项：

1. 默认页 = 菜单、三个入口文案、按钮 × 4 态自定义（§5.1 无系统默认控件）；
2. 两个页面 219 个 Label 全部 ≥16px（§9.1 P0）；
3. 图鉴卡包块 = 8、卡位 = 80、每包块恰好 10 张（结构对齐，不靠总数碰巧相等）；
4. **覆盖 `all_cards()` 的每一张**（15 座塔）+ 每张说明非空（图鉴不是"只有卡名"）；
5. 返回键回菜单、开始游戏只发 `start_requested`（不自己开流程）；
6. 文案零开发占位。
