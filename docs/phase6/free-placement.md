# 自由摆放：从「6 个固定塔位」到「网格任意格点」

> 需求原文：**「玩家应该可以自由的摆放防御塔，而不是只能在固定的格子内摆放，在进行防御塔摆放的时候，将地图进行网格化显示」**

改造前，塔只能落在 `Geo6.SLOTS6` 的 6 个编译期常量坐标上（`S0(6,33) … S5(48,42)`），
`TowerState.slot` 既是塔的主键**又是**坐标索引。玩家没有任何"选择位置"的余地 ——
所谓"摆放"只是从 6 个既定点里挑一个。

---

## 1. 三个由玩家拍板的设计取舍

| 议题 | 选定 | 理由 / 代价 |
|---|---|---|
| 战场形态 | **保留圆形竞技场**，盘内铺**六边形**网格 | 不推翻 GDD 的径向围攻设计（核心居中、四面来敌、暴露度模型、威胁楔形都是围绕它验收的）。把战场改成方形地图会作废这一整套机制。 |
| 塔数上限 | **放宽到 10**（`tower_cap`） | 位置自由之后，6 座塔的"稀缺感"消失，需要更多塔位才有构筑空间。⚠️ 这个 10 是**起点值，没有经过 MC 校准**，见 §6。 |
| 可建范围 | **圆盘内除核心禁建区** | 核心周围 4u 禁建 + 外径 44u 封顶。贴脸堆塔会让"堆核心"变成唯一最优解，禁建圈把这条捷径掐掉。 |

---

## 2. 为什么不能直接改 `n_slots`

`cfg["n_slots"] = 6` 这个参数同时承担两个语义：

1. **金标本的槽位编号空间** —— `shop_ai.free_map_slots()` 用 `range(n_slots)` 枚举落子位，
   `damage_engine` 用 `geo.n` 建索引表，300 局 MC 与 κ_r / ATTRITION 全部基于 6 座塔标定。
2. **玩家的塔数上限** —— UI 上写「塔位 z/6」。

位置自由之后这两个语义必须拆开，否则"槽位数"会随摆塔无限增长，而"塔数上限"才是玩法旋钮：

```gdscript
"n_slots": 6,        # 金标本槽位数 —— 🔴 一字不动（改了 MC 全废）
"tower_cap": 10,     # 🆕 玩家路线塔数上限 —— 玩法平衡旋钮
```

**金标本零扰动的保证**：`n_slots` 没变，`Geo6.SLOTS6` 没变，`Geo._init()` 的 `dist` / `cov`
计算路径没变。新方法 `Geo.add_slot()` **只有玩家路线调用**，金标本引擎（`run_loop` / `wave_sim` /
`shop_ai`）与 MC 从不调用它 → 默认 6 槽的派生结构逐位不变。

## 3. 架构：四件事

### 3.1 `scripts/geo/build_grid.gd` —— 网格的唯一来源

```gdscript
const HEX_R := 1.55            # 外接圆半径（格心 → 顶点）
const HEX_HALF_H := HEX_R * 0.8660254   # 半高（平顶 → 上下是边，= 边心距）
const COL_STEP := HEX_R * 1.5           # 列距
const ROW_STEP := HEX_R * 1.7320508     # 行距 = 相邻格心距离 = √3R
const CORE_BAN_R := 4.0    # 核心禁建半径
const FIELD_R := 44.0      # 可建外径（出生环 55 − 11）
```

逻辑层（落子判定）与渲染层（网格绘制 / 命中）**都调这一个文件**。
上一轮 `run_slice4_scene_smoke.gd` 的 `SLOT_W/SLOT_H` 是手抄的第二份数字，实现改了忘改测试
→ 静默 45/46。这次不重复那个错误。

#### 为什么是六边形，不是方格（2026-11-07 玩家要求改掉方格）

| | 方格 | 正六边形 |
|---|---|---|
| 邻格数 | 4 + 4（斜角） | 6 |
| 邻格距离 | 正邻 `a`、斜邻 `1.414a` | **全等 `√3R`** |
| 后果 | 斜向埋塔"更便宜" → 玩家自发只走对角线，塔阵退化成菱形条纹 | 没有"免费的方向"，塔阵形态由射程覆盖率决定 |
| 与圆形战场的匹配 | 自带 4 重方向偏好，与 360° 来敌的事实冲突 | 6 重方向，各向更同性 |

`1.414a` 不只是"数值略大"：它是**玩家会在 10 分钟内发现的最优解**。一旦发现，斜向布阵就
变成唯一正解，位置策略从"选位"退化成"沿对角线排队"—— 这正是自由摆塔想避免的东西。

#### 尺寸怎么定的（不是随手取的数）

正六边形面积 = (3√3/2)·R²。取 `R = 1.55` → **6.242 u²**，与改前方格 `2.5 × 2.5 = 6.25 u²` 基本相等：

- 网格覆盖 **960 个格心**（改前方格版 964）
- 平均塔距不变、`tower_cap` 的可建空间不被这次改形偷偷改变

**改格形 = 只改"方向的公平性"，不改"容量"。** 这条是刻意的：`tower_cap = 10` 还在等 MC 校准，
不能在同一次改动里再动容量，否则两个变量缠在一起无法归因。

#### 吸附：轴向坐标 + 立方取整

```gdscript
static func cell(q: int, r: int) -> Vector2:      # 轴向 → 世界
    return core() + Vector2(COL_STEP * q, ROW_STEP * (r + 0.5 * q))

static func cell_of(p: Vector2) -> Vector2i:      # 世界 → 轴向（cube round）
    var fq := (2.0 / 3.0 * x) / HEX_R
    var fr := (-1.0 / 3.0 * x + y / SQRT3) / HEX_R
    ...
```

`y = ROW_STEP * (r + q/2)` 里那个 `q/2` 就是**列交错**，漏掉它会得到一个歪掉的斜网格。

立方取整（cube round）的四舍五入三分量 + 把误差最大的分量改成另外两个的相反数和，
保证 `q + r + s = 0`。`snap(p) = cell(cell_of(p))`，`same_cell(a,b) = cell_of(a) == cell_of(b)`
—— 同格判定**不用距离容差**（容差法在六边形上会误判，因为格边界到格心不等距）。

任意点到最近格心的距离上界 = 外接圆半径 `R`（最远点就是顶点），实测 4000 点最大偏移 1.5404。

#### 网格绘制：一次 `draw_multiline` 画完 3660 段边

整盘 960 格 × 6 条边 ≈ 5760 段，去重后（一条边被两个相邻格各算一次）**3660 段**。

- 逐段 `draw_line` = 每帧 3660 次 draw call —— 方格时代只有 68 条线才承受得起
- 改为 `PackedVector2Array` 成对扁平数组 + **一次 `draw_multiline`**
- 屏幕坐标按 `(ox, oy, sc)` 签名缓存（抽屉开合会改 `_field_width()` → 战场重新居中）

每段边裁到可建圆内（参数化线段-圆裁剪）→ 边缘是**被圆切断的半条边**，既不过界也不留空档。

🔴 **径向模式不需要路径避让**：怪走的是「出生点 → 核心」直线，不是 PATH 折线，且 MVP 无碰撞
（怪穿塔而过）。照搬路径模式的 `dist_to_path` 会让半个盘都不可建 —— 那是另一个战场的遗留约束。

### 3.2 `Geo.add_slot(pos)` —— 槽位表运行时增长

```gdscript
func add_slot(pos: Vector2) -> int:
    var idx := slots.size()
    slots.append(pos)
    n = slots.size()
    for i in range(dist.size()):
        dist[i].append(_dist(slots[i], pos))     # 增量：O(n)，不重建全表
    ...
```

同时 `Geo.links()` 里的 `dist[i][j]` 改成 `_dist_at(i, j)`（越界时现场算距离 / 退回 INF）。
槽位表增长后，`links()` 不会因为矩阵短一行就硬崩。

### 3.3 `shop_runtime` —— 坐标驱动落子

| 旧 | 新 |
|---|---|
| `confirm_placement(slot)` | `confirm_placement_at(pos)`（吸附格点 → 查重 → 新建/升级/拒绝） |
| `_slot_at` 不存在 | `_slot_at(gpos)` 查该格已占用的槽（**复用拆塔留下的空槽**，避免槽位表无限增长） |
| `range(cfg["n_slots"])` 构造快照槽位 | 遍历 `geo.slots`（第 7 座塔终于能显示） |
| `towers_max = n_slots` | `towers_max = tower_cap()` |

玩家路线的 `geo` 从**空槽位表**起步（没有预置塔位），起手塔（`SimPlayer.new_player` 送的
`Arrow@slot0`）随后补一个格点坐标 —— 沿用改造前的 `S0` 位置吸附到格点 → 老玩家手感不变。

**槽位不变式**：每座塔的 `slot` 必须能在 `geo.slots` 里找到坐标。
改造前这由 `SLOTS6` 免费保证；现在由构造方维护。`snapshot()` 里加了 `maxi(geo.slots.size(), max_slot+1)`
兜底，防止手工构造的场景漏塔。

### 3.4 `monster_layer` —— 网格绘制 + 格点命中

点击不再找"最近的塔位"，而是**屏幕 → 世界 → 吸附格点 → 问 runtime 这一格能不能落**：

```gdscript
var wp := _BuildGrid.snap(_to_world(mb.global_position))
var info: Dictionary = controller.runtime.placement_mode_at(wp)
```

`placement_mode_at()` 是只读预览，返回 `new` / `upgrade` / `invalid` / `blocked`。
**只对鼠标所指那一格查**（O(塔数)），不遍历全盘 960 格。

## 4. 视觉：为什么必须画网格，以及两个实测踩到的坑

改造前塔位自带八边形轮廓，玩家"看得见也点得到"。位置自由之后如果只画一片空地，
玩家无法判断"点哪里才算一格、哪里算建成了"。网格不是装饰，它是把「自由」变成
「可操作」的界面。

| 层 | 内容 | 参数 |
|---|---|---|
| ① 网格线 | 3660 段六边形边，一次 `draw_multiline`，已裁剪到可建圆 | 耀青 α 0.11，宽 `max(1.0, 0.045·sc)` |
| ② 可建区边界 | 外圈 44u 圆 + 核心禁建圆 | α 0.30 / 暗盘 α 0.60 + 红环 α 0.45 |
| ③ 悬停格 | **六边形**描边 + 呼吸 + 徽标 | new = 耀青 ＋；upgrade = 辉金 ↑；blocked/invalid = 钢灰无徽标 |

🔴 悬停高亮**必须跟格子形状走**：方格时代用 `draw_rect` 没问题，六边形还画方框的话，
方框在对角方向会超出格界、把邻格也罩住 —— 玩家看到的高亮范围和 `cell_of()` 的判定范围
就对不上，又变回"看到能建、点下去不能建"。所以用 `corners()` 取 6 个顶点 +
`draw_colored_polygon` 填充 + `draw_polyline` 描边。

### 坑 1：网格线不能画在塔上，但悬停框必须画在塔上

第一次实现把网格和悬停格放在同一层（层 4.5，塔之下）。结果**升级态的格子框被塔身整块盖住** ——
只看得见上方的金色 ↑ 徽标，看不出"这一格可以升级"。

正解是**同一函数分两段调用**：

```gdscript
_draw_placement_marks(sc, "bg")   # 层4.5：网格 + 可建区（塔之下，否则网格横穿塔身）
_draw_radial_towers(sc)           # 层6：塔
_draw_placement_marks(sc, "fg")   # 层6.5：悬停格 + 徽标（塔之上）
```

升级态另外**只描边不填充** —— 半透明填充会把塔身整块染色，看不清原来那座塔是什么。

### 坑 2：窗口模式拿不到可靠的鼠标位置

探针截图时 `warp_mouse` 完全不可靠：本工程视口 1920×1080、窗口 1600×900，
warp 到 `(870,450)` 后 `get_mouse_position()` 读到 `(73,775)` —— 截图拍到的是"错的格子"，
看起来像高亮逻辑有问题。

正解是给 `MonsterLayer` 加一个显式注入点 `probe_hover_world`（默认 `null` = 跟随真实鼠标），
探针截图前写入世界坐标。它只影响悬停高亮，不是玩法状态。

## 6. ⚠️ 必须说清的一件事：塔数上限 10 没有经过校准

`n_slots = 6` 不是随手写的数字，它是 κ_r = 0.050 / ATTRITION = 1.50 / 三原型平衡 /
300 局 MC 判据链的**共同基准**。把玩家路线放到 10 座塔，等于在一个未验证的配置上运行：

- **经济曲线会变**：废料收入 vs 塔投入的比值被摊薄（同样收入要养 10 座塔）
- **κ_r 未重标**：`n_hist_max` 只增不减，塔数上限提高后 κ 的收敛路径不同
- **ATTRITION 未重扫**：每波掉塔的期望值随塔数上升

这是**已知的、被玩家选定的**取舍（"放宽到 8-12 座"）。要把它变成可发布数值，需要：

1. 用 `run_loop_aggro` 跑 10 槽口径的商店 AI / MC 300 局
2. 重标 κ_r 与 ATTRITION
3. 对照 6 槽基线的起飞率 / 通关率

在此之前 `tower_cap = 10` 应视为**未经平衡验证的默认值**。

### 一键回退

```gdscript
# scripts/gameplay/shop_runtime.gd
var free_placement: bool = true     # false → 回到 6 个固定塔位（金标本口径）
```

关掉后 `geo` 重新用 `_Geo6.build_by_slots(n_slots)`，`legal_note` / `slot_usage` 也各自回退。
用于回归对照或出问题时快速切回。

  `_draw_radial_slot_layer` 直接跳过所有未占用槽 —— 不画"虚位以待的八边形"，
  因为没有"空塔位"这个概念了。
