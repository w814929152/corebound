## §2 项② —— 反直觉的成因：**rng 再分岔 × 指标钝感**（解释成立）

### 2.1 直接证据：**前缀 hash 测试**（我自写探针的核心）

我在探针里对每次 run 的 **W1–9**（`core_hp_raw, ratio_raw, build`）逐 run 拼接取 `hash()`。
**关键前提**：Sapper 仅 W≥10 生效（`w<10 → g≡1`，`monster_data.gd:65-66`）⇒ 中性 vs 翻参的 **W1–9 必须逐位一致**。

| rng 方案 | 前缀 hash（W1–9）中性 | 前缀 hash（W1–9）翻参 | 含义 |
|---|---|---|---|
| **连续共享 rng**（各 MC 门禁/scан 的标准做法） | 1998867701 | **2549223616** | 🔴 **不同！W1–9 被污染** |
| **per-run rng**（每 run `rng(SEED+i)`，我加的对照） | **3485991772** | **3485991772** | ✅ **相同！W1–9 干净** |

**⇒ 机制被钉死**：MC 的 rng 是**一条跨 300 局连续消费的流**（`_PyRandom.new(SEED)` 只建一次，`shop_ai.shop_phase` 每波消费）。一旦 W10 处 Sapper 强度变化 → 该局 W10+ 的 build/收入变 → **该局后半段 rng 消费量变** → **后续所有局的 rng 起点被平移** → 连"本应惰性"的 W1–9 都变了（前缀 hash 变）。
这就是工程假设的「**加速器改 W10 结果 → 整局 build/rng 轨迹漂移 → 聚合非单调**」—— **成立，且现在有可观测痕迹**。

### 2.2 指标钝感：起飞率对"塔死"几乎不响应

`scan_sapper` 同一次运行内的旁证（**中性**）：

```
B 无 Sapper：towers_disabled=1.2
B 有 Sapper：towers_disabled=2.4      ← Sapper 确实多打死 ≥1 座塔
但 ΔB（起飞率差）= −0.077 …… 翻参后塔死更多，ΔB 反而 −0.007
```

⇒ Sapper 的**塔死亡效应真实且可观**（+1~2 座），但**起飞率指标只动 ±2 局（≈0.7%）** —— 起飞率是「整局 build/dps 比值过线」的**粗粒度**结局，对单座塔的死不敏感。于是**残差全部落在 rng 再分岔的噪声带里**。

### 2.3 clean 对照：方向回到"预期"

| 指标 | 连续 rng 中性→翻参 | **per-run-rng 中性→翻参**（干净） |
|---|---|---|
| PRICED 起飞率（RADIAL 六槽） | 0.850 → 0.850（平） | 0.867 → **0.863**（**预期微负**） |
| OFF 起飞率（RADIAL 六槽） | 0.677 → **0.683**（反直觉升） | （同 per-run 干净口径见 §3.3） |

**⇒ 加压后聚合"变好"是 rng 假象**：把 rng 换成 per-run（消掉跨局污染）后，起飞率回到**预期的小幅下降**。工程所指的「PATH 六槽 scan 与 RADIAL 探针方向相反」**并非几何之争的本质** —— 本质是**两者都让聚合档被 rng 再分岔主导**（方向随漂移而翻转）。
