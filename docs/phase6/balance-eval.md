## 0. 结论摘要（TL;DR）

OBS-2 的**主因是 ③ 收入曲线**（收入长期高于「**值得买的面**」→ 尾部盈余 + 玩家无压力地持续加码），**① `hp_growth=1.42` 是结构性共因（且为冻结项，不可单独动）**，**② 「修复一次即一劳永逸」是下游症状、非根因**。〔复核订正 V2：主因方向保留，但「数学迫出」须改用**实机**机制表述，见下。〕

三条硬证据：

1. **收入曲线超线**〔复核订正 V1/V2/V3〕：W1–20 **账面**收入 ≈ **4126**（不含 `income_mult`）；**实机**因 `income_mult` 饱和（ScrapUp，封顶 +1.0 → ×2）**总收入 ≈ 8252**、**总支出 ≈ 7292（≈365/波）** → 终局盈余 **960** 为**实**（约占收入 12%）。🔴 **实机 `shop_runtime.buy()` 无每波动作上限**——`max_actions(12)×单价(12)=144/波` **仅为 `shop_ai`（AI/MC）路径的上限，不可用于论证实机**。实机盈余的真正成因 = **收入随波高增长 vs「值得买的面」饱和**（6 槽 / 升级递减 `h^0.6` / ScrapUp 封顶 / 3 位发牌 / 合法宿主有限）→ 后期收入**无法被高效吸收**。
2. **威胁曲线 vs 力量曲线失衡**：敌方「零漏怪 DPS 门槛」每波增长 ≈ **1.42–1.55×**（含只数/窗口的复合，见 §1.2），而玩家力量由**收入驱动的升级 + 共鸣复利**推动、增长更快 → W6 之后玩家 DPS 稳定盖过门槛 → 精英波零威胁。
3. **W5 是唯一硬墙、且与 HP 无关**〔复核订正 V4/V5〕：`threshold(6)=32.5 > threshold(5)=21.2`，**W6 门槛更高却零漏怪** → 门槛**不解释**掉血（其成因由 **W5 三塔全 Disabled** 观测承载）。硬墙的**多因子假设** = **Sapper（×3、锁定即远程扣塔）+ 窗口最窄（0.30）+ 玩家恰在最低 ramp**；**权重待 MC 消融臂确认**（§1.5）。

**读法**：门槛每波 ×1.42–1.55（≈ `hp_growth` × 只数比 ÷ 时长比）。
🔁 **〔复核订正 V4〕**：`threshold(6)=32.48 > threshold(5)=21.24`，W6 零漏怪、W5 掉血——但**门槛是「零漏怪所需 DPS」，玩家 DPS 也逐波增长**。若 `DPS(W5)∈[13.70, 21.24)`（W4 已零漏怪 → `DPS(W4)≥13.70`）且 `DPS(W6)≥32.48`，**无需任何机制**即可解释 W5 漏 / W6 不漏。→ **门槛反例不支持「硬墙必另有成因」**（避免推理跳跃，同 T-CP-08 家族）。掉血的**直接事实**由另一条观测承载：**W5 结束时 3 塔全 Disabled**（§1.1）→ 塔被打停 → DPS 崩塌 → 漏怪。机制结论应挂在**该观测**上（§1.5），而非门槛反例。

### 1.3 数值链（玩家经济侧）—— 收入曲线 vs 吸收能力〔复核订正 V1/V2/V3〕

- 收入/波 = `n(w) × scrap_per_kill(w) × (1+income_mult)`，`scrap_per_kill=2+0.5w`（`shop_runtime.grant_wave_result:1168`）。`income_mult` 由 ScrapUp 每次 +0.20、封顶 +1.0（`shop_runtime.gd:535`）→ 饱和即收入 ×2。
- 🔴 **路径纪律（核心订正 V2）**：`shop_ai.shop_phase` 每波在 `actions ≥ max_actions(=12)` 时 break（`shop_ai.gd:389-390`）→ **AI/MC 路径**消费 ≤ `12×12=144/波`。**但实机 `shop_runtime.buy()`（`:502-540`）仅校验 `scrap ≥ cost` 与 `legal`，无 `max_actions` 计数 → 实机消费无 144/波 上限**。OBS-2 症状**来自实机**（经 `runtime.buy`）→ **不得用 AI 的 144 论证实机**。

| 口径 | 累计收入 | 累计支出 | 终局盈余 | 说明 |
|---|---|---|---|---|
| **实机（观测症状来源）** | **≈ 8252**（4126×2，income_mult 饱和） | **≈ 7292（≈365/波 ≫ 144）** | **≈ 960（实测）** | 无每波动作上限；≈365/波 远超 144 → **实机确实不受 144 约束** |
| AI/MC（对照，非症状来源） | 4126（不含 mult） | ≤ 2880（144×20） | ≥ 1246（模型下界） | 仅 AI 路径成立；**该模型与实测 960 不相容**（见下） |

🔁 **〔复核订正 V3〕「960 与模型下界吻合」不成立**：AI 上限模型给出盈余**下界 1246**，而**实测 960 < 1246** → **观测落在模型下界之外 → AI 上限模型不适用于实机**（这**反证**实机不受 144 约束）。→ 原「观测量级吻合」佐证**删除**。
🔁 **〔复核订正 V1〕交叉点订正**：若以 **AI 路径**的 144 上限为参照，收入/波首次 > 144 为 **W10**（W9=143.0 < 144；W10=168.0 > 144），**非 W13**（原「从 W13 起」有误，且与 §1.2 表 W10=168 自相矛盾）。**该交叉仅具 AI 路径意义**，不用于实机结论。

**实机盈余的真正成因（据实机约束，非 144）**〔复核订正 V2〕：实机消费**无硬上限**，但**「值得买的面」饱和** ——
1. **槽位有限**（`n_slots=6`，且 κ 广度折价 `disc=0.01·(N−2)` 反而惩罚铺塔）；
2. **升级递减**（Base ∝ `h^0.6`，边际 ΔDPS 递减 → 后期升级性价比塌陷）；
3. **ScrapUp 封顶**（`income_mult` 上限 +1.0，买满后再买增值为 0）；
4. **发牌/合法宿主有限**（`shop_offers=3`，且强化卡需同 Tag 宿主）。
→ 后期收入（≈365/波）增速 > 「值得买」的边际价值增速 → **尾部盈余 960（约占收入 12%）**。这不是「玩家不会花」，而是**后期「值得花」的出口不足**。

### 1.4 逐因定位

| 候选因 | 判定 | 定量依据 |
|---|---|---|
| **③ 收入曲线（scrap 收入 vs 消费缺口）** | 🔴 **主因** | **实机**收入 ≈ 8252、支出 ≈ 7292 → 尾部盈余 **960（实）**；成因 = **收入随波高增长 vs「值得买的面」饱和**（§1.3，**非** AI 的 144 上限）〔订正 V2〕；收入是「玩家持续加码 → 力量超线」的**燃料**（§1.2 门槛被盖过）。 |
| **① `hp_growth=1.42` 不够** | 🟠 **结构性共因（冻结项）** | 威胁仅 ×1.46/波，**低于**玩家复利力量增长 → 中后期门槛被稳定盖过。**但 `hp_growth` 是金标本冻结项**（`mvp_config._assert_frozen:243`），**动它 = 改判据链基线**，不可单独动。 |
| **② 「修复一次即一劳永逸」** | ⚪ **下游症状，非根因** | 修复价 `ceil(0.30·invested)`（`shop_runtime.REPAIR_RATE:880`）相对收入**恒可负担**；更关键：**W5 之后塔不再被打停**（Disabled=0）→ 修复**频率→0** → 「修一次」是「塔不再死」的**结果**，不是原因。**把修复抬贵并不能恢复后期压力**（死循环：塔不死 → 修复无意义）。 |

**一句话链**：③ 收入过宽（收入增速 >「值得买的面」增速）→ 玩家力量（升级 × 共鸣复利）持续超线 → 盖过 ① 的 1.42 威胁曲线 → 后期塔不再被打停 → ② 修复退化为一次性事件 → 表现 = 「前重后轻 + 经济过宽」。

### 1.5 W5 硬墙的归因（多因子假设 · 非 HP）〔复核订正 V4/V5〕

W5 = **唯一硬墙**，且**不是 HP 门槛造成的**（§1.2 V4：门槛不解释掉血）。**直接观测**：`playtest-report` §1.1 —— **W5 结束时 3 塔全部 Disabled**（塔被打停 → DPS 崩塌 → 漏怪）。可能的多因子：

1. **首个精英波 → Sapper 登场**：`n_e=max(2,round(0.10·16))=2`。Sapper 对塔伤害 `= ATTRITION(1.5) × HP0(120) × m_dps × SAPPER_DMG_MULT(3.0)`（`wave_director._damage_tower:519-527`），且 **Sapper 锁定即每子步扣塔、不限距离**（`_aggro_target_valid` 对 sapper 恒 true，`:509-511`）→ 对 h=1 裸塔（HP=120）在 **≤~0.4s**（Swarm 最慢上界；Rush/Tank 更快）内打到 Disabled。
2. **`spawn_window(5)=0.30` 最窄**：16 怪压缩进 `0.30×39=11.7s`，`interval≈0.73s` → 同时在场最多、仇恨并发最密。W6 起窗口翻倍（0.60）→ 并发骤降。
3. **玩家恰在最低 ramp**：R3 记录 W5 安全窗「花光 99 积分」→ W5 前玩家**现金几乎见底**（收入 W1–5 累计仅 231.5），构筑刚够门槛 → 一扰动即翻车。

🔁 **〔复核订正 V5〕权重待确认**：**静态分析无法隔离**「Sapper 首登场」的因果权重 —— `WARMUP=2` 使 **W3 起常规 aggro 已活跃**，任何怪在 `AGGRO_R=9` 内均可打停塔；Sapper（×3 + 锁死）与其「首登场」的正/负权**需 MC 消融臂**（关 Sapper / 抬窗口 / 补现金 三臂）方能定序。→ 三因子为**多因子假设**，**权重标「待消融验证」**。

→ W5 的「硬」= **正确的设计意图**（首精英 + 教「修复」的关键节点）。**问题不在 W5 太难，而在 W6 之后没有再出现第二个「W5 级」节点**（§1.4）。

### 2.1 P1 · 收紧收入侧 / 抬高消费天花板（**直击主因 ③**）

- **动作**：二选一或合用 ——
  - **P1a**：启用**已存在但置零的休眠旋钮** `wave_price_step`（`mvp_config.gd:166` 现 = 0.0）。设 >0（如 +2/次重购）→ `action_cost = base + step·counts[name]`（`shop_ai.gd:355`）→ 重复购买递增涨价，**把后期盈余吸收进涨价**。
  - **P1b**：下调收入侧 `scrap_growth(0.5)` / `scrap_base(2.0)`。
- **影响数值**：`wave_price_step` 0.0→N；或 `scrap_base/scrap_growth`。
- **是否定稿值**：`wave_price_step` = **非定稿（休眠旋钮）**；`scrap_base/scrap_growth` = **v03 金标本基线**。
- **需否用户批准**：🔴 **需要**（经济口径变更 + 须重扫 MC 基线）。
- **预估影响面**：**全局**。前期（W1–12）影响小；后期（W13+）显著 —— 正好吸收 §1.3 的尾部盈余。
- 🔁 **〔复核订正 V6〕**：P1a **并非「不破 PATH 逐位等价」** —— 改默认 `wave_price_step` → `cfg_of` → `test_suite_slice2` 的**逐位 MC 金标（B 起飞率 91.3% / 274·300 / 20 局 trace）全变 → 默认回归 FAIL（须重签 `G.MC_TIER`/`MC_TRACE`）**。**「最小 diff」卖点成立（旋钮已实现、默认 0），但「不破金标」不成立**。

### 2.2 P2 · 精英波梯度化（**直击「前重后轻」症状面 + B-2/B-3**）

- **动作**：给 Elite 波加**随波递增**的强度维度。当前 `n_e=2/2/3/4`（几乎平）、`SAPPER_DMG_MULT=3.0`（恒定）→ 加入**随 w 的缩放**（如 Sapper 数量或对塔倍率随 w 上升）；**可选**：非读数的强度档位预告（呼应 B-2，不违反「无数字/倒计时」）。
- **影响数值**：`SAPPER_DMG_MULT`（**推荐，Sapper 域**）、或 `elite_count` 系数、`m_hp_elite`（**Elite 域**）。
- **是否定稿值**：`SAPPER_DMG_MULT` = **T1 诊断域（非产品定稿）**；`n_e=max(2,round(0.10N))`、`m_hp_elite=2.5` = **GDD §2.5.4 定稿**。
- **需否用户批准**：🔴 **需要**（改口径 + 重扫）。
- **预估影响面**：**仅精英波 {5,10,15,20}**。🔁 **〔复核订正 V7〕「与守恒律正交」仅对 `SAPPER_DMG_MULT` 域成立**（Sapper 是 Elite 词缀、不改三原型 `Σp·m_hp / Σp/m_spd`）；**若动 `n_e`/`m_hp_elite`，则进入 GDD §2.5.4 的 Elite 守恒（`c(w)` 缩放），不再正交**。默认回归两域均**不消费**（`elite_waves_enabled=false`）→ ✅ 不破默认金标。⚠️ **风险**：W5 已是硬墙 → 建议**梯度只作用于 W≥10**（保留 W5 作为教学墙）。

### 2.3 P3 · 修复经济对齐（**② 的下游修正 · 条件性**）

- **动作**：让修复成为**真正循环的消费**——但**仅当 P2 恢复了「塔损频率」之后才有意义**。可在 P2 生效后重新校准 `REPAIR_RATE`（或引入「损血比例定价」）。
- **影响数值**：`REPAIR_RATE(0.30)`，或损伤比例化的新定价式。
- **是否定稿值**：**Q-T8 定稿口径**（`shop_runtime.gd:864-880`）。
- **需否用户批准**：🔴 **需要**（Q-T8 定稿 + 依赖 P2 + 重扫）。
- **预估影响面**：塔损频发时才有账面影响。🔴 **独立落地无效**（塔不死 → 修复无意义，§1.4 ②）→ **必须与 P2 捆绑评估**，否则是「废按钮」。默认不消费（`repair_on_disable=0`）→ ✅ 不破默认金标。

### 2.4 关于 ①（`hp_growth`）的处置建议

🟠 **不建议单独动 `hp_growth`**：它是**金标本冻结项**（`_assert_frozen:243`），单独改动会使全部判据链作废。若用户希望「抬高威胁曲线」，**优先走 P2**——「把难度补到缺的后期节点上」比「均匀抬高全场 HP 曲线」**更精准、影响面更小**。

### 2.5 提案优先级（建议）〔据复核订正 V6 调整〕

1. 🔁 **P2-Sapper 域（只动 `SAPPER_DMG_MULT` + 仅 W≥10）** —— **三栏全绿（不破金标 / 不触守恒 / 非定稿）→ 影响面最小**，先做。
2. **P1a（`wave_price_step`）** —— 直击主因，但**破默认金标、须重签**（成本高）。
3. **P3** —— **仅在 P2 生效后**评估。

## 4. B-1（零教学）权重评估

- **独立严重度**：**Minor**（与 `playtest-report` §4 R1 一致）—— 失败路径本身健康（W1→W4 收口清晰），缺的只是一段最简引导。

- **权重结论**：B-1 本身 **Minor**，但**优先级应上调至「与 OBS-2 同批、但独立先行」**——理由：
  1. **零数值、零判据链影响**（纯文案 / 一次性引导 UI）→ **不需 MC 重扫、不需用户签基线**，成本远低于 P1/P2；
  2. **投入产出比高**：3–4 步最简引导（**买→放→跑→修**）即可把 W5 从「莫名撞墙」变成「可理解的机制节点」；
  3. **与 OBS-2 解耦**：即使平衡提案待用户拍板，B-1 也可**先做、单独发布**。
- **建议**：**作为独立轻量批次先行**（不阻塞、不依赖 OBS-2 裁决）。
