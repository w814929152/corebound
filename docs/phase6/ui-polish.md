## 2. 交付

### 2.1 新增：统一样式层 `scripts/ui/ui_style.gd`

单一来源，四处界面共用。**纯静态、无状态、preload 友好、不写 `class_name`**。

- **调色板**：§2.2 的 8 个登记色逐字对齐（耀青 / 熔橙 / 辉金 / 警报红 / 钢灰 / 夜幕紫 / 正文 / 辅助）。
  *不在本文件新增任何未登记色。*
- **几何令牌**：`RADIUS=6` · `BORDER_W=1` · `BORDER_W_EMPH=2` · `FONT_MIN=16`
- **动效令牌**：`SCALE_HOVER=1.05` · `SCALE_PRESS=0.97` · `MOTION_SEC=0.12`（§5.1 原文数值）
- **StyleBox 工厂**：`panel()` / `card(state)` / `inset()` / `bar_fill()` / `divider()`
- **按钮变体**：`primary`（金描边）· `normal`（青描边）· `ghost`（无底）· `danger`（红描边）· `unavail`（钢灰）
  每个按钮自动挂 **hover 抬起 / 按下缩放** 弹性缓动（`scale` 不参与容器布局，不会推动邻居）。
- **`label()`**：低于 16px 时**强制抬到 16**，把 §9.1 P0 变成 API 约束而不是靠人记得。

### 2.2 商店抽屉（`shop_overlay.gd`）

| 项 | 改造前 | 改造后 |
|---|---|---|
| 抽屉底座 | 无 StyleBox（透明） | 深色底 94% + 耀青 2px 描边 + 圆角 6 |
| 商品卡 | 无 StyleBox（漂浮文字） | 亮一档的卡片底 + 钢灰描边；**买得起时描边提亮**（第二通道，可购性另有 ✓/✗ 字形冗余） |
| 卡内层级 | 6 行同字号 16px | 序号 16（辅助）→ **卡名 26（L1 白）** → 类型 16 → **价格 20（L1 辉金）** → 细分隔 → 备注 16 |
| 按钮 | Godot 默认主题 | 购买 = `primary` 满宽 · 锁定 = `ghost` · 刷新 = `normal` · 处置 = `danger` |
| 顶部信息 | 一行 5 组数字拼接 | **3 列网格**（废料 / 主塔塔位 / 塔位 · 强化槽 / 全局槽），分组可扫读 |
| 预算条 | 直角 `ColorRect` | 圆角轨道 + 圆角填充；耗尽转红 |
| 重决策按钮 | 「弃卡（🟡 后续切片）」 | `弃卡` / `卸下改投`（`unavail` 变体表达"未开放"，不再靠 emoji 说明）· `拆除回收` / `处置受损塔` 2×2 网格 |
| 分区 | 靠空白分隔 | 四处 `hline()` 细分隔线（§5.1） |

**合规保持**：`SLOT_SIZE` 仍是**唯一**尺寸常量、三位逐字同构（X3 禁止用布局暗示）；三张卡结构完全相同，只有文字与描边态不同。

### 2.3 HUD（`hud.gd`）

- **积分卡**：新增深底 + 细描边面板承托；加 **「废料」说明行**（与引导 / 商店统一术语）；数字 52 → 44 以适配面板；硬币 32 → 28 半径。
- **波次区**：`WAVE` 字号 44 → 42、上移到 `y=8`；进度条下移到 `y=90`（与文字留 22px 呼吸，原 8px）；条高 8 → 10、宽 320 → 300、**加轨道 + 圆角**；条下新增 **`已出 / 总数` 读数**（§5.2 数字优先）。
- **精英标记**：从「条上方、会压 WAVE 大字」改到**进度条左侧右对齐**，垂直居中于条。
- **「开始下一波」**：`primary` 变体（金描边 + 金字），尺寸 128×40 → 150×44 —— 它是安全窗**唯一**的推进操作，原先视觉重量远低于重要性。
- **键位提示行**：`vh - 44` → `vh - 112`，移出血条底槽带。
- **性能**：`_draw` 里的 StyleBox 全部在 `_build()` 缓存，**不在每帧绘制里 new**。

### 2.4 核心血条（`core_hp_bar.gd`）

- 距底边 28 → **46**（原设计在 1080p 下仅 18px，像被裁掉）。
- 段间隙 3 → **4**，段加 3px 圆角（直角方块在暗底上过于生硬）。
- 底槽改为圆角 + 2px 描边（原 3px 外框比填充还亮，抢视线）。
- 数字 30 → **22**，抬到条上方留白区，不再压条顶。
- 新增左侧 **「核心」** 说明（原来只有一串裸数字）。

### 2.5 弹窗与结算（`result_overlay` / `salvage_confirm_dialog` / `disabled_tower_dialog`）

- 面板补深底 + 2px 描边 + 圆角（结算用耀青、两个处置弹窗用警报红 —— 按语义分）。
- 按钮全部走 `ui_style` 变体；处置弹窗行内按钮改为等宽撑满。
- **修复居中偏差**：`set_anchors_preset(PRESET_CENTER)` 后必须配
  `grow_horizontal/vertical = GROW_DIRECTION_BOTH`，否则控件从中心向右下长。
  （这是三个弹窗同时存在的隐性缺陷，改造前一直偏右下半个面板。）
- 结算标题改用登记色：胜利 = 辉金、失败 = 警报红（表外绿/红已移除）。
- 结算正文术语「本局积分」→「本局废料」。

### 2.6 引导浮层（`tutorial_overlay.gd`）

- 补 1px 描边（原纯色底压在暗战场上边缘糊在一起）。
- `PANEL_BOTTOM_GAP` 96 → **120**，跟随核心血条上移，避免与血条数字行贴死。

## 4. 已知剩余缺口（未做，需另行拍板）

| # | 缺口 | 原因 |
|---|---|---|
| 1 | **等宽数字（tabular）** | §5.2 要求「数字必须等宽，避免滚动抖动」。工程尚未接入字体资产（§5.4 缺口），`ThemeDB.fallback_font` 不是等宽字体。需要先定字体（SIL OFL）再谈。 |
| 2 | **卡牌蓝图风 / 稀有度色阶** | §5.5 / §2.3 的 P1-6 缺口。稀有度体系本身不在当前卡池里（7→10 张卡无稀有度字段），不是纯 UI 能补的。 |
| 3 | **UI 缩放 100/125/150%** | §9.1 的 D5 缺口。全工程用绝对坐标布局（`_layout()`），整体缩放需要先做一层 scale 容器 + 事件坐标换算。 |
| 4 | **高对比模式 / 减弱特效开关** | §9.1 的 D6 / D8 缺口，属独立无障碍批次。 |
| 5 | **字体** | §5.4 缺口，同上第 1 条。 |

> 上述五项都不在本轮范围内：它们是**资产 / 系统级**改造，不是样式收敛。本轮只做「不加资产、不改布局基准」的前提下能拿到的全部收益。
