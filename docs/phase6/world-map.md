## 0. 一句话

选关从「按章排列的卡片矩阵」改成**一张全屏的裂隙航图**：三章沿同心环由外向内铺开，
终局落在正中的核心，玩家点节点直接进关。

## 1. 为什么是径向航图，不是列表

旧版是 4 行卡片（每章一行），问题不在「能不能选」，而在**它不表达任何空间信息**：

- 本作战场本身就是径向核心围攻（出生环 → 核心），而选关界面却是横向列表 —— 两套空间语言；
- 卡片矩阵里「1-1 在左上、4-1 在右下」，玩家读不出「越往里越难 / 终局在核心」；
- 10 张卡同尺寸、同权重，一章和三章的视觉分量一样，**推进感被摊平**。

航图直接复用战场的几何隐喻：

| 章节 | 离核心 | 理由 |
|---|---|---|
| 第一章 · 熔炉 | 最外环 | 起点，离核心最远 = 最安全 |
| 第二章 · 霜序 | 中环 | 向内收一环 |
| 第三章 · 枢网 | 内环 | 逼近核心 |
| 终局 · 核心 | 圆心 | 「打到最后就是核心本身」 |

节点角向按 `200° + 62° × i` 等差递推 → 10 个节点连起来是一条**向心螺旋**。
推进方向不用文字解释，形状自己会说。

## 2. 布局（纯函数，可断言）

`layout_points(sz)` 是纯函数，只吃画布尺寸，**零 RNG、零场景依赖**：

```
unit  = min(高, 宽 × 0.62)
r(ch) = unit × [0.320, 0.225, 0.130, 0.0][ch-1]
点(i) = 中心 + (cos θ, sin θ) × r(章)，θ = 200° + 62° × i
中心  = (宽/2, 47% 高)          # 略上移，给左下角详情卡留位
```

不变量（`run_campaign_asserts` §9 钉住）：

1. 节点数 = 关卡数（10），位置互不重合；
2. `dist(1-1) > dist(2-1) > dist(3-1) > dist(4-1) = 0`（第一章最外、终局在核心）；
3. 三章颜色互不相同（颜色只是第二通道，见 §4）。

## 3. 三种状态 = 三个形状

| 状态 | 形状（第一通道） | 颜色（第二通道） | 文字（第三通道，详情卡） |
|---|---|---|---|
| 已通关 | ✓ 对勾 | 辉金描边 | 「✓ 已通关 · 点击可重复挑战」 |
| 当前 / 可挑战 | ▶ 三角 + 外环 | 章节色 | 「▶ 可挑战 · 点击进入」 |
| 未解锁 | 🔒 锁 | 钢灰（低透明） | 「🔒 未解锁 · 先通关 1-2」 |

> 🔴 art-bible §9.2：颜色不得是唯一信息通道。这里形状、颜色、文字三条都在，
> 色盲/灰度截图下仍然可读。

## 4. 交互

| 输入 | 行为 |
|---|---|
| 悬停节点 | 六边形放大约 8% + 外侧白环 + 左下详情卡实时切换 |
| 点击已解锁节点 | **直接进入**（无二次确认 —— 「选择即进入」是玩家对地图的直觉） |
| 点击锁定节点 | **无反应**（不弹错、不踢人，与放置模式「点错不踢人」同纪律） |
| ← → / ↑ ↓ | 沿推进链移动焦点（越界不循环） |
| Enter / Space | 进入当前焦点关 |
| Esc | 不关闭（必须选一关才能开始） |

## 5. 与开局流程的接线

```
boot._ready()
  └─ add_child(StageSelect)
     └─ call_deferred(_open_stage_select)     # CAMPAIGN_ENABLED = true
        └─ 玩家选关 → stage_selected(sid)
           └─ _open_pack_select()
              ├─ 已解锁 ≤ 3 包 → _begin_run(RunMeta.unlocked_ids())
              └─ 已解锁 > 3 包 → 弹选包界面 → _begin_run(packs)
                 └─ _begin_run：注入 wave_count + SpaceModel.set_active_map(map_id) → start_new_run()
```

- **再来一局**：`shop_controller.restart_hook` 指向 `_open_stage_select`（关卡推进 ON 时）
  → 结算后先回航图，能立刻看到新解锁的关，再选包。关闭关卡推进则回到老口径（直接选包）。
- **记账**：`boot._on_run_finished` 调 `campaign.on_cleared / on_failed`，
  解锁下一关 + 发 Ember，与卡包的最佳波次解锁互不读写（两条线，见 card-packs.md §3）。

## 6. 已知取舍

1. **航图不支持缩放 / 拖动**：10 个节点一屏放得下，加相机控制反而增加操作成本。
2. **节点数写死 10**：布局是按 `STAGE_ORDER` 长度算的，加减关卡自动适配，但螺旋会多绕一圈；
   若超过 ~14 关需要改成多圈或分页。
3. **详情卡在左下而非跟随鼠标**：跟随鼠标会压住节点标签，固定位置读起来更稳。
4. **不画章节文字在环上**：弧中点正落在该章中间节点，会撞节点标签 → 章名统一进左上角目录。
5. **锁定关不显示「需要多少 Ember 提前解锁」**：`campaign.unlock_stage_with_ember` 逻辑已在，
   UI 入口留到下一刀（提前解锁还缺一个代价确认弹窗，避免误花 Ember）。
