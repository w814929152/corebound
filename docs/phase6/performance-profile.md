## 1. 真实帧测量（FPS / 帧时间分布）

检查点 **W1 / W5 / W10 / W15 / W20**，每点：5.0s 预热 + 6.0s 采样（窗口模式，真实帧）。

| 波次 | FPS(均) | 帧时间 mean | **p50** | p95 | p99 | **最坏帧 max** | 在场怪 max(采样内) | 采样帧数 |
|---|---|---|---|---|---|---|---|---|
| W1  | **301.5** | 3.315 ms | 3.223 ms | 3.984 ms | 4.480 ms | 6.079 ms | 4 (~now 3) | 1806 |
| **W5** | **255.1** | 3.918 ms | **3.968 ms** | 4.683 ms | 5.102 ms | 6.387 ms | **13 (~now 12)** | 1531 |
| W10 | 297.6 | 3.358 ms | 3.322 ms | 4.115 ms | 4.503 ms | 7.075 ms | 8 (~now 8) | 1787 |
| W15 | 335.5 | 2.979 ms | 2.900 ms | 3.681 ms | 4.199 ms | 6.669 ms | 5 (~now 5) | 2016 |
| W20 | **349.3** | 2.862 ms | 2.802 ms | 3.388 ms | 3.870 ms | 6.582 ms | 6 (~now 6) | 2099 |

**最坏帧场景定位**：**W5**。这是全场 FPS 最低点（255.1），帧时间 p50/p95 全场最高（3.968 / 4.683 ms），也是**在场怪峰值所在**（13 只）。反直觉的是高波次（W15/W20）反而更快——因为这些检查点在「预热+采样」窗口内并发怪数更少（W20 仅 6 只在场），说明**帧成本由「同时在场怪数」而不是「波次数字」驱动**（与 §3 合成伸缩的线性结论相互印证）。

**分布特征**：全检查点 p99 ≤ **7.1 ms**、max ≤ **7.1 ms**，即**最坏帧也在 141 FPS 以上**；帧时间分布紧凑（p50→p99 仅抬升 ~1.3 ms），**无长尾尖峰**。相对 60 Hz 预算（16.67 ms）最坏帧余量 **≥2.3×**，相对 120 Hz（8.3 ms）仍有约 12–15% 余量。

> 结论：**当前 polish 期机器配置下，帧率有充足余量**（最低 255 FPS）。性能不是当前的止损项；下述热点分解用于给未来「规模放大 / 低端机 / 高刷新率」预留优化弹药。

## 2. 热点分解（逐层消融）

**方法**：W5 稳态（冻结子步 `wd.set_process(false)` 以隔离渲染层，与逻辑解耦），在场怪 **M=12**；逐层关闭采样 1.2s，比较帧时间 p50。**Δp50 = 该层关掉后省下的帧时间**。

| 层 | 内容 | p50 | p95 | max | **Δp50（占用）** |
|---|---|---|---|---|---|
| [A] 全开（基线） | — | 4.040 ms | 4.738 ms | 5.678 ms | — |
| [关] **MonsterLayer** | 逐怪/逐塔/场地/威胁楔 | **0.840 ms** | 1.215 ms | 2.832 ms | **−3.200 ms（≈79%）** |
| [关] HUD | 积分/波次/横幅/进度条 + Label | 3.955 ms | 4.505 ms | 5.423 ms | −0.085 ms |
| [关] ShopOverlay | 商店抽屉 | 4.230 ms | 4.809 ms | 5.792 ms | +0.190 ms |
| [关] ThreatPulse | 边缘红光脉冲 | 4.327 ms | 4.886 ms | 5.365 ms | +0.287 ms |
| [关] CoreHpBar | 核心 HP 条 | 4.085 ms | 4.604 ms | 6.021 ms | +0.045 ms |
| [G] 关全部 UI 层 | 只留 MonsterLayer | 3.522 ms | 4.026 ms | 4.634 ms | −0.518 ms |
| [H] 关全部渲染层 | 空场 | **0.355 ms** | 0.679 ms | 2.425 ms | **−3.685 ms** |

**读法（关键）**：
1. **渲染层占绝对大头**：全开 4.040 ms → 空场 0.355 ms，**渲染层总占用 Δp50 = −3.685 ms（≈91% 帧时间）**；逻辑子步在本独立测量中已被冻结。
2. **其中 MonsterLayer 独占 −3.200 ms（≈79% 帧时间 / ≈87% 渲染层）**——`scripts/ui/monster_layer.gd` 是**唯一的第一热点**。
3. **HUD 仅 −0.085 ms**：`scripts/ui/hud.gd` 每帧 `snapshot()` 三连拷 + Label 文本重排，但实测开销极小（<2% 帧时间），**当前无需优化**。
4. **ShopOverlay / ThreatPulse / CoreHpBar 的 Δp50 为正值**（关掉反而更慢）：这是**测量噪声**（量级 +0.05 ~ +0.29 ms，均 < 一次采样的抖动带宽），**不构成真实占用**——它们在战斗稳态下基本无重绘负担。合起来 [G] 关闭全部 UI 只省 −0.518 ms，也印证 UI（除 MonsterLayer 外）整体近乎零成本。

**渲染层内部细分（读代码对齐）**：`monster_layer.gd` 的 `_draw()`（line 661）每帧经 `queue_redraw()`（`_process` line 281）触发，逐帧执行约 11 个子绘制：`_draw_radial_ground`（全场底圆）、`_draw_all_shadows`（逐怪阴影）、`_draw_radial_slot_layer`、`_draw_threat_wedges`（逐怪威胁楔）、`_draw_radial_core`、`_draw_radial_towers`（逐塔形态）、`_draw_radial_monsters`（逐怪高细节）、`_draw_projectiles`、`_draw_revive_charge/flash`、`_draw_exposure_icons`。另有 `scripts/ui/battlefield_placeholder.gd` 的 `_draw_radial_ground`（line 164）**每帧 `draw_rect` 铺一张全屏不透明矩形**（line 168）。这些**逐怪 / 逐塔 / 全屏**绘制是 MonsterLayer 占 79% 的来源。

## 3. 子步尖峰评估（`MAX_SUBSTEPS_PER_FRAME=64`）

**机制**：`scripts/gameplay/wave_director.gd` 的 `advance(dt)`（line 334）内部按固定 `DT=0.1` 离散步推进，单帧最多追赶 **`MAX_SUBSTEPS_PER_FRAME := 64`**（line 171）步 = 最多消化 **6.4 游戏秒**。当窗口失焦（`Engine` 帧暂停）后重新聚焦、或低帧率导致单帧 real-dt 变大时，这一 `while` 循环会一次性跑满多步。

**失焦→回焦跳变模拟**（直接给 `advance(dt)` 喂大 dt，取最坏 64 步）：

| 波次 | 1 子步 | **64 子步追赶** | 每子步 |
|---|---|---|---|
| W1  | 0.0130 ms | **0.272 ms** (M=8→5) | 0.0043 ms |
| **W5** | 0.0390 ms | **1.437 ms** (M=10→10) | **0.0225 ms** |
| W10 | 0.0260 ms | 1.002 ms (M=6→9) | 0.0157 ms |
| W15 | 0.2510 ms | 0.654 ms (M=4→5) | 0.0102 ms |
| W20 | 0.0220 ms | 0.682 ms (M=4→6) | 0.0107 ms |

**评估**：
- **最坏情形（W5，满 64 步，M≈10）单帧逻辑成本 ≈ 1.44 ms**，即便叠加渲染层（§2 全开 p50 4.04 ms）后单帧仍 **≈5.5 ms < 16.67 ms**，**不会打穿 60Hz 预算**，不会造成可见卡顿。
- **跳变后不会雪崩**：64 步是硬上限，`while` 到达上限即停（不会因低 FPS 无限累积），尖峰被**封顶在 ~1.4 ms**。
- **风险窗口**：只有当**在场怪数远超正常波峰**（见 §3 合成：M≥100 时 64 步 >10 ms）时，一次失焦回焦的追赶才可能产生单帧尖峰。**当前真实波峰仅 10–16 只**（§1 实测 W5 峰值 13），**离危险区有 ~6–8× 安全距离**。
- **观察建议**：若未来引入「怪海波次 / 召唤分裂」使并发怪数上升，应回归本表：**M≈50 时 64 步 ≈5.2 ms、M≈100 时 ≈10.3 ms**，届时应考虑将 `MAX_SUBSTEPS_PER_FRAME` 与并发怪数挂钩或改为「每帧时间预算」式追赶。

**合成伸缩（“若 M 更大”探针，§3 数据）** —— **严格线性**：

| M | 64 子步 | 每子步 |
|---|---|---|
| 0 | 0.098 ms | 0.0015 ms |
| 10 | 1.105 ms | 0.0173 ms |
| 25 | 2.694 ms | 0.0421 ms |
| 50 | 5.173 ms | 0.0808 ms |
| 100 | 10.303 ms | 0.1610 ms |
| 200 | 20.565 ms | 0.3213 ms |
| 400 | 41.089 ms | 0.6420 ms |

拟合：**约 0.0016 ms / 怪 / 子步**（M≥25 段线性度极高）。这是**逻辑子步**成本对怪数的标定曲线，用作未来扩容的容量预算表。

> **§2/§3 交互结论**：真实帧的瓶颈在**渲染层 MonsterLayer**（逐怪绘制，79%），而非逻辑子步。逻辑子步相当廉价（正常波峰 64 步仅 0.3–1.4 ms）。优化弹药应**优先投向渲染层**。

## 4. 优化候选清单（按 收益 / 风险 排序）

> **说明**：以下**均为候选，本轮未实施**。任何代码改动需用户审批后另行排期。收益估算基于 §2 消融（MonsterLayer 占 79% 帧时间 / 3.2 ms）与 §3 线性标定。

| # | 候选 | 目标层 | 预估收益 | 风险 | 触碰红线? | 说明 |
|---|---|---|---|---|---|---|
| **C1** | **批量绘制（batched draw）**：把逐怪/逐塔的 `draw_*` 调用从「每实体多次 `draw_circle/draw_polygon`」改为**先收集几何、按材质/颜色合批**（或改用 `MultiMesh` / `draw_multimesh` / `RID` 批），减少 draw call 数量 | `monster_layer.gd` 逐怪/逐塔 | **高**（MonsterLayer 占 3.2ms，draw call 是主因；预估省 30–50% ≈ 1.0–1.6 ms） | **中**：需保证绘制顺序/Z 序与视觉完全一致（否则破坏 golden sample 观感） | **否**（纯呈现层，不改数值/口径） | 收益最大，但需逐函数改造 + 视觉回归 |
| **C2** | **离屏裁剪（off-screen culling）**：径向布局下仍对超出可视圆的实体跳过 `_draw` | 逐怪/逐塔 | **中**（仅当实体出屏时省；当前场地基本全在屏内，收益中等） | **低**：纯跳过不可见项，无视觉变化 | 否 | 与 C1 正交，可叠加 |
| **C3** | **几何缓存（geometry caching）**：塔形态（`_draw_tower_form`）、场地底圆（`_draw_radial_ground`）、槽位层（`_draw_radial_slot_layer`）等**静态/低频变化几何**缓存为 `ImageTexture`/预生成 `PackedVector2Array`，避免每帧重算 | 静态层 | **中**：底圆/槽位/塔体每帧重算顶点是纯浪费 | **低**：缓存失效仅在层变化时刷新 | 否 | 低风险高性价比 |
| **C4** | **描画去重（draw-call dedup）**：`_draw_all_shadows`（逐怪阴影）+ `monster_layer._draw_radial_ground` 与 `battlefield_placeholder._draw_radial_ground`（每帧铺全屏不透明矩形，line 168）存在重复/冗余覆盖 | 逐怪阴影 + 全屏底 | **中**：全屏不透明 rect 每帧重铺 + 逐怪阴影可合并 | **低**：删除纯冗余覆盖层；需确认无透出需求 | 否 | 建议先做（改动面小） |
| **C5** | **抑制无效重绘**：`_process` 无条件 `queue_redraw()`（monster_layer line 281 / hud / battlefield）；在**无状态变化帧**（静止、无新事件）跳过重绘 | 全 UI 层 | **低–中**：HUD/Shop/Pulse/HpBar 实测近零成本（§2），主要对 idle 帧省电/省算 | **低**：需事件驱动重绘门槛，实现需谨慎 | 否 | 对当前帧率无感，但利于低端机/后台 |
| **C6** | **子步预算化追赶**：`MAX_SUBSTEPS_PER_FRAME` 由固定 64 改为「时间预算封顶」 | `wave_director.gd` 逻辑 | **低（当前）**：正常波峰 64 步仅 ≤1.4ms，非瓶颈 | **高**：**改动逻辑层 → 有触碰确定性/复现风险** | **⚠️ 需评估**（可能触及逻辑层，非纯呈现） | **不推荐本轮**；仅作为「未来怪海」预案记录 |

**推荐执行序（若未来获批）**：**C4（去重）→ C3（缓存）→ C2（裁剪）→ C1（批绘）**，先做低风险小改动，C1 收益最大但需完整视觉回归；C6 暂缓。

## 7. 附：健康度小结

- ✅ **帧率余量充足**：最低 255 FPS（W5），最坏帧 ≥141 FPS，**无长尾尖峰**。
- ✅ **逻辑子步廉价**：正常波峰 64 步追赶 ≤1.4 ms，`MAX_SUBSTEPS_PER_FRAME` 封顶有效，**不失焦雪崩**。
- ✅ **瓶颈单点明确**：渲染层占 ~91%，其中 **MonsterLayer 独占 ~79%**——唯一值得投弹的热点。
- ✅ **UI（除 MonsterLayer）近乎零成本**（HUD <2%，Shop/Pulse/HpBar 在噪声带宽内）。
- ⚠️ **未来扩容预警**：子步成本对怪数**严格线性**（~0.0016 ms/怪/子步）；若并发怪从 ~13 抬到 ~100，64 步追赶将逼近 10 ms，需重估。
- 🔴 **红线**：本轮只读，**未触碰**。
