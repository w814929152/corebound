## 1. P1-1 · 投射物（装饰性弹流）

> 对齐 art-bible §3.3（投射物形状）+ §8.6 锚点4（不得遮挡塔轮廓）+ §8.5（投射物 ≤300）。
> 🔴 **诚实边界优先**：因玩法是 hitscan（§0.1），**弹流不承载因果**。本节的规格目标是"看起来像命中"，不是"是命中"。

### 1.1 形状与配色（§3.3 落地）

| 阵营 | 形状 | 尺寸（**屏幕空间恒定 px**，沿用 §7.2"远近视同"原则） | 长宽比判定 | 配色 |
|---|---|---|---|---|
| **友方** | **梭形 / 箭形**（尖端朝飞行方向） | 长 **16–22px** · 宽 **5–7px** | ≈ **2.7–3.1 : 1**（满足 ≥2:1） | 主体 `P_ALLY #3ED0E8` · 尖端高光 `#EAFBFF` · 尾迹渐隐 |
| **敌方**（可选·低优） | **圆球 / 不规则碎块** | 直径 **10–14px** | ≈ **1 : 1** | `P_ENEMY #FF6B3D`；精英弹 `P_ELITE #E8437F` |

- **尺寸随体量映射**：弹体尺寸**不随塔/怪体量缩放**（屏幕空间恒定，保证远处细小单位也看得见、近处不糊）——这与 `U_OUTLINE`（`:98` 恒定 2px）同口径。
- 友方弹**尖端高光**是"读得动"的关键：16px 长的细弹在深底上，靠尖端一点亮色 + 尾迹才成型。

### 1.2 运动与淡出

| 参数 | 规格 | 理由 |
|---|---|---|
| 起点 | 塔位中心（`_slots_arr()[slot]`） | 现成 |
| 终点 | 当前**最前活怪**（`min t_remain`）的 `pos`；若中途目标消失则**重定向**到新的最前怪 | 与集火口径同源 |
| 飞行 | **固定滞空 0.10–0.15s**（`lerp` 起→终），**与距离无关** | 距离无关 → 永远"干脆"，不会远塔弹慢吞吞 |
| 尾迹 | 沿速度反向 **6–10px** 渐隐（α 0.6→0），宽度 = 弹体宽 × 0.5 | 强化"发射感"，不占视觉重心 |
| 命中 | 抵达终点即销毁；**可选**在终点触发一次 1 帧白闪（微反馈，见 §1.4） | 无因果 → 只是"看起来打到了" |

### 1.3 密度调制（"看起来像"的关键表现手法）

**目标**：让弹流密度**大致匹配输出强度**，制造"越强越密"的观感（服务 §0 第二原则 + P2）。

| 调制源 | 规则（建议初值，实现期可调） |
|---|---|
| 单塔视觉射速 | `fire_hz = clamp(2 + 0.5 · h, 2, 12)`（`h` = 塔层数；越强射越快） |
| 全局放缩 | 由 `dps` 归一化放大到 **×1 → ×3**（早期稀、后期密） |
| 硬上限 | **同屏投射物 ≤ 300**（§8.5）；触顶时**降低发射频率**而非堆积 |
| 目标数 | 每塔独立计时（可用 `_vfx_t` 相位错开，避免齐射"一坨"） |

> **表现手法要点**：**相位错开**（每塔起点相位不同）+ **箭形朝向速度**，让弹流读起来是"喷射的火力网"而非"一排行进队列"。

### 1.4 🔴 诚实边界（必写进代码注释）

- 弹流是**氛围/爽点装饰**，**与真实伤害分配无因果对应**（玩法 hitscan 聚合，见 §0.1）。
- 密度**只能由 `dps`/`h` 调制**（近似匹配输出），**不能**做到"这发弹 = 这只怪挨了多少血"。
- **若产品要求"因果投射物"** → 必须把 hitscan 拆成真实 projectile 实体 = **玩法机制变更**，超出 VFX 范畴，**另议**（不建议，代价远超收益）。
- ⚠️ **不得**用弹流**遮挡**塔轮廓或核心 HP 条（§8.6 锚点4-1）→ 弹体绘于**层8**（塔=层6、怪=层7 之上，核心 HP=CanvasLayer 130 之上仍穿透）。

### 1.5 参数汇总

| 项 | 值 |
|---|---|
| 友弹 | 长 16–22px / 宽 5–7px / `P_ALLY` + 尖端 `#EAFBFF` |
| 敌弹（可选） | φ10–14px / `P_ENEMY`（精英 `P_ELITE`） |
| 飞行 | 固定 0.10–0.15s（lerp，距离无关） |
| 尾迹 | 6–10px 渐隐 |
| 密度 | `fire_hz = clamp(2+0.5h,2,12)` × `dps` 放缩(×1→×3) |
| 上限 | ≤ 300 · 对象池化 |
| 层 | 层8（怪之上） |

## 2. P1-2 · 伤害数字

> 对齐 art-bible §8.3（五档分级）+ §8.6 锚点4-2（**固定网格排布、禁止乱飞重叠**）+ §8.5（≤40 聚合）。

### 2.1 五档分级表（§8.3 落地）

**基准字号**：**20px @1080p**（× 倍率；最小 16px 红线见 §5）。数字用**等宽**、**描边**（深底描边提升对比）。

| 单次伤害占目标最大血量 | 字号倍率 | 字号(px) | 颜色 | 动画 |
|---|---|---|---|---|
| < 10% | 1.0× | 20 | 白 `#FFFFFF` | 上浮 + 淡出 |
| 10–30% | 1.3× | 26 | 淡金 `#FFE38A` | 弹出 + 轻微缩放 |
| 30–60% | 1.7× | 34 | 辉金 `#FFC94A` | 弹出 + 旋转抖动 |
| 60–100% | 2.2× | 44 | 橙金 `#FF8A2B` | 弹出 + 冲击环 + 1 级震屏 ⚠️ |
| **超杀 / 溢出** | **3.0×** | 60 | **彩虹流光** | 弹出 + **彩虹色文字 + 字号弹跳 + 一次性亮环**（2D 替代，见下注） |

> ⚠️ **两条红线规避（务必执行）**：
> 1. **"1 级震屏"**：本项目**尚无震屏系统**；一旦做，**必须可在设置中关闭**（§9.1 P0）。建议**首版先做"数字弹出 + 冲击环"、震屏延后**，避免引入不可关的震屏。
> 2. **"全屏色差 / 慢动作 0.35×"**：`gl_compatibility` **无 Bloom/色差**；且**慢动作 = 写 `Engine.time_scale`** → **与 P1-3b hitstop 同源，触碰"时间轴权威"架构红线**（唯一写入者须为 `TimeDirector`）。→ **超杀档的"慢动作"与"色差"，在本轮一律降级**为：**彩虹色文字 + 字号弹跳 + 一次性亮环**（2D 替代，不碰 `time_scale`）。

### 2.2 固定网格排布（锚点4-2 · 防重叠核心）

**目标**：后期同屏数十个数字**不重叠、不乱飞**。参考《吸血鬼幸存者》的处理。

- **网格化**：把战场可视区划分为**规则网格**（建议单元 ≈ 96×48px，覆盖阵场内区）。每个伤害数字**吸附到最近的空闲网格中心**。
- **占位**：数字出现时占其网格单元；单元生命周期 = 该数字动画时长（约 0.5–0.8s）。
- **冲突**：目标单元被占 → **沿螺旋/外扩**找最近空单元（半径递增，≤ 3 圈）；仍无 → 触发**聚合**（见 §2.3）。
- **禁项**：**禁止**随机散点、禁止"从怪身上水平飘"（会与怪/塔重叠）。
- **层次**：数字绘于**独立文字层**（**层之上**，始终压在所有世界元素之上；不遮塔轮廓由"网格落点避开塔位"保证）。

### 2.3 同屏 ≤40 聚合规则（§8.5）

- **上限 40**：超过 40 个待显数字时，**同网格/邻近的伤害合并**为一个聚合数字：文本 `×N`（N=合并次数）+ **升级一档**表现（如聚合达标则跳档颜色）。
- 聚合数字优先级高于单发数字（聚合框更醒目）。
- 目的：**防刷屏 + 防性能崩塌**（§8.5）。

### 2.4 数据来源（三要素）

| 要素 | 来源 | 状态 |
|---|---|---|
| **在哪** | `monsters[].pos` | ✅ 已有 |
| **哪只怪** | `monsters[].index` | 🔑 **拟新增 1 只读键**（§0.1） |
| **受多少伤** | **帧间差分**：缓存 `index → prev_hp`，本帧 `Δhp = prev_hp − hp`（>0 即伤害） | 需 `index` 键 |
| **击杀数字** | 订阅既有 `monster_killed(m)`（携带存活 Monster 对象），用 `m.pos(v0_)` 弹出 | ✅ 信号已存在，**连 `index` 键都不需要** |

- **缓存清空边界**：波号 `w` 变化时清空 `index → prev_hp`（`index` 每波重置，天然无跨波冲突）。
- **对象池**：数字节点池化（≤40 活跃）。

### 2.5 同怪续喂（v1.2 实现增强 · 2026-11-07）

> **动因**：玩法是 hitscan **连续结算**（`_WaveSim.DT = 0.1s`），每 tick 单怪都会掉一次血。按 §2.4 逐帧差分直接弹数字 → 0.7s 寿命内**同一只怪会铺出 7 个同值数字**、按 §2.2 网格排成 3×3 一片（实测 `G:/AI Demo/shots_dmg/before-02.png`：7×「2」）——读不出信息，只剩噪点。

口径（**不改玩法、不改 §2.1 五档、不改 §2.2 网格尺寸、不改 ≤40 上限**）：

| 项 | 口径 |
|---|---|
| 续喂窗口 | 同一 `index` 的活跃数字在 `life ≤ 0.45s` 内被新伤害**累加**（不新建、不换格） |
| 断代 | 单数字 `age > 1.0s` → 停止续喂；下 tick 在怪的**新位置**新建（同屏最多 2 个并存，旧的淡出） |
| 主文本 | **累计伤害值**（`_fmt_dmg(amount)`）——不再只写 `×N`，数值信息不丢 |
| 次数 | 右上角小号 `×N`（`count`）→ §2.3 的 `×N` 语义保留，主次分明 |
| 档位 | `max(旧, 新)`；击杀帧再升一档（§2.1 不变） |
| 位置 | 首次分配后**不动**（§2.2 禁乱飞）；候选顺序改为**上方优先**（正上 → 斜上 → 两侧 → 下方），避免数字均匀铺满怪四周 |
| 反馈 | 每次续喂触发 0.1s / +5% 脉冲缩放（"又打到了"），幅度与频率均低于 §9.2 闪烁红线 |

**效果**：同屏数字 **7 → 1–2**（22 dps 受控探针），单怪读数稳定在怪正上方一格、不遮怪。

### 10.2 项 2 · 超杀档（tier4）实践不可达（手感 / 数值）

**根因（精确）**：`vfx_layer.gd:275-289` —— `tier` 由 `frac = dmg/hp_max` 分档（`>1→4`；`≥0.60→3`；…），`escalate`（**仅击杀帧**）再 **+1**。故 **tier4 = 击杀 `∧` 击杀帧 `Δhp ≥ 0.60·hp_max`**（= "近满血一击"）。玩法为 **hitscan 逐帧小增量** ⇒ 击杀帧 `Δhp` 通常只是一小块余量 ⇒ `+1` 后仅到 tier1-2 ⇒ **tier4 实践恒 0**（复核：20 波实测）。

**三选项 + 代价 + 红线影响**：

| 选项 | 动作 | 代价 | 红线影响 |
|---|---|---|---|
| **(a) 接受「超杀=稀有」** | 文档明写其为低概率瞬间、对齐期望 | 最低（零代码） | ✅ **无**（纯文档）—— 但等于承认 tier4 渲染近乎不可见（§8.3 一档 + 已实现渲染成"死演出"） |
| **(b) 改 `escalate` 阈值**（≥60% → ≥35%） | 改击杀升档判定 | 低（1 常量） | 🔴 **触「不改定稿数值/口径」红线 → 须用户拍板**；⚠️ `60%` 同时是 §8.3 **定稿档界**（橙金档下界）→ 改它须**同步**评估 §8.3 表 |
| **(c) 加表现层独立触发**（"爆发击杀"） | 新增一条 tier4 入口 | 中（VFX 逻辑 + 复验） | 🟡 **取决于实现**：**纯表现层变体**（用现有 `index→prev_hp` 帧差缓存、**零新 snapshot 键**）→ **不触只读契约、不改定稿数值**；若需**新 snapshot 键** → 🔴 **触只读契约 → 须用户拍板** |

> 1. **零定稿数值改动**（保留 §8.3 五档与 `60%` 档界不动）；
> 2. **零新契约**（复用既有帧间差分缓存 `_hp_cache`，`vfx_layer.gd:89/253-268`）；
> 3. **使 tier4 在真实高 DPS 后期"可达但不泛滥"** —— 触发语义改为"**爆发击杀**"（例：该怪在被击杀前的**短窗口**内（≤T 秒 / ≤K 观测帧）从 **≥X%·hp_max** 直接归零），与 art-bible **§8.4「单秒击杀数 ≥ 阈值」的"快"语义同源**；
> 4. **加法式**：不改既有五档；tier4 只是**多一条入口**。
