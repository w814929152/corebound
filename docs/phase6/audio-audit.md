## 1. 现状核实（只读审计）

**审计方法**：`find`（音频扩展名）+ `grep`（`AudioStreamPlayer` / `AudioServer` / `AudioStream` / `AudioBus` 等 token）+ 人工核对 `project.godot` 与场景文件。审计命令均为只读，未改动任何文件。

| 检查项 | 方法 | 结果 |
|---|---|---|
| 音频资产文件（`.ogg/.wav/.mp3/.flac/.aac/.m4a/.opus`） | `find . -type f -iname '*.ogg' -o ...` | **0 个** ✅（零资产） |
| `AudioStreamPlayer` / `AudioStreamPlayer2D/3D` 节点（`.tscn`） | `grep -rin` over `scenes/ tools/ autoload/` | **0 处** ✅ |
| `AudioStream` / `AudioServer` / `AudioBus` / `AudioListener` 代码引用（`.gd`） | `grep` over 全仓 `*.gd` | **0 处** ✅ |
| 音频/声效/音乐目录（`audio/ sfx/ sound/ music/`） | `find . -type d -iname ...` | **无** ✅ |
| `project.godot` `[audio]` 段（总线布局引用） | `grep -n '\[audio\]'` | **无该段** ✅ |
| `default_bus_layout.tres` / 任何 `*bus*layout*` | `find` | **无** ✅ |
| `autoload/` 目录 | `ls` | **空目录**（无全局单例） ✅ |

**结论**：本项目当前是**音频白纸**——没有总线结构、没有播放节点、没有资产、没有中间件集成。这意味着：
1. **无历史包袱**：总线布局、命名规范、事件约定可一次性按最佳实践建立，无需兼容旧资产。
2. **无「对齐既有音频」的约束**：本报告的方向即为该项目的**听觉起点**，而非改造。
3. **风险**：音频缺席使得 art-bible §8「反馈必须随数值升级」与 §8.4「超载演出」目前**只有视觉半边**——「低频充能音效」（art-bible 原文指派给阮和鸣）尚无落点，这是 P2「雪崩爽感」的一个明确缺口。

> 附注（维度事实，影响衰减设计）：当前 MVP 渲染层为 **2D**（`scenes/battle_shop.tscn` 用 `Node2D` / `CanvasLayer`；`monster_layer.gd extends Node2D`，世界→屏幕映射见 `_to_screen()`），**非** art-bible 目标中的 3D 低模。故 §4.5 的声像/衰减按 2D 战场设计，并预留 3D 迁移路径。

## 2. 音频方向（简化 art-bible 体例）

### 2.1 一句话听觉身份

> **「一座冷静的青色精密机械，在一局之内逐渐失控成橙色的咆哮。」**

- **青色（冷 / 玩家 / 精密）** = 塔、UI、积分、增益、build 成型 → **清亮、金属、规整、有颗粒的电子音色**。
- **橙色（暖 / 敌人 / 混沌）** = 怪物、来袭、威胁、爆炸 → **低沉、肉感、噪声、失真驱动**。
- **失控** = 从开局的克制稀疏，到后期的轰鸣洪流——**音频的"音量/密度"必须和画面一样随数值升级**（art-bible §1 第二原则 / §8.2）。

对齐四条支柱：
- **P2 雪崩无上限** → 音乐与战斗层 SFX 的**密度、低频能量、失谐度**随波次与 DPS 指数抬升，让"音墙"成为数值爆炸的听觉载体。
- **P4 零操作高密度** → 「本作的操作层就是刷商店本身」——**翻牌/购买/锁定的触感必须像动作游戏一样干脆**。这是 SFX 侧**最高优先的"手感"任务**（§5 MVP 第 2 项）。
- **P1 不动如山** → 声音不喧宾夺主；战场靠**余光**（art-bible §2.1 C3 的"红光脉冲"）+ **低频环境层**维持，不要求玩家盯战场。
- **P3 每局一个新解** → 三条 build 路径的**雪崩音景彼此可区分**（§2.3 第三层，Phase 6.3）。

### 2.2 设计原则（六条硬约束）

1. **听 = 视觉的第二编码（同构映射）**：art-bible 已用「青 vs 橙」做红绿色盲安全的**第一编码**，音频必须同构——**玩家侧事件用青系音色（中高频、明亮、谐波干净），敌方事件用橙系音色（中低频、噪感、谐波失真）**。
2. **反馈随数值升级（JuiceScale → AudioScale）**：art-bible §8.2 定义全局 `JuiceScale ∈ [0,1]`（由 DPS/连击/波次推导）。**同一音效的音量、低频量、变体数、混响尾巴必须乘 `AudioScale`**——1 级击杀与 30 级击杀听感必须不同（§4.2 事件参数化）。
3. **稀缺高光（反脱敏）**：art-bible §8.4 明令超载「冷却 ≥ 6s、上限 8s」是为了「爆炸成为稀缺高光而非常态噪音」。**音频必须同源**：Overload 充能音效（§3 事件 F-06）触发即压低其他总线，冷却期内不再触发。
4. **零操作 → 手感即反馈**：无技能、无微操 → 玩家的**每一次输入（R / 1·2·3 / Space / Tab / 点击卡牌）都必须有即时、干脆、分层的听觉回弹**（art-bible §5.1 的"实体感卡牌"听觉对应物）。
5. **事件驱动 · 只读 · 零玩法写入**：🔴 音频层是**纯表现层订阅者**——**不新增信号、不写玩法状态、不拥有游戏数据**。所有触发来自既有信号或只读 `snapshot()`（对齐 `control-manifest §5`：UI/表现层不持有游戏状态）。
6. **不糊（频段分工）**：后期数百怪同屏，若所有音效挤在中频 → 听觉糊成一团。**为每类事件预留频段**（§2.4），并用总线让「人声/UI 永远清晰」。

### 2.3 音乐基调 —— 三阶段情绪弧（对齐 game-concept §2.2 心流三阶段）

> **技术形态**：**不做一次性长曲**。采用 **垂直分层（vertical layering，stems）+ 水平过渡（horizontal resequencing）**——同一段和声/节奏素材拆成 4~6 条音轨（stem），按游戏状态**实时增删层**。理由：波次与起飞点是**连续变量**，长曲无法"随数值增长加音量"，分层才能让音乐成为**数值的可听映射**。

```
情绪强度
  ↑
  │                                             ┌─── 雪崩期 C（W13+）· 全 stem 满编 + 失谐
  │                                       ╱╱╱╱╱╱
  │                                 ╱╱╱╱╱╱       ← 成型期 B（W6-12）· 逐件加入 stem + 首次协同相变
  │                     ╱╱╱╱╱╱╱╱╱╱
  │           ╱╱╱╱╱╱╱╱╱                            ← 苟活期 A（W1-5）· 稀疏心跳 + 悬念和声
  │   ╱╱╱╱╱╱╱
  └────────────────────────────────────────→ 波次
     A 苟活期(W1-5)      B 成型期(W6-12)      C 雪崩期(W13+)
```

| 阶段 | 波次 | 主导情感（game-concept §2.2） | 音乐形态 | 技术参数 |
|---|---|---|---|---|
| **A 苟活期** | W1–5 | 紧张 · 脆弱 · 期待 | **稀疏**：低频心跳脉冲 + 未解决的和声悬念 + 大量留白；怪物来袭时加入不协和的高频警示层 | 1–2 stem；BPM 低；动态范围大；`AudioScale ≈ 0.2` |
| **B 成型期** | W6–12 | 顿悟 · 掌控 · 焦灼 | **相变**：**首次 Tag 协同成立**（§3 事件 F-05）触发主题"点亮"——主导旋律 stem 首次进入 + 短暂 ritardando/挂留弦解决感；此后每波逐件加入节奏/低音 stem | 3–4 stem；首次出现完整主题；`AudioScale ≈ 0.5` |
| **C 雪崩期** | W13+ | 狂喜 · 主宰 · 观赏 | **失控**：全 stem 满编 + 逐步升调的失谐层 + 环回加厚；**Submission 美学**（观赏自己造物）→ 音乐要"耐听、可循环、不抢戏" | 5–6 stem；饱和/压缩/轻度失真；`AudioScale ≈ 1.0` |

**环境换装音乐分层**（对齐 art-bible §2.4 波次色彩迁移，`3s` 缓动过渡）：

| 波次区间 | 主题（art-bible） | 音乐色彩 | 与视觉同步项 |
|---|---|---|---|
| 1–5 | 晨雾 | 冷色、留白、单一脉冲 | 与雾色 `#2A3550` 同冷 |
| 6–10 | 黄昏 | 加入暖音色与节奏件 | 主光转橙白 `#FFD9A8` |
| 11–15 | 血夜 | 加入低频轰鸣 + 边缘脉冲同步音 | 边缘红光缓慢脉冲 |
| 16+ | 虚空 | 加入高频星屑式颗粒 + 失谐 | 星屑粒子缓慢飘落 |
| **Elite / Boss 波** | —（压暗 20%） | **临时 duck 常规音乐 + 插入精英主题动机**（水平过渡） | Letterbox + 地面符文 |

**Overload / 起飞高光**（art-bible §8.4，用户原话已把「低频充能音效」指派给阮和鸣）：
- 进入演出（0.4s）：**低频"充能"上升扫频** + 其余总线**侧链压缩**（duck 下降 -6~-9 dB）。
- 持续：**加厚低音层 + 每 10 连击一次"字样"重音**（对齐 art-bible「每 10 连击跳一次字」）。
- 退出：**一次下行释放尾音**（对齐"能量向内收束消散"）。
- 🔴 **冷却 ≥ 6s、上限 8s**（与 art-bible §8.4 数值严格一致），冷却内不再触发，防脱敏。

## 3. 音频事件表（绑定真实游戏事件）

> 🔴 **三条铁律**：① **事件驱动**；② **零玩法写入**（只订阅、只读 `snapshot()`，绝不 `emit` 新信号、绝不改玩法状态）；③ **零新信号**（不向 `wave_director.gd` / `time_director.gd` / `shop_controller.gd` 加任何 `signal`）。
> **优先级**：P0 必播（信息关键）/ P1 重要（情感/反馈）/ P2 增强（密度/氛围，可被抢占）。
> **触发时机说明**：`wave_result` 在 `TimeDirector.wave_ended` **之前**发出（见 `shop_controller.gd:108` 注释）→ 结算音先于安全窗音。

### 3.1 生命周期（局 / 波次）

| ID | 事件 | 触发源（既有信号 / 只读派生） | 时机 | 优先级 | 变体 | 衰减 | 备注 |
|---|---|---|---|---|---|---|---|

## 4. 实现策略（Godot 4 最小可行接入）

### 4.1 架构总览：`AudioDirector`（表现层 autoload，只读订阅）

```
AudioDirector (autoload, process_mode = ALWAYS)   ← 唯一音频权威，表现层
 ├─ 订阅层：连既有信号（TimeDirector / WaveDirector / ShopController / Dialogs）
 ├─ 派生层：PollingProbe（~10Hz 轮询 snapshot()，派生无信号事件 §3.5）
 ├─ 调度层：SFX 池 + 优先级抢占 + 节流聚合器
 ├─ 音乐层：StemPlayer（垂直分层 + 水平过渡）
 └─ 输出层：AudioServer 总线（Master → Music / SFX / UI / Voice）
```

- **零玩法依赖方向**：`AudioDirector` **只持有对既有节点的弱引用（只读）**，不反向调用任何 gameplay 方法（对齐 `control-manifest §5`）。
- **autoload 注册**：需向 `project.godot` 增加 `[autoload]` 段（当前 `autoload/` 为空目录）。🔴 属**代码改动**，本批次**不做**，仅在 §4.6 分期中列出。
- **不引入中间件**：MVP 用 Godot 原生 `AudioServer`（理由见 §4.7）。

### 4.2 总线结构（AudioServer Bus Layout）

```
Master
├── Music     （音乐：stems 混合，支持 duck）
├── SFX       （战斗音效：命中/击杀/爆炸/塔）
├── UI        （界面/商店：恒定音量，永不被战斗淹没）
└── Voice     （🔴 预留：未来 VO / 本地化，本项目 MVP 不用）
```

- 落地方式：建立 `res://default_bus_layout.tres`，并在 `project.godot` `[audio]` 段引用（当前二者皆无）。
- **动态混音（duck）**：Overload 触发时对 `Music`/`SFX` 做 -6~-9 dB 侧链式 duck（0.15s 上升 / 0.5s 回落，对齐 art-bible §4.4 包络）。
- **减速（C1 战术减速）**：商店开门 → `Music`/`SFX` 加**低通滤波**（模拟"聚焦/失焦"），**不改音高**（🔴 理由：`Engine.time_scale` 默认**不影响**音频播放；若对音乐 pitch-bend 会破坏氛围且像卡带故障。用滤波更优雅）。

### 4.3 事件 / 资产命名约定（对齐 art-bible §10.2 `snake_case`）

```
res://assets/audio/
├── music/    music_<层>_<名>_<stem>.ogg    例：music_core_loop_arp.ogg
├── sfx/      snd_<类>_<名>[_<变体>].ogg    例：snd_combat_kill_01.ogg
├── ui/       snd_ui_<名>.ogg               例：snd_ui_reroll_02.ogg
└── vo/       vo_<角色>_<行>.ogg            （🔴 MVP 空，预留）
```

| 前缀 | 类别 | 示例 |
|---|---|---|
| `music_` | 音乐 stem | `music_snowball_bass`, `music_elite_stinger` |
| `snd_combat_` | 战斗音效 | `snd_combat_leak`, `snd_combat_tower_down` |
| `snd_ui_` | 界面音效 | `snd_ui_reroll`, `snd_ui_buy_legendary` |
| `snd_warn_` | 警告 | `snd_warn_core_low`, `snd_warn_budget_drained` |
| `snd_sting_` | 乐句点缀 | `snd_sting_takeoff`, `snd_sting_victory` |
| `vo_` | 配音（预留） | `vo_announcer_wave` |

> **规则**：禁止空格/中文文件名；变体用 `_01` 递增（对齐 art-bible §10.2）；BGM 用 `.ogg`（流式，省内存），超短 UI 音可用 `.wav`（低延迟）。

### 4.4 SFX 池 / 优先级抢占 / 同发上限

**对象池**（对齐 art-bible §8.5「所有 VFX 必须对象池化，禁止运行时 instantiate」——音频同纪律）：
- 预建 **N=24 个 `AudioStreamPlayer`**（非定位）+ **4 个 `AudioStreamPlayer2D`**（定位，用于漏怪/塔位等战场事件）。**禁止运行时 `new()`**。

**优先级抢占**：池满时，**低优先级（P2）让位高优先级（P0）**——例如后期击杀洪流（P2 聚合层）不得挤掉塔被摧毁（P0）、核心受创（P0）等关键音。实现：每个播放请求带 `priority`，池满时抢占 `priority` 最低且**已播时长最长**的实例。

**同发上限（并发预算）**：

| 类别 | 并发上限 | 说明 |
|---|---|---|
| 击杀个体音 | **8** | 超出转"连续收割"聚合层（见 §4.5） |
| 全局战斗 SFX | **24** | 池规模 |
| UI 音效 | **4** | 恒定清晰，独立小池 |
| 音乐 stem | 6 | 常驻，不占 SFX 池 |
| **Voice** | 1 | 预留 |

**高密度事件节流（关键）**：
- **`monster_killed` 聚合器**：滑动窗口统计 kill/s。
  - `< 10 kill/s`：逐只播（受并发 ≤ 8 限制，超出的丢弃最低优先级）。
  - `≥ 10 kill/s`：切换为**连续颗粒层**（一个循环采样，音量随 kill/s 抬升）+ 每 N 杀一次**爆点变体**。→ 听觉从"噼啪"变为"洪流"，**天然映射 P2 雪崩**。
- **`monster_spawned`**：每 0.15s 窗口最多 1 次"浪"音，不逐只播。
- **全部派生事件**（§3.5）统一走 ~10Hz 轮询器，天然限频。

### 4.5 定位 / 声像（2D 战场现状 + 3D 迁移预留）

- **现状（2D）**：战场为 `Node2D`（`monster_layer.gd`）。非定位全局音用 `AudioStreamPlayer`；少数战场定位音（漏怪、塔位事件）用 `AudioStreamPlayer2D`，其位置由 `monster_layer._to_screen()` 映射的屏幕坐标反推世界位；或更简：**按屏幕 x 相对中心做双声道 pan**（`AudioStreamPlayer.panning_strength`）。
- **衰减（`AudioStreamPlayer2D`）**：`max_distance ≈ 2~3 屏宽`；`attenuation` 用对数。**UI / 音乐永不定位**。
- **3D 迁移预留**：若后续切换到 art-bible 的 3D 低模（等距相机），将定位播放器换为 `AudioStreamPlayer3D` 并接 `Camera3D` 的 `AudioListener3D`，事件表与命名**不变**——只需替换"输出节点"。

### 4.6 与 `time_scale` / `paused` 的关系（🔴 必读坑）

| 场景 | 引擎事实 | 处理 |
|---|---|---|
| **安全窗 `get_tree().paused = true`** | `AudioStreamPlayer` 默认 `process_mode = INHERIT` → **随暂停静音/停播** | 🔴 `AudioDirector` 及所有音频节点设 `process_mode = ALWAYS`；音乐在安全窗**继续**（情绪不断），或用 `stream_paused` 显式控制 |
| **战术减速 `Engine.time_scale = 0.35`** | `Engine.time_scale` **默认不改变音频播放速度** | 商店开门用**低通滤波**表达"聚焦"，**不**对音乐 pitch-bend（理由见 §4.2） |
| **窗口失焦** | delta 跳变 | 音频无此问题（采样时钟独立），但轮询器（§4.1）需 clamp，防一帧内刷爆派生事件 |
