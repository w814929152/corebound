### 2.1 程序化生成的可行性判定（Godot 原生 / 脚本）

**✅ 可在 Godot 内/用脚本程序化生成（成本≈0，授权=自有 CC0）**：
- **UI 类**（S-02/S-03 翻牌/购买）：click、滤波噪声滑音、FM 铃 → 短小确定，`AudioStreamGenerator` 实时合或离线 numpy 渲染。
- **冲击/受创类**（C-03 漏怪）：低频 sine 撞击 + 饱和失真。
- **Riser/扫频**（L-02 波次、F-06 充能）：HP/带通扫频噪声，脚本确定性生成。
- **Sub drone / pulse**（音乐 stem 1–2）：正弦/方波 + LFO + 滤波，程序化天然契合基调 A。
- **"洪流"颗粒层**（C-02 聚合）：噪声/颗粒循环，参数随 `kill/s` 调制。

**🟡 建议外部资产（程序化难到"好听"）**：
- **金属断裂**（C-04 塔摧毁）：真实金属采样 + 梳状滤波处理，效果远胜纯合成。
- **音乐 stem 3–4（harmony_pad / rhythm）**：建议用**免费合成器 + 免费 DAW 自制**（**仍属自有**，非外部库）——比外包便宜、比授权库安全。
- **胜负乐句**：自制或短 sting 授权。

**🔴 必须外部/专业制作**：
- 无。但**若追求商业级音乐质感**，4-stem 音乐建议**要么自制（免费工具）要么买断外包**——**不推荐**用通用授权 loop 拼（撞库+与基调 A 不融）。

### 2.2 工具链建议（Solo）

| 环节 | 免费工具 | 说明 |
|---|---|---|
| 合成器 | **Vital**、**Surge XT**、Cardinal | 自制 stem/音色，覆盖 FM/sub/减法 |
| DAW | **Reaper**（评估版）、**LMMS**、**Ardour** | 编配 stem、导出分轨 |
| 音效处理 | **Audacity**、**Sox**、Python(numpy/scipy) | 噪声合成、批处理、响度归一 |
| 格式 | `.ogg`（Vorbis q5–7，流式）/ `.wav`（短音） | 见 §4 |

## 3. Solo 推荐路径（成本最优 + 授权最稳）

> **核心判断**：基调 A = **电子合成**，天然适合**程序化 + 自有合成**。→ 走 **「程序化/自制 为主，CC0 库补关键采样，外包仅保底」** 的混合路径。

| 阶段 | 动作 | 预计投入（人时 / 成本） | 授权结果 |
|---|---|---|---|
| **第 1 步** | **程序化生成** UI 类（8）+ 漏怪 + 波次 + 塔复活 + 击杀（≈14–16 个） | ~2–4 人天（写生成脚本 + 调参） | **自有（CC0）** |
| **第 2 步** | **CC0 库**补：金属断裂（C-04）、少量冲击真实采样 | ~0 成本 + 0.5 人天筛选 | CC0 / 少量 CC-BY（署名） |
| **第 3 步** | **免费合成器 + 免费 DAW 自制** 4-stem 音乐（BPM96/D 小调） | ~3–6 人天 | **自有（CC0）** |
| **第 4 步** | 胜负 sting：自制；若不满意 → 短外包 | 0 或 $150–500 | 自有 / 买断 |
| **保底选项** | 若时间紧 → 关键项（音乐/金属）外包 | $300–1200 | 🔴 须**买断/独家**条款 |

**预计总成本**：**$0–500**（自助路径） / **$800–2000**（音乐+金属外包保底）。

### 3.1 授权/合规注意（🔴 上线前必查）

| 来源 | 风险 | 处理 |
|---|---|---|
| **CC0** | 最低（无署名要求） | 优先；仍需留存"来源+许可"记录 |
| **CC-BY** | 需**署名** | 在游戏 credits 署名；确认署名格式 |
| **免版税商用库**（Sonniss/Freesound Pro/Splice 等） | 各平台 EULA 不同（是否允许游戏内再分发、是否需要额外授权） | 逐条读 EULA；**保存购买凭证与许可文本** |
| **外包定制** | 若未约定版权 → 可能只获"使用权" | 🔴 合同须写明 **work-for-hire / 独家买断 / 可商用可再分发** |
| **AI 生成音频** | 版权归属不确定、部分平台禁 AI 内容上架 | 🟡 谨慎；如用须核对 Steam 政策与生成工具条款 |
| **采样库内置 loop** | 部分禁止用于"音乐本身"（仅限影视配乐） | 禁用纯 loop 拼音乐 |

## 4. 交付格式与规格（给制作者/采购的验收标准）

| 项 | 音乐 | 音效 |
|---|---|---|
| 格式 | **`.ogg`（Vorbis q5–7）**，**流式**（`AudioStreamOggVorbis.loop=true`） | 短音 `.wav` 48 kHz/24-bit 或 `.ogg`；超短 UI 可 `.wav`（低延迟） |
| 声道 | 建议 **stereo**（若分层 stem 则各 stem 对齐等长） | **mono**（定位音，交给引擎声像）；**stereo**（UI/音乐） |
| 循环点 | 无缝循环（**首尾样本对齐**，无爆音；导出前做零交叉） | 一次性 |
| 响度 | 参考 **−16~−14 LUFS**，真峰 ≤ −1 dBTP | 归一化到统一基准（建议 −18~−14 LUFS，真峰 ≤ −1 dBTP） |
| 命名 | `music_<层>_<名>_<stem>.ogg` | `snd_<类>_<名>[_<变体>].ogg` |
| 落盘路径 | `res://assets/audio/music/` | `res://assets/audio/sfx/` 或 `.../ui/` |
| 尺寸预算 | BGM ≤ ~25 MB（合计） | SFX ≤ ~15 MB（合计） |

> 🔴 **命名与 `audio-spec-a §3.1`/§4.6 的「资产 id」逐字一致**——engine 端 `SFX_TABLE` 靠 id→路径映射，改文件名即断链。

## 5. 待用户拍板项（剩余）

1. **资产来源最终选型**：自助（程序化+自制，$0–500） / 混合（+关键外包，$800–2000） / 全外包（高成本）？——**推荐自助 + 保底外包**。
2. **音乐是否必须原创**：自制 4-stem（推荐，自有版权） vs 授权 loop（便宜但撞库+不融）。
3. **MVP 取舍确认**：`audio-spec-a §3.1` 的 7 核心（+ 6.3 的 Overload）是否照单，或先做更小集（如只做 4 个：击杀/翻牌购买/漏怪/波次）。
4. **外包预算线**（若选混合/外包路径）。
5. **是否在本期启动音乐（成本最高）**，还是先出 SFX、音乐延到 6.2。

## 6. 风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| A-a | **音乐撞库 / 授权不清**（上线法律风险） | 优先自制（自有版权）；若授权须逐条核 EULA + 留凭证；外包须买断条款 |
| A-b | **程序化音效"廉价感"** | 关键项（金属/胜负）用真实采样/自制；程序化仅用于瞬态与 UI |
| A-c | **制作周期挤压试玩** | 分期：6.1 先出 7 音效（周期短）；音乐按 §5.5 可延 |
| A-d | **格式/命名不统一 → 接不进 engine** | §4 规格为验收基线；命名与 spec-a 逐字对齐 |
| A-e | **响度不一致 → 混音难** | 统一 LUFS 基准（§4）+ 总线（music 挖坑） |
