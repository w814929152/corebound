## 0. 结论摘要（TL;DR）

| 维度 | 判定 | 一句话 |
|---|---|---|
| **配色一致性** | 🟢 大体达成 | 青橙双极 + 主色板精确 hex 已落地；**遗留 PATH 旧口径怪色**（Tank 用蓝，落在"我方极"）与**稀有度五级色阶缺失**两个缺口 |
| **形状 / 层级可读性** | 🟡 部分达成 | 塔/怪形状对立、描边、blob 影、rim、威胁楔、⚔🛡 形状冗余**均已落地**；**RADIAL 塔不看原型色**（三塔同形）、投射物层空、体量分层不足 |
| **可访问性** | 🟡 部分达成 | "亮度/形状替代纯色相"策略**在战场侧贯彻良好**；但**商店买得起/买不起=纯色**（违反 §9.2 红线）、**最小字号 <16px**、**无任何设置/色盲/减弱特效选项** |
| **VFX 密度与 P2「雪崩」兑现** | 🔴 **缺失（本作最大视觉债务）** | **零投射物、零伤害数字、零击杀碎片/冲击环、无 Overload 演出、无震屏/hitstop**。W16（雪崩期）截帧几乎空屏 → P2"屏幕被弹幕填满"**在画面上无载体** |
| **整体风格 / 等距（§1/§7）** | ⚫ **明确偏离（需用户拍板）** | 实现是 **2D 正交俯视径向 `draw_*`**（0 个 3D 节点），非 §1「3D 低模+Toon」、非 §7「2:1 等距」→ **美术圣经未随"径向核心围攻"转向更新，文档-实现失同步** |

**一句话总结**：**色彩与形状语言（静态可读性）已相当扎实**（这是本项目最被低估的成就），但**"动效层/爽点层"（弹幕、伤害数字、超载演出、震屏）几乎为零**——恰好是 P2 支柱和美术圣经 §0 第二原则的核心载体。**先还特效债，再谈美术升级。**

### 2.5 整体风格 / 等距（§1/§6/§7）—— ⚫ 文档-实现失同步

- 实现 = **2D 正交俯视径向**（`Node2D` 程序化 `draw_circle/draw_polygon/draw_arc`），**0 个 3D 节点**（grep `Node3D/MeshInstance/Camera3D/StandardMaterial3D/ShaderMaterial` 全空）。
- 美术圣经 §1 要求"3D 低模 + Toon 分层着色 + Inverted Hull 描边"；§6.1/§7 要求"2:1 等距菱形、相机 -30°45°、正交 size 6.0"。**均未实现**。
- 这是 Phase 3「径向核心围攻」玩法转向的直接结果（见 `README.md`、`docs/phase3/quality-gate-radial-migration.md`），但**美术圣经 v0.1 未随转向更新**。
- **锚点1「等距要塞」在径向模式下不成立**（俯视 ≠ 等距）。
- 连带失效的条款：C12（单光）、C17（等距网格/深度排序）、§4.2（toon/贴图）、§6.2（三角面预算）、§6.3（贴图/图集/材质数）、§7.2（3D 深度排序）——**这些"看起来该做"的条款其实是"不适用"而非"未做"**。

> **处置建议（需用户拍板，见 §5）**：A) 把美术圣经改写为"2D 俯视径向"适配版（低成本，承认现状，保留静态可读性成果）；B）或按原圣经补 3D 管线（高成本，Solo 风险大）。**在拍板前，不应按原 §7 等距规格"补齐"。**

## 6. 🔴 不做项（"看起来该做"但违背 P1 或视觉锚点，明确不做）

| 不做项 | 违背 | 依据 |
|---|---|---|
| ❌ **常驻侧栏商店** | 锚点6 / §2.1 C3 | 永久占 25–30% 屏，与 P2"屏幕被弹幕填满"冲突；**覆盖层是唯一可行形态** |
| ❌ **合成 / 塔进化 UI** | **P1 不动如山** | 合成销毁塔位→需重新布局（变相逼玩家"操作战场"）；且是一次性跃迁非持续复利（概念 §2.4.4 已否决） |
| ❌ **任何战斗内操作**（集火/撤退/技能/调兵） | **P1 不动如山** | P1 禁战场层微操；本作无操作层 |
| ❌ **纯色彩编码的游戏状态** | §9.2 红线① | 反向要求：**已存在的纯色编码（D1/D2）应补形状，而非新增纯色编码** |
| ❌ **高饱和战场底色 / 五颜六色场景** | 锚点2（克制底色） | 底色越静，爆发越响；底色饱和须 ≤ 特效的 1/3 |
| ❌ **遮挡塔轮廓或核心 HP 条的特效** | 锚点4-1 / C28 | additive + 深度裁切；核心 HP 是唯一豁免遮挡的 UI |
| ❌ **随机乱飞的伤害数字** | 锚点4-2 | 若做伤害数字（P1-2）**必须固定网格排布**，禁止重叠乱飞 |
| ❌ **暗色低对比"写实暗黑" / 无描边柔和渲染** | §1.3 风格红线 | 描边是可读性生命线；暗色低对比在百怪同屏=自杀 |
| ❌ **写实 PBR / 手绘贴图 / 骨骼动画（杂兵）** | §1.3 + §6.4 Solo 约束 | 成本与产能不匹配；继续走**程序化动画** |
| ❌ **纯像素等距风** | §1.3 | 与卡牌 UI 混搭撕裂；且与现径向俯视管线冲突 |
| ❌ **任何"必须盯战场读数"才能反应的机制** | **P1 / 锚点6 余光可读** | 实时商店下战场靠余光维持；告警必须编码为**运动+亮度**，禁止把关键告警做成只读数字 |
| ❌ **第二视觉焦点之外的常驻 HUD 膨胀** | 锚点6-1（禁止两区同等亮度） | 商店开→战场压暗；两区同等亮度=都看不清 |
