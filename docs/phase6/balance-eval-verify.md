## 1. 复核①：收入曲线（P1 的立论基础）

### 1.1 累计收入 4126 —— ✅ 证实（逐波独立重算）

公式（`wave_sim.monster_stats:48-50` + `mvp_config.cfg_of`）：
`hp=16·1.42^(w-1)` · `n=round(8+1.6w)` · `spk(scrap_per_kill)=2+0.5w` · **收入/波 = n·spk**（不含 mult）。

| w | n=round(8+1.6w) | spk=2+0.5w | 收入/波 | 累计 |
|---|---|---|---|---|
| 1 | 10 | 2.5 | 25.0 | 25.0 |
| 5 | 16 | 4.5 | 72.0 | 231.5 |
| 6 | 18 | 5.0 | 90.0 | 321.5 |
| **9** | **22** | **6.5** | **143.0** | 695.0 |
| **10** | **24** | **7.0** | **168.0** | 863.0 |
| 13 | 29 | 8.5 | 246.5 | 1520.5 |
| 15 | 32 | 9.5 | 304.0 | 2094.5 |
| 20 | 40 | 12.0 | 480.0 | **4126.0** |

→ **Σ = 4126.0，与原文逐行逐位一致**。✅ **证实**。

### 1.2 消费「144/波 硬上限」—— 🟡 数量对，但**范围滑移**（AI 路径 ≠ 实机）

- `max_actions = 12`（`mvp_config.gd:165`）✅；单动作基价上限 = `PRICE_STRUCTURE = 12`（`:58`；`shop_ai._TD.PRICE["tower"]`）✅；`shop_ai.shop_phase` 在 `actions ≥ max_actions` 时 `break`（`shop_ai.gd:389-391`）✅；`action_cost` 仅 `base + wave_price_step·counts`（`:355`）。
- 因此 **≤12×12 = 144/波** 是 **`shop_ai`（MC / AI 路径）** 的消费上限 ✅。

**🔴 但关键滑移**：**实机 runtime `shop_runtime.buy()` 无任何 `max_actions` 检查**（`:502-540`：仅校验 `scrap ≥ cost` 与 `legal`，**不计数动作**）→ **实机消费无 144/波 上限**。而 OBS-2 的**观测症状来自实机**（`playtest-report` §1.1，经 `runtime.buy`）。→ 用 AI 路径的 144 上限去论证**实机**盈余「被数学迫出」，**属路径错配**。

### 1.3 交叉点 W13 与「观测量级吻合 960」—— ❌ 证伪 / 需订正

- **交叉点**：收入/波首次 > 144 = **W10**（W9=143.0 < 144；W10=168.0 > 144）。原文「**从 W13 起**」**证伪**；且**与原文 §1.2 表自身 W10 行（收入/波=168.0）自相矛盾**。
- **盈余下界**：`4126 − 2880 = 1246` ✅ 算术成立，**但仅在「实机服从 144 上限」的前提下**。
- **吻合性**：原文称「观测量级吻合（终局 960）」。**独立反证**：
  - playtest 实机终局余额 **960**（`playtest-report` §1.1）。
  - **960 < 1246（模型下界）** → 观测值**落在模型下界之外** → 模型**不成立**于实机。
  - 佐证：我 T-P6-01 的仪器钩子记录 `[run_won] w=20 runtime.scrap=0 … scrap_earned(this)=480`，随后 W20 入账 → 余额 960 = **480×(1+income_mult) → income_mult≈1.0**（ScrapUp 饱和，`shop_runtime.gd:535`）→ **实机总收入 ≈ 8252（4126×2）**、总支出 ≈ **7292 ≈ 365/波 ≫ 144** → **实机确实不受 144 约束**。
  - → 「960 与 ≥1246 量级吻合」**不成立**（其**下界**已被观测违反）。

**小结（§1）**：收入 4126 证实；但把 **AI 的 144 上限**用于**实机 OBS-2**，并据此宣称「盈余被数学迫出 + 960 吻合」——**均需订正/降级**。（「收入长期高于可吸收消费」的**方向**可能仍立，但正确模型应是实机的**发牌/合法宿主/收益饱和**约束，而非 144。）

## 2. 复核②：W5 硬墙归因

### 2.1 threshold 数值 —— ✅ 证实

`threshold = total_hp/(D+t_reach)`，`D=wave_dur=28+2.2w`（`wave_sim.gd:57` / `mvp_config.gd:96-97`）。独立重算：
- w=5：hp=16·1.42⁴=65.05、n=16、total=1040.8、T=49.0 → **21.24** ✅
- w=6：hp=16·1.42⁵=92.37、n=18、total=1662.7、T=51.2 → **32.48** ✅
- 环比（w vs w−1）：W5=1.55 / W6=1.53 / W10=1.49 / W20=1.46 → 与原文 1.42–1.55 ✅ 一致。

### 2.2 「不同号 → 硬墙**必另有成因**」—— ⚠️ 推理过度（同 T-CP-08 家族）

`threshold(6)=32.48 > threshold(5)=21.24`，而实机 **W5 掉血、W6 零漏怪** —— 该**事实**成立 ✅。**但**由此推「硬墙**必**另有成因」**不成立**：门槛是「零漏怪所需 DPS」，而**玩家 DPS 也逐波增长**。若 `DPS(W5) ∈ [13.70, 21.24)`（W4 已零漏怪 → `DPS(W4) ≥ 13.70`）而 `DPS(W6) ≥ 32.48`，则**无需任何机制**即可同时解释 W5 漏、W6 不漏 → **门槛反例被 DPS 增长混淆**。

**真正支撑机制的是另一条观测**（原文亦引）：实机 **W5 结束时 3 塔全部 Disabled**（`playtest-report` §1.1）——塔被打停 → DPS 崩塌 → 漏怪。**机制结论应由「Disabled 观测」承载，而非门槛反例**。建议 §1.2 的「必另有成因」改为「门槛不解释掉血；掉血与塔被打停观测一致」。

### 2.3 Sapper 机制 / 窗口 / 现金 —— ✅ 机制与数值证实；单独归因 ⚠️ 无法确认

- **首登场**：`is_elite_wave(5)=true`（`monster_data.gd:158-159`）；`n_e(5)=max(2, round(0.10·16))=2`（`:163-166`）✅；`elite_indices(16,2)` = 出生序号 {4,12} 被标 `m.sapper`（`wave_director.gd:746-751`）✅。
- **伤害式**：`dmg = ATTRITION(1.5) × HP0(120) × m_dps(proto) × SAPPER_MULT(3.0) × DT`（`wave_director.gd:525-526`）✅ —— 与原文公式**逐字一致**。
- **不限距离**：`_aggro_target_valid` 对 `m.sapper` 恒 `true`（`:509-511`）✅。
- **~0.4s 打停 h=1 裸塔**：塔 HP `=120·1^0.6=120`（`monster_data.gd:107-109`）；Sapper 对塔 DPS `=540·m_dps` → Rush 432/s→0.28s · Swarm 324/s→0.37s · Tank 1188/s→0.10s → **「~0.4s 内」= 最慢（Swarm）上界，成立** ✅（但与 proto 相关，非唯一定值）。
- **窗口**：`spawn_window(5)=0.30` 最窄 ✅；`0.30×39=11.7s`、`interval=0.73s` ✅；W6 起 0.60 ✅（`mvp_config.gd:100-105`）。
- **现金见底**：W1–5 累计收入 **231.5** ✅（§1.1）。
- **⚠️ 无法确认项**：把硬墙**单一归因**为「Sapper 首登场」。W3 起常规 aggro 已活跃（`WARMUP=2`），**任何怪**在 `AGGRO_R=9` 内均可打停塔；Sapper 的角色（×3 + 锁死）与其「首登场」的**因果权重**，**静态分析无法隔离** → 需 MC **消融臂**（关 Sapper / 抬窗口 / 补现金 三臂）方能确认。原文三因子并列（未独断 Sapper），方向可接受，但**权重排序**应标「待消融验证」。
